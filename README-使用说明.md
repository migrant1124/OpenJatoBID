# OpenJatoBID v1.8.0 R3：使用说明

本包是已经确认需求与视觉方向后的**完整实施资料**，不是只做规划的任务书。

## 三份主文件

| 文件 | 作用 |
| --- | --- |
| [`docs/v1.8.0-spec-final.md`](docs/v1.8.0-spec-final.md) | 完整产品目标、全部功能、来源规则、模型复用、状态与 AC01–AC60 验收 |
| [`docs/v1.8.0-ui-handoff-final.md`](docs/v1.8.0-ui-handoff-final.md) | 11 张有效设计图、逐页组件交互、勘误、响应式与 UI 验收 |
| [`v1.8.0-CODEX-GOAL.md`](v1.8.0-CODEX-GOAL.md) | 一次提交后连续完成规划、实现、测试、修复和交付的目标提示词 |

补充资源：七源精确配置 JSON、11 张 PNG、4 份静态排版 HTML 及示意素材、图片哈希清单。打开 [`UI-图稿索引.html`](UI-图稿索引.html) 可逐张查看设计。

**本包未包含真实提示词数据快照、翻译后的完整数据库、业务实现代码或新测试结果。** 初始中文资源与代码是 Codex 要实现并验收的目标；源配置 JSON 和设计中的案例不是完整数据包。现有图片只是设计参考，不能作为真实作品或运行截图。

## 放在哪里

解压后，把本包 `docs/` 合并到 `D:\Documents\OpenJatobid\docs\`，把 `v1.8.0-CODEX-GOAL.md` 放到项目根目录。

目录只增加本版资料，不替换整个原 docs。已有同名文件时先比对并保留原件；本包主文件首行可识别 R3。不能覆盖其他版本的规格或用户代码。新的设计资产目录为 `docs/assets/v1.8.0-r3/`，与旧目录隔离。

## 给 Codex 发送一次

将以下内容直接发送，或完整粘贴本包 Goal 文件：

```text
请读取项目根目录 v1.8.0-CODEX-GOAL.md，并完整执行其中的 R3 目标。
该文件及所引用的 Spec、UI Handoff、设计图已是本轮确认后的实施依据。
直接在现有 v1.8.0 生图分支成果上完成开发、测试、修复、审查和交付，
不要停在规划阶段，不要逐项等待我说继续，不要推送、合并、打标签或发布。
有真实外部阻塞时只隔离受影响部分，其余工作继续；所有结论必须有对应证据。
```

不需要再逐条发送 T180 编号，也不需要把旧 Spec／补充 Spec 拼起来才能执行。Codex 内部仍可以拆任务，但开发执行状态只维护既有 `tasks/todo.md`。

## 本轮三个关键决定

模型复用原设置：文本及视觉为当前 `gpt-6-sol`；图片为当前选择的 `gpt-image-2` 或 `gpt-image-2-1k`。页面不新增第二套 Key／Base URL。

来源沿用 infinite-canvas 七源，初始中文数据须随包；用户可增删改启停来源，升级保留用户覆盖和删除选择。默认地址不是已验证大陆镜像，不以新建服务器为前提。

继续使用本包的已认可独立图稿，排除多页概念海报；旧图虚构模型、投标示例、误画菜单和 PSD 文案按 Handoff 修正，不重新改视觉方向。

## 一次执行仍保留的边界

范围内常规开发和修复连续进行；不等于无限收费、绕过登录、安装新付费服务或自动发布。本 Goal 沿用真实测试上限：文本 6 次、图片／编辑 6 次，每次图片最多 1 张，重试计入。额度外操作必须隔离，不将假数据或模拟测试标成实测。

**一句话总结：用三份主文件和一份完整 Goal 接续现有代码，减少逐任务操作、旧文档冲突和视觉返工；文档完成不等于软件已完成。**
