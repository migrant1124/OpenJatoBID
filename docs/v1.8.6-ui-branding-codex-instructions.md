# v1.8.6 UI 名称与导航显示调整：Codex 一次性执行指令

## 使用方式

将本文件与 `v1.8.6-ui-branding-spec.md` 一起放到 OpenJatoBID 仓库的 `docs/` 目录。然后把下方“执行正文”完整粘贴给在该仓库中工作的 Codex，或让 Codex 读取并执行本文件。

这份指令用于实施已经确认的 UI 调整。当前对话只交付文档，并未修改项目源码。

## 执行正文

请在 OpenJatoBID 现有 `v1.8.6-OPT` 分支上，依据 `docs/v1.8.6-ui-branding-spec.md`，连续完成本轮 UI 名称与导航显示调整、相关验证和实施记录。

用户已经明确同意菜单顺序、英文名称以及客户端/管理端一起调整。不要重新开展产品定位讨论，也不要重复询问这些已经确认的事项。

本轮只改运行界面的文案、一级菜单显示顺序、对应页面主标题及两端主窗口标题。保留当前真实功能、业务代码和流程。菜单“文件管理”仅为原入口改名，不新增文件管理功能，不把招标工作流通用化。

### 二、按以下步骤执行

#### 步骤 1：读取规则，核对并保护本地基线

**输入：**根目录 `AGENTS.md`、`开发说明.md`、本轮 spec、相关局部规则、现有 `tasks/plan.md` 和 `tasks/todo.md`、真实分支与工作区状态。

**操作：**

- 读取上述文件，核对当前分支、HEAD、`git status --short` 和已有差异。
- 规格阅读基线为 `79b9a1a320db6dc1832f3888aa7335803c9b7130`；它仅供定位，不是回退目标。保留本地更晚的提交和用户未提交优化。
- 用 `rg` 搜索本轮明确列出的 UI 字符串，结合真实组件确认修改位置。优先检查 spec 第 8 节文件，不把旧文档、安装包命名、历史业务内容算作 UI 漏改。
- 记录执行起点与冻结对象的状态，便于区分本轮差异和用户原有修改。只记录必要摘要，不输出密钥、许可证内容或客户资料。
- 将本轮小范围计划写入现有任务记录，不覆盖其他任务。

**输出：**当前基线摘要、本轮文件清单、原有修改保护说明，以及冻结对象的执行起点记录。

**关键约束：**不自动拉取、切分支、新建分支、stash、reset、clean 或回退。分支不符时先报告只读核对结果，不自行切换。同文件有已有改动时，基于当前内容做可明确隔离的最小修改，不能覆盖用户内容。

#### 步骤 2：调整一级菜单名称和排序

**输入：**`client/src/app/menuConfig.ts` 与上面的七项映射。

**操作：**移动完整一级菜单对象，按固定顺序排列；只改规定的一级 `label`。核对图标、高亮、折叠提示仍按原 id 关联。

**输出：**七个一级菜单准确改名并重排，原功能路由与二级入口保留。

**关键约束：**保留 id、children、description、开发者菜单条件、统计值、路由和父子关系。只读核对 `App.tsx` 中默认与回退仍为 `bid-generation`，不要按第一项计算默认页；不改 `SectionId`、`AppRouter.tsx` 或业务页面映射。

#### 步骤 3：同步对应页面标题和客户端品牌

**输入：**客户端侧栏、登录、关于、对话、生图、PPT 页面，HTML title 和 Electron 主窗口创建位置。

**操作：**

- 侧栏改为 Jato AI；登录、关于中文品牌改为佳图智能助手。
- 登录副标题和关于用途说明逐字使用确认文案。
- 对话顶部 H1 改为“智能对话”；只把无真实会话标题时的“对话模式”回退字符串改为“智能对话”。
- 生图 H1 改为“视觉创作”，对应 aria-label 改为“视觉创作页面”。
- PPT H1 改为“PPT 制作”，对应 aria-label 改为“PPT 制作页面”。真实路径是 `client/src/features/ppt/PptPage.tsx`。
- 文件管理、Word 模板入口页继续通过 `SecondaryMenuPage` 读取菜单 label，自然同步标题，不新增页面。
- 将 `client/index.html` 的 title 与 `client/electron/main.cjs` 的主窗口 title 同步为“佳图智能助手”。
- 按 spec 同步相关 Logo alt，保持图像文件本身不变。

**输出：**客户端各指定品牌位置、页面主标题和主窗口标题一致。

**关键约束：**不改用户自定义会话、项目、作品名称，不改 Jato Agent/Jato PPT，不替换内部 bridge 的 appName，不新增客户端全局窗口管理逻辑，不改 Token 统计或 Pi 监视器等子窗口名称。

#### 步骤 4：更新设置页版权和公司称谓

**输入：**`client/src/features/settings/pages/SettingsPage.tsx` 的关于信息和隐私说明。

**操作：**按确认值更新“版权所有”“Company”；只替换本文件中已规定的公司称谓片段。检查长中文和英文能完整阅读。

**输出：**确认后的中英文公司显示，以及语义保持现状的同页称谓统一。

**关键约束：**不要全仓替换公司名，不改隐私规则、使用限制、数据处理逻辑、历史材料或输出文档，不改 package.json 的 author/copyright/description。若文字发生溢出，只对实际受影响的现有版权区域做局部 CSS 调整，沿用原设计。

#### 步骤 5：同步管理端品牌、主窗口和托盘

**输入：**管理端 `AdminLoginPage.tsx`、`App.tsx`、`index.html` 和 `electron/main.cjs`。

**操作：**

- 保留已有 `page-title-updated` 防覆盖、`ready-to-show` 设置标题、窗口隐藏到托盘等机制，仅更新对应字符串。
- 按 spec 更新登录 Logo alt，不修改 Logo 资源。

**输出：**管理端运行界面的品牌与客户端一致，窗口切换和托盘恢复后标题仍正确。

**关键约束：**不改授权审批、资源中心、统计、登录或托盘服务行为；不修改管理端菜单和包配置；不顺带修复登录页写死版本号等无关问题。不扩展修改 `analytics/dashboard/` 或 Worker。

#### 步骤 6：检查本轮差异与冻结范围

**输入：**执行开始时的本地快照、当前 diff、spec 第 8、9 节。

**关键约束：**用户在执行前已经存在的改动必须保留；不要把相对 HEAD 有差异等同于本轮误改。不得用全仓旧品牌零命中作为验收条件。打包元数据、内部标识、历史记录和保留的业务词汇中出现旧名称是允许的。

#### 步骤 7：执行必要验证并记录证据

**输入：**已完成的 UI 改动、现有依赖和测试、可用桌面调试环境。

**输出：**实际命令结果、UI 核验记录、可取得的截图，以及失败/未执行项及原因。

**关键约束：**不调用真实付费模型，不重新生成标书/图片/PPT，不改授权或生产数据，不运行 dist、打包发布、Worker 部署或更新下载验证。缺少环境时完成独立可做的检查，将原生窗口/托盘等列为待人工验证；不能用静态代码检查冒充桌面验收，不为了让检查通过扩大业务改动。
