## 2. 组件树与责任

建议职责拆分如下，命名可以沿本地现有架构：

- LocalEditDialog：来源冻结、关闭保护、焦点约束、总布局。
- LocalEditToolbar：三个工具、历史操作和zoom；不负责模型请求。
- SelectionViewport：原图、坐标换算、实时草稿轮廓、有效遮罩、标号、滚动和平移。
- NavigatorMiniMap：同一原图的缩略导航及当前可视范围；不创建选区。
- ModificationPanel：有效列表/临时卡、自动聚焦、独立滚动、输入/删除。
- ModificationCard：编号色、选区裁切缩略图、500字多行意见、删除。
- LocalEditFooter：有效数、阻塞原因、提交/取消及进行中状态。
- LocalEditSession/History：唯一状态源，稳定区域ID、草稿、历史、提交快照。

以上是组件职责，不要求创建重复数据Store。PSD细修继续独立消费共享坐标/遮罩基础能力，不消费修改意见状态机。

## 3. 尺寸、布局与独立滚动

### 3.1 宽屏基准

以1536×1024窗口、100%系统缩放取证：
- 对话框宽度约视口减32px，上限1560px；高度约视口减40px，不能超过可用视口。
- 外边距约16–24px，内部24px左右；白底、低强度边框、8–12px圆角、遮罩及阴影沿项目token。
- 头部约76–88px；工具栏约60–72px；主内容用剩余高度；底部约64–76px。
- 主体左右两栏：左图弹性，占约68%–72%；右栏建议360–420px，间距20–24px。
- 图像与右栏顶部对齐，不在左侧再加图片列表或“添加图片”功能。
- 标题20–24px，卡片标题14–16px，正文14px左右，辅助文字不低于12px；不得通过把全部文字缩小来塞满窗口。

### 3.2 常用较小窗口

| 测试窗口 | 布局要求 |
| --- | --- |
| 1440×900 | 保留左右结构；右栏约360px；必要时右列表内部滚动 |
| 1280×800 | 右栏约320–340px；图像按可用空间适应；工具可分成两个完整工具组行 |
| 1024×768 | 右栏约300–320px；输入仍可见，顶部/底部固定；不把文字挤成竖排 |
| 窄于以上且应用确实允许 | 优先压缩留白与左图；可将修改栏变成右侧覆盖抽屉，新选区后自动展开并聚焦；不能回退为底部小输入带 |

同时测Windows100%/125%缩放，条件允许补150%。记录实际CSS视口和DPR，不把一张截图拉伸成不同尺寸的验收图。

### 3.3 滚动责任

对话框外壳自身不承载整页滚动。使用固定头部/工具/底部与中间 `minmax(0,1fr)` 思路。左图溢出由左侧视口滚动，右列表由右列表滚动。所有中间容器有正确的 `min-height:0`。

右侧标题/排序固定在面板顶部；卡片列表滚动；提示可在空间不足时缩成一行或放入使用说明；提交操作独立于列表。活动输入框必须滚入右栏视野，不能只滚动整页。

## 4. 工具栏细节

从左到右保持图中顺序：

**画笔圈选｜矩形框选｜魔法套选**　分隔　**撤回｜重做｜清空选区**　分隔　**－｜缩放滑块｜＋｜实际百分比｜适应窗口｜原始尺寸**。

- 不额外加入“笔刷大小”滑块。本方案的画笔圈选是自由轮廓套索，按闭合区域选择，不是旧粗笔刷涂抹。
- 工具按钮高度约36–40px，操作区可达，不继承主生图页18px的紧凑按钮规则。
- 三个工具选中态为明确蓝色强调；普通操作使用轻边框；不可用撤回/重做灰化。
- 工具组内部不拆成逐字竖排。每个中文标签不换行；窄窗在工具组之间换行，不固定一个极窄label宽度。
- 撤回/重做可用图标＋短标签，hover显示准确说明。清空表示清空所有选区及对应意见，与逐卡删除区分。
- 使用项目已有图标，不插入表情符号作为正式工具图标，不引入另一套整体UI库。
- 控件焦点可见，所有icon-only按钮有中文可访问名称。

## 5. 选区显示、鼠标与动画

| 状态 | 鼠标/画面表现 | 结束条件 |
| --- | --- | --- |
| 框选待命 | 十字光标；简短拖框提示 | 左键开始框选 |
| 框选拖动 | 实时边框与很浅的填充；拖动范围始终可见 | 抬起生成选区 |
| 圈选待命/绘制 | 小画笔/套索光标＋可见热点；实时细轮廓，不盖住细节 | 抬起后自动闭合、填充内部 |
| 魔法待命 | 小魔法棒图标/热点，提示“点击一个物体” | 单击请求分割 |
| SAM处理中 | 点击处短反馈、识别中提示；可取消 | 真实结果/错误，不能用假的百分比 |
| 临时选区待输入 | 区域高亮、编号，与右侧新卡呼应 | 非空文字自动有效，或按业务规则放弃 |
| 有效但非当前 | 淡色遮罩、细边界与编号 | 激活后加强边界 |
| 当前激活 | 更清晰的边界、对应右卡边框/色条 | 激活另一项 |
| 空格平移 | 按下时抓手，拖动时握手 | 松开返回原工具，不新增选区 |

建议遮罩透明度18%–28%，颜色轮换红、蓝、绿及后续可区分色；编号同色且有白色描边。颜色只是辅助，必须始终显示数字。颜色分配绑定稳定ID，删除重排编号时不重新换色。

轮廓和编号不能烘焙进源图。编号优先落在可见选区内部；小区域编号可放附近并引线，不能遮盖输入或工具。高缩放下编号保持约24–30 CSS px便于阅读，锚点跟随原图坐标。

动画建议100–180ms卡片展开、轻量焦点描边、短暂鼠标点击反馈；只允许轻量边界运动，不持续大幅闪烁。启用减少动态效果时改用静态高亮，不损失反馈。

## 6. “选完即输入”的页面落点

**右侧的新卡片就是自动弹出的输入区**。它立即展开并滚入视野，textarea获得焦点。图片附近的小气泡只提醒对应编号，不承载第二套编辑框。避免用户不知道是在图片弹框填写还是右栏填写。

### 6.1 卡片结构

第一行：区域色圆点/编号＋“修改区域 N”＋右侧删除图标。  
第二行：约64×48px选区裁切缩略图＋宽大的多行输入框。  
第三行：实际字数 `/500`；必要时显示待填/冲突/超长提示。

- 输入框默认可见高度约100–120px，最少约4行中文；可以随文本增长到约180px，超过后在文本框内部滚动。
- 不硬编码实际输入只有一两行；不以三张卡必须永远同时可见为由缩到很小。
- Placeholder统一为“请输入要修改的内容”。
- 空白新卡不另设“添加/保存本条”主按钮；输入即生效。
- Enter换行，不提交；中文输入法组词期间不触发放弃或快捷提交。
- 不添加推荐关键词小胶囊、自动扩写、更多工具等第一图未要求的新能力。

### 6.2 计数及排序

标题“修改列表（N）”与右下“共 N 处修改”使用同一有效项集合。临时空项单独显示待填写，不凑数。编号默认按创建顺序；图中的排序控件可提供“按编号升序/按编号降序”，只影响列表展示，不改变区域ID、编号映射和实际修改语义。不得出现不产生效果的假下拉。

新增项无论当前排序如何都应滚入视野并聚焦。删除后就近激活仍存在的项；没有项时恢复空状态。

### 6.3 可读空态与提示

空态：“在图片上选择一处区域，完成后在这里输入修改要求。”

常驻轻提示：“选一次，写一条。未填写的选区将在离开该项时放弃；每条修改都可删除。”

选区旁气泡：“已选择区域 N，请输入要修改的内容。”已有非空文字后隐藏，不要像演示图一样永久显示过期提示。

不把“未输入”实现成一秒超时、立即删除、每次blur都删除；具体结算见Spec第4.3节。

## 7. 缩放、平移及小地图

### 7.1 局部编辑内固定说明

**滚轮移动画面 · Ctrl＋滚轮缩放 · 空格＋拖动平移**。

缩放滑块、+/-、Ctrl＋滚轮写入同一scale；普通滚轮只控制视口滚动。不要同时设置原生滚动又用第二个wheel handler额外平移。Ctrl＋滚轮要取消该次默认行为，防止还缩放整页；监听只覆盖画布区域，不能扩散到右侧输入框和其他窗口。依据Spec中的MDN参考处理passive与cancelable。

### 7.2 坐标换算说明

用“鼠标在已显示原图中的位置 ÷ 当前真实显示比例”得到原图位置；要扣除容器位置、图像居中留白并考虑滚动。可直接从图像的实际矩形统一求逆变换，但不得再次重复加减同一滚动值。

Ctrl＋滚轮缩放前先记住鼠标下面的原图点，缩放后调整视口使这个点仍停在鼠标位置。图像、遮罩和编号共同使用该变换；变更DPR只影响渲染清晰度，不改变模型坐标。

以上说的是显示位置换算，不是调整原图大小，不对照片进行再次重采样。

### 7.3 小地图

按照第一图保留左下角轻量导航缩略图，建议约160×104px。展示完整同一原图与当前可视区域边框；点击/拖动视口矩形移动大图，不建立选区。若保留其 +/-，必须与顶栏同一缩放状态；不能独立维护另一个百分比。

小地图不得挡住卡片或提交。窄窗/画布很小时允许折叠为导航图标，选区操作热点附近可暂时隐藏；不能为了小地图压缩主图和意见输入。

## 8. 底部动作、错误与异步

取消和提交固定在右下，按钮约40–44px高；提交采用现有主蓝色，显示“提交局部修改”和“共 N 处修改”。原图左下等位置可以显示真实分辨率与缩放，不新增无意义大卡。

| 状态 | 主按钮与提示 |
| --- | --- |
| 0条有效项 | 提交不可用；提示先选择并填写一处 |
| 只有临时空白项 | 提交不可用；不以灰按钮掩盖未实现后端 |
| 有效项＋空白临时项 | 允许提交有效项；提交时先丢弃空白临时项 |
| 有重叠冲突或超500字项 | 定位问题项并解释；不默默截断/覆盖 |
| SAM正在计算临时选择 | 提示识别中；可取消该候选后提交已有有效项 |
| 已在提交/服务端处理中 | 禁用重复提交与改写快照；保留图片查看；状态从真实事件得到 |
| 明确失败 | 保留卡片及选区，用户可改后再次提交 |
| 结果不明或停止等待 | 不自动重发，不显示“未计费/保证已取消服务端” |

后端无真实百分比时采用阶段文字，不使用虚构进度到99%。关闭处理中窗口时不丢任务ID和恢复信息。

## 10. 明确勘误与取舍表

| 设计稿中容易误读的内容 | 实施口径 |
| --- | --- |
| 一开始已经有3项 | 是完成态示例；产品初始0项，选择后才出现 |
| 图片上红猫/蓝绿抱枕 | 是遮罩色；不预先改变原图或声称编辑成功 |
| 图片区域气泡同时出现已填写项 | 气泡只在待输入时短暂显示 |
| 固定100% | 使用真实比例；fit不是必然100% |
| 卡片计数18/500等 | 计算真实输入长度；中文输入法不被打断 |
| 窗口外六步指南 | 不加到产品常驻界面；“使用说明”可显示简短对应文字 |
| 拖动/选区显示可能类似专业控制点 | 本轮不顺带开发复杂路径编辑；新选错可删/撤回再选 |
| 三种工具示例中都是漂亮对象轮廓 | 框选是矩形、圈选是用户路径、魔法才是SAM轮廓；不能全部伪装成SAM结果 |
| 未输入就放弃 | 指明确结束该项时为空；不是刚自动聚焦就销毁 |
| 清空选区 | 同时清空意见，需一致且可撤回；不是只清除屏幕红色 |
