## 3. 已查明的问题与诊断边界

`ResourceCenterPage.tsx`把checkbox的onChange直接连到`api.enable`；`resourceSyncService.enable`又立即等待`check`，页面全局busy连带禁用其他来源。因此问题不只是控件样式，前后端都需要拆分“选择”和“执行”。

`resourceSyncService`逐条prepare失败后累计failures并记录ITEM_FAILED；已有旧条目时复用旧条目，成功条目可组成有效发布。`resourceStore.finish`只有完全无error才更新success_at。前端对checkedAt和successAt共用“尚未检查”空值文案，会把“暂无完整成功记录”错误表达成“尚未检查”。

因此“14项未完成”说明该次出现14个条目准备失败，不代表整库全坏，也不代表没有任何成功更新。真实的下载、解析、预览、校验等失败原因须读当地ITEM_FAILED审计；仅凭这三行不能认定代理、磁盘、格式或固定组件中的某一项就是根因。

`resourceStore.publishSource`已有业务内容差异比较，无差异会返回旧version。必须复现用户“重试似乎不断产生版本”的观察，排查不稳定assetId、条目状态变化、排序、临时路径、hash/预览变更及统计混用；不能把猜测写成已确认缺陷。客户端当前“版本按钮”主要是选择历史更新概括，不等同于让用户切换已应用资源快照，但界面仍应去掉版本号和版本选择。

PPT目前以plan/generate按钮、页面计划折叠区和最近一次答复串联业务；已有宿主PPT工具及确认接口，不应推倒重写，但不足以等同新的多轮Agent工作台。

## 4. 管理端：批量选择—确认—排队

### 4.1 交互流程

进入页面读取已生效来源列表 → 用户勾选/取消勾选（仅草稿） → 底部出现“已修改N个来源”操作条 → 点击“确认并加入队列” → 展示新增启用、停用、将排队来源及影响 → 确认提交 → 返回排队成功 → 后台执行。

确认层属于一次批量执行确认，不得每个来源再弹一次。可将底部按钮文案和最终确认层统一简化，但“修改草稿”与“执行提交”必须是两个不同动作。

无变化时提交按钮禁用。取消修改恢复到服务器已生效列表。周期刷新只能更新真实运行状态，不覆盖当前未提交的checkbox草稿。草稿离开提示“放弃修改/继续编辑”，不自动保存为生效配置。

已启用且未改变的来源不因保存其他来源而重复下载。需要手动检查时，点击“检查已启用来源”；确认层可多选本次检查范围。该选择只表示本次任务范围，不修改enabled；确认后进入公共队列，不重置周计划。

### 4.2 原子提交与后台队列

IPC可采用`applySelection({requestId, expectedSettingsRevision, enabledSourceIds})`等名字，名称可复用项目习惯，但合同不得减少：

- 一次Main侧事务校验来源、保存启用结果、写入批次/任务及审计；HTTP/文件下载在事务外进行。
- 相同requestId重发返回同一结果；双击、IPC超时重发不重复建任务。不同请求命中同一个已有排队/执行来源时合并到现有任务，并返回“已在队列”。
- 新启用来源只在确认事务成功后建立首次周锚点并排队；调度器看不到UI草稿。
- 不允许先持久化enabled后等待另一个异步操作创建任务，否则周调度可能抢跑。
- 提交返回`accepted`和任务集合，表示已排队，不表示下载或发布完成。UI只对提交操作短暂busy，不等待整个下载。
- 默认来源级FIFO并发1，当前来源内部文件准备并发最多2，形成全局可解释上限；复用既有队列设施，禁止两个各自无限运行的队列。授权/统计不能被同步下载阻塞。
- 队列和必要检查点存SQLite；重启不丢已确认排队任务。下载可以在hash校验后续传/重取；不能把历史running永久保留为运行中。

### 4.3 停用、停止、重试

停用来源停止后续周计划并撤销未开始的来源任务，不删除已发布资源和历史；若正在执行，确认层必须说明“停止当前同步”，按取消令牌结束当前任务，保留已提交发布和完整旧镜像。

“停止本次”只停止当前任务，不默认停用来源。用户取消不是失败，不能被自动重试立即重新启动。

对失败条目优先按稳定资源ID重试，已成功且未变化的条目不重复解析/下载。重试发生前若上游已变，重新检查来源并基于新来源快照决定目标，不把不同提交文件混成同一文件版本。重试入口保留在管理员详情/任务区，普通客户端不出现“重试失败来源”。

### 4.4 固定每周规则

周周期固定7×24小时，不提供每天/小时/手填周期或定时编辑控件。首次确认启用初始化一次；以后保持持久化锚点，手动检查和重试不改变锚点。重启跨过多个周期只补一次过期检查，不回放多个周任务。

同一来源自动/手动任务必须去重。原本已有锚点的来源重新启用不得无意把周计划“重置到每次勾选”；保留原锚点，补一次必要初始化/到期检查。关闭管理窗口与退出服务区分：驻托盘时按真实现有能力运行；进程退出或电脑关机不能宣称继续运行。

## 5. 管理端：状态、审计与错误呈现

### 5.1 面向用户的状态

| 内部状态 | 首页显示 | 用户动作 |
|---|---|---|
| disabled | 未启用 | 勾选后确认 |
| queued | 等待同步 | 查看任务/取消排队 |
| checking/downloading/parsing/validating | 正在同步 | 查看进度/停止本次 |
| success，无变化 | 已检查，无更新 | 无需操作 |
| success，有有效变化 | 已更新 | 可查看更新内容 |
| partial | 部分资源待更新，现有资源可继续使用 | 查看详情 |
| failed且有旧镜像 | 更新未完成，现有资源可继续使用 | 查看详情 |
| failed且无旧镜像 | 资源暂不可用 | 查看详情 |
| cancelled/interrupted | 已停止/上次任务中断 | 继续或重新检查 |

不得把没有旧镜像的来源写成“现有资源可继续使用”。错误码、失败项计数、上游地址、栈、内部发布ID等不在首页连续堆叠，但必须在管理员审计中完整、脱敏地保留。

时间拆为“最近检查”“最近完整成功”，空值分别显示“尚未检查”“暂无完整成功记录”。主表可以只保留“最近检查”一列，完整成功时间放详情。显示统一为`YYYY-MM-DD HH:mm`，精确到秒的值在详情；页面不得输出多余反斜杠、原始转义符或null。

### 5.2 同步审计与只读计划按钮

首页右上一个次要按钮“同步审计与只读计划”，打开抽屉/模态；内部为“运行记录”“周计划”两个标签。不是两个首页大卡片，也不是点击后直接运行同步。

运行记录支持来源/结果/时间筛选、分页、单条展开与导出脱敏诊断。默认展示自然语言摘要；原始结构化数据只有“技术详情”展开后显示。周计划展示启用状态、锚点、下次检查和是否运行，只读，不含修改周期控件。

首页status接口不再每3秒返回100条完整audit/大量history。拆轻量摘要和按需分页详情，或用等价的includeDetails参数。打开/关闭查看层保持主表筛选、选择草稿、焦点和滚动位置。

### 5.3 失败分类与证据

为本次任务分开记录attempted、preparedNew、unchanged、failed、reusedOld、publishedChanges。复用旧条目不计入“本次成功更新”。失败按下载、解析、预览、校验、空间、代理、权限、取消等实际阶段记录；未知原因保持unknown，禁止替错误编造友好原因。

审计含taskId/sourceId/资源稳定ID/阶段/时间/错误码/可重试性；本地完整路径或上游token仅限必要诊断且脱敏。不得把凭据、原始投标内容、模型输入输出传到埋点系统。

## 6. 资源发布与客户端更新：内部保留，界面去版本化

资源发布ID是资源目录快照的内部编号，不是客户端1.8.4，也不是用户项目历史修订。保留协议版本、资源hash、快照、读游标、审计及项目锁定的资源版本，只去掉员工端的版本选择和数字展示。

发布流程：来源枚举 → 获取/复用 → 条目验证 → 计算有效变化 → 原子提交完整快照/差异 → 客户端从管理端获取并校验 → 应用成功 → 必要时展示更新概括。

对有效变化进行稳定比较：来源和资源ID稳定；集合排序标准化；hash、可用能力、可见内容的真正变化才算变化。检查时间、重试次数、错误文本、临时路径、重新生成的随机assetId不能造成伪变化。文件相同的重复下载不能增加发布。

完全失败或全部复用旧条目且无变化：不发布、不增加客户端未读更新。部分成功且存在有效变化：只发布成功变化，失败项保留旧条目，新失败条目不伪装可用；同一批次的细粒度完成事件合并发布，不逐文件推通知。源清单异常为空或骤减保留旧快照，不解释为全部删除。

客户端移除公共资源历史的“版本X”按钮及版本选择交互。可以保留“更新记录”，但按日期和内容摘要展示，不可点击切换全局资源快照。更新概括继续按两中心分类、按稳定ID去重，只有数据已应用才出现；编辑/导出/确认进行中延后，不为每个重试弹窗。

在制项目使用已复制/固定的资源，不被公共目录更新静默替换。用户明确更换模板/技能时记录新项目修订及影响确认。PPT“历史与恢复”是用户稿件历史，应保留，不能因本条被误删。

## 7. 资源中心统一视觉

统一管理端资源卡片结构为Header/Body/Footer，标题16px、正文14px、辅助信息12px（长解释可13px）；镜像体积、可用空间作为辅助统计，标签12px、数值13px，不作大号KPI。

卡片内部20px内边距，标题到说明8px、正文行高20–22px、辅助信息18px、卡片间16px。表格行上下12px、左右16px。详见UI-Handoff，不得留裸p紧贴卡片边缘。

覆盖公共资源同步、来源列表、资源存储与网络、发布记录、技能仓库获取申请、审计抽屉与各确认弹窗。统一不等于全部字号相同，而是相同语义层级采用同一字号和间距。

首页主区优先：页头与摘要 → 来源表/任务摘要 → 存储与网络 → 紧凑发布记录/申请摘要。日志不占首页。次要区域不展开全部记录；进入详情查看。范围只限本轮资源模块，避免全局选择器导致授权/统计/其他设置页回归。

## 8. PPT信息架构：以Agent页为起点

### 8.1 主流程

```text
保留现有PPT首页
  → 点击“开始制作PPT”（现有同义入口按最小必要调整文案）
  → Agent对话页：输入需求 / 追加资料 / 选技能 / 选模板 / 整套或单页
  → 同页多轮澄清与阶段确认
  → 同页真实任务进度、必要确认、失败恢复
  → 可用页面生成后进入既有三栏制作工作区
  → 预览 / 修改 / 审阅 / 导出 / 回到项目
```

流程不增加一级Tab。普通“对话模式”不改名、不被PPT替换，也不获得PPT写工具权限。PPT内部可新增agent视图，但不必把每个技术步骤做成顶部导航。

### 8.2 Agent初始页

红色主标题“让你的演示与时代同频共振”；支持保留“让你的演示惊艳、制作高效”作为简短副标。页面白色、充分留白、中心输入区，不堆能力介绍卡。

输入区可写自然语言并拖入资料；底部紧凑工具：上传资料、技能[ppt-master]、选择模板、整套PPT/单页PPT、发送。默认整套、默认内置ppt-master、模板可不选。技能选项显示名称与可用状态，不让用户理解内部hash/运行时版本。

删除参考图红线划掉的“专业/极速/创意/自由”模式栏及扳手按钮。不能从参考图中的地球图标推断新增联网功能。无模型名称、模型选择器、高级思考档位或Pi技术信息。能力说明置于选项详情，不填满初始页面。

### 8.3 草稿、项目建立和保存目录

点击开始只进入Agent页，不先要求填长新建项目表。初始输入先成为可恢复草稿；用户首次真正导入需要落盘的资料或发送需求时，如没有合法默认父目录，用一个简洁保存位置确认层收集父目录和建议项目名，然后创建独立子目录。

允许首次传送无附件的需求；项目名可由主题建议，用户能修改，不另加必经命名页。系统盘警告“重新选择/仍然使用”沿用已有检测；不是只判断C盘字母。取消目录选择保留输入与待添加文件，不启动模型、不丢失草稿。

已存在项目从原入口打开既有工作区；“继续对话”回到同一个项目会话，不创建第二个项目。草稿及对话业务状态用Main侧Store保存，不把文件内容/业务草稿放localStorage。

## 9. Agent对话与交互合同

### 9.1 真实多轮会话

每个PPT项目拥有持久会话标识。保存用户消息、完整助理答复、附件引用、当前技能/模板选择、阶段摘要、待回答问题、确认及任务引用。原始流式token可内存显示，不逐token写SQLite。

材料、选择和累计需求在后续轮次持续可用；重新打开/切换工作区恢复同一会话。不能只保存agentAnswer或把多轮输入拼成一条临时prompt后丢弃历史。

接入真实流式事件、工具进度、提问和最终结果；订阅按projectId/conversationId/taskId隔离，序号去重、卸载解绑，不能把另一个项目的回复串进来。后台队列返回只表示受理，不显示“已生成”。

### 9.2 提问和确认

`ppt_ask`以及既有Agent问答事件必须在PPT当前会话显示可操作确认卡；用户点击选项或输入回答后，精确回复对应request/questionId，唤醒原任务。不能把返回值写死为confirmed，不能让用户去开发者监视器回答。

等待用户时任务状态为waiting_user，仍持有必要写入锁，但回答/取消走允许的控制通道；不得被普通assertIdle或全局busy禁止。重复点击确认幂等。旧问题、旧方案、其他项目的问题不能回答当前任务。

确认记录至少绑定projectId、conversationId、questionId/gateId、phase、requirementsRevision/specFingerprint、template/skill hash、用户选择、时间。确认从用户操作产生，不能由模型自签。

默认制作保留ppt-master的阶段1“用途、受众、目标、模板/自由设计”和阶段2“完整方案、页面组织与制作设置”语义，两次确认都在对话中完成，不另起大纲/审批页。三种方案意图可用聊天内紧凑选项表达，不用三张占满屏幕的模板宣传卡替代。

用户只说“下一步”但存在多个待选项时澄清；不会把沉默当同意。普通单页不自动绕过确认。明确自然语言快速意图按锁定技能的实际route合同处理，不在界面新增Quick/极速模式选择器。

### 9.3 修改需求与确认失效

用途、受众、页数、画幅、材料范围、模板、技能等实质变化，使对应规划确认失效；同页说明影响并重新确认受影响阶段。不能每次改一个批注或打开面板都触发整套方案重新确认。

将“执行文件的baseRevision”与“需求/方案确认的fingerprint”区分。已有confirmedRevision机制可保留兼容，但不得让正常对话消息或讲稿保存造成永远不能制作，也不得让旧确认授权新方案。

对于只改当前页，确认范围含slideIds和相关源hash；未选页受保护。多页改为单页且已有成品时先提示只影响后续候选，明确保留/替换范围，不静默删除旧页。

### 9.4 输入与附件

复用现有解析器和资料目录。支持类型、单文件/总大小等以真实已支持合同为准核对并在UI提示，不臆造任何格式已支持；至少已支持的Word/PDF/TXT/Markdown等路径不回退。图片、PPTX、表格资料按真实适配能力显示。

一个文件分离“已添加”“解析中”“可用于本次”“解析失败”。坏文件不拖垮所有材料；移除附件仅取消当前会话引用/受管副本，不删除用户原件。追加材料后明确本轮范围，避免输入并未选用却被引用。

无资料但仅为创意/方法性主题可依据用户描述制作；遇需外部证据的数据不编造。既有Agent联网限制不解除；上游要求事实检索而宿主无授权渠道时，当前会话请求补充资料或说明能力缺口，不后台绕过联网。

## 10. 单页PPT专用合同

单页在同一个Agent输入区切换，内部`creationScope=single`，默认目标页数严格为1。允许页面主题、用途、画幅、资料和单页版式在聊天中确认。系统仍可形成仅含一个稳定slideId的内部计划，但不显示必经多页大纲。

生成后进入同一既有制作工作区，仅一张缩略图。不能加封面、目录、章节或总结页，不能把“一页”解释成“一份PPT”。单页插入现有项目与新建单页项目为不同动作，插入时明确位置和范围；不覆盖整稿。

单页不等于只修改当前页；前者是新建范围，后者针对已有项目稳定slideId。四种组合都需要测试：新建整套、新建单页、整稿改单页、整稿中插入一页。

## 11. 充分适配ppt-master，而非只挂名称

取证锁定：`client/electron/services/ppt-runtime-lock.json`，ppt-master **6.6.0**，上游commit **44c10ed0bc3a9e1df7a25aa179ae7c26db09469b**。本轮不自动升级上游。运行时由宿主固定SKILL_DIR、校验和工具适配驱动，不能依赖开发机PATH或系统安装的Python。

第一阶段输出`ppt-capability-map.md`：逐条写上游route/阶段 → 当前宿主工具/适配 → UI入口/确认卡 → 产物 → 测试证据 → 已支持/待补齐/被安全边界阻止。不以README宣传代替可运行证据。

当前SCRIPTS白名单较窄；上游每条命令必须映射到受控宿主工具或等价实现。扩展时逐个明确脚本、参数schema、读取根、写入根、联网需求、超时及测试，不开放任意shell/pip/python。

不得把“安全边界阻止”悄悄改为“全部支持”。核心Generate、单页、确认与既有编辑/导出闭环缺失时不可验收。其他route若经核对确需新增服务、依赖升级或新增权限，输出明确BLOCKED项及最小决策，不擅自扩大范围，不以隐藏入口算完成。

保留上游attribution/integrity保护和许可证，不能因UI优化删除或绕过。读取技能文件的指令视为候选工作流，不得覆盖宿主安全规则、文件授权和用户确认。

## 12. 后续工作区：保持布局，补齐业务状态

保留“页面缩略图 / 中央画布 / 右侧Jato Agent”结构，已有资料、模板、技能、导出、项目工具可达。页面按比例完整展示，不裁切、不拉伸。新对话页中的历史、确认和任务，在右侧Agent继续同一会话，不生成两个脱节会话。

保留文字和元素修改、原生图表数据、批注、讲稿、项目历史恢复、迁移、个人模板、单页插入和资源缓存操作。原复杂表单可以放原位置内的折叠区/抽屉，但不能为“美观”删除业务。

既有候选目录、互斥写锁、基准revision校验、未选页hash保护和提交日志继续生效。原始SVG/PPTX及关联清单是权威，不把Canvas/图片预览当成唯一源文件。预览随资源/页面hash失效，不显示旧图冒充新稿。

成功进入工作区前必须存在真实可读产物并通过应有检查。仅模型回复“完成”或有一张PNG不能判定原生PPT成功。

## 13. 全流程异常与恢复

所有页面在UI-State-Matrix中编号，不把准备/确认/错误/关闭当成“后续再说”。至少覆盖：首用目录、解析失败、技能缺失/依赖、模板不可用/比例冲突、两个确认阶段、制作中/等待回答/取消/失败、未知收费结果、原生导入、单页、审阅/导出、重命名/迁移/恢复/删除、缓存、离线和中断恢复。

下载重试是幂等资源操作；模型/配图请求可能已计费。结果未知时先对账任务状态，不自动重新发送收费请求。只有明确失败在发送前且规则允许，才可安全重试；用户需看到可能重复扣费的真实风险。

窗口关闭、导航离开、应用退出分别处理。未提交文字有保存/放弃/继续编辑，正在等待回答的任务有明确恢复入口；客户端进程退出后不能宣称继续制作。重启恢复会话和检查点，不假装恢复已丢失的token流或自动重放未知外部请求。

## 14. 导出与人工审阅

沿用现有审阅与导出界面布局，补齐检查中、阻断、可导出、写入中、成功和失败状态。页面范围、格式、位置必须明确；当前页导出不修改整稿。PPTX、PDF、图片、讲稿及已授权媒体按实际能力显示。

人工审阅保留为工作区审阅与导出确认，不新增多级审批/强制敏感词弹窗。检查事实、资料来源、中文排版、未解决批注和目标范围；记录用户确认与revision。原投标业务现有内容约束、人工审核和留痕不得削弱，也不套到普通创意PPT成为额外阻塞步骤。

导出成功依据真实文件写入、校验和当前revision，展示“打开文件/打开所在文件夹”；选择位置后取消不算失败。文件占用、磁盘空间不足和转换错误不删除旧成品。不要把结构通过等同PowerPoint/WPS渲染验收。

## 15. 数据与接口迁移

资源队列、同步运行统计、失败条目索引和分页审计需要兼容迁移；旧来源锚点、已发布快照、资源文件及授权库不清空。迁移脚本幂等，失败时保持旧库可恢复并输出诊断。

PPT增加会话/消息/附件引用/待回答问题/确认记录/阶段状态，优先扩展既有Store。旧项目第一次打开时缺失字段有兼容默认，旧报告可作为“历史任务摘要”展示，不能伪造成原本不存在的多轮聊天记录。

任务状态与项目状态分离。页面只读不等于会话不能回答。项目删除/迁移、缓存和技能卸载保持原有归属验证及确认，外部原文件不删。更换默认目录不迁移旧项目，迁移始终显式确认。

前端只经preload桥接Main；同步更新IPC类型和调用方。当前代码仍存在window.yibiao兼容引用，本轮以真实桥接为准，不因记忆中的重命名要求做全仓替换。避免让PPT专用工具进入普通对话session。

## 17. 验收门槛

全部必测用例见Acceptance-Test-Cases.md。P0失败不可交付为完成。至少：

1. 勾选不发起网络/解析/模型任务；批量确认后持久排队，重启、去重、周锚点正确。
2. 失败和旧镜像统计准确；相同内容重试零新发布；客户端无资源版本选择。
3. 资源卡片统一字号/内边距，日志按需打开；截图与UI合同对应。
4. 点击开始到达红标题留白Agent页；默认ppt-master；整套/单页同页选择。
5. 多轮附件/选择持久，两个确认阶段及ppt_ask真等待/真恢复，任务不能自签确认。
6. 单页真实只产出一页；未跳转大纲；整套及已有工作区业务不回退。
7. 本地真实PPT工具、SDK/代理、Electron和Windows安装包分层验证；不以mock或浏览器截图替代。
8. 打包安装后从新用户目录跑核心链路；已有用户目录升级后旧项目可继续。

## 18. 交付与范围边界

Codex最终交付代码、迁移、配置说明、需求追踪表、能力映射、实施记录、分层测试报告、Windows截图对照、已知限制和未执行原因。截图命名使用本包画面编号；每个需求对应源码、测试和证据。

本包ui/prototype.html及截图是设计参考/状态演示，展示数据不是管理端实时数据；不连接模型、不运行下载、不执行安装、导出或删除。本包渲染检查通过不代表上述业务测试通过。原型中的首页连接卡不替代真实首页；已有三级工作区以保留为原则。

需要另行决策的内容只列问题、风险和最小选项，不擅自加功能。所有可独立完成项继续推进；遇权限扩张、依赖升版、真实发布等边界停止该项，不谎报全轮完成。

**一句话总结：把资源操作从“勾选即执行”改为“确认后排队”，把PPT制作收敛到一个可持续对话的Agent入口，减少误触下载、重复发布、流程跳转及旧稿被误覆盖的风险；节省时间需实施后实测。**
