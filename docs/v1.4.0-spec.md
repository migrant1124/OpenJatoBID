# OpenJatoBID v1.4.0 Codex 版本更新实施规格

## 0. 本规格的用途

本文件用于直接指导 Codex 在 `migrant1124/OpenJatoBID` 中完成 `v1.4.0` 版本更新。

它合并并消解以下两份方案中的范围、代码现状、产品边界和实施顺序：

1. `OpenJatoBID_客户端版本显示与更新故障专项优化方案_不改客户端选择器(1).md`
2. `OpenJatoBID-main分支优化建议书(1).md`

本规格是实施规范，不是讨论稿。Codex 必须先核实当前仓库状态；已经满足的要求以测试确认为主，不得为了制造 Diff 重复重写。尚未满足的要求必须实施并提供可复现证据。

本次 Revision 2 新增两项固定 UI 要求：将“文件解析”升级为“组件设置”，以及关于页四项隐私声明的桌面端横向四列布局。

---

## 1. 本次修订的最高优先级决策

以下决策覆盖此前 Spec 中与之冲突的任何内容。

### 1.1 单一 R1 大版本

本次不再拆分 `1.3.x` 补丁版和后续 `1.4.0` 功能版。

本次唯一目标版本固定为：

```text
VERSION = 1.4.0
TAG     = v1.4.0
```

`v1.4.0` 必须同时包含：

- 登录页、关于页和埋点的运行时版本统一。
- Worker 更新许可证兼容验证。
- 客户端更新错误分层和安全日志。
- 本地 Mermaid 与结构化图表渲染。
- 图表源文件确定性恢复。
- Word 导出本地 Mermaid。
- 版本化配置迁移。
- 结构化响应写保护。
- 完整系统能力诊断中心。
- Jato 专用用户手册自动化 Skill。
- 设置页将原“文件解析”页签升级为“组件设置”，同页管理文件解析、Mermaid 本地转换和 HTML 本地转换。
- 关于页隐私声明的 4 个声明在桌面端采用横向四列排布。
- 上游同步 Manifest 和自动审计脚本。
- 图片全局配额及章节冲突优先级产品化。
- 真实外部模型自动 Release Gate。
- 结构化图表 DSL，替代新生成的任意 HTML。
- 完整 ADR 体系。

如果远程已经存在 `v1.4.0` Tag，Codex 必须停止版本写入并报告冲突；不得自行改成 `v1.4.1` 或移动既有 Tag。

### 1.2 渲染并发与内存模型必须保留

本次明确接受并保留上游渲染模型：

```text
Mermaid 默认并发 = 5
结构化图表默认并发 = 5
用户可配置范围 = 1–20
内部硬上限 = 20
每个执行中的渲染任务创建一个独立隐藏 Electron BrowserWindow
超长图片分段截图后，最终申请 width × height × 4 字节连续 RGBA 位图进行纵向拼接
```

Codex 不得实施：

- 默认并发改为 1 或 2。
- 普通设置上限改为 4 或 8。
- 基于系统内存自动下调并发。
- 20,000,000 像素硬限制。
- 16,000 像素总高度硬限制。
- 因预计连续位图较大而预先拒绝渲染。
- 将每任务独立隐藏窗口改成共享单窗口。
- 将最终连续 RGBA 拼接改成磁盘流式拼接。

允许并且必须实施：

- 在诊断中心显示并发、活动窗口数、队列深度和估算位图内存。
- 在开发者日志记录安全的尺寸、耗时和峰值数据。
- 捕获可捕获的分配异常并给出明确错误。
- 保证成功、失败、暂停和超时后窗口与调试器均被清理。
- 通过 ADR 明确记录该资源权衡。

### 1.3 结构化图表 DSL 替代任意模型 HTML

从 `v1.4.0` 起，新图表生成的规范产物必须是受版本控制的 JSON DSL。

模型不得再直接生成可执行的完整 HTML 文档。应用根据经过校验的 DSL，使用受控模板编译为静态 HTML/SVG，再交给本地隐藏窗口渲染。

历史工作区中的 HTML 源文件可以只读兼容，但：

- 不再作为新任务的输出格式。
- 不允许在重试时继续让模型生成任意 HTML。
- 需要重新生成时必须转为 DSL。
- 历史 HTML 只允许在隔离、断网的 Legacy Renderer 中读取，不能访问网络、Node 或任意本地文件。


### 1.4 本轮固定 UI 变更

以下两个 UI 变更属于 `v1.4.0` 的强制范围，不得作为后续优化延期。

#### 1.4.1 “文件解析”升级为“组件设置”

设置页顶部原：

```text
文件解析
```

必须改为：

```text
组件设置
```

页面结构固定为：

```text
组件设置
├─ 文件解析
│  ├─ 文件解析方式
│  ├─ MinerU Token（按当前选择条件显示）
│  └─ 现有解析方式介绍/对比
└─ 本地转图组件
   ├─ Mermaid 转换并发量
   └─ HTML 转换并发量
```

其中：

- `Mermaid 转换并发量` 默认 `5`，允许 `1–20`。
- `HTML 转换并发量` 默认 `5`，允许 `1–20`。
- “HTML 转换”指 DSL 编译后的受控静态 HTML/SVG 与历史只读 HTML 共用的本地 HTML→PNG 渲染池。
- 该 UI 名称不代表允许模型重新生成任意 HTML；新图表仍必须使用结构化 DSL。
- 不再保留并列的“文件解析”独立页签。
- 系统诊断仍保留为独立能力，不与组件设置混为一个状态模型。
- 页面视觉结构应与上游组件设置页一致：同一主卡片内先显示“文件解析”，再显示“本地转图组件”。

#### 1.4.2 隐私声明桌面端横向四列

关于页的 `01–04` 四个隐私声明必须在桌面端同一行横向排布。

规范 CSS 语义：

```css
.privacy-list {
  display: grid;
  grid-template-columns: repeat(4, minmax(0, 1fr));
  align-items: start;
}
```

响应式规则：

```text
> 1100px：4 列，同一行
≤ 1100px：2 列
≤ 860px：1 列
```

要求：

- 只改变排布，不删减、合并或改写四项隐私声明正文。
- 四项编号、标题和顺序保持 `01 → 04`。
- 卡片文本自然换行，不出现横向滚动条。
- 桌面端截图回归必须证明四个卡片处于同一横向网格行。
- 当前分支若已经满足该布局，Codex 应增加回归证据而不是重复重写。

## 2. 规范性用语

- **必须 / MUST**：不可省略。
- **不得 / MUST NOT**：明确禁止。
- **应该 / SHOULD**：除非存在可验证的技术阻碍，否则实施。
- **可以 / MAY**：可选。
- **验证项 / VERIFY-ONLY**：当前实现可能已经满足，先测试，缺失时才修改。
- **发布门禁 / RELEASE GATE**：未通过时不得正式发布、提升 `latest.json` 或声称完成。
- **受保护路径 / PROTECTED PATH**：只能局部语义修改，禁止以上游文件整体覆盖。
- **规范产物 / CANONICAL ARTIFACT**：恢复、缓存和重试的权威输入，派生产物不得反向覆盖它。

# 第一部分：发布拓扑与执行原则

## 3. 单版本、分阶段实施

虽然只有一个版本 `v1.4.0`，实施和发布仍分阶段执行：

```text
A. 基线、保护测试、ADR 和上游同步治理
B. 更新通道与运行时版本修复
C. 结构化图表 DSL
D. 本地渲染、恢复、导出和图片策略
E. 系统诊断中心
F. Jato 用户手册自动化
G. 真实外部模型 Release Gate
H. 全量回归、版本提升、候选制品和真实升级
```

Worker 兼容部署必须先于 `v1.4.0` 客户端正式发布，但 Worker 和客户端仍属于同一个 `v1.4.0` 发布计划。

现有安装版升级路径固定为：

```text
1.3.1 → 1.4.0
```

不得要求用户先安装一个中间补丁版。

14. 添加自动内存下调或像素硬限制。
15. 删除内部技术文档。
16. 伪造 Build Attestation。
17. 未经明确授权推送、打 Tag、部署 Worker、发布 Release 或提升 `latest.json`。
