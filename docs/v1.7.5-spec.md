## 3. 轻量项目工作区

### 3.1 项目字段与界面

项目必须有稳定、不可因改名变化的内部 ID。最小业务字段为：项目名称、招标人／采购人（选填）、项目编号（选填）、标段／标包（选填）、当前阶段、创建时间、最近保存时间、最后访问位置及工作区存储关联。

新建弹窗只要求项目名称必填，其余可空；不让用户填写工作区路径、数据库、Agent 配置或暂停策略。名称相同也不能覆盖另一个项目，以内部 ID 区分。

P01 表格为：`项目名称｜招标人／标包信息｜当前阶段｜最近保存时间｜操作`。项目名称可点击，操作列只有红色删除按钮。当前阶段不是项目运行状态；不能把“执行中／已暂停／成功”换个名字放回来。搜索使用本机保存数据，不调用 AI。

### 3.2 项目保存范围

各项目独立保存招标资料、原方案（扩写模式适用）、选定投标范围、解析结果、目录与编写说明、全局事实、项目理解研究版本／证据／引用／审核、正文、图片计划与源文件／成图、导出记录及现有任务结果。

公共知识库、模板库、提示词库、模型与解析服务配置、API Key、授权及统计继续共享。保存项目选用的公共资源标识和该项目实际生效配置，不复制整套公共库，不随切换改变全局设置。

### 3.3 工作区切换与故障

只有当前项目相关任务、Agent 请求、导入转换、图像渲染、数据提交和导出写文件都已停止，才能切换。Agent进程空闲运行不算执行任务。检查由 Main 统一承担，UI 禁用只是反馈；不能只依赖一个前端布尔值。

**不新增用户主动暂停入口。**做完当前步骤后不进入下一步，即为暂时不继续；没有“暂停工作区”的动作。故障后保存已完整返回的结果与错误信息，资源真正释放后允许切换。原引擎已有的恢复字段／底层暂停代码不必删除，但不能据此新增“暂停后切换”的产品机制。

打开项目恢复页面与已保存数据，不自动执行 AI。失败位置的重试沿用现有任务能力；不能承诺 token 级续跑。已完成结果不能因项目切换而重置。切换期间禁止旧页面在新项目里提交未处理的保存请求。

### 3.4 项目删除

先点击红色删除按钮，再显示确认弹窗，默认焦点落在取消上。弹窗必须显示目标项目名称及以下含义：

> 删除项目后，会清空该项目在本应用中的所有资料、生成内容和历史记录，且无法在应用内恢复。是否继续？

补充边界用简短小字说明：导入前的外部原始文件、公共知识库／模板及另存到工作区之外的导出文件不删除。用户导出到项目内部目录的副本属于项目资产，一并删除。

取消不修改数据；确认后阻止重复点击。目标项目仍有运行中任务时不可删除，也不能把强制终止任务隐藏在删除操作里。成功清理该项目独占的业务记录、托管原件与 Markdown、缓存、研究证据、配图、临时文件和导出记录；共享资产只解除引用，不能删实体。

删除失败不能弹“已删除”并让行消失。记录失败阶段，允许从同一个删除入口重试完成清理。不得自动扫描并删除工作区之外的相似文件或文件夹。删除的是该项目，不是整个 `workspace` 根目录。

保留必要的本地删除结果留痕，仅记录不可读业务 ID／操作／时间／成败，不保留已删除的正文、文件内容或完整项目详情。迁移前备份与用户自行备份独立于正常工作区删除，不声称对所有备份或磁盘残留完成了安全擦除。

P01 页面最下方显示用户指定原文：**定期清理不用的项目，项目资料会占用C盘空间。** 本轮不增加磁盘扫描或自动清理。

## 4. 招标资料管理：P02

### 4.1 页面与可见操作

页面主体只包含当前项目信息、标题说明、一个“添加文件”按钮、文件列表及原有必要导航。右上角保持“开始招标文档解析”入口；其功能复用现有设置弹窗、范围选择和启动链路，不创建第二套解析任务。

表格列固定为：`文件名称｜文件类型｜上传时间｜操作`。**没有转换状态列。没有转换按钮。没有资料集状态／数量统计卡片。没有解析结果面板或大面积 Markdown 阅读区。**

行内显示“移除”；前面已确认的单文件替换能力放入该行“更多”菜单即可，不再常驻一个转换类操作。文件名超长省略，悬停可读全名。格式说明由当前解析器真实支持能力生成；图片中的 Excel/JPG/PNG 等示例不能被当作新增格式授权。

### 4.2 导入与追加行为

“添加文件”同时支持一次多选、分多次添加。导入新一批时保留已有文件；不能沿用“每次重新上传就清空来源集合”的旧行为。后台格式转换复用现有解析服务及配置，转换只是内部处理，不新增一个可操作流程页面。

优先对托管原件做内容哈希以识别完全重复文件，转换缓存另外绑定解析器和配置版本。文件名不能充当唯一标识。完全重复跳过并提示；同名异内容不得覆盖，询问替换既有文件或作为新文件保留。替换新文件失败时保留原文件。

同一次多选有失败时保留已成功加入的文件，通过现有提示方式集中列出失败文件及原因；不恢复状态表、转换按钮或统计卡片。失败的未加入文件不伪装成可解析输入，用户可以重新添加。

内部允许记录准备中／可用／失败状态，用于阻止未完成的输入进入分析；**后台有状态，不等于界面必须有状态列**。导入时使用现有加载反馈，解析入口在材料尚不可用时禁用并说明原因。

### 4.3 文件替换、移除和分析版本

移除仅作用于当前项目的托管副本及引用，外部原件不动。文件集合的添加、替换、移除成功后，递增资料修订号。未改变内容的重复添加，不触发无意义的新修订。

若已有解析结果，用一条轻量提示说明“招标资料已更新，现有解析结果待重新核对”，不新建资料集卡片。上传完成不自动运行项目分析。用户点击原右上角入口后，对当前整组资料分析；可复用未变文件的转换结果，但不做复杂条款级增量重算。

资料变更本身不清空已保存的目录、正文、项目理解或图片。已有结果可标记基于旧资料，后续按用户明确的重新分析／重新生成动作更新。必须核对 `clearDownstreamFromTender` 等旧清理路径，不能用“复用原函数”为理由静默删成果。

重新分析后若旧下游结果与新资料不一致，保留旧成果并标注需要复核；不要在本轮自动改写旧正文或逐章判断影响。未重新分析前不能把旧报告、旧全局事实包装成新资料的结论。

### 4.4 多文件来源与投标范围

保存每份文件的稳定来源身份及内部 Markdown 位置。组合输入时保留文件边界，不把不同文件无标识地拼成一段长文本。已有锚点采用项目／文件命名空间或兼容映射，防止同名标题、同样条款号造成锚点碰撞。

后续结果有可用定位时保留来源文件、条款／段落；只有原始解析器可靠给出页码时才使用页码，不伪造。上传时间不代表文件效力，不执行“最后上传自动覆盖前文”。有相互矛盾要求时保留相应来源并提示人工核对，不开发复杂法律优先级引擎。

已有多标段识别、单／多标段模式及确认动作继续使用。处理工作副本时不能丢失通用条款或其他来源文件的必要附件；“新建项目”与“更换所投标包”不得混为同一动作。

## 5. Step 02 招标解析报告导出：P03

### 5.1 仅追加导出能力

在当前解析结果查看页的现有操作区增加一个“导出 Word”按钮，导出对象是当前项目已保存的《招标解析报告》。沿用原结果导航、字段、折叠／阅读方式、解析设置和重试入口。

参考图只说明“导出位于结果页上方操作区”，不授权把现在的解析结果改成图中五个固定页签，也不授权新增整页仪表盘。图中“打开最近导出文件”如当前页面没有，不必增加第二个常驻按钮；保存成功后复用现有打开文件反馈即可。

### 5.2 内容与格式

直接读取保存结果并确定性转换为 `.docx`，不再调用 AI 摘要、改写、联网或重新核验。报告至少包含：

- 当前项目／所选投标范围，来源文件清单和对应资料修订，报告导出时间及已有解析时间。
- 当前解析模式和实际选中项目，按现有定义顺序输出完整结果；不能只导出正在看的页签。
- 原有 Markdown 标题、列表、表格，以及结构化 JSON 的中文字段和值；未知字段不能静默抛弃，可放到相应结果中的其他字段区域。
- 原有来源引用、错误及待人工复核信息。`0`、`false`、空数组、缺失和“未发现”不得一概变为空白。

保留表格为可编辑 Word 表格，不截屏代替。默认沿用当前导出格式中适用的纸张、正文和表格样式；不把技术正文的章框格式强行套到解析报告，也不新增报告模板管理页。表格跨页时保持表头与合理换行，长链接不撑破版心。

有已保存的部分结果但部分失败时允许导出“部分完成／待复核”报告，明确未完成项目及范围。完全没有可导出结果时禁用。正在分析时不导出半写入状态：第一版等待当前任务结束再导出，保留任务停止后的已保存部分结果导出。

资料已更新但未重分析，导出旧结果须明确标注其原资料修订及“待重新核对”，不能将最新文件清单与旧分析错误配对。

### 5.3 导出行为

导出从 Main 读取项目绑定的稳定快照，不依赖 Renderer 当前显示的零散缓存。保存对话框取消不改变数据，不提示失败。建议文件名 `{安全项目名}_招标解析报告_{时间}.docx`；部分／过期结果增加待复核标识。文件写出失败保留原业务结果，使用现有 Toast 提示。

不生成正文，不依赖目录、图片计划或全局事实齐全，不触发最终投标正文的门禁。导出记录属于当前项目；打开文件用现有安全能力。两类新增导出可共享底层转换器，但要明确报告、纯大纲、完整正文三个不同输出范围。

## 6. 目录大纲导出与正文前层级调整：P04

### 6.1 整体大纲导出

从已保存的完整目录树输出 `.docx`，包含所有折叠节点、实际顺序、显示编号及真实 Word 标题级别。不输出正文、图、附件，不调用 AI，不生成尚不存在的最终标书页码。

提供一次性的“包含编写说明”选项，默认关闭；放在导出选项内，不在页面增加重复预览卡片。开启时将节点既有 `description` 放在标题下，不让 AI 补写。内部 ID、来源锚点、调试标记、AI／人工操作标签默认不混入标题。

无目录时禁用。有未保存调整时先保存或取消导出，不导出与用户所见不一致的旧树。导出不改目录、不改变流程阶段。文件名建议 `{安全项目名}_目录大纲_{时间}.docx`。

### 6.2 层级调整的适用时段

仅允许在目录已生成、正文生成尚未启动时使用本轮新增结构调整功能。应同时检查是否有已有正文／原方案回填内容，不能仅看当前页面是否叫“目录编辑”。导入既有正文的扩写模式不默认套用该轻量结构移动。

正文已经启动或存在正文的项目，不启用本轮新增升降级；保留原有查看／导出等行为。不得通过自动清空正文、图片或附件解锁按钮；不新增迁移和重写流程。旧项目已有其他编辑行为不借本轮扩大或重构。

### 6.3 操作定义

| 操作 | 行为 |
| --- | --- |
| 升一级 | 选中节点连同全部后代，移动为原父节点的同级，位于原父节点之后 |
| 降一级 | 选中节点连同全部后代，成为前一个同级节点的最后一个子节点；不存在前一个同级时禁用 |
| 上移／下移 | 只调整当前父节点下的同级顺序，整棵子树同行 |
| 保存调整 | 连续操作先在草稿中预览，最后一次保存并统一编号；可取消未保存调整 |
| 添加同级／下级、修改标题／说明 | 复用当前已允许的规则和操作，不额外开发全文编辑器 |

保持节点标题、编写说明、编写方式及当前来源字段。显示编号由树顺序生成，不把用户新编号当成稳定身份。内部仍采用路径式 ID 时，必须同步该目录阶段的引用映射，例如项目理解定位、评分承接和来源标识；这是目录数据一致性，不是正文迁移。

### 6.4 必要约束

根节点不能再提升；不能形成循环或把节点放入自身后代；整棵子树移动后不得突破已有最大深度或重点五级边界；来源明确锁定的父子关系、层级、顺序继续保护。不得重新引入“两个下级”“第六个必须分组”等已淘汰规则。

人工编写标记保留，遵守当前祖先人工保护规则；不能把含人工节点的分支自动改为 AI 可覆盖。UI 禁用原因要具体，如“当前已是一级目录”“没有可作为父级的前一个同级”“该层级由招标文件锁定”。保存以事务应用，失败保留原保存版本与当前草稿。

不新增“模板生成”等第三种编写方式，不按截图中“AI生成为主”创造新枚举。使用当前业务真正支持的“AI编写／人工填写”等正式名称。

## 7. HTML 横版配图：后台默认规则，无新增 UI

### 7.1 复用边界

保留当前全文配图规划、计划确认（若现有流程有）、存储、失败恢复、本地 Electron 渲染、正文锚点插入及人工核对。**不新增 HTML 控制页面、比例下拉、逐图配置卡片或新一级入口**。前面所有 HTML 工作台高保真图不属于本包，也不属于实施需求。

不引入此前调研的外部图形库或 Skill，不新增独立“图形表达清单”研究阶段，不改造整套视觉审核系统。既有结构化图表模块可增量补齐，但不能只换函数名而仍输出与图种不符的卡片列表。

### 7.2 默认比例与输出规格

| 情况 | 首选比例 | 设计画布（CSS px） | PNG（2 倍截图） |
| --- | --- | --- | --- |
| 流程、步骤、时间轴、横向时间进度表达 | 16:9 | 1280 × 720 | 2560 × 1440 |
| 组织图、层级图、架构图、矩阵及需要纵向层次的结构 | 4:3 | 1280 × 960 | 2560 × 1920 |
| 未明确类型或两者均适合 | 4:3 作为保守默认 | 1280 × 960 | 2560 × 1920 |

先将当前图种的中文／代码值归一化，再应用规则。新生成 HTML 图片只允许上述两种比例；当前计划里已经合法且与实际内容适配的比例可保留，不能使用随机比例。首选布局不通过时，可以在现有修复次数预算内试另一种横版比例，不为切换比例另开无限重试。

比例确定后保存到当前图的计划／生成记录，输入不变的重试和恢复继续使用同一比例。历史图片不因升级自动批量重生成；用户明确重生成时才应用新规则。非 HTML 的照片／创意图及旧任意 HTML 渲染调用不被本规则全局改尺寸。

### 7.3 全链路生效

目标宽高必须贯穿计划、普通模型提示词、Agent 提示词、布局修复、本地探测、截图、成图元信息和 Word 插图。删除新横版路径中的“高度自适应到1800px”冲突指令，不能只在提示词里追加比例。

先在目标视口排版并检查内容是否完整，再按目标画布截图；不能只按固定矩形裁掉越界内容。输出 PNG 的实际像素比必须符合选择比例，CSS 尺寸和 2 倍像素尺寸分别记录，不混用。

保留现有字号底线和布局检查；不能靠压扁、旋转、缩小字号、大片空白补边、藏溢出或删关键节点来通过。放不下时重排／压缩非关键信息；仍失败则沿用已有失败反馈并保留正文，不自动拆多图或突破数量预算。

Word 等比例缩放，不能拉伸到固定框。应检查普通与章框导出中实际可读性；像素变多不代表图中文字就足够大。

### 7.4 图种表达补齐

本轮优先覆盖现有流程图、组织图、时间轴和架构图，按图种把可校验数据接入受控模板／布局：

| 图种 | 最低正确表达 |
| --- | --- |
| 流程图 | 节点、方向、先后关系；有分支的不能变成无分支的平铺卡片 |
| 组织图 | 真实父子层级与连接关系，不只列岗位名称 |
| 时间轴 | 有序阶段与对应时间；没有日期依据时不得编造实际日期 |
| 架构图 | 模块、分层／分组及正文中存在的连接关系，不仅是无关联卡片 |

所接入类型必须有实际调用与语义测试。其他现有图种仍走原路径并遵守横版输出；不借本轮扩建全图表引擎。未支持类型不得假称完成结构化改造。数字和对象只使用当前正文／已确认事实，不虚构统计数值。

当前 HTML 本地渲染的网络与文件隔离保持，禁止在线字体／CDN 依赖。默认渲染并发 5、最高 20 的既有产品参数保留，不为这次横版改造擅自降低或删除。不能全局解除 Agent 联网限制。

## 8. 数据与架构交接要求

这是实现约束，不向用户暴露新的设置页面。优先复用现有 Electron Main、SQLite、Store、任务队列、文件解析和 Word 导出，不增加外部低代码平台或服务账户。

### 8.1 必须隔离的上下文

每个项目业务操作从启动时绑定 `project_id` 及所需资料／目录修订；异步返回时只写回该项目，不能读取一个已变化的“当前项目”变量决定目标。事件同时携带项目身份，Renderer 丢弃非当前项目的页面更新，但不能把别项目结果误显示为失败。

项目切换、删除、来源变更与任务启动使用同一 Main 级忙闲／写入保护，防止“检查空闲后刚好又启动请求”的竞争。旧请求、已删除项目的回调和过期修订不能复活项目或回写新目录。无需建设跨项目调度中心。

### 8.2 存储实现选择

默认优先评估“全局项目索引＋每项目投标业务数据及资产目录”的小范围实现。具体采用项目专用 SQLite 还是给现有投标业务表添加项目键，由 Codex 在核查 Store 的依赖注入和 SQL 后选择改动最小且能通过隔离测试的方式，记录选择及原因；不是要求用户选择数据库方案。

两条方案都必须满足：不复制全局库；不把多项目切换实现成覆盖一个公共临时槽；不更改应用 `userData` 来模拟切换；不把普通JSON文件变成业务权威状态；不新建第二套完整应用实例。

推荐最小逻辑实体：项目索引、项目文件清单、现有项目业务状态、项目导出记录、必要修订／操作留痕。现有能表达的字段复用，不把下列设计名当作强制建表命令：

| 逻辑信息 | 要点 |
| --- | --- |
| Project | 稳定 ID、名称、当前阶段、时间、最后位置、存储关联；无用户可见运行状态列 |
| SourceFile | 稳定文件 ID、项目 ID、名称、类型、托管路径、内容哈希、导入时间、内部可用状态 |
| Revision | 资料集合修订、分析来源修订、目录修订，用于过期判断与防旧结果回写 |
| ExportRecord | 项目、输出类型、实际文件路径、导出时使用的修订和结果 |
| LocalAudit | 新建／删除／文件变动／导出／目录调整等轻量本地记录，无全文与密钥 |

### 8.3 项目删除与路径安全

先解析并验证项目的真实受管目录，再执行清理，拒绝越界路径、目录穿越和链接跳转到其他资源。索引更新与文件清理采用可重试步骤；全成功才显示删除成功。Windows文件占用、中文／长文件名、磁盘不足都需要错误处理。

不按文件名模糊搜索后删除，不清空全局生成图片目录，不删除外部原始投标文件。资料先进入临时位置，通过校验后原子性替换当前文件记录；不要先删旧文件再解析新文件。

### 8.4 原有项目迁移

本轮场景为已有 v1.7.4 功能基线升级至 v1.7.5。首次升级时仅将原单项目状态登记为一个已有项目。先做可恢复备份，再迁移／登记，核对旧资料、目录、正文、图片路径、项目理解证据和任务状态。确认完成前不删除旧数据；重复启动不重复创建迁移项目。

当前共用 SQLite 可能包含知识库、模板及其他功能数据，不能直接将整库归属某投标项目，也不能删除旧库作为“迁移完成”。Schema 和运行时 migration 以当前实际最新版本为基础递增，不硬编码回 v25。

发生故障可回到备份或兼容读取方式，不能为回滚降级数据库并丢字段。备份还原步骤要在测试副本验证；不要为了演示回滚动用户真实数据。

### 8.5 扩写模式、项目理解和引用

“已有方案扩写”保留原方案输入，单独标识，不纳入招标来源清单。共用页面改动必须验证两个入口。

项目理解的研究记录、引用ID、当前应用版本和人工复核状态属于项目。跨项目同样 `PU` 编号不得串用；在目录阶段被重新编号时，定位需保持正确。不得放松已合并的事实核验、引用守恒、自然拆分和人工保护规则。
