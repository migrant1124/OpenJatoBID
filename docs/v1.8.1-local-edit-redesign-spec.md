## 4. 用户故事与主流程

| 用户故事 | 输入 | 输出 | 关键限制 |
| --- | --- | --- | --- |
| US-LE-01 我选一处就能马上说明怎么改 | 一次框选/圈选/魔法选择 | 右侧聚焦的新修改卡 | 不先按“新增”，不跳转到主输入框 |
| US-LE-02 选错或不想改可以立即放弃 | 临时空白选区、撤回或删除 | 对应选区与输入同时撤销 | 不能影响其他有效修改 |
| US-LE-03 连续修改多个物体 | 多个独立选区与各自描述 | 同图上的多条有效修改 | 编号、颜色、文字绑定不串位 |
| US-LE-04 放大查看不会误画或误滚 | 滚轮、Ctrl＋滚轮、空格拖动 | 可预测视图变化 | 不修改遮罩、不缩放整应用 |
| US-LE-05 填写长意见仍能看到图片 | 右侧长文本、多卡片 | 独立滚动、足够输入空间 | 提交始终可见，不出现底部狭窄输入带 |
| US-LE-06 提交后保留原图 | 有效修改集合 | 一个逻辑任务、一个新版本 | 只提交所确认区域；失败不丢稿 |

### 4.1 首次打开

冻结本次编辑的 `sourceId/sourceHash/width/height`。初始有效修改数为 0，显示右侧空状态，不提前造“修改区域1”的空记录。默认激活图中第一项“画笔圈选”；原图按可用画布适应窗口，不拉伸。

### 4.2 每次选择

1. 工具变更立即改变工具高亮、鼠标形态与简短提示。
2. pointerdown 开始、移动中实时反馈、pointerup 完成；圈选自动闭合。
3. 对有效选择创建唯一内部 ID，并在右侧立即展开输入卡，滚入视野、自动聚焦。图片附近短暂提示“已选择区域 N，请输入要修改的内容”。
4. 新输入卡是本方案的“即时弹出输入框”；不再增加遮挡目标物体的第二个大弹窗。
5. 用户填入非空文字后，该项自动有效，不要求另按“保存本处/确认新增”。
6. 再次在图片上选取即创建下一项，不追加进旧项。至多保留一个正在等待文字的临时空白项。

### 4.3 “不输入则放弃”的精确定义

- 用户刚完成选区、刚获得焦点时，**绝不能因为字段为空就立即删除**。
- 停留、思考、输入法组词、操作滚动条、缩放、拖动画布，都不是放弃；不设置自动超时。
- 开始下一次选择、点击另一条修改卡、明确删除/取消当前项、或提交全部修改时，先结算当前输入。
- 若结算时 `trim()` 后为空：移除该临时选区与卡片，不进入提交、计数或持久化有效列表。
- 若已有文字：保存为有效项并继续该动作。
- 已有有效项在编辑中被暂时清空，不立即删除；在明确离开该项时仍为空才按删除处理，且可以撤回恢复原选区及文字。
- DOM 的一次普通 `blur` 不是唯一删除依据；例如点击缩放控件不应误删当前空白项。
- 清空所有内容、取消并退出的意图必须明确；已有非空未提交修改时关闭整个窗口要确认放弃，不静默丢失。

### 4.4 多区域示例

① 猫：把毛色改为橘色，保持姿势和毛发质感。  
② 蓝色抱枕：改为深蓝色，保持布料纹理和形状。  
③ 花纹抱枕：改为浅绿色，保持原形状。

此示例只用于验收，不写死为初始内容，不表示模型已生成这些效果。

## 5. 工具规则：只保留三种选择方式

### 5.1 画笔圈选

按钮沿设计图叫“画笔圈选”。行为定义为**自由手绘轮廓、松开后自动闭合并选中内部**，不是把粗画笔轨迹本身当成选区。一次按下—绘制—抬起即一次选择，不再采用旧版“多笔累计同一区＋手动新增”的流程。

绘制时显示细轮廓与起点提示；完成后以半透明遮罩和细边界表示实际选中区域。去抖、路径简化不得改变用户指定的主要轮廓。过短路径、画布外起点、零面积不产生修改项；自交路径采用一致的填充规则并让可视预览与实际遮罩相同，不隐式切成多条意见。

### 5.2 矩形框选

十字光标、实时矩形边框；任何方向拖拽均归一化坐标，出界部分裁到图像内部。松开后框内部为实际选区并立即出现输入卡。只点一下或几乎零面积的框不生成空修改。

### 5.3 魔法套选

点击图片中的一个物体，由现有 SAM 路径获得真实对象遮罩，完成后进入同样的输入流程。指针有魔法棒标识；点击有一次短反馈，推理期间显示“正在识别对象…”；没有真实进度时只用不确定加载，不编百分比。

失败保留其他项，提示重新选择或使用框选/圈选；不将任意矩形当作“识别成功”。切图、关窗、撤回、取消、重新选择后，旧请求结果必须丢弃。对同一源图复用已有图像特征缓存，不重复加载整套模型。

删除本局部修改窗口的“补选”“减选”“新增修改区域”及相关快捷键/隐式模式。普通用户选错后删除或撤回，直接重新选。不得把这三个功能换个名称藏到菜单中重新加入。

### 5.4 选择、激活和重叠

- 点击编号或右侧卡片只激活对应项，不新增、不更换工具、不改原图。
- 三种工具的新的有效拖选/点选都建立独立候选，不修改已有遮罩。
- 魔法选择识别到与现有项相同的对象，优先激活已有项并提示“该区域已有修改”，不重复新增。
- 不同项发生实质面积重叠时标明涉及编号，不能悄悄后者覆盖前者；将冲突项标为需处理并阻止整组提交。用户可删除并重新选取。不要求引入补选/减选来解决。
- 边界像素的反走样接触与大面积重叠应区分；判定阈值必须是透明度/面积可解释规则并有测试，不能用整个包围框相交代替真实遮罩相交。

## 6. 数据一致性、撤回和删除

### 6.1 内部 ID 与显示编号

每项固定 `regionId`，显示编号从当前有效顺序派生。颜色绑定 `regionId`，不是绑定数组索引。删除第2项后，第3项显示为第2项，但内部 ID、图像遮罩、意见、缩略图和颜色仍属于原来的物体。

空白待填项可以暂显示下一个编号；右侧标题只计算有效修改数，同时显示“1处待填写”提示。放弃空项不消耗永久编号。正式提交时编号快照与请求引用使用相同映射。

### 6.2 删除

每张卡右上角提供图中垃圾桶按钮。一次点击删除该项的选区、编号标记、缩略图和文字，动态更新标题计数与提交按钮，不逐项弹确认；由撤回提供恢复。不能通过删数组第N项连带删错元素。

### 6.3 撤回/重做

使用一份编辑命令历史，记录完整原子操作：创建有效修改、修改已保存文字、删除、清空。撤回与重做恢复完整项，不只恢复轮廓或只恢复文字。

- “撤回”先取消当前未完成手势或空白临时项；没有这些状态时撤回最近一次有效编辑命令。
- 有效文字以一次编辑会话/明确结算作为历史步，不按每个字符复制大图。
- “清空选区”按图保留，含义是**清空全部修改项，包括选区和对应意见**；存在有效项时确认一次，完成后可一步撤回恢复。
- 视图缩放、平移、切工具、输入框聚焦不进入内容历史。
- 新编辑命令使 redo 分支失效；单纯视图操作不清空 redo。
- 焦点在文本输入中时，Ctrl＋Z/Ctrl＋Y 保留文本自身撤销；不能因改一个字误删整项。点击工具栏撤回则明确操作编辑器历史。
- 不在撤回、重做、删除、清空时发起生图请求。
- 历史有合理内存上限，保存几何/遮罩引用，不为每次输入克隆整张原图；额度清理不删仍被当前草稿、历史和提交快照引用的资产。

## 7. 滚轮、平移和坐标规则（本窗口确定口径）

| 操作区域/输入 | 唯一行为 |
| --- | --- |
| 图片上普通滚轮 | 图像溢出时纵向移动；适应窗口没有溢出时保持不动，不缩放 |
| 图片上 Shift＋滚轮 | 有横向溢出时横向移动，不缩放 |
| 图片上 Ctrl＋滚轮 | 围绕鼠标所在图像点缩放；不同时触发滚动或整个 Electron 页面缩放 |
| 图片上按住空格＋左键拖动 | 临时平移，手形指针；松开空格回到原工具 |
| 顶部 +/-、缩放滑块、比例 | 与 Ctrl＋滚轮驱动同一视图状态 |
| 适应窗口 | 完整显示原图，居中，不拉伸；不得将实际62%伪标100% |
| 原始尺寸 | 图像像素与 CSS 像素按1:1显示，比例为100% |
| 右侧卡片、文本框上滚轮 | 滚动对应内容，不缩放图片、不把图片带走 |
| 文本框内空格 | 正常输入空格，不触发平移 |

图片、全部遮罩、轮廓、编号、小地图共享一个坐标变换。图像始终按原始宽高比绘制；存储与模型输入全部使用原图坐标。不要用截图尺寸或 CSS 缩放后的尺寸生成最终遮罩。

建议缩放范围10%–800%；当超大图的适应比例小于10%时允许该适应值，不能因为范围下限裁切原图。所有比例均为真实显示比例而不是“相对适应窗口倍率”。

同一滚轮事件只允许一个消费者执行一次。优先采用一个画布滚动容器表达平移，禁用第二套叠加的平移监听。不要在 document/body 上全局拦截滚轮。技术实现需考虑可取消事件、监听器 passive 选项、触控板以及 delta 单位，详见 Handoff。[E5]

绘制期间不同时接受缩放/平移；要先正确结束或取消当前手势。pointercancel、失去捕获、窗口失焦和 Escape 都不能留下“持续画线”状态。[E6]

| regions | regionId、提交时编号、工具类型、几何/受管遮罩、对应提示词 |
| unionMask | 所有有效区域的并集，作为选区外保护依据 |
| requestId / idempotencyKey | 防连点重复提交；一次提交对应同一个逻辑任务 |
| requestSnapshot | 提交时不可变区域、文字、模型与来源快照；结果可追溯 |

结构化状态进入既有工作区 Store/SQLite；大遮罩进入受管本地资产，Renderer 不直接读写文件。临时空白项不进入持久化有效列表，有效草稿可按现有保存机制存储；改表前备份并验证旧库迁移，不清空真实数据。

### 8.2 发送与结果

1. 提交前结算当前文字，剔除空白临时项。没有有效项则不发请求；存在重叠冲突或无效遮罩则定位问题项。
2. **编辑要求来源是这些卡片，不是主创作页的 `prompt`。** 主创作提示词只可作为历史背景，不覆盖本次意见。
3. 原图、多区域编号标注和每项要求必须在实际请求中对应。沿现有适配处理单 mask 接口：可发送原图、明确编号的标注参考与并集 mask，同时在提示词中列出区域对应；不能只传一个无编号大遮罩和不关联的几段文字。
4. 每条独立遮罩保留到业务快照中，用于调试、范围保护和恢复；显示色不能被当作真实图像颜色提交为目标结果。
5. 本轮默认一次用户提交产生一个编辑任务、一个新版本；不因有N项就静默发N次生成请求，不额外探测计费端点或无提示重试。需要改变已验证调用编排时，必须报告实际成本和依据，不能擅自升档。
6. 复用当前生图设置和 `aiService`。不将本次界面重构当作更换模型、安装另一套SAM服务或新建账号的授权。
7. 结果不得含编辑编号、彩色遮罩或工具文字；保留原图尺寸。并集选区外使用原图像素合成保护，不能仅靠“其他区域不变”的文字约束。
8. 与原图尺寸不同的结果不可默默拉伸或裁切后报成功；保留返回结果与错误证据，并允许使用现有明确适配方式处理，不自动重复付费。
9. 完成后保存独立作品并指向本次冻结的父作品。不得因为后台新图到达或用户切换主页面而编辑到另一张图。

### 8.3 失败、停止等待与关闭

提交期间锁定此次快照和重复提交，仍可查看缩放；卡片显示当前任务状态。已发送后的“停止等待”不宣称已取消服务端或免计费。不自动重发结果不明的请求。明确失败保留有效选区与文字，重新提交由用户决定。

选区阶段的 Escape 优先取消当前手势/候选；有文字的窗口关闭按放弃确认处理；不会通过按一次 Esc 无声丢掉整组意见。中文输入法组合期间不能把 Escape/Enter 误作窗口动作。Enter 在文本框换行，不直接提交生图。

## 9. PSD 细修与回归边界

现有 `ImageStudioMaskEditor` 也服务 `ImageStudioLayers` 的 `mode='refine'`。本轮的“每选一次就写修改意见”只适用于 **edit**。

可提取共享画布、坐标和视图引擎，再分别实现局部编辑与图层细修；或者增加清晰的编辑模式分支。不得对 `refine` 强制创建修改卡、要求文字、自动删除无文字遮罩、调用GPT或改变遮罩alpha含义。原来的图层细修能保存、PSD会话能恢复、图层导出不变。

已接入的 SAM 像素选择工具可复用，但组件UI的删除补选/减选不意味着删除所有PSD算法能力。不要重构整个分层工作流、背景补全策略或改变图层数量目标。

## 10. 安全、性能与实施约束

- 执行完整目标不等于授权Git操作：不自动pull/fetch、切分支、建分支、reset、提交、push、merge、tag或发布。
- 不改 management、analytics、Worker、R2、Release工作流和授权边界。本次版本字段仅核对；若已是1.8.1保持，若本地版本更高不降级；需要补一致性时只修改客户端既有版本来源及锁文件，不改管理端版本。
- UI样式使用独立类名前缀，例如 `image-studio-local-edit-*`；不全局覆盖所有 `textarea`、`label`、`dialog`、`button`。
- 模型图片、遮罩、提示词不写入公开日志或埋点。审计记录操作类型、任务/区域ID、数量、耗时、结果状态，不泄露密钥或私有路径。
- 人工检查通过右侧意见列表、统一提交和新版本预览完成；不额外加投标合规审批、不默认注入公司/客户品牌或竞品词库，本功能保持通用创作。
- 运动仅用于选区轮廓、点击反馈、卡片展开；加载动画不冒充精度或进度。支持减少动态效果，不持续大面积闪烁。
- 本轮不引入新的整套UI库，不用低代码外站代替客户端；复用现有组件和服务，由Codex完成必要改造。
- 实测使用用户允许的素材和已有明确调用额度；无新增费用授权时先完成可离线的实现和验证，仅将相关实测记为未执行，不能据此把按钮长期锁死或把SAM退化为假算法。
