### 2.3 内部展示与许可记录的准确边界

因此本产品的内部展示默认行为为：

- 不将“删除署名页”扩展为去除其他来源作品中已有的权利管理标识；本产品不新增不必要署名，与修改第三方原有标识是两件事。

## 3. 产品目标、角色和范围

### 3.1 产品目标

把 PPT 制作从“一次性生成文件”变为“可选模板、可修改、可恢复、可积累资料和技能”的内部工作区。减少员工处理网络、文件路径、环境安装与整份返工的工作。

不预设节省时长百分比；后续以同一份样稿在旧流程与新流程中的实际操作时间、局部修改次数和重生成页数衡量。

### 3.2 角色

| 角色 | 工作与权限 |
|---|---|
| 员工 | 选模板、上传资料、创建和编辑 PPT、管理个人技能与项目、获取公共资源 |
| 管理员 | 配置来源、范围、目录和可信技能；查看固定每周计划，执行手动检查/停止/重试；不编辑周期 |
| Jato Agent | 根据员工意图规划和调用受控工具，不替用户决定付费、删除或扩权 |
| 管理端后台任务 | 自动检查、下载、校验、缓存、发布公共资源版本；不作为任意远程命令执行器 |

### 3.3 本轮完整功能范围

| 模块 | 同一轮交付内容 |
|---|---|
| PPT 创作 | 主题／资料／已有大纲／单页／原生 PPT 编辑／美化／模板应用与模板提取 |
| PPT 编辑 | 直接编辑、对话修改、页与元素定位、页面增删排序、全局主题修改、历史版本与撤销 |
| 视觉及数据 | 参考图理解、图片生成与编辑、信息图、原生图表表格、必要的页面视觉检查 |
| 演示与交付 | 本地预览、PPTX、PDF、页面图片、讲稿；用户明确启用的转场、动画、旁白和演示视频 |
| 模板库 | 固定资源源、真实预览、分类筛选、整套模板与单页版式、个人模板、可复用性标识 |
| Skill 管理 | 四种导入入口、依赖自检、启停、更新、卸载、恢复、项目锁定版本 |
| 管理端资源中心 | 生图与 PPT 来源集中管理、定期同步、有变更自动发布、VPN／代理适配、资源镜像、局域网分发、异常与存储管理 |
| 资源更新提醒 | 客户端上线后获取更新，合并两中心概括、去重弹窗、查看对应新内容；不新增客户端一级通知中心 |
| 项目与存储 | 自选目录、系统盘提示、自动保存、异常恢复、迁移、重新定位、快捷删除 |
| 工程完整性 | 权限、记录、迁移、两端 API 兼容、安装包验证、原业务回归 |

“支持某能力”指需要实现且验收通过。需要外部模型或组件的能力在运行时根据实际配置显示，不用假成功、不用整页图片伪装原生编辑。

### 3.4 不因本轮顺便扩张的事项

不另建完整 SaaS、不引入第二套 PPT 主引擎、不要求使用 Docker 或另一个数据库服务、不新增数字人直播或多人实时协作。不将现有程序发布更新、模型调用代理、标书业务数据库整体迁往管理端。以上不是分期，而是不属于已经确认的本轮目标。

现有 Electron 原生文件操作、Agent SDK、Python 工具和局域网分发需要应用代码适配，不宜用通用低代码平台拼出第二套后台。无代码体验体现在用户端的可视化配置和管理中。

## 5. 总体架构与网络边界

### 5.1 资源与制作分离

```text
GitHub / 模板 CDN / 生图公开资源
                 │
          管理端 VPN 或代理
                 │
       现有管理端：统一资源中心
       ├─ 来源配置与定期同步
       ├─ 下载、内容检查与版本快照
       ├─ 封面、预览、模板、Skill 资源镜像
       └─ 局域网鉴权分发
                 │
       客户端：本地缓存与使用
       ├─ 生图模式复用公共提示词和参考图
       ├─ PPT 模式选模板、制作、修改、导出
       ├─ 个人 Skill / 模板 / 资料
       └─ 用户选择的本地项目目录
```

这张图描述拟建架构，不表示已经部署。管理端只集中公共资源维护，不自动接收员工的项目原文、生成图片、PPT 文件或模型密钥。

### 5.2 三类网络不得混为一谈

| 网络用途 | 本轮处理 |
|---|---|
| 生图／PPT 公共仓库及资源更新 | 全部由管理端访问上游；客户端访问管理端与本地缓存 |
| 文本、视觉、生图、语音模型，以及用户明确启用的事实检索 | 复用现有授权和配置；不因为管理端有 VPN 就自动改变调用归属或数据发送目标 |
| 客户端／管理端程序 EXE 更新、授权和统计 | 保留原有程序发布更新体系及既有兼容约束；资源更新不能变成未授权的软件发布通道 |

因此“客户端不必直连 GitHub 获取模板”不等于“使用云模型时不联网”，也不等于“任何公司材料都可经管理端上传外网”。

### 5.3 Skill 链接安装的网络路径

客户端将用户提供的 Skill 仓库地址提交给管理端的“资源获取申请”，由管理端验证来源并下载，客户端安装验证通过的副本。管理端不得提供接受任意 URL 的通用代理接口。

本地 Skill 文件、文件夹和 ZIP 的安装继续在客户端完成；不以管理端在线为前提，也不自动上传到公共技能库。安装、启用、授权执行是分开的动作。

### 5.4 离线和不可用行为

管理端不可达时，已有本地模板、Skill、项目和已缓存生图资源仍可使用；原授权规则不变。未缓存资源显示“需连接管理端获取”，不静默改为客户端直连上游。

缺失模型网络与缺失模板网络分别提示。管理端只有 VPN 不通时，已经镜像完成的资源仍可通过局域网提供。管理端本身关机时，只能使用客户端已缓存内容。

## 6. 管理端统一资源中心

### 6.1 职责及页面入口

在现有管理端新增“资源中心”页面，供管理员维护生图资源、PPT 模板和受管 Skill 包。复用现有登录、设置、托盘、数据库及 HTTP 生命周期，不要求单独启动命令或浏览器服务。

不把该页面新增成客户端全局“资源下载”旧入口的复活。客户端只在生图／PPT 对应模块消费资源。

### 6.2 公共资源类型

| 类型 | 同步内容 | 不应遗漏 |
|---|---|---|
| 生图模式 → 提示词中心 | 公共提示词清单、提示词正文、标题、标签、分类、已有可发布译文及参考图片 | 不只是同步仓库地址或图片；coverUrl 等资源不得仍让客户端直连外网；不新增长期自动付费翻译任务 |
| PPT 模板源 | 索引、封面、逐页预览、PPTX 或结构模板包 | 目录只有链接时，必须继续获取本体，链接不等于已缓存 |
| Skill 包 | 入口、参考资料、脚本、模板及必要许可文件 | 不能只同步 SKILL.md；脚本更新不能自动获得执行授权 |
| 运行组件包 | 已批准、平台对应的运行组件 | 与普通模板区分信任等级，不随普通 JSON 更新自动执行 |

### 6.3 同步策略（周期为用户固定要求，其他建议单独标明）

| 设置 | 行为与性质 |
|---|---|
| 周期 | **固定每 7 天检查一次已启用来源**；只读显示“每周一次”，不提供周期输入框或下拉框 |
| 启动行为 | 启动后若已到期，补一次检查，不把关机错过的每次计划都堆成任务 |
| 手动控制 | “立即同步”“停止本次同步”“重试失败项” |
| 初次同步 | 先获取索引和轻量封面，再在管理端队列补齐已启用范围的本体及预览 |
| 管理端存储策略 | 对已启用公共模板范围完成增量镜像；初次开启先显示估计／已知容量与剩余空间 |
| 发布行为 | 检查到实际内容差异且校验通过后，自动发布资源快照与结构化更新记录；没有内容差异只更新检查时间 |
| 客户端 | 上线后轻量同步目录及公共提示词更新，模板及图片按使用下载；汇总提醒，不向所有员工推送全库 |
| 初始并发 | 小规模受限并发，建议下载 2 路；结构检查与大文件任务独立限流，可调整 |
| 失败策略 | 超时／限流退避重试，保留最后成功版本，不清空客户端已有列表 |

以上是同一版软件的运行行为，不是分期开发。管理员可限定同步的类别和磁盘配额；默认不因资源增长无限占满磁盘。未知容量必须显示未知，不能当作 0。

“全量镜像”指已启用来源及筛选范围中的实际公开可获取资源，不是抓取站点所有未知 URL，也不是认为目录中的未来文件已经存在。

### 6.3.1 固定一周的调度合同

- 自动检查间隔固定为 7×24 小时（604800 秒）。界面使用“每周一次”；协议/设置不得允许另设小时或天数。
- 首次启用资源中心立即进行一次初始化检查并建立持久化定时锚点；锚点是内部执行细节，不要求用户选择星期几。
- 手动“立即检查”、失败重试及客户端“同步目录”不改变该锚点；客户端同步目录不是请求管理端绕过周期扫描上游。
- 管理端休眠、关机或 VPN 失联后，只补一个已到期检查，不把错过的多个周期排成大量任务。补检查后计算下一个未来周锚点。
- 定时器依赖管理端进程实际运行，关闭界面进托盘可继续；完全退出服务/关机时不声称仍在同步。源内失败项退避重试不等于缩短全库检查周期。
- 持久化下一次到期时间；重启不重置成又等待一周。服务器时间变化与并发运行需去重，同一来源只允许一条发布流水线。

### 6.4 同步流水线

```text
读取本地来源配置
 → 到期检查上游索引／版本
 → 比较业务内容，排除检查时间等非内容变化
 → 没有变化：只记录检查结果，不发布、不通知
 → 有变化：在暂存目录下载新增或变化资源
 → 校验类型、实际长度、哈希、结构和允许的来源
 → 从通过校验且有实际变化的条目形成待发布集合
 → 建立不可变资源版本与结构化差异
 → 同一事务／可恢复提交中发布快照、发布记录与摘要依据
 → 客户端上线时按版本获取，成功应用后汇总展示
 → 记录结果并安排下一次检查
```

必须把“索引更新成功”“本体下载完成”“模板结构检查通过”“AI 套用验收通过”分开。某一项下载失败不能将全库显示为同步完成；也不应让一个失败项永久阻断其他独立资源发布。

允许逐资源发布成功版本，但必须明确快照引用的每项版本及每项状态。客户端只看到已发布版本，不能读取暂存半成品。

### 6.5 不重复下载、不破坏旧项目

优先使用 ETag／Last-Modified／提交或资源版本等进行增量检查；文件落盘后计算实际 SHA-256。没有强校验值的来源应记录观察到的哈希，不把上游自称的“最新版”当成信任证明。

资源身份用稳定 source_id + 上游 ID／slug；内容版本用来源提交、内容哈希和适配器版本共同描述。更换镜像线路不改变来源身份。新版本不原地覆盖旧版本文件。

删除上游条目时先下架新项目可选项，保留仍被项目引用的版本；安全风险资源另行标记禁用与恢复路径，不把“允许回滚”当成忽略漏洞的理由。

### 6.6 VPN／代理适配

管理员的浏览器能访问 GitHub，不代表 Node 或子进程必然使用同一网络设置。因此资源下载器必须真实验证其运行时使用的网络路径。

提供“使用系统网络设置”和“管理端专用代理”配置，代理凭据只在管理端保存。测试至少覆盖 GitHub 元数据、raw 文件、实际模板 CDN、重定向和局域网客户端连接。

局域网服务不经上游代理；不得为修复访问而全局关闭 TLS 校验、放宽任意内网抓取或修改其他模式的网络权限。文件内链接和重定向都按受控规则校验，不能因管理员粘贴了 GitHub 链接就无限信任下游地址。

### 6.7 管理端运行状态

管理端沿用关闭窗口后驻托盘、退出服务后停止的现有行为。[S02]

定期同步只有在管理端进程运行、设备未休眠且具备网络时才能执行。页面必须显示运行状态、最后成功时间和下次计划时间，不宣称关机时还会同步。除非另获确认，本轮不额外改为 Windows 系统服务。

### 6.8 存储与清理

管理员自行选择资源存储目录；选择系统卷时提醒。源文件、预览、缓存、暂存与旧版本大小分别统计，不将资源库放入安装包目录或 SQLite BLOB 中。

清理默认只处理无任务占用、无保留策略约束的暂存和旧缓存。清理原始镜像、停用来源、删除来源配置是不同操作，确认卡说明影响及可恢复方式。不得删除授权数据库、管理员凭据或签名密钥。

### 6.9 有变更才发布：公共资源更新记录

**用户已明确：** 定期更新由管理端自动执行；有更新内容后发布，客户端上线时看到更新概括。以下去重、统计与展示细节为本稿的配套默认规则。

“检查上游”“缓存候选”“发布资源”“客户端应用”“用户看过概括”是不同结果，不可互相代替。管理端发布是将已校验版本写成客户端可获取的快照，不是强制唤醒离线客户端，也不是要求员工手动复制文件。

**变更判断：** 以稳定资源 ID 及业务内容比较为准。提示词正文、标题、分类、标签、关联图片、模板本体、页面预览或真实可用状态发生变化，才形成对应业务差异；检查时间、排序波动、JSON 空白、下载线路变化或无关 README 提交不单独生成内容更新通知。哈希不同先检查是否确有业务差异，不机械把全库算作更新。

普通公共提示词及模板数据在已批准来源、范围和校验规则内自动发布，无须管理员每次点击批准。Skill 脚本、可执行组件、新权限等仍执行原有信任和启用规则；不能借“自动发布提示词更新”自动安装或执行代码。

每次成功发布保存发布 ID、资源协议版本、前后快照、来源版本、发布时间、资源变更明细与每类统计。快照和摘要依据必须一致；不可出现通知宣称已更新，而对应数据仍在暂存区的情况。独立成功条目可组成一个有效发布批次，失败项保留旧版本并在管理端展示，不计入本次成功数量。

同一次同步运行中的小文件完成事件合并为发布批次，不每下载一个文件就发一条公告；增量镜像很大时允许受控批次发布，客户端仍按未查看范围汇总。网络故障、无效 JSON、异常空清单不能推断为上游已删除全部条目。

| 更新概括范围 | 统计与概括依据 | 不允许的表述 |
|---|---|---|
| 生图提示词中心 | 按提示词条目统计新增、更新、下架；概括实际变化的分类／标签和代表条目；参考图片变化归到相关条目，不重复计数 | 把源检查次数算作提示词新增；把个人改写内容当成管理端更新 |
| PPT 模板中心 | 整套模板与单页版式分别统计；显示新增／更新／下架及必要的准备、验证状态 | 把多页预览算成多套模板；把未下载或未完成 AI 复用验证的模板写成“新增即可直接套用” |

概括默认由结构化差异通过固定中文句式生成，不要求新增模型调用或让管理员每轮手写公告。可显示“新增 12 条流程图提示词”“新增 3 套商务汇报模板”等有数据支撑的描述；不得臆测“质量大幅提升”“修复全部问题”。付费模型不可作为发布与通知的必需依赖。

仅索引已发布但资源仍需准备时，摘要必须写“新增目录条目，部分仍需准备”，并分列真实就绪数量。下载／结构／AI 验证三个状态仍按第 9 节分别管理。管理端只进行下载及轻量检查，不因发布摘要擅自运行付费 AI 套用测试。

普通自动更新的摘要由程序生成；管理员手动下架、恢复等行为也要有真实变更记录。恢复至旧内容须形成新的发布记录，而不是倒写或复用旧的发布 ID。

## 7. 客户端获取与既有生图来源迁移

### 7.1 客户端资源访问

客户端只保存管理端连接配置、可信资源清单及本地缓存。网络请求按资源 ID 和版本发起，由管理端解析为受管路径，不让客户端传入任意服务器磁盘路径。

目录与资源传输支持分页、明确总数、资源长度、哈希、断点续传及取消。哈希匹配后才将 `.part` 临时文件改为可用文件；下载途中断开不产生损坏的“已安装”资源。

资源路由应独立于既有授权 API，例如 `/api/resource/v1/...`；这只是接口命名建议，不代表现有接口。客户端与管理端按资源协议版本协商，不要求两个安装包版本完全相同。

### 7.2 可信分发

沿用已有授权身份，并设计最小权限的资源读取票据；不能把管理员会话凭据发给员工客户端。可执行 Skill／组件还应验证发布清单签名和客户端兼容性。

受信公钥或证书必须通过已有可信配对或安装信任链建立；不能把同一条未认证连接下载的公钥当成天然可信。哈希防损坏不等于来源可信，签名有效也不等于脚本天然安全。

既有普通 HTTP 授权服务不因本轮被宣称为加密传输。资源通道的身份、完整性与必要的保密传输必须独立验证，不能扩大原风险。

### 7.3 生图模式迁移要求

1. 管理端接管公共源的 URL、备用线路、同步时间和缓存；员工端取消编辑公共源外网地址的普通入口。
2. 员工端“刷新”改成获取管理端已发布快照；必要时可请求管理端检查，但不能触发所有员工各自拉上游。
3. 保留 source_id／item_id。不要因为迁移重建 ID，导致收藏、个人副本、译文或引用失联。
4. 保留已有本地可用快照作为切换兜底，迁移幂等；失败不清空数据。
5. 公共源变更不覆盖用户自己复制并编辑的提示词；私人条目不因管理端删除公共来源而丢失。
6. 禁止沿用启动逻辑重新写回客户端公网默认 URL。应检查初始化、刷新、封面加载、失败备用线路和迁移后的重启行为。
7. 公网下载使用严格公网规则；局域网资源使用独立内部通道。不能将旧的公网 `assertPublicUrl` 放宽为允许所有私网地址。
8. 原始来源信息可保留供详情查看，但不会被渲染器自动当作图片下载或埋点地址。

### 7.4 多客户端效率与故障提示

同一个资源的多个请求应合并管理端上游下载，客户端不反复向上游取相同数据。下载队列不得阻塞授权校验和既有统计服务。

UI 区分：管理端未连接、管理端上游暂不可用、资源仍在同步、资源未通过检查、客户端版本不支持、空间不足。不要全部合并为“网络异常”。

### 7.5 上线后弹出两中心更新概括

此处“上线”指客户端已进入可用主界面，且成功连到已配对管理端的资源服务；不要求新增一次账号登录，也不能用“电脑已连互联网”代替管理端资源服务可用。

| 环节 | 默认行为 |
|---|---|
| 启动／登录后进入主界面 | 在后台请求管理端已发布资源版本与差异，不阻塞主界面打开 |
| 启动时管理端不可达，随后连接恢复 | 自动补查一次，并对重复网络恢复事件去抖／合并 |
| 有客户端尚未获知的更新 | 获取并校验目录、公共提示词正文及相应元数据，原子应用本地快照；成功后再安排更新概括 |
| 首次打开即在执行用户操作 | 不覆盖输入、确认、导出或制作对话；等当前操作结束或页面空闲后显示 |
| 已持续在线，后来出现更新 | 已获取的更新可在两中心入口显示轻量未读标记；不增加周期性强弹，下次上线再合并提醒 |
| 无变化、重复上线或只有同步错误 | 不弹更新概括；失败使用原有连接／同步状态，不将失败伪装成内容更新 |

上线只需检查管理端发布结果，不要求管理端为每位员工上线重新扫描 GitHub。无需为了实现本功能新增 WebSocket、通用消息队列或第二个服务；沿用管理端资源 API、后台任务和本地持久化接口即可。这里描述拟建方案，不声称相关代码已经实现。

一个弹窗包含“生图提示词中心”和“PPT 模板中心”两个区域；只有一个中心变化时，另一区域简洁显示“本次暂无更新”，不弹两个连续窗口。客户端离线数天错过多批发布时，在当前可见范围内汇总到最新成功应用版本，只弹一次，不逐版本补播。

PPTX 和图片本体仍按使用从管理端下载，不能为弹概括强制下载全库。说明“目录已更新，模板按使用获取”；生图公共提示词正文应与列表对应版本一起成功应用，不能列表已换新而点击后仍读旧正文。

管理端尚无可发布的新版本、客户端同步失败、版本不兼容或校验失败时，保留最后成功数据；不更新“已应用”或“已展示”标记。公共资源更新不覆盖个人提示词、收藏、改写副本、私人模板或项目锁定版本。

### 7.6 汇总基线、首次使用和防重复

1. **已应用不等于已看过。** 分别保存客户端成功应用的数据版本和概括实际展示到的版本。后台同步成功但尚未弹窗时，下次上线仍须呈现未展示的变化。
2. **汇总比较两端状态，不累加日志条数。** 以该用户／设备上次已展示的内容版本，与本次已成功应用的最新内容版本比较。一个条目被改多次只计一次；先新增后下架、且员工从未看到的条目不算当前新增；模板页面预览不冒充整套数量。
3. **实际显示后才去重。** 弹窗完成可见渲染时，持久化该弹窗绑定版本的已展示记录；只下载摘要不算已展示。关闭、点击“知道了”或进入查看页后不重复强弹；仍可在中心的“更新记录”入口回看。当前会话加本地去重保护，持久化失败记录真实状态而不连续刷弹窗。
4. **范围是用户＋设备＋管理端资源流。** 不要求新增跨设备阅读同步。换管理端、重新配对或权限范围变化时单独初始化可信基线，不能只比较一个时间戳或无命名空间的版本号。
5. **首次无历史基线。** 首次安装／接入且没有旧数据或展示基线时，完成初始加载，以轻量“资源已就绪”提示替代把整个资源库称为“本次新增”。从旧版本迁移时，有可比旧快照则据实比较，已记录的展示游标也要迁移。
6. **历史不足不编造累计数。** 旧快照缺失、服务端明细已清理或权限集合不可比时，可使用现存受管快照计算；仍无法准确比较则提示“资源库已更新至最新可用版本”，不虚构新增数量。失败不抹掉本地原有基线。
7. **权限和可见范围一致。** 只计入该客户端有权看到且已同步的两类资源，不泄露隐藏来源或其他员工数据；个人屏蔽条目不被恢复。一个范围应用失败时允许独立成功范围提醒，失败范围保留原游标供重试。
8. **同次连续使用最多自动弹一次。** 两中心同时有变化合并；后续新发布显示轻量提示，留待下一次上线汇总。弹窗显示期间新发布到达，不悄悄改变当前概括及计数，当前弹窗只记它实际绑定的版本。

“已展示”仅表示应用确实显示过，不证明员工认真阅读；不得把管理端发布、客户端下载或窗口创建记录标成所有员工“已读”。

### 8.2 模板库对员工的分类

主分类为“整套模板”“单页版式”“我的模板”。风格、品牌、配色作为筛选／设计设置；不要把一个颜色配置伪装成一整套模板。

卡片展示真实封面、名称、画幅、页数或版式数、编辑能力和准备状态。相同版式的配色变体放在一张卡片内切换，不用变体重复撑大模板数量。

“模板已下载”“可原样编辑”“可作为风格参考”“需准备”必须是不同信息。先显示与内部商务、培训、方案汇报相关的筛选结果可以作为推荐，但不强制把所有 PPT 写成投标格式或植入佳图 Logo。

### 8.3 选择模板后的动作

用户点击模板时，系统取得管理端的具体资源版本和哈希，复制或引用受管副本，完成所需准备；模板可复用缓存键至少含：模板内容哈希、适配器版本、运行组件版本及影响布局的字体信息。

同一模板不重复做相同转换。选择了模板不意味着允许使用模板里原有公司的事实、数据、Logo 或样本文字。引用模板的是设计与结构，新项目内容以用户材料和明确需求为准。

### 9.2 复用类别

| 内部能力分类 | 用户看到的名称 | 允许的操作 | 禁止的承诺 |
|---|---|---|---|
| native_reuse_verified | 可直接套用 | 经验证的文字、图片、表格或图表替换；按实际支持范围显示 | 不宣称所有复杂对象均无损支持 |
| mixed_reuse_verified | 部分可编辑 | 修改已映射原生对象；其他部分作为保留的图片／装饰 | 不把图片上的文字称作可直接改写 |
| visual_reference_verified | 按此风格制作 | 提取设计规则，用新内容重新生成可编辑稿；明确不是对原文件原位换字 | 不承诺像素级一致、不假造隐藏结构 |
| unverified | 待验证／需准备 | 下载、检测、准备，或查看说明 | 不显示“已验证可套用” |
| unsupported_or_failed | 暂不可用 | 查看失败原因、重试或选择其他模板 | 不自动降级为截图后仍标记可编辑 |

编辑类别与下载状态分别存储。例如“已缓存／待验证”是合法组合；“仅云端／可直接套用”只有在有适用的真实验证报告时才成立。

每个验证结论绑定 source hash、adapter version、验证运行环境、字体与模型能力。换源文件、换适配器或必要运行能力改变时应重验，不永久继承旧绿色标识。

### 9.3 结构检测：全文件检查，不能只数一个文本框

获取 PPTX 后先验证文件签名、ZIP 路径、解压规模及 XML 安全，再读取 presentation、slide、master、layout 和关系信息，至少检查：

| 检查范围 | 要查清的内容 |
|---|---|
| 页面 | 实际页数、尺寸、隐藏页、继承关系、页面顺序 |
| 文本 | 原生文字与文本框、占位符、母版／版式上的文字、文字是否可见、是否主要仅有页码 |
| 图形 | 形状、组合、位置变换、连接线、主题与背景，不凭对象数保证视觉正确 |
| 图片 | 独立图片还是覆盖整页的截图；背景图中是否含主要文案或数据 |
| 图表表格 | 原生结构、关联工作簿、缓存与实际数据一致性；图片型图表单独标记 |
| 特殊对象 | SmartArt、OLE、外部关系、音视频、动画、字体依赖及不可支持对象 |
| 备注与附属内容 | 讲稿、超链接、隐藏样本文字、样本工作簿等可能残留的原始内容 |
| 风险 | 宏／可执行嵌入物、外链、损坏 XML、超大解压、路径穿越；不自动执行或访问 |

需要考虑组合坐标和母版继承。纯统计 `<a:t>` 或 `<p:pic>` 的数量只能辅助判断；一张整页图片加一个页码，不是已证明可套用的原生内容页。

普通 XML、文本、对象结构优先，不默认全库 OCR。确实只有图片且用户选择重建时，再调用适合的视觉能力；模糊文字与数据不能补造。

### 9.4 原生模板的实际复用验收

结构检测后必须进行真实的小样替换：

1. 对每种不同布局选取代表页，至少覆盖封面、内容密集页，以及存在的图片／图表／表格类型；短模板检查全部页。
2. 使用无真实客户信息的中文测试内容：明显不同的新标题、比原文更长的段落、可验证的测试数字和自有图片。
3. 由目标 Jato Agent／适配器生成内容映射，执行真实替换，不能仅改文件名或复制原文件。
4. 导出新 PPTX，再重新解析验证新内容、独立对象及图表数据；检查应移除的原样本文字没有残留。
5. 用实际目标 PowerPoint／WPS 打开并查看版式、中文换行、图片比例和可编辑性；SVG 预览通过不等于此项通过。
6. 记录样本、模板哈希、环境、模型、执行记录、输出哈希、覆盖的布局和未覆盖能力。

“套用成功”必须至少证明：新内容真正进入原生对象、页面可打开、必要对象可编辑、无明显溢出或误用模板事实。不能靠在截图上叠新文字来通过测试。

样本级通过不自动推广为同仓库所有模板通过。整库静态扫描和部分模板真实测试必须分别报告覆盖量。

### 9.5 图片型模板的 AI 复用路线

图片型模板可以进入“按此风格制作”：先提取配色、密度、页面构图与表达方式，再根据当前新内容由 ppt-master 生成原生文字、形状、图表和必要图片。

不得把完整参考页铺底后叠一层可编辑字，称为重建成功；不得把参考图中的旧数据作为新项目事实。输出应能修改新生成文字，图表根据真实数据重新绘制。

若用户要求“原样还原为独立可编辑图层”，按专项图片还原能力执行。ppt-master 当前 Image to PPTX 分支的官方验证宿主是 Codex，不等同于 Pi Agent 已兼容；Jato 必须完成参考图编辑、图层配准、文字复原与重组对照的自己的验证。[S11]

视觉参考重建不是原生保真编辑。模型、素材或参考分辨率不足时说明阻塞原因，不虚构字体、数据或隐藏元素。

### 9.6 检测在哪执行

管理端承担下载、安全与轻量结构检查；不要求其为所有模板运行付费 AI 或替员工生成 PPT。

客户端承担与当前 Agent、模型、字体和运行环境有关的模板准备及真实套用验证。可复用结果本地缓存。发布为“已验证”的公共模板需有对应测试报告；新增来源条目在报告缺失时保持待验证，使用时自动走准备，不假装立即可套用。

客户端不自动将用户项目内容上传给管理端作为测试数据。任何用于公共能力登记的报告应来自无业务数据的测试素材，且仅包含允许共享的资源标识、版本、结构统计和结论。

### 9.7 当前技术准入缺口

`GATE-TPL-01A`（free）：CDN 完整样本取得、对象检测与目标 Agent/Office/WPS 验收仍未完成；不能整库开启“已验证直接套用”。

`GATE-TPL-01B`（wuhua）：一个真实页面的结构与工具替换已有证据；其余布局覆盖、完整模板保真、实际 Jato 模型调用与目标 Windows Office/WPS 验收仍是交付测试，不能用封面测试代替。

所有验证结论须区分技术可行性判断、页面样本通过、整套模板通过、全库覆盖率四个层级。

此缺口不阻止讨论模板库 UI，但禁止把“全库直接套用”作为 UI 承诺或实现验收已通过项。软件仍按同一版本完成全部功能；真实验证是交付门槛，不是“放到下一期”。

## 10. PPT 模式完整用户流程

### 10.1 常见用户故事

| ID | 用户故事 | 成功结果 |
|---|---|---|
| US-01 | 我上传资料，选择模板，做一份内部汇报 | 依据材料得到可预览、可修改和可导出的 PPT |
| US-02 | 我已经有大纲，不要重新打乱结构 | 保留大纲，补齐必要设计并制作 |
| US-03 | 我有旧 PPT，只需要改几页 | 原生编辑路线，未修改页尽量保持原样 |
| US-04 | 原文不变，重新美化 | 美化路线保留内容约束，明确不是只改主题颜色 |
| US-05 | 我只要一页流程图 | 单页独立生成，可单独导出或插入当前项目 |
| US-06 | 我选中元素，要求换图或重排 | 精确定位目标，不重做无关页面 |
| US-07 | 我拖入一个技能文件夹 | 一次识别与确认，安装后可知道是否真的可用 |
| US-08 | 我清理不用的 PPT | 一次确认，仅删除应用管理的该项目副本 |
| US-09 | 员工电脑无法访问 GitHub | 从管理端获取已镜像资源，模板和参考图可用 |
| US-10 | 管理端暂时关闭 | 已缓存资源与项目仍可继续，未缓存内容明确提示 |

### 10.2 创作主流程

```text
新建／打开项目
 → 选择项目位置（首次或需要更换时）
 → 输入需求、上传资料、选模板（顺序可自由）
 → Agent 补齐必要信息并形成方案
 → 按所选 Skill 的确认／委托规则推进
 → 大纲与逐页计划
 → 资源准备、页面生成、检查与修复
 → 页面预览、直接修改或对话修改
 → 人工审阅后导出
```

用户已给定的模板、页数、用途和范围不重复询问。AI 推断与用户明确事实区分保存。默认建议值可由用户修改，不将模板原有业务内容强加给新项目。

### 10.3 制作需求摘要

保存用途、受众、主题目标、页数范围、比例、语言、模板、风格、文字密度、配图策略和讲稿要求。高级设置默认收起。

“少文字”应改变表达方式与信息组织，不靠缩小字号塞进原版式。“多配图”不意味着机械地每页加图；数据图表与装饰图片不能互相替代。

### 10.4 大纲与页面计划

页面有稳定 slide_id，不用当前页码作为永久身份。计划保存标题、页面任务、依据资料、核心内容、表达方式和素材需求。

允许直接编辑、拖拽排序、调整层级、增加和删除页面、恢复旧计划。页码变化时同步目录、讲稿、动画、内部超链接等关联，不让批注绑定错页。

模板的内容容量不适合新内容时，Agent 应重排或调整页数并按约定确认，不使用越界文本或极小字号掩盖问题。

### 10.5 直接编辑和 Agent 编辑

确定性的错字、文本、颜色、坐标等优先走直接编辑；改写、布局、视觉取舍走 Agent。优先复用 ppt-master 已有编辑器与批注能力。[S12]

修改任务携带项目、slide_id、element_id、基准 revision、指令和保护项。先生成候选版本并检查，再提交生效；取消或失败保留上一个可用版本。

人工编辑与 Agent 不同时写同一页。生成中的页面默认只读预览；到达上游允许的编辑节点再应用批注。用户点“应用修改”后由应用触发，不要求返回聊天手动粘贴内部提示。

### 10.6 局部修改与联动

“改第三页”不重写全稿；“换全局字体”需要检查所有页面；“增加一页”更新页序和目录。系统解释真正需要联动的内容，不扩大到无关主题。

不承诺所有路线都能任意断点续写。恢复按上游路线要求执行；已完成文件保留，必要时说明重新检查或重建的范围，不能一律从零重跑。[S11][S13]

### 10.7 资料与事实

支持当前能力覆盖的 Word、PDF、Markdown、TXT、PPTX、图片及表格资料，优先复用现有解析能力。新增格式必须有明确错误处理，不能仅允许选择文件却无法解析。

默认“仅依据所选材料”；用户需要公开研究时启用相应能力，并保存事实出处。私人文档中的指令不能修改系统权限。合理实施建议与外部事实区分；不编造业绩、价格、资质或数据。

### 10.8 预览和导出

导出 PPTX、PDF、页面图片、讲稿及用户明确启用的相关媒体产物。保持原生文字、形状和可支持图表表格；照片仍是图片，不承诺照片内部每个细节都可编辑。

普通生成路线以当前上游约定的 `svg_output/` 为页面设计来源，`svg_final/` 为预览。原生编辑路线沿其 round-trip 工作区合同；不强制所有路线套同一组文件。[S13]

每次源文件变动后，过期的检查报告不能继续用于导出。需披露影响使用的字体、图像、对象和媒体警告；严重问题阻止“已完成”状态。

内部展示输出不加模板署名页、许可附件或修改说明附件。记录留在软件内部。导出后仍由用户负责内容审阅，但系统不能以“用户会审”作为跳过结构和文件检查的理由。

## 11. Agent 能力与运行环境

### 11.1 能力配置，而不是另起 Agent

保留内部 runtime_id 与当前工程一致；在共享 Pi 内核外增加 PPT 专用能力配置，不照搬普通聊天的只读限制，也不把全部模式放开。

PPT 会话需具备资料读取、受管写入、确定性工具、受控脚本、模板处理、图片理解、素材调用、用户询问、结果验证、任务取消与恢复能力。模型是否真支持图像、工具调用及所需上下文须实际检测。

### 11.2 技能与工具的关系

Skill 提供方法和流程，不会自动赋予宿主不存在的功能。宿主将上游工具调用映射为已安装且经过校验的程序，并向 Skill 提供真实绝对路径。

技能按需加载：入口和简介用于匹配，激活后读 SKILL.md，按选定路线读参考文件。不把全库一次性灌进上下文，也不全盘扫描员工其他 Agent 配置目录。[S14]

上游 Default、Quick、Create Template、Edit Native 等按各自合同运行。Quick 不是隐藏的省事按钮，不能借此绕过用户选择的交互或必要验证。

### 11.3 低摩擦确认

普通改字、局部重排、已授权方案执行不重复弹窗。危险删除、安装新可执行技能、扩大网络或文件权限、超出已授权的付费调用需要真实确认。

“按上述要求自动规划并完成”只委托 Skill 允许委托的规划与执行判断，不代表同意任意上传、全盘写入或新付费服务。普通 Default 流程的明确确认与授权委托都需要可追溯，不能伪造上游 UI 回执。

### 11.4 执行环境

Windows 员工不需要自己安装 Python、Git、Node、FFmpeg 或编译依赖。组件由程序安装／资源分发机制托管并锁定版本，使用绝对路径；不要依赖开发机 PATH。

主进程只做调度、权限和 IPC，重型工具在独立进程执行。工作目录不是安全沙箱；执行 Agent 生成的代码前必须验证真正的文件、网络、环境变量和进程限制。一般第三方技能导入不自动允许任意 shell 或 pip 安装。

禁止将整份主进程环境及 API Key 传给不可信脚本；模型、图片与网络服务通过专用工具调用。超时和取消需回收完整子进程树，不只结束父进程后留下后台任务。

### 11.5 生图、信息图与数据图表

复用现有生图模型配置、参考图处理和任务统计，不增加第二套账号管理。失败与结果未知分开，不盲目重复付费请求。

原生数据图表使用结构化真实数据；定性流程和关系图可验证引入 AntV Infographic，但 SVG 输出不自动等于 PPT 全对象可编辑。组件通过适配测试才纳入，不能为使用组件而增加第二套页面权威数据。

### 11.6 开源选型约束

主链路是 Jato + Pi + ppt-master。dnd-kit、信息图或选择变换组件按真实缺口择用；现有或上游已经覆盖的能力不重复造轮子。不整包嵌入 Presenton／PPTist／Banana Slides，避免多套存储、导出与模型配置。

任何采用组件均锁定版本、审查许可证和传递依赖。应用支持导入 Skill，不等于支持导入任意可执行插件扩展。

## 12. Skill 安装、更新、删除与恢复

### 12.1 一个面板、四种来源

| 来源 | 处理规则 |
|---|---|
| 文件 | 接受有效 SKILL.md；普通 Markdown 缺元数据时提供明确的“整理为技能”确认，不默默宣称完整 Skill |
| 文件夹 | 从用户授权目录识别入口，复制依赖的相对目录，不修改原目录 |
| ZIP | 自动识别外层目录和内部技能，不要求用户先解压；多个技能提供一次多选安装 |
| GitHub 地址 | 经管理端资源获取接口下载，识别固定提交及子目录；不要求用户手动 clone |

禁止把只有 ppt-master 入口文件、缺 scripts／templates／references 的安装标记为可用。缺失依赖时提示补充完整目录或使用管理端已验证版本。

### 12.2 安装状态

识别 → 待确认 → 安装中 → 依赖／能力检查 → 可用，或缺组件／不兼容／失败。安装成功、启用和实际兼容是不同状态。

面板显示名称、用途、版本、来源、占用空间及启用开关；技术权限放详情，但关键新权限在确认卡显示。重复安装同一内容不产生重复项，更新不破坏旧任务锁定版本。

本地安装默认个人可用，不自动发布为全公司 Skill。用户通过 Agent 说“安装这个包”与点击按钮走同一安装服务，不允许模型自己编写管理员安装命令绕过检查。

### 12.3 安全检查

检查压缩包路径穿越、绝对路径、重复与大小写冲突、链接、实际展开大小、文件数量、可执行依赖和不允许的生命周期脚本。资源说明文本是低信任输入，不能直接赋予工具权限。

脚本／组件版本发生变化时，管理端可自动下载候选版本，但客户端不得未经规则检查自动执行。纯模板或提示词更新与可执行代码更新必须采用不同信任策略。

### 12.4 删除与占用

单项删除或批量删除均采用一次明确确认。先检查正在运行的任务和项目引用，说明“卸载安装副本”与“移除项目所需旧版本”的差别。

删除个人安装副本不删除用户原始文件夹或 ZIP；已导出的 PPT 不受影响。若保留项目固定版本以保证恢复，显示实际保留体积，不谎报全部已释放。

用户要求连同被引用版本删除时，明确哪些项目后续需要重新安装才能继续；先停止相关任务，再执行。基础内置能力若只能禁用或恢复默认，按钮必须如实命名，不用“删除”伪装仅隐藏。

## 13. 项目文件、缓存与系统盘提示

### 13.1 三类目录

| 目录 | 保存内容 | 选择位置 |
|---|---|---|
| 管理端公共资源目录 | 上游资源镜像、预览、暂存与受保留的版本 | 管理员选择 |
| 客户端资源缓存／技能目录 | 从管理端取得的模板与图片、技能版本、运行组件 | 客户端可设置，重型部分支持非系统盘 |
| PPT 项目目录 | 资料副本、页面、素材、讲稿、检查报告、历史版本与导出 | 用户选择默认父目录，也可逐项目更改 |

配置、授权和少量元数据可以沿用既有 userData；不能只把最终 PPTX 放到 D 盘，仍把全部预览、素材、历史和临时大文件藏在系统盘。

### 13.2 项目目录行为

用户选择父目录后，应用创建有独立项目 ID 的子目录，并放置归属标记。选择目录不代表用户授权应用删除该目录下所有内容。

更换默认位置只影响新项目。迁移已有项目需停写、复制、校验、切换和成功确认；失败保留原项目，不使用先删后拷贝。外置盘失联提示重新连接或定位，禁止静默另存到系统盘生成分叉。

### 13.3 系统盘警告

使用实际 Windows 所在卷和目标真实卷判断，不硬编码 `C:`，不忽略目录联接或挂载点。检查写入权限与剩余空间。

建议文案：

> 当前目录位于系统盘（实际盘符）。PPT 制作会保存资料副本、配图、预览和历史版本，可能持续占用较多空间。建议选择非系统盘目录。

按钮：“重新选择（推荐）”“仍然使用”。只在新选择或位置发生变化时提示；用户已确认的默认目录不反复弹窗。仅有系统盘的电脑仍可正常使用。

### 13.4 自动保存与恢复

结构化状态放现有或功能专用 SQLite；文件内容按 ppt-master 所选路线的权威文件保存。数据库只维护索引、状态、确认、版本和关系，不另存一份与源文件竞争的完整幻灯片内容。

阶段完成和完整工具结果原子落盘，不按每个 token 高频写数据库。进程崩溃后根据状态与文件哈希恢复，不能只凭数据库“已完成”而忽略文件缺失。

### 13.5 快捷删除

项目列表支持单项和批量删除，显示名称、完整路径及范围。默认仅操作应用确认归属的项目子目录，优先移入回收站；失败不静默永久删除。

项目外原始资料和用户另存到外部的成品不删除。回收站与永久删除分别说明；移入回收站不能被视为磁盘空间已实际释放。

公共模板“删除”应命名为“清理本地缓存”，不误导为删除管理端或上游资源；“我的模板”删除也不影响已经复制到项目中的版本。

## 14. 下一步 UI 设计输入

### 14.1 全局设计约束

沿用项目已有样式、组件、图标及交互习惯；新增 PPT 一级入口，不重排、改名或恢复其他已删除入口。Word 模板设置与 PPT 模板库是不同功能，不强行合并。

页面可随窗口自由缩放；长列表、对话、预览在页面内部滚动。常用操作直接可见，高级选项收起；不把进度、权限、脚本、来源和所有参数同时堆在主画布。

用户可见中文。开发术语、版本哈希和文件报告放详情；错误需有原因和下一步可操作按钮，不只显示错误码。

### 14.2 页面／面板清单

| ID | 所属端 | 页面或面板 | 主要内容与操作 | 必须展示的异常状态 |

| C01 | 客户端 | PPT 项目页 | 新建、搜索、最近项目、打开、重命名、删除；默认保存位置 | 空列表、项目失联、管理端离线但本地可用 |
| C02 | 客户端 | PPT 制作工作区 | 页面缩略图、预览／编辑、Agent 对话、添加资料、模板、技能、保存状态、导出 | 生成中、等待确认、待审阅、脚本失败、目标页面被锁定 |
| C03 | 客户端 | PPT 模板中心／模板选择面板 | 整套／单页／我的模板，搜索、比例／风格筛选、预览、使用 | 未下载、同步中、待验证、部分可编辑、仅参考、管理端不可达 |

### 14.3 C02 工作区建议结构

建议左侧页面缩略图，中部预览／编辑，侧边可折叠 Agent 对话。此布局是建议而非已确认图稿；不得据此改变原有“对话模式”的布局。

顶部保留项目名与保存状态；常用操作为添加资料、模板、技能和导出。空项目用简单创建区，不让用户先阅读完整工具面板。切换模板或插入单页时保留当前项目上下文。

小窗口优先折叠辅助区域或切换面板，不把画布、输入框和按钮缩到无法操作。不要求某个固定屏幕比例才能使用。

### 14.4 模板卡片及动作

| 状态 | 卡片主提示 | 主操作 |
|---|---|---|
| 文件与适用验证都就绪 | 可直接套用／部分可编辑 | 使用此模板 |
| 已在管理端，未在本地 | 需下载，显示已知体积 | 获取并使用 |
| 仅风格参考通过 | 按此风格重新制作 | 按此风格制作 |
| 只有索引或尚未验证 | 正在同步／待验证／需准备 | 查看进度／准备并检查 |
| 文件失败或环境不支持 | 暂不可用与原因 | 重试／查看原因 |

正常界面不使用“绿色可用”覆盖多个不同状态。目录中有 595 条不等于有 595 个可直接套用模板；数量显示按已发布／已获取／已验证分别统计。

比例不同的模板必须明示；系统建议保持原比例或重新布局，不能无提示横向拉伸。带明显他人品牌的模板不自动植入当前项目。

### 14.5 三种重要确认卡

**安装技能：** 名称、来源、版本、用途、运行组件及新增权限，按钮“取消／安装”。能自动处理的复制与路径问题不逐项弹窗。

**删除项目：** 项目名、完整路径、将删除的内容、外部原文件不受影响，按钮“取消／移入回收站”；永久删除另行明确确认。

**系统盘位置：** 实际系统盘、可能占用空间的文件类型，按钮“重新选择（推荐）／仍然使用”。

### 14.6 管理端同步状态与文案

源状态分为：未配置、待同步、同步中、可用、部分失败、已停用。单个资源另有待下载、已镜像、待验证、不可用，不用一个状态掩盖所有问题。

建议文案：

| 场景 | 文案 |
|---|---|
| 来源检查成功，但还有本体未下载 | 目录已更新，部分资源仍在同步 |
| 定期检查成功且业务内容无变化 | 已检查，无内容更新；显示最后检查时间，不新增发布通知 |
| 新快照与摘要发布成功 | 已发布本次资源更新；客户端上线后获取，不显示“所有客户端已更新” |
| 客户端应用成功且有未展示变化 | 资源库已更新；点击查看新增提示词和模板 |
| VPN 不可用但旧镜像完整 | 上游暂不可用，已缓存资源仍可提供 |
| 管理端离线 | 管理端未连接，当前显示本地资源 |
| 源模板不具备可直接替换的结构 | 此模板需按参考风格重新制作，不能直接修改图片中的文字 |
| 样本尚未测试 | 尚未完成 AI 套用验证 |
| Skill 文件不完整 | 缺少配套资源，请选择完整文件夹或 ZIP |
| 使用者没有视觉模型 | 当前配置无法完成该视觉检查；可更换配置或使用已验证的其他路线 |

### 14.7 下一轮高保真图应覆盖的场景

至少展示：PPT 项目页、制作工作区、模板库与模板详情、Skill 安装管理、系统盘与删除确认、管理端资源中心、来源同步详情、管理端网络／存储设置；新增两中心合并更新概括、只有单中心变化、等待安全展示、管理端“已检查无更新／已发布”的状态。

同一页面的错误状态可以通过状态标注或附图交付，不为每种错误新增一级页面。交付 handoff 应包括组件层级、状态、主要交互、文字与响应式规则；不以静态漂亮图片代替可实现流程。

模板预览可以使用已获授权且已取得的真实资源，或明确标记的设计占位图；不得用占位图声称某个真实模板已经通过生成与编辑验证。

### 14.8 C07 更新概括弹窗与入口

**标题：** 资源库有更新。副标题显示“管理端已发布，自上次查看以来的变化”，并显示实际发布时间或合并期间；首次无历史基线采用第 7.6 节的初始化提示，不套用此文案。

### 15.2 不要建立互相竞争的内容来源

PPT 页面的源文件依从所选上游路线；SQLite 保存权威索引与流程状态，不能又维护一个独立可编辑的完整页面 JSON，导致画布、Agent 和导出各读不同内容。

结构化图表数据应有明确唯一来源，导出后修改关联数据与缓存保持一致。页面顺序、确认、项目路径和资源版本的变更均需事务或可恢复提交机制。

### 15.3 确认失效与并发

当受众、主要目标、模板、画幅、页数范围等实质变动时，相关方案确认失效；小的字词修改不强迫重走完整规划。

任务使用资源与页面锁定版本；资源更新、编辑器操作和 Agent 结果提交采用 revision 检查。发现版本冲突时保留候选结果并让用户选择，不静默覆盖。

### 15.4 任务状态

PPT 任务至少区分：待开始、执行中、等待用户、等待资源、待审阅、已完成、已取消、失败、需恢复。等待资源不等于失败，已完成不等于用户已经审核。

每个耗时步骤有完成条件、结果文件和重试边界。错误修复从拥有错误的层处理：页面问题修页面，素材缺失补素材，源资料变化才重新规划。

### 15.5 发布、应用与展示状态不得混用

管理端发布完成后，资源快照与对应差异必须可同时读取；采用数据库事务加文件就绪标记或其他等价的可恢复提交，不能先发布摘要再冒险补文件。重试同一批次不得产生重复的逻辑发布。

客户端按版本读取和校验，成功应用后更新 `applied_version`；概括可见渲染成功后更新对应 `shown_version`。这两个字段是职责示例，不要求照搬表名。弹窗版本和跳转筛选绑定，不被后续同步覆盖。读取、同步和弹窗操作须幂等，并支持进程重启恢复。

目录协议和资源发布序号独立于 EXE 软件版本；撤回或回滚资源时生成新的事件及差异。已发布但尚需准备的目录项保留明确状态，不能因为通知发送成功而把模板复用状态改成通过。

## 16. 内容、权限、统计与可追溯性

### 16.1 内容与人工审阅

保留公司配置要求的内容检查及人工审阅，但不把本轮通用 PPT 模式重新束缚为标书专用流程。敏感词或禁用名称规则用于生成内容与正式输出，不改写原始资料，不误删模板许可和技术来源名称。

模板样例中的公司、数字、业绩与宣传语不作为新项目事实。内部模板许可记录与事实资料出处是不同事项；用户要求有依据的事实仍需内部可追溯，不因“不展示模板署名”而删除证据。

### 16.2 资源同步不是数据上报

管理端可知道员工请求了哪个公共资源、传输了多少字节及结果，不应因此收集员工项目正文、提示词全文、文件名、完整本地路径或模型密钥。

私人模板、个人 Skill、项目资料默认本地，不自动发布给其他员工。公共资源审阅报告不得夹带测试时使用的真实业务材料。

### 16.3 操作记录

本地记录资源来源与版本、用户确认、关键修改、导出、删除、恢复、Skill 安装／授权和同步结果。UI 默认显示简明历史，完整日志供授权人员查看。

保留现有模型使用统计与埋点能力，但新增事件只记录必要枚举、计数、时长和结果。禁止因日志调试输出密钥、代理口令、整篇资料或含令牌的 URL。

### 16.4 文件与渲染安全

模板／SVG／HTML／网页／Skill 文本都是低信任输入。预览隔离执行，不给予渲染页 Node 权限；阻止未授权脚本、外部请求、文件访问和危险 URL。

外部资源读取按明示允许的来源与当前资源范围执行，不因模板内引用而自动扫描电脑或访问任意网址。删除和迁移以真实路径、归属标记及引用检查为准。

## 17. 容量、安装包与运行资源

### 17.1 口径修正

之前核实的客户端 v1.8.3 正式 EXE 为 359,031,809 字节（约 359.03 MB），不是本轮 1.8.4 或新增 PPT 后的安装包大小。[S16]

此前针对新增 PPT 功能提出的 450～700 MB 是未构建的工程预算，不是实测，也不是对完整媒体工具链的体积保证。现在管理端还增加资源下载与检查能力，两端均须重新测量。

`free-ppt-template` 的目录与模板本体不同：此前文件树记录 index.json 为 1,232,935 字节；不能拿索引大小代表 CDN 全库大小。[S17] 本文没有取得全部 PPTX 与图片长度，因此不写“全库实际共多少 GB”。

### 17.2 分别统计四类容量

| 容量 | 必须包含什么 |
|---|---|
| 客户端安装包 | 现有应用、本轮代码、必须随包运行组件、必要离线基础资源；不包含全部公共模板 |
| 管理端安装包 | 原管理端、本轮同步和分发代码、必要轻量检查组件；不包含全部资源镜像 |
| 管理端运行数据 | 源文件、实际 PPTX／预览／Skill 资源、旧版本、暂存、校验报告 |
| 客户端运行数据 | 下载缓存、安装 Skill／组件、项目素材、历史、预览和输出 |

同一版本全部功能完成，与所有资源塞入 EXE 无关。按需缓存和管理端定时镜像是运行策略，不是分期交付。

### 17.3 体积审计要求

索引、封面、全页预览、模板本体、依赖分别计量；按资源 URL／内容哈希去重，不重复把封面算入两次完整预览。报告未知大小的项数，不能把未知当 0。

比较压缩安装包、解压安装目录、初次运行下载量和稳定缓存；不同单位 MB／MiB 明确标注。模板迁移到管理端不会自动减少原客户端已有大型模型体积，不擅自删除现有生图能力来达到目标。

下载前显示已知大小及当前空间，运行时检查实际写入字节。配额不足暂停新增资源并保留可用版本，不用无限重试或自动删除项目解决。
