# OpenJatoBID v1.8.1 规格文档  
## 版本主题：生图模式优化、缺陷修复与分层链路升级

---

## 1. 文档信息

- **项目名称**：OpenJatoBID  
- **客户端显示名称**：Jato AI BID / 佳图智能投标助手  
- **版本号**：**v1.8.1**  
- **文档性质**：增量优化与缺陷修正规格  
- **适用端**：桌面客户端（Electron Client）  
- **关联基础版本**：v1.8.0 生图模式  
- **本轮目标**：在既有 v1.8.0 生图模式基础上，完成界面优化、交互修正、提示词中心修复、参考图生成放开、局部修改增强，以及 **SAM + GPT Image 2.5 + PSD** 分层链路升级。

---

## 2. 本轮背景与核心结论

v1.8.0 已完成生图模式的主入口、提示词中心、我的作品等基础能力，并完成首轮接入。但在人工测试中暴露出以下问题：

1. 创作页控件比例不合理，提示词输入区偏小，辅助按钮偏大。  
2. 提示词中心图片无法正常预览，分页显示不准确。  
3. 参考图生成被人为拦截，错误提示为“当前渠道的参考图请求合同尚未验证”。  
4. 默认提示词库缺少稳定的自动更新策略。  
5. 任务类型卡片无实际业务作用。  
6. 生图模式图片预览缺少滚轮缩放。  
7. 提示词中心侧边栏和内容区滚动耦合，影响浏览。  
8. 局部修改能力不足，仅支持粗糙选区，缺少逐区域提示词。  
9. PSD 分层功能仅具备写文件能力，缺少真正可用的对象级分层和背景补全，实际效果不满足需求。  

本轮明确采用的新分层与修图链路为：

> **SAM（对象级分割与魔法套选） + GPT Image 2.5（遮挡背景补全 / 局部编辑） + PSD（图层封装导出）**

该链路的核心目标不是“能导出一个 PSD 文件”，而是：

> **图片内的元素个体尽量成为独立图层；被移除对象后，底层背景应能自动补全；最终导出可继续编辑的 PSD。**

## 4. 模型与能力约束

### 4.1 现有文本模型
- **文本模型 / 视觉理解模型**：`gpt-6-sol`
- 用途：提示词优化、图片反推提示词、中文化翻译、辅助生成对象名称等。

### 4.2 生图与编辑模型
- **既有生图模型**：`gpt-image-2` / `gpt-image-2-1k`
- **本轮新增增强链路目标模型**：**GPT Image 2.5**（优先 `gpt-image-2.5-sunburst` 作为高精度编辑 / 背景补全模型；如中转站另有等效命名，以中转文档和实测为准）

### 4.3 分层与选区能力
- **SAM 系列模型**：用于对象级分割、魔法套选、局部修改区域生成。
- **PSD 封装**：沿用现有 PSD 写入能力，但不得再用“主体/背景二层”冒充完整分层。

### 4.4 关键原则
1. GPT Image 2.5 不被当作“直接输出 PSD 图层”的模型。  
2. GPT Image 2.5 主要负责：**背景补全 / 局部编辑 / 遮挡补全**。  
3. SAM 主要负责：**对象识别、对象级选区、魔法套选、对象候选图层**。  
4. PSD 导出由项目端整合图层后生成。

## 5. 生图页（AI 生图）优化要求

### 5.1 提示词卡片与按钮布局

#### 现状问题
- 提示词输入区高度偏小。  
- “优化提示词 / 反推提示词 / 保存”按钮高度过大。  
- 任务类型按钮高度过大。  

#### 调整要求
1. **图片需求输入框默认高度提升至约 210px。**  
2. “优化提示词 / 反推提示词 / 保存”三个按钮视觉高度缩小为当前约 1/2。  
3. 已确认删除“任务类型卡片”，因此不再保留该组按钮。  
4. 生成主按钮保持明显，不跟随缩小。  

### 5.2 参数区调整

#### 现状问题
- 存在“画质”选项，但用户要求删除。  
- 图片尺寸与系统设置绑定，无法在生图页独立控制。  

#### 调整要求
1. 删除“画质”选项。  
2. 将“生成张数”与“图片画幅”放在同一行。  
3. “图片画幅”采用下拉框选择，选项同时展示：
   - 像素尺寸
   - 比例（如 1:1、1:2、2:1、3:4、4:3、16:9、9:16 等）
4. 生图页所选画幅只作用于**本次生成任务**：
   - 不受程序设置中的全局尺寸强绑定限制；
   - 不自动修改系统全局设置；
   - 需记录到草稿、作品和任务历史中。

### 5.3 参考图预览
1. 参考图缩略图支持点击放大预览。  
2. 支持多图切换、适应窗口、关闭。  
3. 预览仅用于查看图片，不触发生图请求。

## 6. 图片预览统一优化

### 6.1 鼠标滚轮缩放
以下区域统一支持鼠标滚轮放大 / 缩小：
- 生图结果大图预览  
- 参考图大图预览  
- 提示词示例图大图预览  
- 局部修改中的主图片预览  

### 6.2 交互要求
1. 鼠标位于图片区域内，滚轮向上放大，向下缩小。  
2. 尽量围绕鼠标所在位置缩放，减少跳动。  
3. 放大后支持拖动查看局部。  
4. 保留“适应窗口”“原始尺寸”操作。  
5. 鼠标不在图片区域时，不拦截正常页面滚动。

## 7. 提示词中心优化

### 7.1 左右独立滚动
#### 现状问题
提示词中心左侧来源栏会跟随右侧内容一起滚动，浏览到底部时左侧消失。

#### 调整要求
1. 提示词中心改为左右独立滚动容器。  
2. 左侧来源栏保持固定可见，仅在自身内容过多时在左栏内部滚动。  
3. 右侧提示词内容单独滚动，不带走左侧来源栏。  

### 7.2 图片预览修复
#### 现状问题
提示词卡片和详情页没有真正显示示例图。

#### 调整要求
1. 提示词卡片显示真实示例缩略图。  
2. 提示词详情页显示真实示例图。  
3. 点击图片可打开大图预览。  
4. 对预览图做按需加载和本地缓存。  
5. 加载失败时显示单条失败状态及重试按钮。  
6. 不再统一显示“图片预览未随包分发”。  

### 7.3 分页修复
#### 现状问题
仅显示当前页，不显示总页数；边界页逻辑不准确。

#### 调整要求
1. 分页区域显示：
   - 总条数
   - 当前页数
   - 总页数
2. 保持每页 40 条。  
3. 依据同一筛选条件下的真实总数计算总页数。  
4. 修复最后一页误进空白页的问题。  
5. 切换来源、关键词后自动回到第一页。  

### 7.4 收藏功能
#### 调整要求
1. 参考提示词卡片支持“收藏”。  
2. 提示词详情也支持收藏。  
3. 收藏后自动生成个人副本并出现在“我的提示词”中。  
4. 同一来源的同一提示词重复收藏时不得重复创建多份个人副本。  
5. 取消收藏仅取消收藏状态，不自动删除个人副本。  
6. 来源更新不得覆盖个人副本内容。  

### 7.5 常用风格说明优化
#### 目标
用户对“常用风格”理解不清。

#### 调整要求
1. 增加简明说明：
   - 常用风格 = 可重复复用的视觉风格描述；
   - 不等同于完整提示词；
   - 不替换主体内容；
   - 主要追加风格信息。  
2. 应用常用风格时：
   - 保留原主体；
   - 避免重复追加相同风格；
   - 支持撤销；
   - 推荐比例仅提示，不强制覆盖当前画幅。

## 8. 删除任务类型卡片

### 8.1 结论
经代码核查，当前“商品图 / 海报图 / 写实图片”等任务类型卡片：
- 仅记录选中高亮和 preset 字段；
- 不参与实际生成请求；
- 不会影响模型、画幅、提示词或工作流。

### 8.2 处理要求
1. 删除“任务类型”卡片区域及其全部按钮。  
2. 不为其补新的业务逻辑。  
3. 旧草稿中若存在 preset 字段，允许兼容忽略。  
4. 释放的空间优先留给提示词输入与参考图片区。

## 9. 参考图生成：取消人为拦截并真正接通

### 9.1 已确认规则
用户明确要求：
> **参考图请求不需要“合同验证”。**

### 9.2 调整要求
1. 删除“当前渠道的参考图请求合同尚未验证，未提交生图请求”的固定拦截。  
2. 参考图生成必须真正将图片传入中转接口，而不是仅保存缩略图或文件名。

   - 主体参考  
   - 风格参考  
   - 构图参考  
   - 色彩参考  
4. 若中转接口真实拒绝请求，应展示具体失败原因。  
5. 失败时保留当前输入、参考图和参数。  
6. 不允许因为接通失败而静默退回纯文生图。

## 10. 默认提示词库后台每周自动更新

### 10.1 已确认规则
用户明确要求：
> **默认提示词库在后台每周自动更新一次。**

### 10.2 调整要求
1. 客户端后台每 **7 天** 自动检查一次默认来源更新。  
2. 首次安装时直接使用内置初始数据，不要求首次联网后才能浏览。  
3. 软件退出期间不运行定时任务；下次启动并联网后应补做一次检查。  
4. 正常内容变化自动更新，不要求用户人工确认“替换旧快照”。  
5. 若某个来源更新失败：
   - 保留该来源上一份成功内容；
   - 其他来源继续更新；
   - 按退避策略重试。  
6. 用户已删除、停用、修改地址的来源不得被静默恢复。  
7. 更新过程不得覆盖：
   - 我的提示词  
   - 收藏状态  
   - 当前编辑中的输入内容  
8. 中文化处理采用增量策略，不每周全量重翻。

## 11. 局部修改能力升级

### 11.1 目标
把当前粗糙的统一遮罩编辑，升级为适合普通用户使用的 **多工具选区 + 多区域编号 + 逐区域提示词**。

### 11.2 必备选区工具
本轮局部修改至少支持：
1. **矩形框选**  
2. **画笔圈选**  
3. **魔法套选**（快速选中图片中的元素个体）  

### 11.3 魔法套选定位
魔法套选的意义是：
> 利用对象分割能力，帮助用户快速选中猫、杯子、沙发、人物等图片元素个体。

它不是简单的颜色选区，也不是 Photoshop 式静态阈值算法，而应尽量以对象为单位进行选择。

### 11.4 多区域与编号
1. 默认仅创建 **修改区域 1**。  
2. 用户创建第二个独立区域时，新增 **修改区域 2**。  
3. 图片上的每个区域都显示对应编号（①、②、③……）。  
4. 图片下方显示与区域一一对应的提示词输入框。  
5. 点击某个区域，高亮对应输入框；点击输入框，高亮对应区域。  

### 11.5 输入区规则
1. 图片下方显示“修改区域 1”的提示词输入框。  
2. 若用户新增第二处选区，才显示“修改区域 2”输入框。  
3. 同一图片可以有多处修改要求，但默认不铺满多个空白输入框。  

### 11.6 工具行为规则
1. **矩形框选**：新建新区域；拖动已有框时是编辑已有区域。  
2. **画笔圈选**：默认连续多笔属于当前区域，不因每一笔都新增新区域。  
3. **新增修改区域**：用户明确点击后，再开始下一处。  
4. **魔法套选**：支持补选 / 减选 / 调整边缘，仍归属于当前区域。  

### 11.7 提交规则
1. 局部修改提交时，应提交：
   - 原图  
   - 多个区域的选区信息  
   - 每个区域对应的文字修改要求  
2. 生成一个新的图片版本，不覆盖原图。  
3. 失败时保留全部选区和对应提示词。  
4. 选区重叠或提示冲突时应提示用户处理。

## 12. PSD 分层能力升级（核心）

### 12.1 当前问题
现有方案仅能：
- 通过粗糙视觉框 + GrabCut 得到主体/背景两层；
- 写出 PSD 文件；
- 无法满足“图片中多个元素个体分别成为图层”的目标；
- 无法在移除对象后自动补全被遮挡背景。

### 12.2 新链路确定
本轮 PSD 分层能力采用：

> **SAM + GPT Image 2.5 + PSD**

#### 角色定义
- **SAM**：
  - 对象级分割  
  - 魔法套选  
  - 多对象候选图层生成  
- **GPT Image 2.5**：
  - 被遮挡背景补全  
  - 局部编辑  
  - 补洞 / 修边  
- **PSD 封装**：
  - 接收独立图层  
  - 组织图层顺序、命名、透明度  
  - 输出 PSD 文件  

### 12.3 核心目标
#### A. 对象级独立图层
尽量将图片中的元素个体分别输出为独立图层，例如：
- 猫  
- 沙发  
- 抱枕  
- 杯子  
- 茶几  
- 其他可识别物体  

#### B. 背景透明图层
每个对象图层自身背景透明。  

#### C. 自动补全被遮挡背景
当对象被提取为独立图层后，底层背景不得直接留空洞。  
例如：
- 移除猫后，应自动补出完整地毯；
- 移除杯子后，应自动补出后方桌面。  

### 12.4 处理流程建议
1. 原图输入  
2. SAM 自动生成多个对象候选  
3. 用户可在分层预览中确认 / 删除 / 合并 / 补充对象候选  
4. 对每个对象生成独立透明图层  
5. 逐对象执行背景补全：
   - 将对象移除后，以 mask 向 GPT Image 2.5 请求底层背景补全  
6. 形成：
   - 背景底板图层  
   - 多个独立对象图层  
7. 组织为 PSD 并导出  

### 12.5 质量要求
1. 不接受只有“背景 + 一个主体”两层。  
2. 不接受简单重复整图、矩形切片或空白占位图层。  
3. 不接受按钮可点但实际不执行。  
4. 不接受仅在程序内部预览，而无法成功导出 PSD。  

### 12.6 需要保留的底层能力
可以保留现有：
- 文件读写  
- 图层写入  
- PSD 封装逻辑  

需要替换 / 重做的部分：
- 对象发现  
- 对象分割  
- 多图层组织  
- 自动补洞背景  
- 分层预览 UI

## 13. PSD 页面 / 交互要求

### 13.1 分层预览
用户选择“分层 PSD”后，应看到：
1. 原图预览  
2. 背景图层预览  
3. 对象图层列表  
4. 每个图层的缩略图、图层名称、显示/隐藏状态  
5. 合成预览区  

### 13.2 支持的操作
1. 删除某个候选图层  
2. 重命名图层  
3. 调整图层顺序（如已有能力则做；如首版不做则明确说明）  
4. 对某个图层再次进行细修选区  
5. 查看单图层透明效果  

### 13.3 导出要求
1. 导出 PSD 前应有预览确认。  
2. 导出后 PSD 必须可在 Photoshop 中打开。  
3. 至少验证：
   - 图层存在  
   - 图层透明背景正确  
   - 图层顺序正确  
   - 背景底板完整

## 14. 研发实施建议顺序

### 阶段 A：确定性修复（优先）
1. 生图页按钮与输入区优化  
2. 删除任务类型卡片  
3. 图片滚轮缩放  
4. 提示词中心左右独立滚动  
5. 提示词示例图加载与预览  
6. 分页与收藏修复  
7. 参考图点击预览  
8. 每周自动更新提示词库  

### 阶段 B：参考图与局部修改打通
1. 删除参考图合同验证拦截  
2. 真正接通参考图生成请求  
3. 局部修改多区域、逐区域提示词  
4. 接入矩形框选、画笔、魔法套选  

### 阶段 C：PSD 分层升级

## 16. 风险与边界
