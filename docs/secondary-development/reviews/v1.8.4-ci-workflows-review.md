# v1.8.4 升级后 GitHub CI 工作流只读审查

审查日期：2026-10-05。请求：检查各项升级后当前项目 GitHub CI 工作流是否正确。本轮使用项目二次开发 Skill 的 Review 流程，包含独立只读 Reviewer；未进入源码修复或发布阶段。

结论：现有发布门禁和配置回归未发现本轮导致的失效，但不能认定“全部升级后的 CI 已正确并通过”。确认 1 项 P1、2 项 P2；P1 属于尚未合入的本地 PPT/资源改动与现有工作流之间的兼容阻塞，当前 GitHub 没有发生该失败的运行记录。

## 一、审查发现

### CI184-F01 / P1：合入当前 PPT 改动后，干净 Windows runner 缺少两端必需的运行包

- 当前本地 `client/package.json:37`、`management/package.json:36` 设置 `beforePack`，分别执行 `scripts/verify-ppt-runtime.cjs`。
- `.gitignore:267–268` 忽略两端 `vendor/ppt-runtime/`；`git ls-files 'client/vendor/ppt-runtime/*' 'management/vendor/ppt-runtime/*'` 为空。
- `.github/workflows/release.yml:186–243` 只安装客户端依赖、准备 Agent 工具、重建 native、构建 Renderer，随后打包；没有 PPT 运行包准备步骤。`postinstall` 也只重建 Electron native。
- 管理端独立 job 在 `release.yml:576–600` 只安装管理端依赖、测试、生成临时凭据、同步版本并执行 `dist:win`；新 `management/scripts/build-win.cjs` 同样不会准备 PPT 运行包。
- 在本轮新建的隔离空 `appDir` 上直接调用真实 `beforePack`：客户端退出 1，报“缺少受管运行组件或 Windows 隔离器”；管理端退出 1，报缺少 `host-tools/pptRuntimeService.cjs`。未移动、删除或清空已有 vendor、工作区、数据与构建产物。

影响：当本地 PPT 改动进入被选中的客户端 tag/管理端 ref，且发布采用新构建模式时，干净 runner 将在打包阶段失败。已有正式客户端的 skip、管理端完整 Draft 的 resume 不执行新构建，不能验证这个条件。此前本地 NSIS 成功使用的是已准备的 ignored 运行包。

最小修正方向：在两个实际构建 job 的打包前，分别准备固定版本运行包并执行完整性校验；下载必须保留锁定 URL/hash 和失败门禁。管理端 `--management` 目标只准备自己的预览运行包。当前准备脚本位于客户端，`client/scripts/prepare-ppt-runtime.cjs:5` 需要从客户端路径解析 `adm-zip`；管理端 job 仅 `npm ci management` 不能满足此依赖。必须明确解决准备器的依赖安装与解析，不能直接追加一条跨目录调用便声称可复现。

### CI184-F02 / P2：客户端升级回归没有进入现有 CI 门槛

- `release.yml:167–175` 的七文件测试覆盖发布脚本、Worker 更新协议与包配置；`release.yml:188–190` 只运行 `test:update`，后续烟测覆盖 Electron native。
- GitHub main、远端功能分支和本地的 `client/package.json:22–23` 都提供 `test:pi-upgrade`、`smoke:pi-upgrade`，工作流均未调用。
- 当前本地新增 PPT、页关联、Skill 引用、业务与资源客户端回归也没有进入现有工作流。管理端已有 `npm test` 会发现新增 `resourceCenter.test.cjs`，不能等价覆盖客户端 SDK/IPC/包内链路。

影响：应用 1.8.4/Pi 1.0.0 已进入 GitHub main，工作流仍只能证明原有发布门禁，不能自动阻止这些升级链路的回归。此项已经适用于当前远端 Pi 代码；PPT 覆盖部分适用于未来合入本地实现后。

最小修正方向：接入适用的离线真实 SDK/模拟供应商回归；真实 Electron、包内验证分开记录。真实外部模型、独立安装和人工 UI/Office 验收保留对应授权/环境门槛，不能自动调用收费模型或绕过授权。不因缺少普通 push/PR CI 而把发布工作流改成自动发布。

### CI184-F03 / P2：部分新增验收脚本依赖本机临时证据，不能直接接入干净 CI

- `client/scripts/ppt-template.test.cjs:9` 固定读取 ignored `.tmp/ppt184-resource-center/baseline` 的两个真实 PPT 样本。
- `client/scripts/ppt-ui-electron-smoke.cjs:6–7` 固定读取此前随机目录 `preview-electron/清理复验-iKbcI9` 和 `public-source/实际提示词-sDeT4a`。

影响：这些脚本保留了本地验收证据，但空 checkout 没有输入数据；直接加入 CI 会先因夹具/证据缺失而失败。当前工作流尚未运行它们，所以此项是本地升级测试的 CI 可复现缺口，不是已发生的 GitHub job 失败。

最小修正方向：提供公开、固定 hash 的测试样本准备流程，或生成合成夹具；对必须使用真实公开样本的验收保持来源及页级证据。把前置结果路径设为显式参数，或串联本轮生成结果。不得上传生产资料、凭据或整份员工工作区来代替夹具。
