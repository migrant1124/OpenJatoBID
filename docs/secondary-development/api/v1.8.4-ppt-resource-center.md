# v1.8.4 PPT 与资源中心：已确认实施契约

本文件细化 D1.2 的技术接口，不改变规格、授权规则或用户操作边界。用户已确认 tasks/plan.md 第28节，源码实现、Debug修复及本地分层验证已执行；当前为最终Review/交付。以下为实际实施契约，验收范围以原始证据、测试报告及 `tasks/todo.md` 为准，不能据接口存在将未执行场景记为通过。

## 1. 身份、版本和通道

- 管理端继续原47821监听与授权/统计接口；资源独立前缀 `/api/resource/v1`，不依赖EXE版本数相等。
- 资源协议版本 `1`；管理端实例/issuer、资源流、中心、稳定ID、不可变发布序号、内容hash分别表示身份，不混用软件1.8.4或检查时间。
- Main 使用已信任管理端地址和授权身份；资源短期凭据由管理端验证现有签名授权、设备及ACTIVE/到期/撤销状态后签发。不接受只报licenseId、不复用管理员登录、不以资源通道修改授权库。
- 签名按现有P256序列化/信任体系核验，明确payload用途、有效期与设备；公钥来自既有绑定的管理端信任，不信任下载包自己携带的公钥。读取许可、票据及代理凭据均不进入Renderer或日志。
- 公共上游请求仅管理端资源下载器，限定启用来源、允许主机、固定提交及资源依赖，逐跳验证公网目的地；LAN客户端独立实现，不放宽 `assertPublicUrl`。
- 代理只用于管理端公共资源下载会话；LAN、既有模型及软件更新网络配置不随之修改。

## 2. 资源身份与状态

共同字段：`resourceId`、`sourceId`、`upstreamId`、`center`、`kind`、`contentHash`、`sourceRevision`、`publishedVersion`、许可/来源、状态。模板保留真实模板类型、页数、画幅、能力检测和报告绑定；不由后缀或来源名生成验证结论。

文件描述：`assetId`、`resourceId`、不可变资源/文件hash、实际或未知长度、MIME、页索引、实际宽高、preview生成器版本、镜像状态。客户端只传这些受管ID，不传任意下载URL/本地路径给HTTP资源接口。

目录可带待准备条目，但必须分别表示目录、原包、首页、全页图、依赖、适用验证的状态。`mirrored`、`preview_ready`、`native_reuse_verified`不能互相推导。资源失败沿用上一个可用版本，错误和待下载新候选另列，不把候选覆盖可用版本。

## 3. 管理端 API

| 请求 | 响应 / 责任 |
| --- | --- |
| `POST /session` | 现有可信许可与设备验证后返回有用途/范围/期限的资源票据；未授权/已撤销拒绝 |
| `GET /catalog?version=&center=&offset=&limit=` | 授权范围内不可变分页目录、协议、管理端实例、发布版本、总数/页及签名/完整性信息 |
| `GET /digest?from=&to=` | 可比可信基线到已发布版本的稳定ID最终差异；新增/更新/下架、整套/单页及真实准备状态 |
| `GET /assets/:assetId?version=` | 已镜像实际文件，按票据、资源版本和已发布记录解析；长度、hash、Content-Type、ETag、Range/206；不允许任意path/url查询 |
| `POST /requests` | 限定已有受管资源ID/版本请求准备；幂等、只准备该资源；不触发员工全库扫描、不执行新Skill |
| `POST /repository-requests` | 尚无资源ID的Skill仓库定位申请：GitHub owner/repo、ref或完整commit、Skill子目录与本次用途；由管理端限定GitHub入口解析成固定commit，不接受任意下载URL |
| `GET /repository-requests/:requestId` | 请求者范围内读取待管理员准入/解析/下载/检查/待确认安装/失败状态、固定commit与受管候选ID；不是通用仓库文件读取接口 |

仓库入口由客户端Main解析用户GitHub链接为定位字段，实际网络和ref解析只在管理端。已获准来源按准入范围处理；新仓库先经管理端管理员准入，不自动把员工请求加入全局启用源。固定commit、规范子目录和完整Skill根必须同时留存；拒绝跨仓库重定向、路径越界或用subdirectory当任意URL。请求幂等且只读准备相应Skill，不执行上游安装/lifecycle脚本。管理端取得完整候选后核对资源完整性、许可、依赖和权限，保存受管ID/不可变hash并用既有可信管理端签名发布候选清单。客户端校验签名/hash，再显示安装确认；下载、安装、启用和执行仍分离。候选不可用或需要管理员批准时如实等待，不退回客户端GitHub直连。T-S01覆盖此前未登记仓库的完整申请到安装路径；不只测试已有ppt-master ID。

协议不兼容返回中文受限原因；目录版本或页不一致整批不应用。错误区分未连接、未授权、不兼容、待镜像、文件不可用、范围不合法、校验失败/配额不足，不能以空数组或200空文件掩盖。

轻量目录/提示词正文先应用；PPTX/预览/Skill按用获取。流式下载有独立并发、字节/空间限额，SQLite短事务，避免阻塞授权/统计。`.part`续传验证ETag、实际hash/类型后rename；取消/重启保留可解释临时状态。

## 4. 固定周锚点与发布

- `period_ms = 604800000`是服务常量，不是配置字段；管理员IPC/UI只读显示。首次启用写 `anchor_at`，立即检查；定期下次锚点为anchor加整周。
- 未处理到期时启动/resume补一次当前观察；跳过历史missed次数，把下次计划推进到未来。手动检查/资源重试更新检查结果但不改anchor/定期游标。
- 每源单一在途任务；同次网络抖动、页面点击或唤醒不重叠；时钟倒退不虚报检查，时钟前进只补一次。托盘继续，退出服务不承诺后台运行。
- 周检查ETag/Last-Modified/固定提交与实际sha，已校验同hash资产复用；内容相同只记检查。变化摘要基于规范业务字段，不含下载地址、排序、JSON空白、检查时间或无关README提交。
- 写受控暂存 → 字节/类型/结构校验 → 文件就绪 → 不可变快照+差异+发布记录+活动指针事务；读者不读stage。崩溃恢复不会留下有摘要无文件或重复逻辑发布。
- 单项失败保留旧成功资源；独立项可发布。异常空/骤减或无效目录先失败审计，不自动全库下架。真实下架阻止新引用，已锁项目资源保留。

## 5. 客户端应用、展示和缓存

- 游标范围是用户+设备+管理端实例/资源流+中心；`appliedVersion`与`shownVersion`分别持久化。设备/管理端改变或历史不可比时初始化可信基线，不编造累计。
- 启动/重连同步去抖，不让每个客户端触发上游检查；下载校验完成后SQLite事务更新公共目录与applied；错误不推进。
- 首次无基线建立当前基线并用初始化文案，不把全库当新资源。已有基线按稳定ID比较最终可见状态，新增后撤销等合并不累加每批计数。
- C07绑定固定起止版本，规则中文摘要、两个中心及实际精选图；图未就绪如实提示/重试。正文可见渲染成功才推进shown，进程退出前未展示保留下次提醒。
- 会话最多自动显示一次；后续更新保留徽标/历史入口到下次会话；输入/生成/导出/确认/离开保护期间延期。手动回看不重置自动会话机会，不擅自离开项目。
- 缓存key包含管理端流、resourceId、源文件hash、asset/preview hash、page index、generator version；`.part`不作为图片成品，文件存在也要hash和解码验证。
- Renderer只收本地`yibiao-asset`或可信管理端受管地址，不能把上游coverUrl直接塞img；本地协议仅解析缓存索引登记文件。可见区懒加载/分页、有界缓存，项目引用锁版本。

| 新 `yibiao.ppt` | 项目/资料、稳定页/元素修订、规划确认、模板路由、候选接受/取消/恢复、生成/编辑/导出/迁移/删除；有写锁和revision检查 |

## 7. PPT / Skill 的权威文件与权限

- 原生路线用真实源PPTX的roundtrip工作区与对象/关系映射；生成/视觉参考路线用ppt-master的SVG源与原生DrawingML导出。SQLite只记项目/索引/修订/任务/引用，不再独立编辑完整页面JSON。
- stable slideId/elementId + baselineRevision → 独立候选 → 结构/字体/溢出/数据与预览检查 → revision一致才原子提交。手动写与Agent互斥；无关页原文件/hash保持；取消只取消候选。
- 原生报告绑定模板/adapter/runtime/字体/hash及测试覆盖；视觉参考报告绑定真实预览/新事实/模型能力与原生输出。全页截图加文字叠加永不当作还原通过。
- PPT profile单独限定项目文件、批准Skill版本/脚本及已授权媒体工具；普通对话保持read/find/ls和off、不自动MCP/Codemode/外部Skill加载。
- 工作目录不当沙箱。批准脚本在受限进程运行，限制真实路径、文件、网络、环境和子进程；仅业务控制层访问模型/管理端资源，worker不继承Main全环境或密钥。运行库包锁与完整性不满足时拒绝该动作。
- 四类Skill入口均先解析资源与依赖/许可/权限，多技能ZIP选择、hash幂等、版本锁；下载/安装/启用/执行分开。卸载只删归属副本，引用版本保留，用户原ZIP/文件夹不动。
- 新项目所选目录建独立归属子目录。实际系统卷与realpath目标卷核对，允许“仍然使用”；旧项目迁移另行确认、停写、复制校验、索引切换，失败原稿保留。删除先回收站，不递归删除用户选中的父目录或外部原文件。

## 8. 预览执行面的隔离

预览和脚本worker是两个边界。PPT/SVG/HTML/网页输入不直接进入带业务preload的主页面，也不加载上游提供的任意编辑器脚本。可信编辑UI只发送受控对象编辑/批注命令，交由PPT业务层的revision/写锁/候选提交；预览页本身无Node、文件、Electron/业务IPC、主会话Cookie或模型凭据。

对显示内容先在拥有导入/预览的层解析并规范化：阻断script、on*事件、foreignObject嵌入执行、javascript/file/危险data URL、外部href/图片/CSS url和@import；页面图片只能引用已登记并校验的受管资源，不能因PPT外部关系主动联网或读磁盘。模板HTML/网页以允许的静态结构显示，脚本原文不执行，失败明确报原因，不把修复提示当预览成功。

独立预览context使用sandbox、contextIsolation、nodeIntegration=false、webSecurity、独立无业务凭据session或等价受限iframe；CSP禁未授权script/connect/frame/object，图片和字体仅允许明确的受管资产。默认不允许导航、弹窗、下载、权限申请或任意网络/文件URL；request拦截覆盖重定向。可信宿主编辑代码与不可信显示内容隔离，使用明确消息白名单/目标和项目修订，不给iframe任意Main调用。ppt-master live-preview本地服务如需保留，只提供项目归属资产与已批准操作，不开放任意路径写入或外网代理；未完成隔离审计前不启用该执行面。

测试用恶意SVG/HTML、脚本/事件、foreignObject、嵌套iframe、外部图片/CSS、file和javascript URL、重定向、弹窗、伪造编辑消息及越界写入，检查实际网络/磁盘/IPC副作用为零；正常受管图、缩放、选元素、批注、候选应用仍通过。仅用图片截图验收不能替代执行面测试。

## 9. 兼容与撤回

新增表/字段采用现有备份迁移路径，不降低授权库校验；客户端已迁移来源不在重启被旧seed覆盖。双方旧资源协议不兼容时保留原授权、已有缓存和旧业务。

只撤本轮代码/新增元数据需另行用户授权；先对比开始时用户输入/任务/源码hash和后续修改。迁移库保留前镜像，新项目/资料不删，已创建用户数据不能通过降schema或reset回旧HEAD撤销。具体步骤见任务计划28.7。

## 10. 最终实施补充（2026-10-05）
