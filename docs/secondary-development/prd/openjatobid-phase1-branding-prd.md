# OpenJatoBID 第一阶段二开 PRD：品牌重塑与基础产品整理

版本：1.0.1  
日期：2026-07-10  
PRD 存放目录：`docs/secondary-development/prd/`  
测试报告存放目录：`docs/secondary-development/test-reports/`

## 1. 背景与目标

OpenJatoBID 基于成熟开源投标工具进行二次开发，当前主流程已经可以基本生成投标技术文件：

上传招标文件 -> 解析招标文件 -> 生成目录 -> 设定全局事实 -> 生成/编辑正文 -> 导出 Word。

第一阶段目标不是重做主流程，而是将现有客户端整理为佳图数科内部使用的品牌化版本，优先完成用户可见品牌、版权信息、安装包识别、Logo/Icon 资源和基础产品入口整理。

## 2. 本阶段范围

- 用户可见品牌从原项目品牌统一改为佳图品牌。
- Electron 安装包、快捷方式、开始菜单、任务栏等系统识别信息改为 `Jato AI BID`。
- 替换 Logo，生成并替换 Windows `.ico` 与 macOS `.icns`。
- 关于页面改为公司版权、版本号、英文公司名与用途描述。
- README 与公开文档替换为 `Jato AI BID` 内部版本说明，分为“使用说明”和“开发说明”。
- GitHub 更新源切换为 `migrant1124/OpenJatoBID`，Cloudflare R2 链接从更新源中删除，本阶段不接入新的 R2 更新源。
- 隐藏明显非必要入口，但保留源码模块。
- 保持现有核心投标文件生成能力可用。

## 3. 不在本阶段做的事情

- 不改主流程业务逻辑。
- 不重构 `technical-plan`。
- 不改 `window.yibiao`。
- 不改 `yibiao.sqlite`。
- 不改 IPC 通道名。
- 不改 OpenCode Agent 运行机制。
- 不开发 analytics 管理端。
- 不接入新的 Cloudflare R2 更新源，不搭建新的下载镜像或 CDN。
- 不删除源码模块。
- 不做全仓库 `yibiao` 搜索替换。
- 不把阶段重点扩展为废标、敏感词、风控或大重构。

## 14. 功能流程

核心业务流程保持不变：

上传招标文件 -> 解析招标文件 -> 生成目录 -> 设定全局事实 -> 生成/编辑正文 -> 导出 Word。

品牌化后的入口流程：

启动 `Jato AI BID` -> 进入首页/主界面 -> 看到保留的一级 Tab -> 进入对应二级功能 -> 完成原有投标文件生成或资料管理操作。

## 16. 风险与注意事项

- `productName`、`appId`、`userData` 会影响安装后系统识别和数据目录；本阶段已确认允许新品牌使用新的用户数据目录。
- 图标生成需要保证多尺寸质量，避免 Windows 安装包、任务栏或 macOS Dock 显示模糊。
- 隐藏入口不能误伤核心流程；隐藏只处理导航可见性，不做源码删除。
- README 替换时要避免把第一阶段描述成完整商业化发布或对外开源发布。
- 关于页不展示授权证明，但内部应保留授权材料。
- 删除 Cloudflare R2 更新源后，第一阶段更新下载依赖 GitHub Releases；如公司网络环境访问 GitHub 不稳定，需在后续阶段单独规划新的 R2/CDN 更新源。
