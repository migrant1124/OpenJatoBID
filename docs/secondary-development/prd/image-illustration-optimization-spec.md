## 1. 背景与目标

当前技术方案已能根据目录、正文、评分项、价值锚点和全局事实形成全文图片计划，并分别生成 HTML 图与 AI 图；但计划完成后通常直接进入生成，用户不能在生成前筛选或调整计划，且已有规划字段没有完整传递至实际生成提示词。

本次优化的目标是：让配图在生成前可确认、可精简、可调整，并使实际图片更准确响应章节、评分项和视觉作用；同时保持正文完整性、事实约束、既有质量 Gate、OpenCode、配图定位和 HTML 布局质量检查。

## 2. 已确认范围

### 2.1 配图规划确认（P0）

正文完成且全文图片计划生成后，系统进入“图片编排确认”子阶段。它属于现有正文生成流程，不新增顶层步骤或独立菜单。

确认窗口顶部应展示本次计划的只读汇总：预计生成图片数、HTML 图片数、AI 图片数、当前图片配额剩余数，以及目录字数控制中的最低字数阈值。最低字数阈值仅用于让用户理解当前生成目标，始终读取目录配置快照；不在此处提供编辑入口，也不恢复正文生成配置中的最低字数控制。

确认窗口应展示每张计划图片的：

- 是否生成（默认全部勾选）；
- 插入章节和正文锚点；
- 图片标题；
- 引擎类型（仅 HTML 或 AI）；
- 图表/图片具体类型；
- 配图目的和视觉作用；
- 关联评分项及价值锚点；
- 图片比例和优先级。

用户可取消任意图片、修改标题、切换 HTML/AI 类型，再选择：

- **取消**：退出本次确认，不开始图片生成，不改写正文；
- **保存计划**：保存筛选与修改后的计划，不开始生成；
- **确认并开始生成**：仅生成仍被勾选的图片，并继续既有插入正文流程。

当计划为空或用户取消全部图片时，应明确说明“本次不生成配图”，并允许继续完成正文流程。

### 2.2 规划字段必须进入实际生成（P0）

HTML 与 AI 的实际生成提示词均须使用已确认计划中的下列信息，而不是只使用标题和章节正文：

- `visual_role`（视觉作用）；
- `purpose`（配图目的）；
- `aspect_ratio`（比例）；
- 关联评分项与价值锚点；
- 章节、正文锚点与相关事实；
- 图表/图片类型；
- 全文视觉风格。

计划被用户修改后，生成应以保存后的计划为准。无关联评分项或价值锚点时允许为空，不得编造关联关系。

### 2.3 图像引擎分工（P0）

本项目只保留 HTML 图与 AI 图。

| 内容特征 | 首选引擎 | 规则 |
| --- | --- | --- |
| 中文标签、数字、人员关系、流程节点、需要逐字准确的信息 | HTML | 图表文字必须可读、可控。 |
| 流程、时间轴、矩阵、鱼骨、组织架构、循环、金字塔等结构化表达 | HTML | 使用统一模板规范与既有截图质量检查。 |
| 场景效果、空间概念、品牌氛围、写实或概念示意 | AI | 不承担必须逐字准确的中文图表。 |

用户在确认窗口切换类型时，系统仅提供符合该类型允许范围的图表/图片类型；无法满足引擎约束时应提示用户改选合适类型或取消该项。

### 2.4 全文视觉风格（P0，新增 UI）

确认窗口提供“全文视觉风格”预设选择。一次正文生成只使用一个视觉风格，应用于该次 HTML 与 AI 配图，保证全文一致而不与具体项目主题冲突。

系统在全文图片编排完成后，基于正文主题、项目性质和已确认的配图计划，从下列预设中推荐一个视觉风格；不设置默认风格。确认窗口初始展示 AI 推荐结果，用户仍可在下拉菜单中改选其他风格。推荐失败或计划为空时，不强制选择风格，也不阻止用户继续完成无配图正文流程。

首版提供以下预设。HTML 图以主色、强调色、中性色和白色背景构成；AI 图继承氛围、主辅色与材质倾向，不强制生成品牌标识或虚构标志。是否使用渐变由 AI 根据图表类型、内容和视觉效果自行判断，生成规则与质量检查均不对渐变作限制或检查。

### 2.5 保留并强化 HTML 图质量规则（P0）

继续保留现有 HTML 生图截图检查与自动返修能力，至少覆盖：文字倒置、文字旋转、镜像、文字/元素叠压、前景遮挡、截断、画布越界、缩放变形，以及固定/粘性布局异常。

竖排文字明确允许，不视为文字旋转，不触发修复。质量检查失败时继续遵循现有的保留 HTML 源码、不保存不合格 PNG 的处理规则。

### 2.6 视觉节奏诊断（P1）

在图片计划阶段增加诊断性提示，用于辅助确认，不以页码或固定图片数量强制生成。诊断包括：

- 高评分章节是否缺少有效配图；
- 是否存在过长的纯文字内容块；
- 同一章节是否配图过密；
- 是否连续出现相同视觉作用；
- 开篇、核心实施章节、保障章节是否获得合理覆盖。

诊断只给出可理解的提示和建议，不自动新增图片、不自动删除图片，也不使用“前几页必须有图”或“连续几页必须配图”的规则。

### 2.7 HTML 标准化图表模板（P1）

为 HTML 生成规则补充流程图、时间轴、矩阵、鱼骨图、组织架构图、循环图和金字塔图的构图约束。模板只约束信息层级、标签长度、留白、对齐、配色和可读性；仍通过现有 HTML 渲染与质量检查生成最终图片。

金字塔图的配色与其他图表一样，由 AI 结合内容和视觉效果决定。

### 2.8 图文衔接与图号（P1）

配图插入正文后：

- 按章节自动编号，编号稳定且在重新生成后可正确更新；
- 生成图注，包含图片标题；
- 仅在确有必要时补充图后说明，说明图中信息如何响应当前章节要求；
- 图后说明基于原正文和已确认事实生成，计入正文字数，不得为凑字数重复正文；
- 不新增“图前引导语”。

### 2.9 AI 图片视觉复核（P1）

在具备合适视觉模型后，对 AI 图检查异常中文、虚假 Logo、虚构人员/证书/设备/客户、风格不一致、主体裁切及构图失衡。

## 3. 明确不做

- 不根据图片数量或图片内容自动删减、压缩或替代正文。
- 不强制使用特定图像模型、地区化规则、固定样本数量或竞争对手比例。
- 不强制每张图片生成多个候选，也不新增候选数量、预计耗时或调用成本设置。
- 不让 AI 图承担需要逐字准确的中文图表。
- 不允许 AI 图生成真实姓名、证书编号、精确业务数据、客户案例、场地或品牌等未经事实支持的信息。
- 不覆盖或弱化既有质量 Gate、OpenCode、配图定位、人工编制保护、正文完整性与 HTML 布局检查。
- 不使用 Word 最终页码作为配图节奏规则。

## 4. UI 参考基线

本次 UI 新增“图片编排确认”对话框、全文视觉风格预设选择及只读汇总区域。用户已选定本次需求评审中的高保真参考图，作为弹窗结构、汇总字段、下拉菜单、表格结构、固定底部操作区和视觉风格的实现基线；不实现其中的“最小图片比例”字段。

界面应遵循现有客户端的全局 CSS、Radix 基础组件、中文文案与内部滚动约束；长计划在对话框内容区滚动，标题、汇总信息和底部操作区保持可见。

## 5. 验收标准

1. 全文图片计划生成后，在任何实际生图前都能看到并操作配图确认窗口。
2. 用户可以默认全选、取消单项、修改标题、切换 HTML/AI 类型，并能保存后再次打开保持结果。
3. 取消全部项目后，正文仍可完成，且不会生成或插入任何图片。
4. 系统基于全文内容与图片计划推荐一个视觉风格，但不设置默认风格；用户可改选。已确认的视觉作用、目的、比例、评分项、价值锚点、锚点和最终视觉风格均会进入对应 HTML/AI 生成上下文。
5. HTML 质量检查仍会识别倒置、旋转、镜像、叠压、遮挡、截断、越界、缩放和固定定位问题；竖排文字不触发修复。
6. 视觉节奏只产生建议，不因页数或固定数量强制新增/删除图片。
7. 自动图号、图注和必要图后说明均不虚构事实；图后说明计入正文字数且不重复堆砌。
8. 渐变既不作为生成限制，也不作为 HTML 或 AI 图片质量检查项。
9. 原有正文质量 Gate、补目录、扩写、人工编制保护、OpenCode 与配图定位回归正常。
