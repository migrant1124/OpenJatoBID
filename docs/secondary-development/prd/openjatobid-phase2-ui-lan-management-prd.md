## 1. Executive Summary

第二阶段在不调整现有用户端布局、导航结构、业务流程和功能位置的前提下，将 `Jato AI BID` 的全局视觉语言替换为 Ant Design v6 风格，并同步完成模型配置文案、API 获取链接和关于页隐私声明调整。同时，新建一个与用户端完全独立的 Windows 管理端软件，将现有公网 Analytics 与授权链路迁移到局域网服务器：员工在用户端输入姓名、手机号和服务器 IP 发起设备授权申请，管理员审批后获得一年授权；授权按员工与设备绑定，每名员工最多绑定 3 台电脑，并至少每 30 天完成一次局域网校验。

管理端采用单管理员、人防保管模式：软件提供一组内置初始管理员凭据，由公司负责人掌握并完成首次登录；首次登录必须修改密码，之后可在已登录状态下使用当前密码主动改密。管理端不提供管理员注册、忘记密码、邮件临时密码或其他自助恢复入口。同一公司局域网只部署一个管理端，安装包、初始凭据和服务器不得对外分发或带离公司；该部署边界由公司负责人和内部制度保障，不宣称由软件技术手段绝对阻止。

本阶段的核心结果是：用户端视觉统一但布局不变；授权入口清晰、可管理、可撤销；现有埋点统计能力在局域网管理端等价保留；客户端的埋点和授权请求不再访问 `analytics.agnet.top`。

## 2. Problem Statement

### 2.1 谁遇到了问题

- 佳图数科内部使用 `Jato AI BID` 制作投标文件的员工。
- 负责软件授权、设备管理、使用统计和 AI 资源消耗管理的内部管理员。
- 负责在局域网服务器部署和维护管理端软件的运维人员。

### 2.2 当前问题

1. 用户端现有布局可继续使用，但视觉风格不符合期望，需要在不扰动工作流的情况下统一升级。
2. 文本模型和生图模型页面仍带有“金龙中转站【推荐】”字样，API Key 获取入口也不是新的指定地址。
3. 当前隐私声明仍描述 Cloudflare 公网匿名埋点，与新的内部专属、局域网管理模式不一致。
4. 当前授权和 Analytics 依赖 `analytics.agnet.top`，管理员无法在公司局域网内直接审批员工、限制设备数量、撤销授权或统一查看本地统计。
5. 当前授权提醒以在线刷新/离线文件激活为主，不符合“员工提交身份和设备申请，管理员审批后使用”的新流程。
6. 已实现的 SMTP 邮件临时密码方案要求部署人员自行填写发件邮箱，并依赖固定外部收件邮箱完成恢复；该方案扩大了管理端外部运行和凭据传递边界，已被用户明确否决。

### 2.3 影响

- **员工影响**：视觉体验不统一；授权方式难以理解；设备更换、到期、撤销和离线校验缺少明确反馈。
- **管理影响**：无法按真实员工与设备建立授权关系，无法执行每人最多 3 台设备的规则。
- **运维影响**：授权和统计依赖公网系统，不符合局域网集中部署目标。
- **隐私影响**：产品真实数据流与界面隐私说明可能出现不一致。
- **管理端控制影响**：若继续保留自行配置 SMTP 和邮件找回，管理端负责人无法通过简单的人防制度控制凭据边界和部署范围。

### 2.4 现状证据

- 用户已明确要求保留现有布置，只替换视觉样式。
- 当前用户端以全局 CSS、Radix 基础组件和 `--yb-*` 视觉变量实现界面；布局由侧栏、主内容区、功能页和浮动工具条组成。
- 当前用户端的 Renderer、AI Main 服务和 OpenCode Runtime 均存在对 `https://analytics.agnet.top/track` 的埋点发送。
- 当前授权服务默认访问 `https://analytics.agnet.top/license/activate`，并已具备设备指纹、本地授权文件和签名校验基础。
- 当前 Analytics 管理端已覆盖客户端、访问、配置、模型用量、Token、Agent 运行、最近事件和留存等统计能力。
- 用户已明确选择由公司负责人保管管理端安装包和内置初始凭据，同一局域网只部署一个管理端，并接受外部运行风险主要由人防而非技术封锁承担。

## 3. Target Users & Personas

### 3.1 主要角色：内部投标员工

- **目标**：打开软件后快速获得授权，继续使用现有投标工作流。
- **行为**：在固定办公电脑上使用软件；偶尔更换或新增电脑；可能短期离开局域网办公。
- **痛点**：不希望注册账号或创建密码；希望授权状态、审批结果和失败原因清楚可见。
- **核心任务**：输入姓名、手机号、服务器 IP，提交当前设备申请，获得授权后进入原有客户端。

### 3.2 主要角色：公司负责人 / 软件管理员

- **目标**：在一套独立管理软件中审批员工设备、控制有效期、撤销授权并查看统计。
- **行为**：掌握管理端安装包和内置初始凭据，在指定局域网服务器上完成唯一管理端部署；首次登录后立即修改密码；日常处理待审批申请和查看运营数据。
- **痛点**：不希望继续依赖公网 Dashboard 或外部邮箱找回密码；需要知道每名员工已经绑定哪些电脑、授权何时到期、最后何时校验。

### 3.3 次要角色：服务器运维人员

- **目标**：完成管理端首次安装、端口/防火墙配置、数据备份和故障恢复。
- **行为**：负责 Windows 服务器和局域网连通性，不参与日常投标业务。

### 3.4 Jobs-to-Be-Done

- 员工希望不创建账号密码，只用真实姓名和手机号申请当前电脑的使用权。
- 管理员希望在公司局域网内确认“谁、在哪台电脑、使用到何时”，并可随时撤销。
- 管理员希望在不接触投标文件正文、API Key、Prompt 或生成结果的情况下，了解客户端活跃和 AI 资源消耗。
- 公司负责人希望只保管一套管理端和一组管理员凭据，不建立额外注册、邮件恢复或中心化账号系统。

## 4. Strategic Context

### 4.1 为什么现在做

- 第一阶段已完成品牌化与基础入口整理，第二阶段可在稳定布局上统一视觉语言。
- 产品被明确定位为佳图数科内部专属工具，需要将授权管理和运维统计收回公司局域网。
- 新隐私声明明确区分业务涉密数据与运维统计数据，产品真实链路必须同步调整。

### 4.2 业务目标

- 形成统一、专业、克制的内部产品视觉体系。
- 建立可识别到员工与设备的授权管理机制。
- 保留现有 Analytics 统计能力，同时停止客户端向现有公网 Analytics/授权地址发送相关请求。
- 降低员工使用授权的理解成本和管理员的设备管控成本。
- 通过公司负责人保管安装包、初始凭据和指定服务器，将管理端使用边界收敛为可执行的内部管理制度。

### 4.3 产品边界

- 用户端仍是 `Jato AI BID`，承载全部投标业务功能。
- 用户端继续保持当前 Windows 与 macOS 打包边界；本阶段新增的视觉和局域网授权流程应在两个用户端平台上保持一致。管理端仅要求提供 Windows 版本。
- 管理端是另一个独立软件个体，拥有独立安装包、可执行程序、进程、配置和本地数据。
- 管理端安装在 Windows 局域网服务器，主窗口关闭后缩至系统托盘，授权与埋点接收服务继续运行。
- 管理端不嵌入用户端，用户端也不提供隐藏的管理员入口。
- 同一公司局域网只允许部署一个管理端；这是公司内部部署规则，不要求软件扫描、识别或技术阻断其他网络中的副本。

## 5. Solution Overview

### 5.1 工作包 A：Ant Design v6 视觉体系迁移

#### 目标

保持当前页面布局、导航层级、信息顺序、业务流程、按钮位置和交互逻辑不变，只替换视觉表达。

#### 迁移原则

- 以用户提供的 Ant Design System v6 Community Figma 文件为视觉参考源。
- 继续使用现有 React、Radix 基础组件和全局 CSS，不引入 Ant Design React 组件库。
- 将现有 `--yb-*` 变量整理为语义化视觉令牌映射，覆盖颜色、字体、字号、行高、间距、圆角、边框、阴影和交互状态。
- 参考设计系统的紧凑桌面控制尺寸与层级：基础正文、标题、说明文字、32px 级常规控件、4/8px 圆角和清晰的主次按钮状态；这些值是视觉样板起点，不得为了套用令牌改变已经锁定的页面结构、内容密度或控件占位。
- 统一按钮、输入框、选择器、开关、标签、卡片、表格、弹窗、Toast、Tooltip、空状态、加载状态和滚动区域的外观。
- 不改变现有侧栏宽度、折叠方式、页面分栏、内容密度、浮动工具条位置和内部滚动方式。
- 新增的用户授权页和管理端软件使用同一套视觉语言。🔶 **Assumption：管理端也采用相同 Ant Design v6 视觉规范，以保持公司内部软件一致性。**

#### 覆盖范围

- 应用外壳：侧栏、品牌区、导航项、状态栏、内容容器。
- 全部当前可见业务页及其弹窗、提示、浮层和状态组件。
- 设置页及关于页。
- 新增用户登录页与授权申请弹窗。
- 新增 Windows 管理端的登录、授权、员工、设备和统计页面。

#### 视觉交付物

- Figma 组件/令牌到本项目语义令牌的映射表。
- 现有 CSS 硬编码颜色、渐变、阴影、圆角和控件状态审计清单；布局尺寸单独标记，未经确认不得改动。
- 用户端页面、弹窗、浮层、Toast、Tooltip、开发者模式页面和管理端页面的覆盖矩阵。
- 固定视口、固定数据状态的改造前后截图基线，用于逐页视觉回归。
- 至少先完成一个包含导航、表单、卡片、弹窗和 Toast 的视觉样板页，确认后再批量迁移其余页面。

#### 明确不改

- 不重排页面。
- 不新增或删除现有业务功能。
- 不修改主导航和二级菜单结构。
- 不因视觉迁移改变技术方案、知识库、查重、废标检查、模板或导出流程。
- 不把现有 Radix 组件批量替换为 Ant Design React 组件。

### 5.2 工作包 B：模型配置文案与链接

文本模型配置和生图模型配置同时执行：

- 服务商名称从“金龙中转站【推荐】”改为“金龙中转站”。
- 金龙中转站的 API Key“获取”按钮跳转地址统一改为：
  `https://jlaudeapi.com/sign-up?aff=smj`
- 金龙中转站原有 Base URL、默认模型和调用方式不因本次文案修改而改变。
- 其他服务商的名称和 API Key 获取地址保持不变。

### 5.3 工作包 C：关于页隐私声明

关于页的隐私声明替换为以下批准文本；标题、编号和强调内容需要在界面中保持清晰层级：

#### PRIVACY 隐私声明

本软件为佳图数科**内部专属工具，仅限公司内部员工使用，禁止对外分发、外传、商用**。软件尽可能将业务数据处理留存于本地设备，仅采集运营运维必需的最小范围信息，严格区分业务涉密数据与后台运维统计数据。

**01 业务涉密数据零集中收集**

应用**不会向佳图数科局域网管理端上传、集中收集或存储**任何业务涉密信息，包含但不限于：

你自行配置的 API Key、本地导入的招标文件、解析后的全文文档、AI 生成的投标方案正文、本地导出文件、项目业务资料及所有业务产出结果；

全部业务文件、密钥、项目内容仅保存在员工本地设备；调用员工自行配置的第三方 AI 服务时，仅将完成当前任务所必需的内容直接发送给该服务商，不发送到佳图数科局域网管理端。

**02 AI 请求直连服务商，无中间中转留存**

使用 OpenAI 兼容接口、MinerU 或其他自行配置的线上 API 时：

完成文档解析、内容生成、模型调用所需的业务内容，仅从员工本地设备直接发送至员工自行配置的大模型服务商；

API 密钥仅在员工本地设备持久化保存，调用时作为鉴权信息直接发送给员工配置的第三方服务商；项目文档、方案文本除完成当前 AI/MinerU 任务所必需的直连传输外，不经过佳图数科局域网管理端，公司管理端不会截留、缓存或留存请求原文和模型返回内容。

**03 后台运维统计信息收集说明**

为保障软件稳定运维、合理管控 AI 资源消耗、优化产品功能，软件后台会采集**无业务涉密属性的运维统计数据**，仅用于内部运营分析，具体收集内容如下：

客户端基础统计：软件活跃使用频次、在线客户端总数量、客户端版本、操作系统平台、系统架构、访问 IP 地址；

功能使用统计：页面与功能标识、非业务内容的配置项取值分布、最近事件类型和活跃/留存趋势；

AI 资源消耗统计：全局 AI 请求总次数、各类模型 Token 消耗总量、模型服务商、接口域名和模型名称；

Agent 运行统计：执行成功或失败状态、重试次数和重试后成功率；失败信息只保留不可还原业务内容的错误类别和计数；

授权状态统计：授权状态、授权到期时间和最近一次校验时间；姓名、手机号和设备指纹的用途及边界见“04 个人信息说明”；

统计范围限制：以上运维数据**不附带任何文档原文、文件名、本地文件路径、API 密钥、用户输入文本、投标方案、业务产出等可还原项目信息**，无法反向定位任何具体业务项目与涉密内容。

**04 个人信息说明**

为方便软件使用和执行内部授权管理，软件登录使用员工真实姓名、手机号码和当前设备指纹。上述信息仅发送至佳图数科局域网管理端，用于身份识别、设备绑定、授权审批、授权校验和设备数量控制，不会发送给大模型或其他第三方，也不会附带任何投标业务内容。

### 5.4 工作包 D：用户端授权入口

#### 登录页

用户端启动后先显示独立登录页，通过授权校验后才进入原有 AppShell。登录页保持简洁，只承担已授权员工登录和新用户打开授权申请弹窗两项任务：

- 页面展示公司 Logo 和简称“佳图数科”。
- 姓名：位于常规登录页的用户名栏位置，字段直接标注“姓名”，不要求用户创建用户名。
- 手机号：位于常规登录页的密码栏位置，字段直接标注“手机号”，不要求用户创建密码，也不使用密码掩码。
- 当前设备指纹由客户端自动获取，不作为可见输入项，不允许员工手工填写或修改。
- “登录”为页面主按钮，用姓名、手机号、当前设备和本地授权凭据完成登录校验。
- 页面左下角提供次级入口“授权申请”，与“登录”主按钮明确区分。
- 已授权员工在最近一次成功校验未超过 30 天时，即使管理端暂时不可达，也可使用姓名、手机号和当前设备匹配本地授权后登录。

#### 授权申请弹窗

点击登录页左下角“授权申请”后，不进行页面跳转，在当前登录页上打开独立模态弹窗。弹窗供尚未获得授权的新用户或需要为新设备申请授权的员工使用，包含：

- 姓名栏。
- 手机号栏。
- 服务器 IP 栏：填写管理端所在局域网服务器地址和端口；首次成功连接后保存在本机，后续授权查询和定期复核复用该地址。
- “提交授权申请”主按钮。
- “取消”按钮和右上角关闭入口；关闭后返回原登录页。

登录与授权申请职责已经定版：已获授权员工点击“登录”；新用户或需要为新电脑申请授权的员工点击“授权申请”，在弹窗内填写并提交申请。弹窗不替换、不隐藏登录页。

#### 核心流程

1. 已授权员工：启动软件 -> 输入姓名和手机号 -> 点击“登录” -> 匹配姓名、手机号、当前设备与本地授权 -> 进入现有主界面。
2. 新用户/新设备：启动软件 -> 点击左下角“授权申请” -> 打开授权申请弹窗 -> 填写姓名、手机号和服务器 IP -> 点击“提交授权申请” -> 等待管理员审批。
3. 审批通过：授权申请弹窗刷新到“已批准”状态 -> 关闭弹窗并回到登录页 -> 输入姓名和手机号 -> 点击“登录”进入现有主界面。
4. 审批拒绝：客户端仅显示“授权申请已被拒绝”，不展示拒绝原因字段；员工需要时可重新提交申请或联系管理员。

仅在用户输入层进行必要校验：姓名不能为空；手机号符合公司采用的手机号格式；服务器 IP/端口格式可连接。进入客户端与管理端传输层后，不重复增加无业务价值的层层校验。

#### 申请状态

- **未提交**：弹窗显示授权申请表单。
- **待审批**：弹窗显示姓名、掩码手机号、当前设备、服务器地址、提交时间和刷新状态按钮。
- **已拒绝**：显示统一拒绝状态，不展示拒绝原因，并允许重新提交申请。
- **设备上限**：明确提示该员工已有 3 台有效绑定，需要管理员先解绑旧设备。
- **已批准**：保存本地授权，提示员工关闭弹窗并在登录页完成登录。
- **已撤销/已过期/超过 30 天未校验**：阻止进入业务主界面，显示原因和重新连接/重新申请入口。

### 5.5 工作包 E：授权规则

- 授权主体为“姓名 + 手机号 + 当前设备”。
- 员工身份按标准化后的“姓名 + 手机号”组合识别；姓名或手机号不一致时不视为同一身份，由管理员在审批时核对。
- 每台新电脑必须单独提交并由管理员审批。
- 同一员工最多同时绑定 3 台有效电脑。
- 3 台上限只计算处于有效授权状态的设备；待审批、已拒绝、已撤销和已解绑设备不占用有效设备名额。
- 第 4 台申请不自动挤掉旧设备；管理员必须先撤销或解绑旧设备。
- 单次批准的授权期为 1 年，起算点为管理员批准时间。
- 授权凭据保存在员工本机，局域网暂时不可达时仍可使用。
- 客户端至少每 30 天成功连接管理端复核一次。
- 管理员撤销授权后，客户端下一次连接管理端时立即失效。
- 连续超过 30 天无法完成复核，客户端暂停进入业务主界面，重新连通并校验成功后恢复。
- 客户端分别记录“最近一次服务端成功校验时间”“最近一次校验尝试时间”和“离线可用截止时间”；只有管理端成功响应并确认授权有效，才能延长 30 天离线可用窗口。
- 每次点击“登录”时先尝试连接管理端复核；连接失败但仍处于离线可用窗口内时允许登录，超过窗口时阻止登录。
- 软件运行期间在网络恢复和系统唤醒后主动发起复核；收到已撤销、已过期或设备不匹配状态时立即结束授权状态并返回登录页。
- 普通网络失败、超时或管理端不可达只更新“最近一次尝试时间”，不得伪装成成功校验，也不得延长离线可用窗口。
- 保留当前“设备指纹 + 签名授权 + 本地验证”的可信机制基础，但签发和刷新地址改为用户配置的局域网管理端。🔶 **Assumption：现有设备指纹在目标 Windows 办公电脑上的稳定性足以支持一年授权，系统常规更新不会频繁产生新设备。**
- 彻底删除用户端全部离线激活入口和员工可触发的离线激活流程，包括启动授权提醒、设置/关于页及共享弹窗中的相关入口。
- “删除离线激活入口”不等于删除本地授权能力：管理端批准后签发的授权仍需保存在本机，并支持 30 天内离线登录与本地校验。
- 第二阶段不接受第一阶段公网授权或离线入口产生的旧授权，升级后员工必须向局域网管理端重新申请；不提供一次性迁移。
- 保留现有匿名 `analytics_client_id` 作为同一安装实例的统计连续性标识；该标识不替代授权设备指纹。

### 5.6 工作包 F：独立 Windows 管理端

#### 软件边界

- 管理端必须是独立于用户端的第二个软件个体。
- 拥有独立安装包、程序名称、可执行文件、窗口、托盘图标、配置目录和数据目录。
- 在仓库中使用独立于 `client/` 和现有 Cloudflare `analytics/` 的源码目录与构建入口，拥有自己的依赖清单、打包配置和版本号；不得依赖根目录 `package.json`。
- 管理端使用与用户端不同的 appId、productName 和 userData 目录，允许两个软件在同一台 Windows 电脑上同时安装和运行而不覆盖彼此配置。
- 管理端不包含投标文件制作功能；用户端不包含管理员审批功能。
- 管理端工作名称为“Jato AI BID 管理端”。

#### 首次启动

首次启动流程完成：

1. 显示管理员登录页，要求公司负责人输入随管理端交付的内置初始用户名和初始密码。
2. 初始凭据验证成功后，必须立即设置并确认与初始密码不同的新管理员密码；新密码保存成功前不得进入管理界面。
3. 初始密码完成替换后不再作为日常登录凭据使用。
4. 确认局域网监听 IP 与端口。
5. 完成服务启动和局域网连通性检查。

内置初始用户名和初始密码的具体值不写入公开 PRD、普通界面、日志或运维统计，由公司负责人通过管理端发布交接材料单独掌握。管理端不允许部署人员自行注册新的管理员账号。

主窗口关闭后缩至系统托盘；授权、校验和埋点接收服务继续运行。托盘菜单至少提供“打开管理端”和“退出服务”。

#### 管理员登录与修改密码

- 管理端只有一个管理员账号，不提供管理员自助注册、多管理员邀请或角色分级。
- 首次登录使用内置初始用户名和初始密码；首次验证成功后必须立即修改密码。
- 首次改密完成后，后续打开管理界面必须使用内置用户名和负责人设置的新密码登录。
- 已登录管理员可从管理端设置入口主动修改密码；修改时必须输入当前密码、新密码和确认密码。
- 新密码至少 8 个字符、两次输入一致且不得与当前密码相同；当前密码错误时不得修改。
- 修改成功后旧密码立即失效，管理端显示明确成功提示；下次重新进入管理端时使用新密码。
- 不提供“忘记密码”、SMTP 邮件、临时密码、重置链接、恢复邮箱、短信验证码或恢复码入口。
- 管理员忘记修改后的密码时，不存在自助恢复路径。公司负责人只能使用仍掌握密码的有效数据备份恢复，或清除管理端本地数据后重新初始化；重新初始化可能导致员工、设备、授权、统计和管理端签名身份丢失，必须在执行前明确提示影响。
- 初始密码、修改后的密码以及任何密码输入不得显示在普通页面、日志、埋点或用户端。

#### 单管理端与人防约束

- 同一公司局域网只安装和运行一个“Jato AI BID 管理端”，员工端统一连接该管理端地址。
- 管理端安装包、内置初始凭据、修改后的密码和服务器控制权由公司负责人保管，不向普通管理员、员工或公司外部人员分发。
- 管理端服务器不得带离公司，管理端不得在公司外部网络安装或运行。
- 本阶段不通过域、云端中心、内部授权根、网络定位、IP 白名单或设备合规系统技术验证管理端是否位于公司网络。
- 产品明确接受残余风险：若公司负责人违反制度并主动复制安装包、凭据或服务器，软件本身不能保证阻止其在公司外部运行。

#### 授权管理能力

- 管理端以标准化后的“姓名 + 手机号”建立员工记录，以稳定 `device_id` 和不可逆设备指纹摘要建立设备记录；原始设备指纹不进入普通管理列表。
- 授权申请携带员工身份与当前 `device_id`；日常埋点只携带客户端/设备标识，由管理端关联到员工，不在每条事件中重复传输姓名和手机号。
- 管理端为设备生成可识别但不泄露原始指纹的设备摘要，供管理员区分同一员工的多台电脑。
- 待审批申请列表。
- 查看申请人的姓名、手机号、设备摘要、来源 IP、申请时间和当前状态。
- 批准一年授权；拒绝授权时直接确认，不提供也不要求填写拒绝原因。
- 员工列表及每名员工的有效设备数量。
- 设备列表、授权起止时间、最后校验时间、最后访问 IP 和状态。
- 撤销授权：立即把该设备授权标记为不可用，保留授权审计记录并释放 3 台有效设备额度。
- 解绑设备：解除员工与设备的有效关联，保留必要审计记录并释放 3 台有效设备额度。
- 设备达到 3 台时禁止继续批准，并给出明确原因。
- 按姓名、手机号、设备状态和到期时间搜索/筛选。
- 重装系统、清空用户数据或关键网卡信息变化后可能形成新设备；员工需重新申请，管理员先撤销或解绑旧设备。本阶段不提供管理员手工设备命名。

### 5.7 工作包 G：Analytics 局域网迁移

#### 链路调整

- 用户端的埋点请求只发送到登录页配置并验证成功的局域网管理端。
- 用户端的授权申请、审批结果查询、定期校验和撤销同步只连接同一管理端。
- 客户端不再向 `analytics.agnet.top` 发送埋点或授权请求。
- 不设置公网 Analytics/授权回退地址。
- 现有公网历史数据不迁移；局域网管理端从启用日开始形成新统计。
- 本工作包替换的是埋点与授权链路。现有公告、资源下载和软件更新等非埋点接口不因本条自动迁移或删除；如需迁移，应另行明确范围，避免把“停止公网埋点/授权”误写成“客户端禁止一切公网访问”。
- 🔶 **Assumption：单台 Windows 局域网服务器的本地存储和查询能力能够承载内部客户端产生的统计量；当前尚无客户端规模、事件量和数据增长基线。**

#### 必须等价保留的统计能力

- 客户端总量、新增、活跃、在线/最近访问状态。
- 页面访问和功能使用频次。
- 客户端版本、平台、架构和访问 IP 汇总。
- 文本/生图服务商、endpoint host、模型使用情况。
- AI 请求次数与 Token 消耗。
- Agent 执行成功率、失败、重试次数和重试后成功率。
- 最近事件和按时间范围查看。
- 配置使用分布。
- 留存/活跃趋势。
- 授权状态、授权到期时间和最近校验状态。

#### 统计口径合同

| 能力 | 局域网管理端要求 |
| --- | --- |
| 时间范围 | 保留“今天 / 近 7 天 / 近 30 天 / 全部历史”查询；业务日期和日界线统一使用 `Asia/Shanghai`。 |
| 客户端概览 | 展示客户端总数、今日/近 7 日新增、活跃设备数和在线设备数；新增按首次入库日期，活跃按时间范围内出现允许事件的去重设备数计算。 |
| 客户端明细 | 可查看员工、设备摘要、版本、平台、架构、局域网来源 IP、首次/最后活跃、授权状态和最近校验，不展示原始设备指纹。 |
| IP 统计 | 公网体系中的“访问 IP”迁移后改称“局域网来源 IP”；统计管理端实际看到的内网来源地址，不再宣称是 Cloudflare 获取的公网真实 IP。 |
| 页面与功能 | 保留 `app_open`、`page_view`、`config_usage`、`resource_click` 等事件的次数、趋势和去重设备数；不保存页面输入内容。 |
| 模型与 Token | 按服务商、接口域名、模型名统计请求次数和 Token；不保存 API Key、Prompt、响应正文或可还原业务内容的错误详情。 |
| Agent 运行 | 保留成功/失败、重试次数、重试后成功率及相关模型维度；错误只保留类别和计数。 |
| 最近事件 | 只展示事件类型、设备标识、时间和允许的低基数字段，不展示业务 payload。 |
| 留存 | 保留固定 30 天留存/活跃趋势，并在管理端界面说明计算口径。 |
| 授权 | 展示有效、待审批、拒绝、撤销、过期、超出复核期限等状态，以及到期时间和最近成功校验时间。 |

“在线客户端”按最近 10 分钟内收到登录、授权校验或业务埋点事件计算；不额外发送独立心跳。

#### 数据边界

管理端不得接收或保存：

- API Key。
- 招标文件原文、文件名或本地路径。
- 用户 Prompt、模型请求正文、模型响应正文。
- 投标方案正文、导出内容或其他业务产出。
- 可还原具体项目业务内容的错误详情。

管理端允许保存：

- 授权所必需的姓名、手机号、设备标识/摘要和授权状态。
- 客户端版本、平台、架构、访问 IP、活跃时间。
- 低基数页面/功能标识、模型服务商、endpoint host、模型名、请求次数、Token 数和 Agent 运行结果。

- 管理端首次使用内置凭据登录后，在完成强制改密前无法进入授权和统计页面；强制改密不得复用初始密码，改密后初始密码不能再次登录。

- 管理端界面、安装向导和本地设置中不存在 SMTP、恢复邮箱、忘记密码或邮件临时密码入口。

### 6.3 护栏指标

- 不改变当前主导航、二级导航、页面布局和核心按钮位置。

- 不因管理端暂时不可达而立即阻断仍处于 30 天校验宽限期内的有效授权。
- 姓名、手机号和设备指纹不得发送给大模型或局域网管理端之外的第三方。
- 管理端管理员密码不得通过邮件、短信、日志、埋点或用户端传输。
- 不得把“只部署一个管理端”和“禁止外部运行”的人防制度描述为软件已具备自动发现或技术阻断能力。
- 拒绝授权不得要求管理员填写原因，也不得在客户端伪造或展示不存在的拒绝原因。

## 7. User Stories & Requirements

### Epic Hypothesis

我们相信，在保持现有工作流布局不变的情况下统一 Ant Design v6 视觉语言，并将授权和统计迁移到独立局域网管理端，可以提升内部软件的一致性和可管理性；通过全量视觉验收、授权流程验收、统计等价性检查和公网请求扫描验证结果。

### Story 1：视觉升级但布局不变

作为内部投标员工，我希望软件采用统一的 Ant Design v6 风格，同时保持所有功能位置不变，以便无需重新学习工作流。

**验收标准：**

- [ ] 侧栏、主内容区、页面结构和浮动工具条位置与改造前一致。
- [ ] 全局颜色、字体、间距、圆角、边框、阴影和组件状态符合定版视觉令牌。
- [ ] 全部可见页面、弹窗、Toast、Tooltip 和加载状态完成覆盖。
- [ ] 交付 Figma 到语义令牌映射、硬编码样式审计和页面/状态覆盖矩阵。
- [ ] 固定视口截图对比确认视觉变化未改变锁定的布局尺寸和内容密度。
- [ ] 不新增 Ant Design React 组件库依赖。

### Story 2：获取金龙中转站 API Key

作为模型使用者，我希望文本模型和生图模型中的金龙中转站名称准确、获取链接一致，以便直接进入指定注册页面。

**验收标准：**

- [ ] 两个模型配置页面均显示“金龙中转站”，不显示“【推荐】”。
- [ ] 选择金龙中转站后点击 API Key“获取”，打开 `https://jlaudeapi.com/sign-up?aff=smj`。
- [ ] 其他服务商链接不受影响。

### Story 3：已授权员工登录

作为已获授权的内部员工，我希望使用姓名和手机号登录，不需要设置用户名或密码。

**验收标准：**

- [ ] 软件启动后先显示带公司 Logo 和“佳图数科”简称的登录页，未通过授权校验前不能进入业务主界面。
- [ ] 登录页包含“姓名”“手机号”和“登录”主按钮，当前设备指纹由客户端自动获取。
- [ ] 登录页左下角显示“授权申请”次级入口。
- [ ] 姓名、手机号、当前设备与本地授权匹配，且未超过 30 天复核宽限期时，可以进入原主界面。
- [ ] 本地不存在匹配授权时停留在登录页，并引导员工使用“授权申请”；不显示离线激活入口。

### Story 4：新用户提交当前设备授权申请

作为尚未获授权或更换电脑的内部员工，我希望从独立入口提交姓名、手机号、服务器 IP 和当前设备申请。

**验收标准：**

- [ ] 点击登录页左下角“授权申请”后，在当前登录页上打开独立模态弹窗，不进行页面跳转。
- [ ] 弹窗包含“姓名”“手机号”“服务器 IP”和“提交授权申请”主按钮。
- [ ] 弹窗可通过“取消”或右上角关闭，关闭后仍停留在登录页。
- [ ] 首次连接成功后在本机保存服务器地址，待审批查询和后续定期复核使用同一地址。
- [ ] 提交后显示待审批状态，不重复创建相同待审批申请。
- [ ] 管理员批准后，客户端获取一年授权并提示返回登录页；员工点击“登录”后进入原主界面。
- [ ] 管理员拒绝后只显示统一拒绝状态，不展示拒绝原因。

### Story 5：管理员审批与控制设备

作为管理员，我希望按员工和设备审批授权并限制每人最多 3 台电脑，以便控制内部软件使用范围。

**验收标准：**

- [ ] 管理端可批准、拒绝、撤销和解绑设备。
- [ ] 拒绝授权时不显示拒绝原因输入框，也不要求管理员填写原因。
- [ ] 每台设备单独申请和审批。
- [ ] 同一姓名与手机号最多存在 3 台有效绑定设备。
- [ ] 第 4 台设备申请不能被批准，除非先解绑旧设备。
- [ ] 授权有效期从批准时起计算 1 年。

### Story 6：离线使用与定期复核

作为已获授权员工，我希望短期离开局域网仍能工作，同时公司可以在设备恢复联网后撤销授权。

**验收标准：**

- [ ] 最近一次成功校验未超过 30 天时，管理端不可达不阻断使用。
- [ ] 超过 30 天未成功校验时暂停进入业务主界面。
- [ ] 撤销后的客户端下一次连接管理端即失效。
- [ ] 网络恢复且授权仍有效时，校验成功后恢复使用。
- [ ] 只有服务端成功校验才能更新最近成功校验时间和离线截止时间；失败尝试不得延长 30 天窗口。
- [ ] 每次登录、网络恢复和系统唤醒均会触发授权复核尝试。

### Story 7：管理员首次登录与修改密码

作为公司负责人，我希望使用管理端内置的初始账号密码完成首次登录并立即修改密码，之后可以在已登录状态下主动改密，以便由我掌握唯一管理端而不依赖外部邮箱恢复。

**验收标准：**

- [ ] 管理端只有一个内置管理员用户名，不提供账号注册、多管理员或角色管理入口。
- [ ] 首次启动使用随管理端交付的内置初始用户名和初始密码登录。
- [ ] 初始凭据验证成功后必须立即设置并确认至少 8 位、且与初始密码不同的新密码，完成前不能进入管理界面。
- [ ] 首次改密成功后，内置初始密码立即失效，新密码成为后续登录凭据。
- [ ] 已登录管理员可输入当前密码、新密码和确认密码主动修改密码；当前密码错误、两次新密码不一致、新密码不足 8 位或新密码与当前密码相同时不能修改。
- [ ] 主动改密成功后旧密码立即失效，并显示明确成功提示。
- [ ] 管理端不存在“忘记密码”、SMTP、恢复邮箱、邮件临时密码、短信验证码或其他自助恢复入口。
- [ ] 密码不得出现在普通页面、日志、埋点或用户端。
- [ ] 管理端完全退出并重新启动后必须使用当前有效密码登录；仅缩至托盘时沿用当前进程内已验证会话。

### Story 8：查看局域网统计

作为管理员，我希望在独立管理软件中查看现有 Analytics 统计，以便掌握客户端活跃和 AI 资源消耗。

**验收标准：**

- [ ] 统计从管理端启用日开始，不导入公网历史数据。
- [ ] 等价保留客户端总量、新增、活跃、版本、平台、架构和访问 IP 统计。
- [ ] 等价保留页面/功能使用、配置分布、模型服务商、接口域名、模型名、请求次数和 Token 统计。
- [ ] 等价保留 Agent 成功/失败/重试、最近事件、留存趋势和授权状态统计。
- [ ] 时间范围保留今天、近 7 天、近 30 天和全部历史，业务日期统一按北京时间计算。
- [ ] 原“访问 IP”在局域网管理端中明确标注为“局域网来源 IP”，不宣称为公网真实 IP。
- [ ] 统计数据不包含业务原文、API Key、Prompt、输出结果、文件名或本地路径。

### Story 9：查看与真实数据流一致的隐私声明

作为内部员工，我希望关于页准确说明业务数据、AI 直连、运维统计和授权身份信息的去向，以便明确哪些信息会离开本机以及用于什么目的。

**验收标准：**

- [ ] 隐私声明完整显示 01—04 四个部分，标题、编号和强调内容层级清晰。
- [ ] 明确业务文件不会上传到佳图数科局域网管理端。
- [ ] 明确完成 AI 任务所需内容只从本机直连员工配置的大模型服务商。
- [ ] 明确姓名、手机号和设备指纹只发送至局域网管理端，用于授权管理，不发送给大模型或其他第三方。
- [ ] 声明内容与实际网络请求和管理端存储字段一致。

### Story 10：独立安装和运行管理端

作为服务器运维人员，我希望将“Jato AI BID 管理端”作为独立 Windows 软件安装和运行，以便用户端与管理端职责、进程和数据彻底分离。

**验收标准：**

- [ ] 管理端拥有独立安装包、可执行程序、窗口、托盘图标、配置目录和数据目录。
- [ ] 用户端安装包不包含管理员页面或管理员登录入口，管理端不包含投标业务功能。
- [ ] 首次启动可完成内置凭据验证、强制改密、监听地址设置和局域网连通性检查。
- [ ] 关闭管理端主窗口后缩至托盘，授权、校验和埋点接收服务继续运行。
- [ ] 只有通过托盘“退出服务”或明确停止后台服务，局域网接口才停止提供服务。
- [ ] 部署说明明确同一公司局域网只安装一个管理端，安装包、凭据和服务器由公司负责人保管；界面不得宣称软件能够自动阻止外部运行。

## 8. Out of Scope

- 不调整现有投标业务布局、信息架构和流程。
- 不引入 Ant Design React 组件库，不批量替换 Radix 实现。
- 不迁移 `analytics.agnet.top` 中的任何历史数据。
- 不提供员工自助注册、用户名、密码、短信验证码或互联网账号体系。
- 不支持公网远程授权或公网 Analytics 回退。
- 不在用户端内嵌管理员功能。
- 不在管理端加入投标文件制作、解析、生成或导出能力。
- 不修改 AI 请求直连第三方服务商的现有原则。
- 不在本阶段重构技术方案、知识库、查重、废标检查或导出业务逻辑。
- 不保留用户端离线激活入口、离线授权码输入框或离线授权文件导入入口。
- 不提供管理员账号注册、多管理员、角色权限、忘记密码、SMTP 邮件找回、临时密码、恢复邮箱、短信验证码或自助恢复码。
- 不通过 AD/Entra、域、云端中心、内部授权根、网络定位、IP 白名单、设备合规或其他技术机制阻止管理端在公司外部运行。
- 不自动发现或阻止同一局域网部署第二个管理端；单管理端由公司负责人按部署制度保障。
- 不设计管理员拒绝原因字段，也不向员工展示拒绝原因。
- 不因本阶段埋点/授权迁移自动迁移或删除公告、资源下载和软件更新等非埋点公网能力。

## 9. Dependencies & Risks

### 9.1 依赖

- 可长期运行的 Windows 局域网服务器。
- 服务器固定 IP 或稳定的局域网访问地址，以及对应端口和防火墙规则。
- 由公司负责人控制的管理端安装包、内置初始凭据交接方式和指定服务器访问权限。
- 管理端本地持久化、备份和恢复方案。
- 现有授权签名/验证机制与新局域网签发流程的兼容方案。
- 管理端授权签名私钥的生成、保存、备份与轮换方案，以及用户端首次信任和固定管理端公钥的方案。
- 现有 Analytics 统计口径和事件字典的迁移映射。
- 独立管理端源码目录、依赖清单、Windows 打包配置和与用户端共存的安装验证。

### 9.2 主要风险与缓解

- **风险：视觉迁移意外改变布局。**
  - 缓解：以改造前截图/页面尺寸为对照，只允许视觉令牌和组件外观变化；逐页截图回归。
- **风险：局域网服务器单点故障。**
  - 缓解：已授权客户端保留 30 天离线宽限；管理端提供本地数据备份与恢复。
- **风险：员工姓名或手机号输入不一致，导致重复员工。**
  - 缓解：输入层标准化姓名空格和手机号格式；以标准化后的“姓名 + 手机号”识别员工。本阶段不提供员工记录合并功能。
- **风险：设备指纹因系统变更而漂移。**
  - 缓解：沿用并验证现有跨平台设备指纹策略；管理员可解绑旧设备后重新批准。
- **风险：升级后旧公网授权或旧离线授权仍被静默接受，绕过新的局域网审批。**
  - 缓解：发布前定版旧授权切换规则，并用带旧 `license.json` 的升级场景验证首次启动、重新申请和统计标识迁移。
- **风险：隐私声明列举的采集范围与实际授权/Analytics 字段发生漂移。**
  - 缓解：以隐私声明 01—04 为字段边界建立数据清单；验收时逐项比对实际网络请求、管理端数据库字段和日志，不允许出现未披露字段。
- **风险：内置初始凭据泄露。**
  - 缓解：初始凭据只随管理端交付给公司负责人，不在公开 PRD、界面、日志或员工文档展示；首次登录强制修改，修改后初始密码立即失效。
- **风险：公司负责人忘记修改后的管理员密码。**
  - 缓解：产品不提供自助恢复。部署前必须建立管理端数据备份和负责人凭据保管制度；恢复备份或重新初始化前必须明确其对员工、设备、授权、统计和签名身份的影响。
- **风险：同一局域网被重复安装多个管理端。**
  - 缓解：由公司负责人维护唯一服务器和管理端地址，安装包不向其他人员分发；产品不承诺自动发现或阻断第二个实例。
- **风险：管理端被负责人主动复制或带到公司外运行。**
  - 缓解：该风险由负责人权限、安装包保管、服务器资产管理和公司制度承担；本阶段不增加技术封锁，并在 PRD、部署说明和验收中明确这一残余风险。
- **风险：公网 Analytics 停用后统计能力缩水。**
  - 缓解：建立旧接口/页面/指标到新管理端的逐项映射，并以等价性清单验收。
- **风险：客户端离线期间产生的埋点被直接丢弃，导致统计能力和趋势口径失真。**
  - 缓解：客户端使用本地有界队列补发，最多保留 30 天或 10,000 条事件；每条事件携带唯一事件 ID，管理端按事件 ID 去重，超限时删除最旧事件。
- **风险：管理端数据库、授权签名密钥或配置丢失，导致历史统计不可恢复或已签授权无法继续校验。**
  - 缓解：管理端首次投产前定义同机备份、异机备份、恢复演练和密钥轮换/恢复流程。
- **风险：管理端退出导致服务停止。**
  - 缓解：关闭主窗口默认缩至托盘；只有明确点击“退出服务”才停止；管理端随 Windows 用户登录自动启动。当前版本采用纯 Electron 托盘进程，Windows 用户注销或系统关机后不继续提供服务。
- **风险：Windows 用户端验证通过，但 macOS 用户端的新授权门禁或视觉样式发生回归。**
  - 缓解：用户端视觉、登录、申请、本地授权和 30 天复核均纳入 Windows/macOS 双平台构建与回归；管理端仍只在 Windows 验收。

## 12. PRD Self-Assessment

### Strongest Section

登录页供已授权员工使用、左下角“授权申请”打开独立模态弹窗的交互已经定版。授权主体、3 台设备上限、一年有效期、30 天定期复核、撤销规则、拒绝无需原因、用户端离线激活入口删除、管理端独立软件边界和公网 Analytics 替换方向也均已由用户明确确认；管理端认证已改为负责人掌握单一内置初始凭据、首次登录强制改密、登录后主动改密且无自助找回；隐私声明已形成业务数据、AI 直连、运维统计和授权身份信息四段式结构。

### Weakest Section

登录、授权、局域网统计和管理端运行边界已经定版。当前最弱环节是人防模式依赖公司负责人持续正确保管安装包、凭据和指定服务器，软件不提供外部运行技术阻断；此外仍需验证跨 Windows/macOS 的设备指纹稳定性和单机统计容量。

### Top Assumptions to Validate

| #   | Assumption | 风险 | 验证方式 |
| --- | --- | --- | --- |
| 1 | 管理端采用与用户端相同的 Ant Design v6 视觉规范 | 两个软件视觉体系不一致或管理端 UI 返工 | 管理端 UI 定稿前确认 |
| 2 | 现有设备指纹足以稳定支撑一年授权 | 系统更新后误判为新设备，占用 3 台绑定额度 | 在目标 Windows 版本上执行重启、系统更新和网卡变化测试 |
| 3 | 单台 Windows 服务器可承载全部本地统计 | 数据增长后查询变慢或存储不可控 | 取得客户端数/日事件量基线并进行容量压测 |

### 已接受的残余风险

- 公司负责人若主动复制安装包、内置凭据、修改后密码或整台服务器，管理端可能在公司外部运行；本阶段明确由人防和公司制度承担，不作为技术缺陷验收。
- 管理员忘记修改后的密码时没有自助找回入口；是否能够恢复取决于负责人是否保留可用数据备份和相应密码。
- 同一局域网是否只运行一个管理端依赖部署制度，软件不自动发现或阻止第二个管理端。

PRD 0.5 已获用户批准。下一阶段应先修订 ADR、管理端认证相关计划、任务清单和验收用例，并等待计划批准后再进入代码修改。
