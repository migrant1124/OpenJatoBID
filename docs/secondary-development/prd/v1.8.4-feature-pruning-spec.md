## 1. 问题、目标与实施方式

### 1.1 当前问题

菜单配置通过 `phaseOneHiddenSectionIds` 隐藏了一部分入口，但相关类型、图标、页面路由和页面实现仍有保留；三个开发者入口只展示静态演示内容。隐藏菜单不等于删除功能。[S03][S04][S05][S06][S07]

本轮要解决的是源码中的废弃入口和独占实现，而不是重做界面或重构业务架构。

### 1.2 目标

| 目标 | 完成后的可观察结果 |
| --- | --- |
| 删除废弃业务入口 | 8 个目标入口不再注册为现行业务导航，不再加载其独占页面 |
| 删除独占实现 | 对应页面、动态导入、专用样式和专属图标按依赖核验结果删除 |
| 保留真实能力 | 现有技术方案、扩写、对话、生图、模板、知识库、查重、废标检查继续使用 |
| 保持操作习惯 | 普通用户侧栏顺序、位置、名称、折叠行为和业务页布局不变 |
| 可核验、可回滚 | 每项删除有调用关系依据、测试证据与独立变更范围；不清空用户数据 |

### 1.3 为什么本轮直接使用 Codex

这是现有 Electron 项目的源码删除与依赖核验任务，无代码表单或流程平台不能替代编译、路由和安装包检查。本轮不引入新的无代码/低代码平台：产品范围由本规格定义，代码和验证交给 Codex，技术计划和最终结果由用户人工审核。

### 6.4 资源下载的网络与统计边界

资源页目前有页面内资源列表请求、搜索和资源点击调用。[S08] 下线该页面时：

- 移除资源页主动读取列表/搜索/详情的执行路径，不再由该页面触发资源接口请求。
- 保留共享 `trackResourceClick` 等统计契约、共享 Analytics 服务、队列、离线重试、模型使用统计、历史页面映射与看板；即使其中某个共享函数因该页下线暂时没有客户端调用，也不擅自删除。
- 已删除页面本身不再产生新点击，属于页面下线的自然结果；不能伪造点击，也不能因此取消其他页面统计。
- `analytics/` 和 `management/` 下的资源相关历史数据、接口和页面映射不在本轮删除范围。
- 网络测试以已退役的具体资源接口为对象，不能通过全域名封禁来达到“无请求”，更不能阻断授权、公告、模型调用或自动更新。

项目规则明确要求保留统计能力。因此，通用“零引用代码清理”不能越过上述边界。[S11][S14]

### 6.5 后台服务、IPC 与预加载桥接

基线中这些目标页面主要位于前端导航层，本规格没有批准整块删除任何 Main 服务。[S04][S12]

以下原则不变：

- 不删除 `taskService`、SQLite、文档解析、导出、知识库、对话、生图或 Agent 服务。
- 不修改现有 preload API 与 IPC 合约；确有必要时进入 Change，说明两端类型及回归影响。
- 不削弱原有后台任务生命周期、离开页面守卫、授权检查或审计记录。

| 对象 | 是否可删 |
| --- | --- |

当前旧路由与 `new-template` 都打开模板创建页面；我的模板编辑也复用 `ExportFormatPage`。[S04]

### 7.2 Plan 必须完成的核验

搜索单引号、双引号、模板字符串及导航调用中的旧 ID；同时区分目录路径、历史统计字符串和真正能产生导航的调用。

检查是否确实存在当前调用、持久化页面偏好、深链接、IPC 导航消息或其他旧值读取边界。不能因为“理论上可能有”就新增一个全局兼容框架；也不能只依据本轮在线搜索片段认定全仓零调用。

### 7.3 三种结果

| 核验结果 | 处理 |
| --- | --- |
| A：只有定义/映射/路由残留，没有现行调用，也没有实际旧值读取边界 | 删除旧 ID、图标映射和冗余路由；保留模板页面与服务；不新增兼容层 |
| B：有现行内部调用，但可以无歧义改为 `new-template` | 将这些内部调用迁移到 `new-template`，同步测试，再按 A 清理残留 |
| C：证实现有外部或持久化边界仍可能读到旧 ID | 仅在该已存在的边界把旧值归一为 `new-template`，不形成第二套页面；记录兼容原因、入口、测试和后续移除条件 |

历史统计中保留的 `'export-format'` 标签允许存在，因为它解释历史记录，不是第二个业务入口。若证据不足以在 A/B/C 中做选择，报告阻塞，不删除模板相关代码；其他已确认删除项仍可独立推进。

对于 8 个已删除的入口，只有发现当前程序真的会恢复这些旧页面值时，才利用现有导航机制回到保留页面。基线没有相应消费路径时，不新增通用旧路由恢复系统。测试不得为访问已删除页面而向生产代码加调试入口。

## 15. Git、回滚与变更控制

### 15.1 开始前

只读检查当前分支、HEAD、`git status --short`、remote、本轮候选文件差异和现有计划。不上来就 `git pull`、`git fetch`、切换分支或安装依赖。

如本地比快照更新，基于本地已确认代码重新核对，不回退；如本地未提交修改与本轮重叠，先列出冲突和保护方案，不覆盖、不自动 stash、不删除用户文件。

### 15.2 分支与提交

用户已新建本轮实施分支。Plan、Build、Verify、Review 和修复阶段都复用该现有分支；本规格不指定或猜测名称，也不授权 Codex 创建或切换分支。

开始时用 `git branch --show-current`、`git rev-parse HEAD`、`git status --short` 等只读命令记录真实状态，并与既有计划记录对照。当前为正常实施分支且工作区安全时继续。若仍在 `main`/`master`、处于 detached HEAD，或当前分支与已确认计划不一致，保留工作区并报告状态，不进入源码修改、不自动选择另一分支；不能因为用户说“已新建”就宣称已经切换成功。

所有阶段禁止自动执行创建分支、`git switch`、`git checkout`、分支重命名、分支删除、重置或强制覆盖。未获另行明确授权，不执行 `git add`、`git commit`、`git push`、`git pull`、`git fetch`、`git merge`、`git rebase`、`git reset`、`git clean`、`git stash`、创建 tag、强推或发布；不运行 `npm version` 触发隐式 Git 操作。

客户端版本同步到 `1.8.4` 仅是 Build 阶段的文件修改授权，不是 Git 写操作或发布授权。完成时再次报告实际分支、HEAD 和未提交差异，与开始时记录核对。

### 15.3 回滚

回滚方案以撤销本轮独立 diff 为单位，保留用户原有修改，不用重置整个仓库。撤销操作本身需要用户明确授权，不能因为测试失败就自动清空工作区。

本轮没有数据库迁移，原则上不需要数据回滚。发生数据异常时先停止验证并保存证据，不通过删数据库来“恢复正常”。

### 15.4 范围变化

发现值得删除的真实功能、大型依赖、旧 Agent 兼容层、管理端代码或统计服务，只记录为后续候选。进入 Change 说明影响，经用户批准后才能另行实施。
