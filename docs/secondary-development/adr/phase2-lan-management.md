# ADR：第二阶段局域网授权、独立管理端与管理员认证架构

- 状态：Accepted（PRD 0.5 修订）
- 日期：2026-07-10
- 关联 PRD：`docs/secondary-development/prd/openjatobid-phase2-ui-lan-management-prd.md`

## 背景

第二阶段把客户端授权和运维统计从 `analytics.agnet.top` 迁移到公司局域网，同时保留公告、资源和更新检查等公共内容服务。管理员在 Windows 服务器上运行独立管理端，审批员工设备并查看无业务涉密属性的统计数据；客户端继续支持 Windows 和 macOS，并允许已授权员工在最长 30 天内离线使用。

PRD 0.4 原方案由部署人员配置 SMTP，并向固定邮箱发送一次性临时密码。用户在 PRD 0.5 中否决该方案，改为公司负责人保管单一管理端和内置初始凭据：首次登录强制改密，登录后可主动改密，不提供忘记密码或自助恢复。禁止管理端外带和同一局域网重复部署采用人防制度，不再增加域、云端中心或网络归属验证。

## 决策

1. 独立 `management/` Electron 应用保持不变，产品名“Jato AI BID 管理端”，appId `com.jiatu.aibid.management`；它拥有独立进程、安装包、配置目录和数据目录，不嵌入 `client/`。
2. 管理端 Main 提供局域网 HTTP 服务、SQLite 存储和授权签名；Renderer 只通过 preload/IPC 管理本机能力。SMTP、恢复邮箱、临时密码和找回密码能力全部移除。
3. 管理端采用单一管理员账号。内置初始用户名和初始密码由私有构建配置提供；仓库、PRD、ADR、普通日志和构建输出不保存或显示明文密码。
4. 构建准备步骤读取被 Git 忽略的私有配置，生成只包含用户名、随机盐、密码摘要和凭据版本的运行时模块。开发启动和 Windows 打包缺少有效私有配置时必须失败，不使用公开默认密码回退。
5. 新数据库或旧 SMTP 方案数据库第一次进入新认证版本时，将管理员认证状态初始化为内置凭据并标记“必须修改密码”；旧临时密码字段失效，旧 SMTP 配置删除。员工、设备、授权、统计和签名密钥继续保留。
6. 初始化只执行一次。公司负责人必须把初始密码修改为不同的新密码；数据库保存新密码摘要并标记负责人已接管，后续启动和后续版本不得再次用内置摘要覆盖负责人密码。
7. 每次打开管理界面输入用户名和当前有效密码。首次登录成功后只能进入强制改密流程，完成前不能进入授权、统计或服务器设置。
8. 首次改密完成后进入局域网监听地址设置；后续已登录管理员可以从“系统设置”输入当前密码、新密码和确认密码主动改密。新密码不得与当前密码相同，改密成功后旧密码立即失效。
9. 不提供忘记密码、自助注册、多管理员、恢复邮箱、SMTP、临时密码、恢复码或技术支持后门。忘记密码只能按负责人掌握的有效备份恢复，或在明确数据与签名身份影响后重新初始化。
10. 管理端采用托盘常驻模式并随 Windows 用户登录启动。关闭窗口不停止服务；显式“退出服务”、Windows 用户注销或系统关机才停止。
11. 同一公司局域网只部署一个管理端，安装包、私有构建配置、初始凭据、修改后密码和指定服务器由公司负责人保管。软件不自动识别公司网络，也不自动发现或阻止其他管理端实例。
12. 局域网 HTTP 默认端口为 `47821`，首次设置可修改。客户端输入接受 `IP` 或 `IP:端口`，未写端口时使用默认值。
13. 管理端首次启动生成 ECDSA P-256 签名密钥。客户端首次获得有效授权时固定管理端公钥，公钥变化不静默接受，必须清除本机授权并重新申请。
14. 授权主体为标准化后的姓名 + 手机号 + 当前设备；每名员工最多 3 台有效设备，每台设备单独审批。批准和续期均从操作时起授予 1 年。
15. 客户端保存签名授权与最后一次成功校验时间。只有管理端成功校验才能延长离线窗口；离线超过 30 天、授权过期或联网确认已撤销时暂停使用。
16. 客户端授权与埋点只连接配置的局域网管理端。公告、资源和更新检查继续使用当前公共服务；旧公网授权、旧离线授权和公网历史数据不迁移。
17. 离线埋点队列最多保留 30 天或 10,000 条事件，管理端以事件 ID 去重；在线客户端口径为最近 10 分钟内发生登录、授权校验或业务埋点，统计默认保留 24 个月。
18. 客户端和管理端共享 Ant Design v6 视觉方向，但不共享构建产物，也不引入 Ant Design React。

## 管理员状态迁移

```text
无数据库 / 旧 SMTP 认证数据库
  -> 注入内置凭据摘要
  -> INITIAL_PASSWORD_REQUIRED
  -> 初始凭据登录
  -> FORCE_PASSWORD_CHANGE
  -> 负责人设置新密码
  -> OWNER_PASSWORD_ACTIVE
  -> 日常登录 / 主动改密
```

- `INITIAL_PASSWORD_REQUIRED` 和 `FORCE_PASSWORD_CHANGE` 均不得访问管理业务页。
- `OWNER_PASSWORD_ACTIVE` 不受后续安装包中内置凭据版本变化影响。
- 从旧方案迁移时只替换管理员认证状态和删除 SMTP 配置，不清空其他管理端数据。

## 接口边界

- 客户端 Renderer → 客户端 Main：preload/IPC。
- 客户端 Main → 管理端：版本化 JSON HTTP API；本次管理员认证修订不改变 LAN API。
- 管理端 Renderer → 管理端 Main：preload/IPC；登录改为用户名 + 密码，并区分强制改密与已登录主动改密。
- 管理端 Main → SQLite/本地签名密钥：本机服务调用。
- 私有构建配置 → 凭据准备脚本 → 只含摘要的生成模块；明文密码不进入运行时数据库初始化参数、打包日志或源码。
- 客户端 → 第三方 AI 服务商：继续按现有模型配置直连，不经过管理端。

## 被否决方案

- SMTP 发件邮箱 + 固定恢复邮箱 + 邮件临时密码：扩大外部依赖和凭据传递边界，已被用户否决。
- 在公开源码中硬编码明文初始密码：用户选择私有构建配置注入，不接受仓库保存明文。
- AD/Entra、内部授权根、公网中心或离线签名许可：用户选择由公司负责人进行人防管理。
- 自动检测公司网络或第二个管理端：不能满足用户选择的简约边界，且不作为产品承诺。

## 后果与残余风险

- 优点：删除 SMTP 和邮件明文临时密码；管理员认证流程简单；内置明文密码不进入仓库；员工授权与统计链路不受影响。
- 代价：管理端打包依赖负责人提供的私有凭据配置；忘记修改后密码没有自助恢复；旧认证数据库第一次升级必须强制重新接管。
- 已接受风险：安装包中包含可离线验证的初始密码摘要，仍可能被离线猜测；公司负责人主动复制安装包、凭据或服务器时，软件无法保证阻止外部运行；同一局域网单管理端依赖制度执行。
- 恢复：代码层面可回退认证实现，但不得恢复已否决的 SMTP 方案；数据回退必须使用升级前完整 `userData` 备份，避免管理员状态或签名身份不一致。

## 验证

- 凭据准备测试证明缺少私有配置时开发启动/打包失败，生成文件和构建输出不包含明文密码。
- 数据迁移测试覆盖空数据库、旧 SMTP 数据库、已完成负责人改密数据库和重复启动幂等。
- 认证测试覆盖用户名错误、初始密码错误、首次强制改密、初始密码失效、主动改密、当前密码错误、旧密码失效和重启后登录。
- UI/IPC 运行时测试覆盖首次登录 → 强制改密 → 服务器设置 → 管理界面，以及系统设置主动改密。
- 静态扫描确认 SMTP、恢复邮箱、忘记密码和临时密码代码/依赖/界面为零；重新执行管理端测试、构建、Windows 打包和解包运行检查。
