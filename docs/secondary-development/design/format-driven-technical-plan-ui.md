# 格式要求驱动目录与人工填写 UI 基线

- 状态：Approved
- 日期：2026-07-13
- 修订依据：`docs/secondary-development/changes/format-requirements-simplification-change.md`
- 关联契约：`docs/secondary-development/api/technical-plan-format-contract-v1.md`
- 范围：技术方案共用流程的 Step02、Step03、Step05 与导出提示

## 设计原则

1. “生成技术方案”和“已有方案扩写”继续复用现有页面和交互骨架。
2. 不再展示 profile、来源锚点、固定模板确认、slot 或表格单元格编辑器。
3. 格式要求以普通 Markdown 呈现；一级目录来源必须向用户可见。
4. 人工填写是简单业务状态，不等同于模板锁定；用户可以直接编辑完整 Markdown。
5. 保留现有全局 CSS、Radix、Toast、页面内部滚动和 FloatingToolbar 约定。

## Step02：招标文件解析

### 关键项

关键项共 7 项，顺序固定为：

1. 项目概述；
2. 技术评分要求；
3. 格式要求；
4. 采购与报价；
5. 项目信息；
6. 甲方信息；
7. 交货和服务要求。

“格式要求”的代码 ID 为 `responseFileRequirements`，结果使用现有 Markdown 阅读器展示。页面不再区分结构化格式任务，也不展示：

- profile 与适用范围；
- 格式强度；
- 来源文件、行号或锚点；
- 固定模板列表；
- 确认并锁定、重新核对等入口。

旧 `bidDocumentFormatRequirements` 和 `quotationRequirements` 不显示、不计入进度。

结果首行的 `【技术文件目录状态】：明确/未明确` 可与正文一起展示，不增加独立 profile 控件。

配置 Dialog 继续使用自然高度：关键项网格结束后再显示“其他项”，内容超出时在 Dialog 内滚动，不得出现叠字。

### 格式要求结果

结果标题显示“格式要求”，正文直接显示 AI 整理后的 Markdown，例如：

```text
响应文件组成
技术文件目录
固定表格、承诺函与附件
签章与文件编制要求
上传与递交要求
```

无明确目录格式时，结果中显示可读的“未找到明确技术文件目录格式”说明，但该解析项仍可成功。

## Step03：目录生成

### 生成来源提示

生成 Dialog 在用户执行前显示本次一级目录来源：

- 有明确格式：`一级目录将按招标文件“格式要求”生成。`
- 无明确格式且已选知识库：`招标文件未规定明确目录格式，一级目录将参考已选知识库文档生成。`
- 无明确格式且未选知识库：显示阻断提示并禁用生成按钮。

阻断提示固定为：

> 招标文件未规定明确目录格式，请至少选择一份参考知识库文档后生成目录。

不得显示“将按技术评分大类生成一级目录”。

### 知识库选择

- 有明确格式时，知识库选择仍可用于下级目录和正文参考，但不影响一级目录。
- 无明确格式时，至少选择一份知识库文档后才能生成。
- 多份文档同时选择时，说明文字提示“系统将综合所选文档目录生成一套目录”。
- 只使用用户当前勾选的文档，不隐式读取其他知识库内容。

### 一级目录与评分项

- 有明确格式：一级目录标题和顺序来自格式要求。
- 无明确格式：一级目录来自所选知识库文档目录的综合结果。
- 两种情况下，技术评分项只能生成二级及以下目录。
- 目录页面不显示 profile 选择器、格式 Hash、固定顺序锁或来源编号。

### 人工填写标记

固定表格和承诺函节点显示紧凑标签：`人工填写`。

目录编辑器提供简单切换项：

```text
正文方式：AI 编写 / 人工填写
```

- 默认由目录生成结果标记固定表格和承诺函；
- 用户可以修正误判；
- 切换为人工填写时说明“正文生成将跳过该章节”；
- 切换回 AI 编写时恢复普通章节行为；
- 不显示固定模板、标题锁定、顺序锁定、层级锁定、响应模式或模板 ID。

## Step05：正文生成与编辑

### AI 编写节点

沿用现有 Markdown 编辑器、批量正文生成、单节重新生成、扩写和允许的后处理能力。

### 人工填写节点

- 左侧目录显示“人工填写”标签；
- 主区继续显示普通 Markdown 编辑器；
- 编辑器上方提示“该章节需要人工填写，正文生成与自动改写将跳过此章节”；
- 隐藏或禁用单节 AI 生成、重新生成、扩写和自动改写入口；
- 用户使用现有保存按钮保存完整 Markdown；
- 不显示 slot 表单、固定正文只读预览、固定表格单元格编辑或模板确认状态。

若通过快捷入口触发 AI 操作，使用 Toast：

> 该章节需要人工填写，不能使用 AI 生成或改写。

### 任务完成提示

批量正文任务完成时，人工填写节点不计为 AI 失败。若仍有空白人工节点，成功提示为：

> 正文生成已完成，仍有 N 项需要人工填写。

目录列表和正文页面应能定位这些节点。

## 导出提示

点击导出时：

- 存在空白人工填写节点：阻止导出，Dialog 列出节点标题；
- 所有人工节点均有非空 Markdown：允许进入现有导出流程；
- 不显示模板 Hash、固定正文不一致、slot 缺失或表格结构损坏等旧错误；
- 不对人工填写内容执行招标原文逐字校验。

错误标题使用“请完成人工填写章节”，正文使用：

> 以下章节需要人工填写后才能导出：{节点标题列表}

## 兼容与清理提示

- 用户重新解析“格式要求”且已有目录或正文时，沿用现有 Radix Dialog 告知后续内容将失效。
- 重新选择无格式场景的知识库参考文档并生成目录时，同样提示将清理旧目录和正文。
- 历史 profile 和固定模板数据不在 UI 展示；不提供迁移或恢复旧模板入口。

## 视口与验收

- 固定视口：1440×900、1920×1080；最小可用视口沿用现有 860px 边界。
- 检查 Step02 7 个关键项自然换行、“其他项”下移和 Dialog 内滚动。
- 检查格式要求 Markdown 长内容在结果区内部滚动。
- 检查 Step03 三种来源提示：明确格式、知识库目录、缺少知识库阻断。
- 检查多份知识库选择文案和只使用已选文档。
- 检查目录节点“AI 编写/人工填写”切换与保存。
- 检查 Step05 人工节点跳过 AI、可手工保存、空内容阻止导出。
- 对两个技术方案入口分别验证启动、恢复、目录、正文和导出。
