# 招标格式驱动技术方案 UI 基线

- 状态：Approved
- 日期：2026-07-13
- 范围：技术方案共用流程的 Step02、Step03、Step05 与导出门禁
- 关联契约：`docs/secondary-development/api/technical-plan-format-contract-v1.md`

## 设计原则

1. “生成技术方案”和“已有方案扩写”继续复用现有页面，不复制流程。
2. 保留现有全局 CSS、Radix、Toast、页面内部滚动和 FloatingToolbar 约定，不引入新 UI 框架。
3. 锁定状态必须在界面可见，但 UI 禁用不是唯一保护；Main 仍执行同一业务门禁。
4. 执行状态与合规状态分开显示，避免把“任务跑完”误写成“材料完整”。

## Step02：招标文件解析

### 关键项与旧工作区

- 活跃解析任务共 18 项。关键项区域按 Main 返回的元数据展示 7 项，顺序为“项目概述、技术评分要求、格式要求、采购与报价、项目信息、甲方信息、交货和服务要求”。
- 旧工作区的缺失提示按当前任务状态动态列出；已有成功结果继续保留，不写死旧任务数量或专用提示文案。
- 默认启动只请求当前缺失的关键项；现有单项重试继续保留，并允许用户主动重跑任一成功项。
- 历史 `quotationRequirements` 行不显示、不计入 7 项完成度，也不冒充“采购与报价”成功结果。
- 若补充格式解析会使已有目录和正文失效，启动前使用 Radix Dialog 列明将清理的后续状态。
- 7 项未完成时，主流程保持或回到 Step02，Step03 入口禁用并显示缺失项。

配置 Dialog 使用内容自然高度：关键项在 3 列视口中允许出现完整第三行，在窄视口按既有断点切为 2 列；“其他项”标题始终位于关键项网格之后并保留组间距。内容超出 Dialog 时由配置区内部滚动，不允许通过固定高度或负间距造成叠字。

### 格式要求结果

结构化结果区按以下层级展示：

```text
格式要求
├── profile：适用标段/标包、document_type、format_strength
│   └── 递归目录树
│       ├── 源编号与原标题
│       ├── 响应模式
│       ├── 锁定状态
│       └── 来源文件与位置
└── 固定模板
    ├── 固定承诺函
    └── 固定 Markdown 表格
```

固定模板操作：

- 未确认：显示“待核对”，可打开结构化核对 Dialog；
- 核对 Dialog 可修改解析错误的固定片段、slot 定义、表头、固定单元格和说明；
- 点击“确认并锁定”后由 Main 计算 Hash；
- 已确认：只读展示，提供“重新核对”入口；重新核对必须说明会清理引用节点的正文缓存。

### 采购与报价结果

- 以 Markdown 展示采购清单、规格数量、交付验收，以及报价方式、限价、税务、公式、报价表、平台规则、一致性、无效报价、异常低价和结算要求。
- 该项沿用通用 Markdown 结果视图，不新增写入技术目录或正文的专用逻辑。
- 无明确内容时展示可读的未发现说明，不显示为空白成功结果。

## Step03：目录生成与编辑

### profile 选择

- 无明确格式时自动使用唯一全局 `technical/none` profile，并显示“将按技术评分大类生成目录”。
- 显式格式的唯一最高 specificity profile 自动选中并显示适用范围。
- 显式格式零个或最高分并列多个匹配时，在生成 Dialog 中要求用户选择；不猜测、不静默回退。
- 只有选中 `format_strength = none` 时，界面显示“将按技术评分大类生成目录”。
- 明确格式模式显示“将以招标文件格式骨架为准，评分项用于映射与补充”。
- “已有方案扩写”存在明确格式时隐藏 `original-only` 选项并说明原方案只作为补充参考。

### 节点状态

节点按实际约束组合显示紧凑标签：

- 固定目录
- 不可删除
- 标题锁定
- 顺序锁定
- 层级锁定
- 只保留标题
- AI 正文
- 固定表格
- 固定承诺函
- 证明材料
- 明确无内容响应

编号展示：

- `auto`：继续显示现有自动编号；
- `preserve-source`：显示 `source_number`，不再显示内部 ID 编号；
- `none`：不显示编号。

### 操作边界

- 锁定标题不显示编辑入口；
- 必留节点不显示删除入口；
- 顺序或层级锁定节点不可拖动；
- `allow_ai_children = false` 不显示添加子目录入口；
- 未锁定节点继续使用现有编辑、添加、删除和排序交互；
- 直接 IPC 绕过时由 Main 返回同一中文错误并通过 Toast 展示。

## Step05：按响应模式展示

### 自由正文

继续使用现有 Markdown 编辑器、保存、单小节重新生成和允许的正文处理能力。

### 固定承诺函

- 左侧目录显示“固定承诺函”和响应状态；
- 主区上部为固定正文只读预览；
- 下部为 slot 表单，标明数据来源和必填状态；
- 不显示扩写、改写、润色、表格清理或单小节 AI 重生成按钮；
- 未确认模板显示“待确认并锁定”，只提供返回 Step02 的入口；
- 必填字段缺失时显示“待人工填写”，保存走专用接口。

### 固定 Markdown 表格

- 表头、固定单元格和固定说明只读；
- 仅 slot 单元格可编辑；
- 只有 repeatable region 显示“新增行/删除行”，并遵守最大行数；
- 无偏差等场景仍保留完整表格，通过模板允许的空响应值填写；
- 不允许切换为自由 Markdown。

### 证明材料

- 展示 Agent 匹配的材料索引、知识条目来源和附件顺序；
- 原始证明材料不在编辑器中改写；
- 无匹配材料时保留节点并显示“无。”；
- `high` 或 `potential-rejection` 使用显著风险条，不能用成功色掩盖。

### 容器与明确无内容

- `container` 只显示说明和子节点完成统计，不显示编辑器；
- `explicit-none` 显示确定性响应和风险状态，不显示 AI 重写入口。

## 完整性与任务完成提示

正文任务完成时分两层反馈：

- 执行结果：成功、失败、暂停；
- 合规摘要：已实质响应、明确无内容、待人工填写、缺少强制证据。

若仍有待处理节点，成功 Toast 使用：

“正文生成已完成，仍有 N 项待人工填写、M 项缺少证明材料。”

不得只显示“正文生成完成”。

## 导出门禁

点击导出后：

1. 未确认模板、Hash 不一致、固定表格损坏、必填 slot 缺失、`pending` 或 `needs-manual-input`：硬阻断并定位节点。
2. 仅存在 `missing-required-evidence`：Radix Dialog 列出节点、风险和来源，用户明确选择“知悉风险并继续导出”后允许本次导出。
3. 风险确认不修改节点状态，不把风险标记为已解决。
4. Main 回读权威 Store 后执行最终校验；Renderer 不发送可替代权威正文的 outline。

## 视口与运行验收

- 固定视口：1440×900、1920×1080；最小可用视口沿用现有 860px 响应式边界。
- 检查 Step02 解析配置 Dialog 中 7 个关键项自然换行、“其他项”下移和内部滚动；检查 profile/树和模板 Dialog 的内部滚动。
- 检查 Step03 深层固定目录不导致 body 滚动。
- 检查 Step05 固定表格宽表的局部横向滚动。
- 检查键盘 Tab、焦点环、Dialog 关闭和 Toast。
- 对两个工作流分别验证启动、恢复、步骤切换、目录、全局事实、正文和导出。
