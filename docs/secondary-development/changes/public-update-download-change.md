# 更新与下载去除员工许可证门禁

## 原约定与问题

原发布方案第 8 节要求 Worker 用员工许可证保护 `/updates/latest` 与 `/updates/download`，GitHub Actions 也用测试设备许可证验证发布。该许可证的离线期限为 30 天，使发布流程依赖局域网管理端的定期续验。

## 用户确认的修订

- 发布验证、更新查询和安装包下载不要求员工许可证；R2 仍为私有 Bucket，由 Worker 提供公开的更新接口。
- 已发布客户端的 POST 更新查询及携带许可证 Header 的下载请求继续可用，Worker 不再读取或校验其中的许可证。
- 客户端不再向更新服务传输员工许可证，继续校验下载文件的大小和 SHA-256。
- 未获授权或授权已过期的客户端不在启动授权页检查或下载更新。客户端业务使用继续遵循现有局域网管理端授权和 30 天离线规则。
- 发布仍须验证 Worker 更新查询、完整 EXE 下载及 SHA-256，并保留 Draft、R2 回读和失败回滚。

## 依据与影响

用户于 2026-09-27 确认上述边界。本修订替代原发布方案中“更新和下载必须验证员工许可证”的条款，以及 `tasks/todo.md` 中 T81、T84 对该门禁的历史描述；其他发布和授权要求继续有效。公开下载允许持有链接的人获取安装包，GitHub Release 的正式客户端安装包也已公开。上线时需先部署兼容新旧客户端的 Worker，再发布不发送许可证的新客户端。
