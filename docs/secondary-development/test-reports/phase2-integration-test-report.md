# 第二阶段局域网授权与统计集成测试报告

日期：2026-07-10；2026-07-11 按 PRD 0.5 复验  
范围：独立管理端、管理员认证、用户端 Main 服务、局域网 HTTP API、授权签名与统计入库。

## 自动化端到端链路

测试文件：`management/electron/services/phase2LanIntegration.test.cjs`

测试使用真实本机 HTTP 监听和临时 SQLite 数据库，按两个软件的正式服务边界执行：

1. 用户端向管理端提交姓名、手机号、当前设备和客户端 ID；
2. 管理端生成待审批申请；
3. 管理员批准，生成 ECDSA P-256 签名的一年期授权；
4. 用户端轮询申请状态，验证签名并将管理端公钥首次绑定到本机；
5. 用户端使用姓名、手机号和当前设备登录；
6. 用户端向同一局域网服务提交运维事件；
7. 管理端按员工、设备和来源 IP 入库并聚合；
8. 管理员撤销设备授权；
9. 用户端下一次联网校验收到 `REVOKED` 并停止授权。

结果：通过，已包含在管理端 36/36 测试中。

## PRD 0.5 管理员认证链路

| 场景 | 证据 | 结果 |
| --- | --- | --- |
| 私有构建凭据注入 | 临时凭据生成测试；生成模块仅含用户名、随机盐、摘要和凭据版本 | 通过 |
| 空库首次接管 | 初始账号密码登录后会话标记 `mustChangePassword` | 通过 |
| 强制改密门禁 | 未改初始密码时，服务器设置、授权管理和统计 IPC 均拒绝访问 | 通过 |
| 初始密码必须真正变化 | 服务层拒绝把新密码设置为当前初始密码；界面切换后两个新密码输入框为空 | 通过 |
| 初始密码失效 | 完成改密后，初始密码不能登录，新密码可以登录 | 通过 |
| 主动改密 | 要求正确当前密码；拒绝短密码和相同密码；成功后旧密码失效 | 通过 |
| 旧认证数据库迁移 | 管理员进入待接管状态；删除旧邮件设置；保留服务器、员工、设备、授权、统计和签名数据 | 通过 |

Playwright 以独立浏览器会话完成“账号密码登录 → 强制改密 → 局域网服务设置 → 系统设置主动改密”，控制台为 0 error / 0 warning。截图见 `docs/secondary-development/design/phase2-visual-regression.md`。

## 安装包边界与运行时

- Windows NSIS、ZIP 和 `win-unpacked` 生成成功。
- 构建链使用 Electron 41 实际加载 `better-sqlite3`，防止宿主 Node ABI 污染安装包。
- ASAR 包含生成的初始凭据摘要模块，不包含私有明文 JSON，不包含 `*.test.cjs`，也不包含明文初始密码。
- `win-unpacked` 使用全新隔离 `userData` 启动成功；SQLite 初始化为 `INITIAL_PASSWORD_REQUIRED`，启动标准错误为空。

## 网络边界

- 用户端授权和埋点统一使用 `lan_management.server_address`。
- 服务器地址解析只接受局域网 IP 或 IP:端口，不接受 URL 路径、认证信息、域名和非法端口。
- 静态扫描未发现 `analytics.agnet.top/track`、旧授权或离线激活接口。
- 公告 `/notice`、资源 `/resources` 和 GitHub 更新检查按 PRD 保留。
