## 2. 实施结果

### 2.1 OpenCode

- 建立独立 HOME、Config、Data、State、Cache、Temp、AppData 和受控 PATH。
- 禁止项目/用户配置、外部插件、MCP、远程 Skill、外部目录访问及非白名单本地 Skill。
- 打包态固定使用安装包内 OpenCode 和工具路径；两个开发覆盖环境变量仅在非打包态生效。
- Server 启动前执行 `debug paths --pure`、`debug skill --pure`，启动后复核 `/path`、`/config`、`/skill`、`/agent`。
- 最终 Provider、Model、Base URL、API Key 占位/本次 proxy token、超时和上下文配置逐字段校验，畸形响应 fail-closed。
- 隔离失败关闭 sidecar/proxy，只将 Agent Runtime 标记为不可用，不阻断客户端其他服务。
- stdout/stderr、状态、事件、请求日志、自检、报告和 `console.warn` 均经过敏感信息脱敏。
- 设置页沿用现有 Agent 自检状态，增加隔离结果、Skill 来源和违反项展示。

### 2.2 知识库

- 使用当前文本模型上下文的 80% 作为请求预算，并为任务、条目、JSON 约束和消息开销保留 20%。无有效上下文配置时回退为 400000。
- 初次提取、补充遗漏、条目匹配、未归属 Block 补漏四阶段均支持自动分段。
- Block 连续打包；异常超大 Block 在正式持久化前切为顺序不变、正文无损且 ID 唯一的业务 Block。
- 条目超预算时拆子批；单个不可再拆条目超出整个请求预算时在发起超预算请求前失败。
- 多段合并保证每个 Block 最多一个最终归属，优先级固定为 `matches > new_items > discarded`，最终 ranges 由已认领 block_ids 重建。
- 初次提取、补充和匹配复用字节级稳定 Block 前缀；首段后固定等待 5000ms，再以 `Promise.allSettled()` 展开并发。
- 所有请求继续经过现有 `aiService` 全局队列；回归中使用真实请求队列验证 `concurrency_limit=2`。
- `batchSize` IPC 参数继续兼容但服务端忽略；知识库页面已删除手工批次输入，改为自动分段文案。
