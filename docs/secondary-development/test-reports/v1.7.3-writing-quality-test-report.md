# OpenJatoBID v1.7.3 正文写作质量优化测试报告

## 1. 范围与环境

- 规格：`docs/v1.7.3-spec.md`
- 分支：`0920v1.7.3-textedit`
- 核查起点：`dbda5ddfd68cf229aa07d41d1bfd3e02935bedbf`
- 客户端目标版本：`1.7.3`
- 范围：员工客户端技术方案正文编排、生成、原方案优化、局部扩写与修订、轻量章节上下文、本地写作质量诊断、策略版本和测试。
- 未修改：管理端、Analytics、发布与更新体系、模型并发和供应商配置。

## 2. 实现结果

1. 新增 `contentWritingPolicy.cjs`，集中维护正文表达、方法与事实边界、章节编排和局部修订规则。
2. 删除实际正文提示词中的 30 字拆句、固定主语、连接词禁用和机械词汇替换；没有增加新的句长、段长或固定主题数量模板。
3. 首次生成、单节重生成、原方案优化 Agent、最低字数扩写、原方案覆盖修补、一致性局部修复、表格转文字和小节字数复核按任务职责复用适用政策；普通与 Agent 原方案补写都输出局部操作，并统一走精确锚点及图片、代码块、表格保护运行时。
4. 章节计划格式化会传递 `excludes`、`related_node_ids` 和禁止复述事项，空的量化、证据与交付字段不再格式化为大量“无”项。
5. 每轮使用稳定的已落盘正文快照，向当前章节提供同级职责、排除主题和预算内相关摘录；并发生成不依赖其他请求的完成顺序。
6. 本地质量诊断覆盖同节/跨节非开头精确重复、轻微改写重复和连续同主语碎片句；保留原文证据，不自动删除正文，不改变 `can_proceed`。
7. 计划结构版本保持 v5，仅将提示词版本更新为 `content-plan-v5-writing-1.7.3`；旧计划可读取，重新编排时保留原方案来源映射。任务统计和本地开发日志记录 `writing-v1.7.3`。
8. 原方案优化的普通请求与 Agent 路径、后续字数复核及 Agent 一致性回写均校验受保护富内容：原表格块按多重计数原样存在，图片引用多重集合完全一致；表格无法安全理解时保留原表格并记录跳过，不再要求模型编造概括。
9. 模型请求期间若检测到同一正文已被用户修改，本轮生成、扩写或修订结果不覆盖用户内容。
