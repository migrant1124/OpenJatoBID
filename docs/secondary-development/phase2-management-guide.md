# 第二阶段管理端部署与运维说明

## 软件边界

“Jato AI BID 管理端”与“Jato AI BID”员工用户端是两个独立软件个体：安装包、appId、进程、代码入口、数据目录和升级生命周期均相互独立。服务器只需安装管理端，员工电脑只需安装用户端。

同一公司局域网只部署一个管理端。安装包、内置初始凭据、修改后的管理员密码和指定服务器由公司负责人保管，不向普通员工或公司外部人员分发。该边界采用公司制度和负责人管理，软件不自动判断自己是否位于公司网络，也不自动发现其他管理端。

## 首次部署

1. 在一台长期在线的 Windows 局域网服务器上安装并启动“Jato AI BID 管理端”。
2. 使用随安装包私下交付的内置初始用户名和初始密码登录。
3. 首次验证成功后立即设置并确认至少 8 位、且与初始密码不同的新密码；完成前不能进入管理界面或服务器设置。初始密码在修改成功后失效。
4. 监听 IP 通常保持 `0.0.0.0`，端口默认 `47821`；如修改端口，员工申请时必须填写 `IP:端口`。
5. 在 Windows 防火墙入站规则中放行配置的 TCP 端口，并限制为公司局域网网段。
6. 确认首页右上角显示“局域网服务运行中 · IP:端口”。

关闭管理窗口只会隐藏到系统托盘，授权和统计服务仍运行。需要真正停止时，使用托盘菜单“退出服务”。管理端会为当前 Windows 用户启用登录自启动；Windows 用户注销或服务器关机后服务不会继续运行。

## 授权管理

- “待审批申请”显示员工姓名、手机号和设备信息。点击批准后生成 1 年有效授权。
- 同一员工最多 3 台有效设备；达到上限时先撤销不用的旧设备，再审批新电脑。
- “拒绝”只拒绝当前申请，不创建授权。
- “撤销”使当前设备在下次联网校验时失效。
- “续期”从管理员操作时刻重新延长 1 年。
- 员工无需设置账号密码；获批后使用姓名、手机号和当前设备登录。

## 运维统计

统计页支持今日、近 7 天、近 30 天和全部范围，显示活跃客户端、在线客户端、版本、平台、IP、页面访问、配置变化、AI/Token、Agent 和最新事件。在线口径为最近 10 分钟有登录、校验或埋点。

管理端仅接收无业务涉密属性的白名单字段，不接收文档原文、文件名、本地路径、API Key、用户输入、投标方案或模型返回正文。事件默认保留 24 个月，可在统计页手动清理过期数据。

## 修改管理员密码

已登录管理员从“系统设置”进入修改密码页面，依次输入当前密码、新密码和确认密码。新密码至少 8 位且不能与当前密码相同；当前密码错误、两次新密码不一致、长度不足或重复使用当前密码时不能修改。修改成功后旧密码立即失效，完全退出管理端后使用新密码重新登录。

管理端不提供“忘记密码”、邮件、短信、临时密码、恢复码或技术支持后门。负责人忘记密码时，只能恢复一份密码仍已知的完整管理端数据备份，或清除管理端本地数据后重新初始化。清除数据会影响员工、设备、授权、统计和管理端签名身份，不得在未备份和未确认影响时执行。

## 备份与恢复

备份前从托盘选择“退出服务”，确认管理端进程已结束，然后完整备份该软件的 Electron `userData` 目录。当前 Windows 包默认目录为 `%APPDATA%\jato-ai-bid-management`；如使用了自定义 `--user-data-dir`，以该目录为准。

必须整体备份，不能只复制 `management.sqlite3`。数据库内同时保存员工、设备、授权、统计、管理员密码摘要及签名密钥；丢失签名密钥会导致现有客户端不再信任新的授权。

恢复时：

1. 在相同或兼容版本的管理端上先退出服务；
2. 将完整备份恢复到原 `userData` 位置；
3. 启动管理端，确认局域网服务和历史授权正常；
4. 使用一台已授权客户端执行登录/校验，再检查统计事件是否到达。

## 升级、回退与卸载

- 从旧 SMTP 认证版本升级前先完整备份 `userData`。升级后第一次启动要求使用新安装包的内置初始凭据接管并强制改密；旧 SMTP 配置和临时密码状态删除，员工、设备、授权、统计和签名身份保留。
- 后续普通升级不得用安装包初始凭据覆盖负责人已经设置的密码。
- 用户端与管理端可以分别升级，但应先在测试机器验证 API 兼容性。
- 回退安装程序不会把局域网授权转换为旧公网授权，也不要通过重新初始化管理端来回退。
- 卸载前必须备份数据。卸载后如仍保留 `userData`，重新安装可继续使用；是否删除该目录由管理员明确决定。

## 上线验收

至少验证管理端初始登录、强制改密、主动改密、退出后新密码登录、申请、审批、员工登录、断网使用、重新联网校验、撤销、3 台上限、统计入库和托盘重启。若有 macOS 用户端，还需在实际 macOS 设备验证同一链路。
