# OpenJatoBID v1.8.0：页面清单、高保真设计需求与 UI Handoff

> 输出：页面与弹窗清单、9 张高保真主图的内容要求、组件交互、异常状态、响应式要求和视觉验收方法。

## 1. 已确认边界与设计默认值

### 1.1 不得再自行改变的内容

一级入口固定为“生图模式”；二级入口固定为“AI 生图”“提示词中心”“我的作品”。仅简单模式。既不展示专业模式开关，也不出现无限画布、节点、视频、插件或 AI／AIT 入口。

页面无需招标项目即可工作。不得把公司名称、Logo、客户、招标项目或知识库素材自动放入创作内容。现有客户端 Logo 可以正常作为应用外壳标识，但不能混入用户作品。

既有标题栏、一级导航其他项目、窗口缩放、对话页、投标页和设置页大布局不重做。

### 1.2 设计默认值，不冒充用户已确认尺寸

以下为制作第一轮视觉稿的建议基准：1440 × 900 逻辑像素桌面稿；页面内边距 24；主创作区左右间距 24；输入栏初始宽度约 360，结果区占用剩余宽度。

尺寸须对照现有客户端的真实截图和 CSS 后调整。颜色、字体、按钮、圆角、边框、图标线宽、焦点和 Toast 样式优先复用现有规范，不另起一套品牌。实际 token 名称由 Codex 在 T180-00 查明，不能把本文建议值强行写成新的全局 token。

### 1.3 已核对的仓库约束

现有客户端使用 React／TypeScript、全局 CSS 和 Radix 基础组件，明确不使用 Tailwind。业务页面内部滚动，不能依赖 body 全局滚动。[S1][S2]

现有多子功能一级菜单通过 `menuConfig.ts` 与 `SecondaryMenuPage` 组织；`AppRouter.tsx` 对有 children 的入口先显示二级菜单页。[S2][S3][S4]

本 Spec 又要求 AI 生图为默认创作页。因此：只对新增生图父入口做必要的默认子页定向，或采用新模块内部页面宿主；具体方案在 plan 阶段对照真实代码确定。不能为了新模块重写所有二级菜单。三个二级入口位于右侧主内容区，不在左侧栏新增折叠树或悬浮菜单。

H07 可以增加一张局部状态图解释“常用风格”，不需要为了同一页面的切换再设计一个完全不同的主页面。

### 3.2 先确认代表性样式，再扩展全部页面

第一组 H01、H02、H03、H05 覆盖主页面、结果、图片编辑和提示词弹窗。优先确认这一组，避免九张图分别出现不同风格。

第一组确认后再按同一套组件继续 H04、H06、H07、H08、H09。所有稿件均标明版本、图号、状态和待确认项；未确认稿不得被当作开发验收基线。

### 3.3 每张图的统一交付要求

每张高保真图须有对应 handoff 说明：组件边界、复用组件、操作行为、滚动区域、最大内容状态、窄窗口表现、键盘操作和业务状态。

视觉图片仅用于确认布局和样式。图片里画出的进度、参数、成功图、PSD 图层不构成功能已完成的证据。实际运行截图必须来自后续真实客户端，单独归档。

参考产品只借鉴低门槛操作，不复制其广告、价格、Logo、示例素材权利或账户体系。素材使用自有或已获授权图片；不得从私有投标资料取图装饰视觉稿。

## 4. P01：AI 生图组件与交互

### 4.1 左侧创作输入区

从上到下为：任务预设、需求输入框、提示词工具、参考图片、常用参数、生成按钮。

| 组件 | 展示与行为 | 禁止行为 |
| --- | --- | --- |
| 任务预设 | 商品图、海报图、宣传图、插画图、写实图片、图标／小元素、背景图、局部修图；选择后改变引导 | 另做八套页面；填入公司内容 |
| 需求输入 | 普通中文即可；长内容在框内滚动；可见当前文本 | 自动加载招标正文；因切换页面清空 |
| 提示词工具 | 主按钮“优化提示词”；“提示词中心”“保存提示词”为次要操作 | 平铺大量优化类型按钮 |
| 参考图片 | 拖入或添加 PNG/JPG/WEBP；缩略图、移除、主体／风格／构图／色彩角色 | 默认上传其他项目图片；静默丢图 |
| 反推入口 | 有来源图时可直接反推；无图时先选图 | 误把多参考图自动合并反推 |
| 参数 | 比例、张数、质量；风格倾向遵循能力合同 | 显示无法执行的模型参数 |
| 生成 | 有效输入和可用能力后提交；显示排队／生成状态 | 保存、优化或应用提示词时自动生图 |

产品参考图上限为 4；实际模型少于 4 时明确当前限制。不新增“高级设置／专业模式”入口。必要参数收纳只属于简单模式的渐进展示。

### 4.2 中间结果区

初始状态展示简短说明与任务预设或合法示例，不能表现成需要拖节点的空白画布。生成后改为结果网格；当前结果可放大，不自动覆盖其他图。

选中图片后显示轻量工具条：继续创作、局部修改、反推提示词、保存提示词、下载、PSD。次要动作可收在“更多”，但不能把局部修改和下载藏到多层菜单。

继续创作带入明确的源图和该版本参数；不把最新提示词误认为历史版本使用的提示词。作品来自本应用时，“查看生成参数”直接读取快照，不调用反推模型伪造原始记录。

### 4.3 右侧信息

仅在用户查看详情、版本或 PSD 时打开抽屉。默认不常驻第三列，不堆叠第二个助手聊天栏，不把图片任务再转成“必须先聊天”的流程。

### 4.4 参数能力展示

可选参数来自已经验证的模型能力。示例：渠道只支持单张时，界面不能声称单次请求支持 4 张；允许由任务层拆为多次明确请求，但要据实显示总任务数和费用不确定性。

“保守／平衡／明显”等风格倾向可采用经验证的提示词表达，不自动制造 `style_strength` 参数。比例需要裁剪或补边时，应让用户知道，不能把拉伸图当原生输出。

## 5. D01：局部修改

弹窗以图片为视觉主体，提供画笔、橡皮、大小、撤销、重做和缩放；底部或右侧放修改要求及提交按钮。无圈选内容时不允许提交，说明“请先涂抹需要修改的区域”。

视图缩放仅影响显示，选区保存在原始图片坐标中。显示用蓝色／现有强调色遮罩与提交给模型的遮罩要分离，预览色不能污染原图。

原图与候选新版本可以比较。提交后不得把新结果写回原文件；失败保留选择与描述。

对于支持局部合成的实现，明确有效编辑区与边缘羽化范围。不能用“AI 会听话”代替非选区保护。具体数据测试见任务书 T180-09。

## 6. D02：图片反推

单张来源图 + 主提示词是默认结果；风格、构图、光影、色彩、标签、比例等结构项以折叠区补充，不额外增加专业模式。

默认中文；英文或双语属于可选结果。主按钮“用于生成”只应用到输入框；“保存为我的提示词”只保存。两者均不直接扣费生图。

固定说明：“根据图片生成参考描述，不代表原作者使用的原始提示词。”看不清的文字、未知拍摄设备和模型参数不得被当作确定信息输出。

当前输入框有内容时，用清楚的替换预览或明确动作避免误覆盖；原输入可恢复。反推过程中切换来源图，应按来源版本关联结果，不把旧请求结果展示成新图分析。

## 7. D03：优化对比与人工应用

宽窗口双栏：左侧原文只读快照，右侧优化稿可编辑，下方显示少量变化说明。窄窗口改为上下排列。

默认突出“优化”；扩写、简化、翻译、双语和风格改写放在单一操作菜单。风格改写由用户选择，不得把普通润色擅自变成新风格。

底部“取消”“应用优化结果”。支持保存为我的提示词，但保存不等于应用，应用也不等于生成。

保护明确文字、数量、尺寸、主体和排除项。用“优化添加的建议”区别原要求与模型补充，避免未经用户选择就做创意替换。

异步返回时核对原输入的修订号：用户已改过正文，显示“输入已更新，请核对后应用”，不能直接覆盖最新输入。关闭弹窗不会自动应用。

## 8. P02：提示词中心

### 8.1 参考提示词

顶部切换“参考提示词／我的提示词／常用风格”；左侧或顶部提供中文搜索、来源与标签筛选，主区域为预览卡片。详情用抽屉展示中文、原文、来源、更新时间和使用动作。

中文标题、标签、说明与正文应能检索。翻译未完成或失败时显示实际状态及原文，不显示虚假的“已中文化”。来源封面加载失败用占位图，不阻塞文本使用。

应用到输入框时不自动带入版权未知的示例参考图；只在用户主动选择且来源使用条件允许时导入相应参考素材。

刷新显示“来源更新时间”和“上次同步成功时间”两个概念；失败继续使用缓存，不能清空库。用户副本与历史版本不跟随上游被改写。

### 8.2 我的提示词

支持新建、编辑、删除、收藏、分组和标签。来源标识区分“自己编写／图片反推／优化另存／参考另存”。

保存时名称必填，正文非空；已有分组和编辑能力优先复用。编辑同一个个人条目会影响它在其他入口的展示，不能暗中复制成多个同名条目。

现有项目已经有 `promptLibraryStore.cjs`，包含条目、分组与收藏等基础能力，新增设计应以此为兼容对象，而非假设是从零建立库。[S5]

### 8.3 常用风格

风格卡片显示名称、简要风格、比例与用途。编辑表单只放已确认字段，不扩展成复杂模板制作器。

应用前简要展示将追加的风格和将调整的参数；默认保留主体描述与参考图。渠道已变化、参数不支持时提示失效项，不悄悄传送无效参数或切换收费渠道。

## 9. P03：作品与版本

网格卡片显示缩略图、名称或默认标题、时间、生成方式和收藏。筛选按已记录元数据生效，不通过文件名猜测“局部修改过”或“可导出 PSD”。

详情抽屉展示大图、实际提示词、参考图缩略图、模型与输出尺寸、父子版本。版本用列表或缩略图序列，不做节点连线图。

“删除”确认说明删除对象；父版本被删除后，保留子版本仍需的来源元信息／资产引用。无需为了删除一张图把整条创作链删掉。

正在运行任务的资产不执行物理删除；取消与清理依据任务实际状态处理。文件丢失时提示“本地文件不可用”，不能伪显示可正常下载。

## 10. D07：PSD 拆层与导出

流程分成三个可理解的状态：“拆分图层”→“检查图层”→“导出 PSD”。

拆层前显示原尺寸和可用服务；拆层后显示实际尺寸、层数、合成预览与各层缩略图。可以切换图层可见性以检查内容，不扩展为完整专业图层编辑器。

Qwen-Image-Layered 可作为图片拆分为 RGBA 图层的候选；其官方示例含具体分辨率档位，不能从这一事实推导“任意高清图无损分层”。[S7]

`ag-psd` 可作为 PSD 写入候选，但其文档说明 RGB 写入、文字层及其他功能有支持边界；因此默认描述为像素分层，不承诺 CMYK、可编辑文字或完整工程恢复。[S8]

固定提示：“导出的是像素分层 PSD，画面中的文字不一定可以直接改字。请检查尺寸、图层边缘和合成效果。”

拆层能力未配置时允许明确显示“需配置拆层服务”，不假造成功。开发期间这种状态可用于测试异常交互，但不能据此宣布 v1.8.0 PSD 功能通过验收。

## 11. 状态清单

| 状态编号 | 场景 | 用户看到什么 | 可执行操作／保护 |
| --- | --- | --- | --- |
| S01 | 未配置必要模型 | 说明缺少哪类能力 | 前往现有设置；保留草稿 |
| S02 | 上传不支持／超限 | 指明格式、尺寸或数量原因 | 调整或更换文件；不静默裁掉输入 |
| S03 | 排队／生成 | 真实阶段和已完成数量 | 切换页面不丢任务；不显示虚假百分比 |
| S04 | 部分成功 | 如“已生成 2 张，1 张失败” | 使用成功结果；明确重试失败项 |
| S05 | 计费结果不明 | “请求结果待确认” | 优先查询原任务；不自动重提计费请求 |
| S06 | 取消请求 | “正在取消”或“已停止本地等待” | 不承诺上游必然停止或不计费 |
| S07 | 重启恢复 | 已落盘结果恢复；未确认任务显示状态 | 不把中断任务一律重新生图 |
| S08 | 提示词更新失败 | 上次成功时间＋失败原因 | 继续缓存使用，稍后手动重试 |
| S09 | 优化结果过期 | 提醒输入已更新 | 对比后应用，不能覆盖新输入 |
| S10 | 拆层失败／分辨率变化 | 具体问题与尺寸差异 | 保留原图和已有层；不导出假分层 |
| S11 | 导出失败／磁盘不足 | 可理解的文件错误 | 保留作品；清理不完整临时文件 |
| S12 | 删除影响引用 | 说明保留哪些来源关联 | 用户确认后执行，不破坏子版本 |

这些状态是既有功能的必要容错，不是新工具入口。

## 12. 响应式与可访问性

以当前应用可用窗口范围为准，不为本功能擅自修改全局最小窗口尺寸。

建议视觉检查档位：1440×900、1280×800，以及应用实际支持的更窄尺寸。宽度不足以同时容纳输入和结果时改为上下区，不压缩到按钮不可读。弹窗限制在视口内并内部滚动；右侧详情改为覆盖抽屉。

测试 Windows 100%、125%、150% 显示缩放与中文长标签。检查焦点顺序、按钮可读名称、对话框关闭后的焦点恢复和 Esc 行为。正在运行任务时 Esc 只关闭对话框还是取消任务须明确，不得暗中取消。

只在编辑图像时使用绘制画布；关闭专业模式不等于禁止实现局部涂抹所需的 HTML canvas。
