# 0. 修订记录

## Revision 2（2026-08-25）

补充提示词仓库与 Jato Agent 输入框之间的强制主操作：

- 提示词仓库弹窗底部右侧必须显示蓝色主按钮“插入到输入框”；
- 点击后先立即保存当前编辑器最新草稿，再插入 Jato Agent 输入框；
- 插入后关闭弹窗、焦点返回输入框，但不自动发送；
- 保存失败时不关闭、不插入且不得丢失草稿；
- 插入结果继续受 10000 字符与自动 TXT 附件规则约束。

# 1. 文档目的

本文档用于定义 **OpenJatoBID v1.7.1** 的二次开发范围：在“对话模式”中新增 **提示词仓库** 能力，作为 Jato Agent 工作流中的高频便捷生产工具。本文档偏技术规格，明确产品行为、数据结构、Main/Renderer 分工、IPC 契约、数据库迁移、文件导入、编辑保存、撤销能力、验收标准与测试范围，供后续 Plan / Build 阶段直接落地。

---

# 2. 一句话定义

提示词仓库是对话模式中的一个可弹出的、可分组管理、可导入、可编辑、可实时保存、可插入输入框的提示词资产管理器，用于沉淀并复用高质量提示词，提升对话生成效率。

# 6. 用户故事

## 6.1 用户故事 1：快速复用常用提示词

作为对话模式用户，我希望在输入框附近直接打开提示词仓库，选择一个常用提示词并插入输入框，这样我不需要每次重新手写相同提示语。

## 6.2 用户故事 2：按分组管理提示词

作为重度用户，我希望把提示词按“通用”“投标文件分析”“技术方案撰写”“项目管理”等分组整理，方便后续快速查找。

## 6.3 用户故事 3：批量导入历史提示词资产

作为产品经理 / 运营人员，我希望把过去积累的多个 Word、TXT、Markdown 文档批量导入系统，每个文件自动变成一条提示词，减少手工复制粘贴。

## 6.4 用户故事 4：边编辑边保存

作为维护提示词的用户，我希望在右侧内容区修改文本后系统自动保存，不需要每次手动点保存。

## 6.5 用户故事 5：可以撤销编辑

作为维护提示词的用户，我希望误删内容后能撤销，避免实时保存把错误立即写死。

# 8. UI 与交互规格

# 8.1 主界面入口按钮

## 8.1.1 位置

位于 `ConversationComposer` 区域底部工具栏，紧邻“添加附件”按钮，位于发送区域左侧。

## 8.1.2 组成

- SVG 图标；
- 文案：“提示词库”；
- 普通状态；
- Hover 状态；
- Active 状态；
- Disabled 状态（仅在极端异常场景使用，例如数据库未就绪）。

## 8.1.3 点击行为

点击后打开 **提示词仓库弹窗**。

规则：

- 打开时不离开当前对话线程；
- 不清空输入框；
- 不影响当前已选附件；
- 不中断 Jato Agent 正在生成的任务；
- 如果生成中，仍允许打开仓库，仅禁止“插入并立即发送”类行为（本版不做立即发送，因此无冲突）。

---

# 8.2 提示词仓库主弹窗

## 8.2.1 弹窗形式

- 形式：居中大尺寸弹窗 / 窗口内模态层；
- 宽度建议：980px–1120px；
- 高度建议：620px–720px；
- 背后工作台可见但不可点击；
- Esc 可关闭；
- 点击右上角关闭按钮可关闭；
- 未保存风险：由于采用实时保存，因此关闭时不弹“是否保存”确认。

## 8.2.2 结构

### 左侧栏

1. 搜索框；
2. 新建分组按钮；
3. 导入提示词按钮（下拉：单个导入 / 批量导入）；
4. 提示词分组树；
5. 分组内提示词列表；
6. 底部“新建提示词”按钮。

### 右侧编辑区

1. 提示词标题；
2. 标题旁编辑图标；
3. 标签 / 分组标识；
4. 操作栏：撤销、重做、更多；
5. Markdown 风格文本编辑器；
6. 底部状态栏：自动保存状态 / 字数；
7. 弹窗底部固定操作栏：次按钮“关闭” + 主按钮“插入到输入框”。“插入到输入框”是 v1.7.1 必备主操作，不得省略、隐藏到更多菜单或仅保留为内部能力。

## 8.2.3 关闭规则

- 若当前处于导入中流程，不允许直接关闭主弹窗而不提示；
- 若只是普通浏览或编辑，可直接关闭；
- 关闭时保留当前会话输入框内容。

## 8.2.4 “插入到输入框”主按钮（强制）

### 位置与样式

- 固定显示在提示词仓库弹窗底部右侧；
- 位于“关闭”按钮右侧；
- 使用蓝色主按钮样式；
- 按钮文案固定为：`插入到输入框`；
- 不使用“导入”作为按钮文案，避免与文件导入提示词功能混淆；
- 在弹窗滚动时保持可见，不随右侧正文编辑区滚出可视区域。

### 启用条件

仅当同时满足以下条件时按钮可点击：

1. 已选中一条有效提示词；
2. 当前提示词正文去除首尾空白后不为空；
3. 当前不处于提示词导入提交阶段；
4. 当前提示词不存在正在处理且无法提交的保存错误。

以下状态按钮禁用：

- 未选中提示词；
- 提示词正文为空；
- 当前提示词已被删除；
- 正在执行批量导入提交；
- Main 侧提示词服务不可用。

禁用时应通过 Tooltip 或按钮附近提示说明原因。

### 点击流程

用户点击后按以下顺序执行：

1. 获取右侧编辑器中的**最新草稿内容**，不得只读取数据库中可能滞后的旧版本；
2. 立即取消尚未触发的 800ms 防抖定时器；
3. 立即向 Main 提交一次保存；
4. 保存成功后，将最新提示词正文传给 ConversationComposer；
5. 按 8.4.2 的光标插入规则写入 Jato Agent 输入框；
6. 插入成功后关闭提示词仓库；
7. 焦点返回 Jato Agent 输入框；
8. 不自动发送消息，不自动启动 Agent 任务。

若立即保存失败：

- 不关闭弹窗；
- 不执行插入；
- 保留编辑器中的完整最新草稿；
- 显示“提示词保存失败，未插入输入框，请重试”。

### 字符上限联动

插入后的完整输入框内容如果超过 10000 个用户可见字符，继续执行 v1.7.0 已确认的超长文本处理规则：

- 将完整输入框内容转换为 UTF-8 TXT 附件；
- 转换成功后清空输入框；
- 不自动发送；
- 转换失败时保留完整输入框内容。

# 8.3 左侧分组 / 列表区规格

## 8.3.1 搜索框

支持搜索以下字段：

- 提示词标题；
- 分组名称；
- 提示词正文（模糊匹配，首版可选；如果正文全文检索成本较高，可先只搜标题和分组名）。

推荐首版最低实现：

- 标题匹配；
- 分组名匹配。

## 8.3.2 分组展示

每个分组显示：

- 分组图标；
- 分组名称；
- 该分组提示词数量；
- 展开 / 收起状态。

## 8.3.3 提示词列表项

每条提示词显示：

- 标题；
- 可选摘要（首版可不显示）；
- 选中状态；
- Hover 状态；
- 更多菜单（重命名、删除、移动分组，可放后续版本，首版至少支持删除）。

## 8.3.4 默认分组建议

首版初始化时可创建以下默认分组：

1. 通用提示词；
2. 招投标分析；
3. 技术方案编写；
4. 项目管理；
5. 商务方案；
6. 模板类提示词。

若用户不希望预置太多，可只初始化一个“通用提示词”，其余由用户手动创建。建议在 Spec 中定义为：

- 首次初始化默认至少创建：`通用提示词`。
- 其余分组由用户手动创建。

# 8.4 ConversationComposer（更新）

## 8.4.1 职责扩展

在 v1.7.0 基础上新增：

- “提示词库”按钮；
- 接收插入的提示词文本；
- 将提示词文本插入输入框。

## 8.4.2 插入规则

当用户在仓库中点击“插入输入框”时：

### 方案规则（本版采用）

- 如果输入框为空：直接填入提示词全文；
- 如果输入框已有内容：
  - 默认插入到光标位置；
  - 若无法可靠获得光标位置，则追加到文本末尾，并在前面补一个空行。

最终推荐规则：

1. 优先插入到光标位置；
2. 若编辑器状态无法获取光标，则追加到末尾；
3. 插入后不自动发送；
4. 插入后关闭提示词仓库弹窗；
5. 焦点返回输入框。

## 8.4.3 10000 字符上限兼容

若插入提示词后导致输入框内容超过 10000 字符，则沿用 v1.7.0 已确认规则：

- 自动把完整输入框内容转换为 TXT 附件；
- 清空输入框；
- 将插入内容保存在自动 TXT 中；
- 不自动发送。

# 9. 新建分组弹窗

## 9.1 目标

创建新的提示词分组。

## 9.2 字段

1. 分组名称（必填）
2. 分组描述（可选）
3. 分组图标（可选，首版可提供预设色块 / 图标，不支持自定义上传）

## 9.3 校验规则

- 分组名称不能为空；
- 去除首尾空格后长度 1–30 个字符；
- 同级分组名称不可完全重复；
- 保留名称如“全部提示词”“回收站”不可占用。

## 9.4 创建结果

- 创建成功后立即出现在左侧列表；
- 可直接成为当前选中分组；
- 支持随后在该分组下创建提示词。

# 10. 新建提示词

## 10.1 入口

- 左侧底部“新建提示词”按钮；
- 或分组更多菜单里的“新建提示词”。

## 10.2 默认行为

点击后：

1. 在当前选中分组下创建一条空白提示词；
2. 默认标题：`未命名提示词`；
3. 默认正文为空；
4. 右侧立即进入编辑状态；
5. 用户修改标题或正文后触发自动保存。

## 10.3 空内容规则

允许创建空白提示词，但若用户关闭后仍为空：

- 标题若未改，保持 `未命名提示词`；
- 正文为空不报错。

# 11. 提示词编辑区

## 11.1 展示内容

右侧编辑区至少展示：

- 标题；
- 分组信息；
- 正文编辑区；
- 自动保存状态；
- 字符数。

## 11.2 编辑能力

支持：

- 纯文本输入；
- 粘贴；
- 多段落；
- Markdown 原文编辑；
- 基础快捷键。

首版不强制做富文本所见即所得；更推荐使用 **Markdown 文本编辑模式**，这样更轻、更稳定，也与对话模式本身兼容。

## 11.3 标题编辑

- 标题默认可点图标后编辑；
- 回车确认；
- 失焦自动保存；
- 空标题时恢复为 `未命名提示词`。

## 11.4 实时保存规则

### 保存时机

- 标题修改后失焦保存；
- 正文输入 800ms 防抖后自动保存；
- 切换到其他提示词前自动提交未保存内容；
- 关闭弹窗前自动提交未保存内容；
- 撤销 / 重做不要求每个字符立即写库，仍走防抖保存。

### 保存提示

状态栏显示：

- `正在保存...`
- `已保存`
- `保存失败`
- `最后保存于 HH:mm:ss`

### 技术要求

- 保存动作由 Main 进程执行；
- Renderer 不直接操作 SQLite；
- 防抖保存期间，Renderer 内存中保留最新草稿；
- Main 返回失败时，不能丢失用户当前编辑内容；
- 可再次自动重试，或提示用户手动重试。

## 11.5 撤销 / 重做规则

用户要求“可以回撤”，v1.7.1 定义为：

1. 支持 **撤销（Undo）**；
2. 支持 **重做（Redo）**。

### 首版实现建议

- 采用编辑器本地历史栈；
- 只针对当前打开的提示词编辑内容有效；
- 不做跨提示词、跨会话的历史版本树；
- 不做数据库级别的时光机回滚。

### 交互

- 工具栏按钮：撤销 / 重做；
- 快捷键：
  - `Ctrl+Z`：撤销
  - `Ctrl+Y` 或 `Ctrl+Shift+Z`：重做

### 历史栈建议

- 记录最近 100 次编辑快照或操作步；
- 仅保存在 Renderer 内存中；
- 重新打开该提示词时，不恢复旧的撤销栈，只恢复最后一次保存结果。

# 12. 导入提示词

# 12.1 功能目标

将已有文档快速导入为提示词条目。

## 12.1.1 导入原则

- **一个文档 = 一个提示词**；
- 文档正文解析后成为提示词正文；
- 文件名默认作为提示词标题；
- 用户可在导入前修改标题和归属分组；
- 支持单个导入和批量导入。

## 12.1.2 支持格式

至少支持：

- `.md`
- `.markdown`
- `.txt`
- `.doc`
- `.docx`
- `.wps`（如现有解析链已支持则纳入）

若现有 `fileService` 已对更多格式可解析，可不在 v1.7.1 主规格中开放，以免扩大范围。首版对外声明只支持：

- Markdown
- TXT
- Word 文档

## 12.1.3 解析底座

复用现有：

- `fileService.cjs`
- `parseDocumentWithConfig(app, filePath, config, options)`

不重新开发新的文档解析器。

---

# 12.2 单个导入

## 流程

1. 点击“导入提示词”下拉菜单中的“单个导入”；
2. 打开文件选择框；
3. 选择单个文件；
4. Main 解析文件；
5. 创建一条提示词；
6. 默认标题为去后缀文件名；
7. 默认放入当前选中分组；
8. 导入完成后右侧自动打开该提示词。

## 异常

- 文件不支持：提示失败；
- 文件解析为空：提示失败；
- 文件过大：提示失败；
- 存储失败：提示失败；
- 当前文件名重复：允许导入，但自动标题可以重复，或在同分组下做“（1）”后缀。

建议规则：同一分组下标题允许重复，但 UI 提示用户可手动重命名。

---

# 12.3 批量导入

## 12.3.1 流程

1. 点击“导入提示词”下拉菜单中的“批量导入”；
2. 打开批量导入弹窗；
3. 选择多个文件；
4. 系统逐个解析；
5. 生成预览列表；
6. 每一行指定目标分组；
7. 用户确认后点击“开始导入”；
8. 成功后逐条写入提示词库；
9. 弹出导入结果。

## 12.3.2 批量导入弹窗字段

每一行至少包含：

- 文件名；
- 预览内容（前 100 字）；
- 目标分组；
- 状态；
- 操作（删除本行）。

## 12.3.3 状态值

- 待导入；
- 解析中；
- 可导入；
- 导入成功；
- 导入失败。

## 12.3.4 批量导入规则

- 一次批量建议最多 50 个文件；
- 超过 50 个可提示分批导入；
- 同名文件允许；
- 导入过程中失败的项目不影响成功项目；
- 结束后给出：成功数 / 失败数 / 原因摘要。

## 12.3.5 导入模板下载

高保真图中保留“下载导入模板”入口。

首版可提供一个说明文档或样例压缩包，作用是帮助用户理解：

- 一个文档就是一个提示词；
- 推荐文件命名规则；
- 推荐正文结构。

注意：这里的“模板下载”是说明性辅助，不是强制依赖导入的 Excel 模板。

# 13. 数据模型设计

本功能建议在现有 SQLite 工作区数据库基础上新增三张表，版本从 v22 升级到 **v23**。

## 13.1 prompt_groups

```sql
CREATE TABLE IF NOT EXISTS prompt_groups (
  group_id TEXT PRIMARY KEY,
  group_name TEXT NOT NULL,
  description TEXT NOT NULL DEFAULT '',
  icon_key TEXT NOT NULL DEFAULT 'folder',
  sort_order INTEGER NOT NULL DEFAULT 0,
  is_system INTEGER NOT NULL DEFAULT 0,
  created_at TEXT NOT NULL,
  updated_at TEXT NOT NULL,
  deleted_at TEXT
);

CREATE INDEX IF NOT EXISTS idx_prompt_groups_sort
ON prompt_groups(sort_order, updated_at DESC);

CREATE INDEX IF NOT EXISTS idx_prompt_groups_name
ON prompt_groups(group_name);
```

## 13.2 prompt_items

```sql
CREATE TABLE IF NOT EXISTS prompt_items (
  prompt_id TEXT PRIMARY KEY,
  group_id TEXT NOT NULL,
  title TEXT NOT NULL,
  content_markdown TEXT NOT NULL DEFAULT '',
  source TEXT NOT NULL DEFAULT 'manual',
  source_file_name TEXT,
  content_chars INTEGER NOT NULL DEFAULT 0,
  is_favorite INTEGER NOT NULL DEFAULT 0,
  last_used_at TEXT,
  sort_order INTEGER NOT NULL DEFAULT 0,
  created_at TEXT NOT NULL,
  updated_at TEXT NOT NULL,
  deleted_at TEXT,
  FOREIGN KEY (group_id) REFERENCES prompt_groups(group_id)
);

CREATE INDEX IF NOT EXISTS idx_prompt_items_group_sort
ON prompt_items(group_id, sort_order, updated_at DESC);

CREATE INDEX IF NOT EXISTS idx_prompt_items_title
ON prompt_items(title);
```

## 13.3 prompt_import_jobs

用于记录导入结果和恢复状态（首版可选，但强烈建议保留，便于问题排查与进度展示）。

```sql
CREATE TABLE IF NOT EXISTS prompt_import_jobs (
  job_id TEXT PRIMARY KEY,
  mode TEXT NOT NULL,
  total_count INTEGER NOT NULL DEFAULT 0,
  success_count INTEGER NOT NULL DEFAULT 0,
  failed_count INTEGER NOT NULL DEFAULT 0,
  status TEXT NOT NULL DEFAULT 'pending',
  result_json TEXT,
  created_at TEXT NOT NULL,
  completed_at TEXT
);
```

> 若想进一步轻量化，也可以不建 `prompt_import_jobs`，仅在导入流程中以内存态处理。但从技术规格角度，建议保留。

# 14. 数据字段约束

## 14.1 group_id / prompt_id / job_id

- 使用 UUID；
- 由 Main 进程生成；
- Renderer 不自行伪造业务主键。

## 14.2 source 字段

`prompt_items.source` 枚举值：

- `manual`：手动创建；
- `single-import`：单个导入；
- `batch-import`：批量导入。

## 14.3 删除策略

首版采用 **软删除**：

- `deleted_at IS NULL` 表示有效；
- 删除后默认不显示；
- 预留后续“回收站”能力。

若用户期望即时永久删除，也可在 UI 表现为“删除”，但数据库仍建议软删除。

# 19. 文件导入规则

## 19.1 文件大小建议

首版建议限制：

- 单文件最大 20MB；
- 批量最多 50 文件；
- 单次批量总量最大 200MB。

原因：

- 提示词正文通常较短；
- 过大文档不适合作为提示词；
- 能避免 Word/PDF 大文档误导入后拖慢界面。

## 19.2 标题生成规则

默认标题使用：

- 文件名去扩展名；
- 去除首尾空格；
- 截断为 100 个字符内。

## 19.3 正文生成规则

正文内容为解析结果的纯文本 / Markdown：

- 保留标题和段落；
- 保留 Markdown 结构；
- 去除图片；
- 去除空白尾部。

## 19.4 预览摘要规则

批量导入列表中的“预览内容”显示：

- 正文前 100 个字符；
- 连续空白折叠为单空格；
- 换行折叠为可读分隔。

# 20. 插入输入框规则

## 20.1 强制入口

提示词仓库弹窗底部右侧必须始终提供主按钮：`插入到输入框`。

该按钮是提示词仓库与 Jato Agent 对话链路之间的核心连接能力，不属于可选功能，不得：

- 仅存在于右键菜单；
- 仅存在于更多菜单；
- 依赖双击提示词；
- 以复制到剪贴板替代；
- 仅实现内部接口而不提供可见按钮。

## 20.2 默认插入动作

点击“插入到输入框”时：

1. 取右侧编辑器中的当前最新正文；
2. 立即提交尚未保存的最新草稿；
3. 保存成功后插入到 ConversationComposer；
4. 若正文为空，按钮保持禁用，并提示“提示词内容为空，无法插入”；
5. 插入成功后关闭弹窗；
6. 焦点回到输入框；
7. 不自动发送。

## 20.3 不自动发送

v1.7.1 明确：

- 插入提示词 ≠ 发送消息；
- 用户仍需手动点击发送。

## 20.4 兼容已有文本

- 若输入框为空：直接填入；
- 若输入框已有文本：优先插入光标处；
- 无法获取光标时追加到末尾，前置 1 个空行。

# 22. 错误与边界处理

## 22.1 空库状态

当没有任何提示词时：

- 左侧显示空状态；
- 引导用户“新建提示词”或“导入提示词”。

## 22.2 删除当前选中提示词

- 删除后右侧切到最近一条可用提示词；
- 若已无可用提示词，则右侧显示空状态。

## 22.3 删除含提示词的分组

首版建议规则：

- 不允许直接删除非空分组；
- 提示用户先移动或删除分组内提示词。

如果要做“连同提示词一起删除”，风险较高，不建议首版采用。

## 22.4 保存失败

- UI 保留当前草稿；
- 显示“保存失败”；
- 自动重试一次；
- 若仍失败，允许用户继续编辑，但提示尚未保存到本地数据库。

## 22.5 批量导入中断

- 已成功写入的不回滚；
- 未写入的不创建；
- 最终返回成功 / 失败统计。

7. 不影响知识库、标书生成、模板设置等其他一级模块；

# 24. 埋点与隐私边界

如需接入埋点，只允许记录轻量行为，不得记录提示词正文全文。

允许记录：

- 打开提示词库；
- 新建提示词；
- 新建分组；
- 导入条数；
- 插入输入框次数。

禁止记录：

- 提示词完整正文；
- 导入文件原文；
- 本地路径；
- 用户输入中的大段文本。

首版即使不加埋点，也要在 Spec 中明确这些边界。

5. 没有撤销能力却宣称支持“回撤”；
6. 插入提示词后自动发送消息；
7. 导入多个文件却把多个文件拼成一条提示词；
8. 重新开发一套独立文档解析器而不复用现有 `fileService`；
9. 删除非空分组时直接连带删除所有提示词而不给确认或限制；
10. 把提示词正文上报到 Analytics；
11. 只实现插入接口但不在提示词仓库底部提供明确可见的“插入到输入框”主按钮；
12. 使用数据库旧内容覆盖编辑器最新草稿后再插入。
