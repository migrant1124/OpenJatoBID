# v1.8.2 配置说明

## 员工端

在“设置 → 生图模型”选择金龙中转站并填写 API Key，保存后生图模式直接读取该渠道档案的 Key；创作页没有 Key 输入框。设置当前切到其他渠道时，生图模式仍只读取已保存的金龙 Key，不会将其他渠道 Key 发送到金龙接口。GPT Image 系列使用固定 Base URL `https://img-api.jlaudeapi.com/v1`；两个 Nano 根据金龙公开模型页改走 `https://jlaudeapi.com/v1beta/models/{原样模型ID}:generateContent`，沿用同一金龙 Key。配置状态只表示是否已填写，不代表连通。文本模型继续在原设置中配置，仅优化提示词和反推需要；普通生图不依赖文本 Key。

模型下拉只显示：`gpt-image-2`、`gpt-image-2-1k`、`gpt-image-2.5-sunburst`、`gpt-image-2.5-flare`、`Nano Banana Pro`、`Nano Banana 2`。两个 Nano 保留大小写及单个半角空格。四个 GPT Image 型号沿用现有金龙图片适配器；两个 Nano 使用 Gemini `generateContent` 请求体，参考图作为 `inlineData` 传入。GPT Image 2 还沿用已有局部/PSD 编辑适配，其他型号的局部/PSD 编辑仍未开放。Nano 的尺寸选择映射到该接口的 1K/2K 和最接近的支持比例，返回像素可能与界面选择值不同。**本地仅验证请求与模拟响应，未执行真实收费出图**；公开接口说明和 Key 不能证明真实渠道已成功返回图片。

`gpt-image-2-1k` 的设置页请求方式固定显示并保存为“普通”；旧配置即使保存了“流式”，客户端也按该型号公开示例发送普通请求，不附加 `stream` 或 `response_format`；所选尺寸仍随请求发送。用户提供的金龙控制台记录证明此前流式请求渠道侧已出图，但客户端没有取到图片；新普通请求路径尚未真实复测。测试成功只表示收到可识别的图片 URL 或 Base64；仅返回任务 ID、状态或错误字段时不标记通过。若渠道有异步任务查询协议，仍需取得该渠道的实际响应和查询文档后接入。

“参考案例优化”默认使用内置 YouMind 知识。离线时索引可用，但文本模型请求仍需网络。当前未配置在线分发地址，因此“立即检查更新”只查上游提交；“导入离线知识包”只接受本轮公钥签名包。没有声明国内线路稳定。

维护者可在打包前设置 `client/electron/resources/image-studio-knowledge/distribution.json` 的 `packageUrl` 为实际受控、公开可访问的 HTTPS 签名知识包地址。当前为 `null`，因此在线只检查上游。配置后客户端对地址/跳转逐次校验，不访问内网，下载总量限制 35 MB，且只有与本次检查的上游提交匹配并通过签名/哈希/结构验证后才切换；该在线路径尚未实测，不能宣称已部署。

## 知识包维护者

- 固定上游归档：`client/electron/resources/image-studio-knowledge/upstream-c8072428.zip`；SHA-256 和计数见同目录 `manifest.json`。
- 制作脚本：`client/scripts/build-image-studio-knowledge.cjs`，使用项目现有 Node 与依赖运行。脚本只读取本地固定归档，不执行归档内脚本。
- 签名公钥：`client/electron/resources/image-studio-knowledge/trust-public.pem`。私钥仅位于本机 Git 忽略的 `.tmp/image-studio-knowledge-private.pem`，**不在仓库或安装包中**；须由维护者单独安全备份，否则未来新包无法沿用当前信任链。生产轮换需同步客户端公钥及明确迁移策略。
- 离线分发物：`knowledge-package.zip`。它包含清单、规范化数据、许可证、签名，不含 API Key、员工数据或可执行脚本。
- 每次更新先固定上游提交、核对许可证与清单计数，生成签名包，完成导入/回滚测试，再独立分发；本轮没有发布或上传。

模型截图只能证明请求 ID，不证明接口协议成功。真实计费测试须另获额度授权，记录型号、参数、实际响应、耗时和费用。
