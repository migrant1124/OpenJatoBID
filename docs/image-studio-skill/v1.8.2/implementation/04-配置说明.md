# v1.8.2 配置说明

## 员工端

进入“生图模式”后，在“金龙中转站 · 配置密钥”输入本机专用 API Key。固定 Base URL 为 `https://img-api.jlaudeapi.com/v1`；保存不调用付费图像接口。状态只表示是否已填写，不代表连通。文本模型继续在原设置中配置，仅优化提示词和反推需要；普通生图不依赖文本 Key。

模型下拉严格为：`gpt-image-2`、`gpt-image-2-1k`、`gpt-image-2.5-sunburst`、`gpt-image-2.5-flare`、`Nano Banana Pro`、`Nano Banana 2`。两个 Nano 保留大小写及单个半角空格，**已确认的是金龙请求 ID**；它们及 1K 渠道版当前可选择和用于优化上下文，但因调用能力未核实而阻断生成。GPT Image 2 沿用已有文生图/参考图/编辑适配，Sunburst、Flare 当前仅放行文生图；真实权限、尺寸、参考数量及画质仍待渠道验证。

“参考案例优化”默认使用内置 YouMind 知识。离线时索引可用，但文本模型请求仍需网络。当前未配置在线分发地址，因此“立即检查更新”只查上游提交；“导入离线知识包”只接受本轮公钥签名包。没有声明国内线路稳定。

维护者可在打包前设置 `client/electron/resources/image-studio-knowledge/distribution.json` 的 `packageUrl` 为实际受控、公开可访问的 HTTPS 签名知识包地址。当前为 `null`，因此在线只检查上游。配置后客户端对地址/跳转逐次校验，不访问内网，下载总量限制 35 MB，且只有与本次检查的上游提交匹配并通过签名/哈希/结构验证后才切换；该在线路径尚未实测，不能宣称已部署。

## 知识包维护者

- 固定上游归档：`client/electron/resources/image-studio-knowledge/upstream-c8072428.zip`；SHA-256 和计数见同目录 `manifest.json`。
- 制作脚本：`client/scripts/build-image-studio-knowledge.cjs`，使用项目现有 Node 与依赖运行。脚本只读取本地固定归档，不执行归档内脚本。
- 签名公钥：`client/electron/resources/image-studio-knowledge/trust-public.pem`。私钥仅位于本机 Git 忽略的 `.tmp/image-studio-knowledge-private.pem`，**不在仓库或安装包中**；须由维护者单独安全备份，否则未来新包无法沿用当前信任链。生产轮换需同步客户端公钥及明确迁移策略。
- 离线分发物：`knowledge-package.zip`。它包含清单、规范化数据、许可证、签名，不含 API Key、员工数据或可执行脚本。
- 每次更新先固定上游提交、核对许可证与清单计数，生成签名包，完成导入/回滚测试，再独立分发；本轮没有发布或上传。

模型截图只能证明请求 ID，不证明接口协议成功。真实计费测试须另获额度授权，记录型号、参数、实际响应、耗时和费用。
