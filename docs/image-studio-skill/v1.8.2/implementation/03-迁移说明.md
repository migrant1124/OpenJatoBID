# v1.8.2 迁移说明

1. 客户端 `package.json` 与锁文件根版本为 `1.8.2`；管理端版本及发布清单未改。登录、关于和打包沿用客户端 `app.getVersion()` / package 统一版本源。
2. 工作区 SQLite 从 v38 增至 v39，新增 `image_studio_requests(feature, request_id, input_fingerprint, task_id, created_at)`，其中 `(feature, request_id)` 唯一。普通/参考/局部生图使用 `image-studio`，PSD 补全使用 `image-studio-psd`；同 ID 同输入返回既有任务，异输入报冲突。已发送而未得到可信结果的任务保持 `unknown`，不会自动重发。
3. 旧 `image_studio_risk_checks` 表保留历史内容；新流程不读写该表，不恢复旧待确认任务。旧风险确认弹窗/接口已移除。数据库迁移沿用项目原有备份流程；`sql/workspace_schema.sql` 已同步。
4. 生图模式读取设置中 `image_model_profiles.jinlong.api_key` 对应的金龙生图 Key；设置当前选中其他渠道时，也只读取已保存的金龙档案，不复制其他渠道 Key。创作页不再保存独立 Key。此前版本若已产生 `userData/image-studio-jinlong-key.bin`，该文件不再读取；本轮不自动删除用户文件或改写旧配置。个人提示词库不受影响。
5. 内置知识资源位于应用 `electron/resources/image-studio-knowledge/`，可写导入版本位于用户 `userData/image-studio-knowledge/`。导入先校验签名、格式、字节数、哈希和条目，再写 staging 目录并切换 `current.json`。失败继续使用旧快照。清除 `current.json` 可回到随包快照；请先备份用户数据再手工处理。
6. 未建立在线签名包分发端点，当前 `distribution.json` 的 URL 为 null，因此每周/手动操作只检查上游提交；要应用新版需维护者制作签名包并离线导入，或以后配置受控 HTTPS 分发地址。不可直接将任意上游 ZIP 当可导入签名包。

本轮使用隔离 `userData` 做原生迁移/读取烟测，没有对正在使用的真实用户数据执行探针或迁移验证。正式安装后的数据备份、回滚与 Windows 用户环境验证仍待验收。
