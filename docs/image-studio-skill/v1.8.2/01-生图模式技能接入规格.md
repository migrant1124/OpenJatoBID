## 1. 目标与范围

### 1.1 一句话目标

让员工在原有生图页直接选择允许使用的模型，点击位于模型选择之后的“优化提示词”时自动借鉴相关案例；反推、保存和生成保持独立。知识每周检查更新，也能手动更新。减少人工找案例及来回进入设置的操作，不预先承诺节省秒数。

### 1.2 本轮明确改变的内容

| 编号 | 用户确认要求 | 实施边界 |
| --- | --- | --- |
| F01 | 反推和优化都保留 | 反推仍在输入框下方；优化移到模型选择右侧/后方，不保留重复按钮 |
| F02 | 选择模型前增加模型选择说明 | 短说明在模型控件上方；完整官网对比在弹窗内，不强制先阅读 |
| F03 | 生图页直接选模型 | 仅限本规格的 6 个项目；不写回其他模块的全局默认模型 |
| F04 | 用户自己填写 Key，默认金龙 Base URL | 在现有设置中填写，工作页只给轻量入口，不每个模型重复填 |
| F05 | 优化按钮使用 Skill 知识 | 本地相关案例 + 对应模型优化规则 + 一次改写；不运行多轮 Agent |
| F06 | 每周更新且可自助更新 | 复用提示词中心/管理来源，立即更新与离线包导入 |
| F07 | 取消上一轮图像生成预检风险评估 | 移除应用自建的生成前 LLM 风险评估、替代方案二次复核与相关强制弹窗 |
| F08 | 普通员工易用 | 不增加一级导航、技能选择面板、第二个模型下拉或强制案例选择步骤 |

**不在本轮新增** Seedream、其他未批准型号、模型失败后的自动切换、自动生图、强制联网搜索、自动付费模型评测、全量个人提示词参与其他客户创作。

### 1.3 本轮优先级

本规格中对按钮位置、模型范围和本地风险预评估移除的要求，覆盖此前对话和图稿的相反约定。旧的六宫格图和未核实模型对比图不得作为开发依据。

仅取消应用自建的风险预评估，不表示取消中转站/模型提供商的安全规则。不得自动改写被拒请求以规避审核，不得因被拒自动换模型重试。保留人工使用确认、来源标注、错误反馈和脱敏操作记录。

## 2. 已核查的现状

现有 `optimizePrompt()` 仅使用原文和 mode 调用一次 `aiService.chat()`，`noRetry: true`；优化结果在返回后展示。现有界面包含优化、反推、保存、撤销、最多 4 张参考图片、画幅/数量、独立生成按钮。[R1/R2]

现有来源服务已提供来源管理、数据库快照、哈希、失败保留、更新与中文化；需要扩展 YouMind 清单型适配，不能把仓库网址直接当现有数组 JSON 使用。[R4/Y2]

当前 `submit()` 绑定 `riskCheckId` 和风险表；移除风险评估不能只隐藏按钮，否则请求会被后台拦住。当前防重复的一部分依赖该表，必须以独立 requestId 替代。[R2]

现有 AI 请求统一经过 `aiService` 队列。流式解析目前聚合后返回，需增加增量回调，而不是在前端做打字动画。[R3/R5]

来源编号和原始地址见《05-官网来源与核实边界》。本交付是规格和设计，不是代码变更完成报告。

## 3. 用户故事与主流程

### US01 普通员工创作

作为员工，我输入需求、添加参考图，读到简短模型说明后直接选择模型；需要帮助时点击右侧“优化提示词”，确认结果后再点“生成图片”，不必理解 Skill、Agent 或检索配置。

### US02 从图片开始

作为员工，我可以选中受管图片，点击原有“反推提示词”，查看描述并应用；是否进一步优化、是否生图由我决定。反推不依赖所选生图模型，仍沿用现有文本/视觉配置。

### US03 已有满意提示词

作为员工，我从现有提示词库应用文字，选择模型后直接生成，不强制优化或打开案例。

### US04 更新知识

作为员工，我在提示词中心点击“更新知识”，软件检查并安装新知识；即使失败，我仍能用旧知识。我的收藏和自写提示词不被覆盖。

### US05 首次配置

作为员工，我只需在设置中填写自己的金龙 API Key。生成图片不因没有配置文本模型而被一项额外风险预评估阻挡；只有主动使用反推/优化等文字功能时才需要相应文本模型。

### US06 合规交付

作为员工，我可以在应用前审阅优化稿、撤销应用；图片用于对外材料前仍由人核对文字、商标、数据与版权。软件记录操作，不自动发布作品。

### 主流程

输入图片需求 → 可选反推/参考图 → 模型选择说明 → 选择本次模型 → 可选优化与人工应用 → 选择画幅/数量 → 独立点击生成 → 结果查看/下载/局部修改/分层。

优化不是生成前必经步骤。知识更新、模型说明查看也不阻塞主流程。

## 4. UI 合同：位置与交互

### 4.1 创作区从上到下的唯一顺序

1. 图片需求输入框，保持 10,000 字符业务上限。
2. 原工具行：`反推提示词`、`保存`、满足现有条件时显示 `撤销应用`。
3. 参考图片，保持主体/风格/构图/色彩用途和原有最多 4 张限制。
4. `模型选择说明`：两三行摘要和 `查看对比`。
5. `本次生图模型` 下拉框，**同一行右侧为 `优化提示词`**。
6. 轻量文字：`已自动匹配模型优化规则`，无需再选技能。
7. 原有图片画幅与生成张数。
8. 底部独立主按钮 `生成图片`，保留原来的生成动作。

宽度不足时：先完整显示模型下拉框，再在下一行显示“优化提示词”，视觉和键盘顺序不变。禁止把“优化提示词”移回输入框下、复制两份，或与“生成图片”合并成状态切换按钮。

### 4.2 外壳保护

保留现有标题栏、公司 Logo、一级 Tab、工作区和结果区，不根据旧概念图新增“工作台/资料库/我的图片”等导航。本包 UI 仅展示生图模块主内容区，未画部分沿用现有应用，不意味着删除。

### 4.3 模型说明

摘要固定文案：

> 精细修图可考虑 Sunburst；日常快速出图可考虑 Flare 或 Nano Banana 2；复杂图文与多图创作可考虑 Nano Banana Pro。

脚注：`根据官网定位整理，实际功能、费用和速度以金龙接口为准。`

这是场景建议，不是性能胜负榜。完整对比使用《05》的最终文案，来源按钮打开允许的 OpenAI/Google 官网。日常打开不发起网络请求，说明随核实后的应用资料更新；标注核实日期。

不再显示“Sunburst 艺术风格更强”“Flare 光影特效更强”“Nano Banana 文字比 GPT 差”。不显示猜测价格、积分、首图秒数。

### 4.4 优化弹窗

点击后立即打开现有对比弹窗。原文只读，右侧真实增量显示候选稿；完成且通过完整性检查后可编辑和应用。

保留现有方向：优化、扩写、简化、英文、双语、商业海报、产品摄影、写实、插画。更改方向不偷偷发请求；`重新优化` 才明确启动新操作。`参考案例优化` 默认开启，开关放在弹窗内，不扩展主界面表单。

显示当前生图模型和 `本次向 AI 提供 N 条参考案例`，案例详情默认折叠。不得把提供候选说成确定采纳。示例图按需加载，无图不阻塞优化。重新优化可以绕过结果缓存。

底部：`取消`、`重新优化`、`保存到我的提示词`、`应用到输入框`。过程中提供停止按钮；停止或失败不能把不完整结果标成成功。保存/应用均不生图。

提示词/参考图/角色/画幅/模型发生变化，当前候选标为过期，不能无提示应用。模态关闭需清理监听；请求取消尽量传至网络，不承诺提供方已停止计费。

### 4.5 反推弹窗

按钮保持可见，界面继续说明“根据图片生成参考描述，不代表原始提示词”。使用受管图像与现有文本/视觉模型；不改为调用所选生图模型。保存、应用、取消保持独立，允许进一步由用户点击优化。

### 4.6 Key 设置

复用现有设置页/弹窗。生图模式只显示 `金龙中转站 · 配置密钥` 链接；Key 未填时显示明确提示，不在创作页常驻完整连接表单。

Base URL 默认取已核查的金龙配置 `https://img-api.jlaudeapi.com/v1`。[R3] 不由网页说明静默覆盖用户之前保存的其他配置。新增的本模块配置明确选择金龙；非金龙旧 Key 不能自动复制到新地址。

同一金龙连接的六个模型共用用户自己填写的 Key。Main 层安全保存，Renderer 不接收已存明文，不写 localStorage、日志、Prompt、仓库或更新包。填写动作需将输入传递 Main，保存后清空输入；只返回是否已配置。使用项目已有安全存储；需要新增时采用系统凭据保护并记录迁移。

`保存` 不自动发收费请求。`刷新模型列表` 只调用目录接口，不能标为生图已验证。真实出图测试必须用户明确发起。

| --- | --- | --- | --- |
| gpt2 | GPT Image 2 | `gpt-image-2` | 有同名官方模型页 [O1] |
| gpt2_1k | GPT Image 2 · 1K 渠道版 | `gpt-image-2-1k` | 用户提供；未查到独立 OpenAI 模型页 |
| sunburst | GPT Image 2.5 Sunburst | `gpt-image-2.5-sunburst` | 有同名官方模型页 [O2] |
| flare | GPT Image 2.5 Flare | `gpt-image-2.5-flare` | 有同名官方模型页 [O3] |
| banana_pro | Nano Banana Pro | `Nano Banana Pro` | 用户于 2026-09-29 提供金龙模型列表截图确认；官方标识仅作资料，不用于替换路由 [U1] |
| banana2 | Nano Banana 2 | `Nano Banana 2` | 用户于 2026-09-29 提供金龙模型列表截图确认；官方标识仅作资料，不用于替换路由 [U1] |

**六个金龙请求 ID 均已由用户提供，当前不存在“两个 Nano 请求 ID 待核实”的缺项。** 请求中的型号字段必须逐字使用本表 `requestModelId`；尤其 `Nano Banana Pro` 与 `Nano Banana 2` 的英文大小写、单个半角空格均需保留。不要转小写、替换成连字符、添加 `-preview` 后缀，或自动改成 Google 的 `gemini-*` 官方标识。

截图里还有 Claude、Grok、DeepSeek、Dots、其他 Gemini 等型号，它们仅作为截图背景，不加入本轮六项白名单。截图蓝色高亮只说明截图当时选中了 `gpt-image-2-1k`，不作为更换应用默认型号的授权。

界面不再因“ID 未知”禁用 Nano 两项。**型号可被选择、渠道 ID 已确认、接口协议已实现、密钥有权限、真实请求已通过，是不同状态。** 截图不能证明全部接口能力或出图成功；参数、协议、权限、速度和费用仍需渠道资料及授权测试确认。尚缺少协议适配时可以提示“当前调用方式尚未配置”，不得再提示“模型 ID 未确认”。[U1]

### 5.2 模型清单获取

只将中转目录与批准的六个配置项匹配，不新增目录里的其他模型。不通过模糊字符串匹配判断文生图/参考图/蒙版能力。目录没有出现某 ID 并不证明模型不存在；目录接口不可用时保留已确认配置，显示目录状态未知。

白名单在 Main 二次校验。Renderer 只提交 modelKey，不能以任意 baseUrl/modelName 绕过范围。需要渠道 ID 映射时由受控配置承载，保留证据和修订。

### 5.3 两层能力说明

`官方模型能力`供员工阅读，`金龙已确认接口能力`供请求校验，两者不可混用。

每个路由记录 protocolAdapter、requestModelId、文生图/参考图/编辑支持状态、参考数量、尺寸/画幅、输出格式、质量档、蒙版方式、证据和核实日期。支持状态为 supported/unsupported/unknown；未知不得谎报支持。

GPT 优先复用现有金龙兼容图像调用；Gemini 在金龙上究竟使用 OpenAI 兼容图像、兼容 chat 还是 Gemini 原生协议，必须用真实渠道资料确认。不得绕过 aiService 自建 HTTP 客户端，也不得从金龙悄悄切到 Google 官方付费地址。

### 5.4 默认与作用域

进入工作区恢复本工作区上次选择；若不存在，优先继承当前已配置且属于批准范围的金龙型号；仍无可继承项时展示 GPT Image 2 为默认选择，但 Key/路由未就绪不得生成。没有用户同意不按“效果最好”自动切换。

选模型只影响生图模式，不能写回标书正文配图、对话模式或全局模型。配置和任务快照固定引用版本。

### 5.5 参数与编辑

本轮不擅自把应用的最多 4 张参考图提升到官网上限。实际限制为应用限制和渠道已确认限制的较小值。所选模型不兼容已有参考图、蒙版或画幅时，明确提示用户调整，禁止自动删图、裁图或放大/缩小原图冒充输出。

生成张数保留 1/2/4 的 UI；按适配器实际能力组织请求，记录每张实际返回数量及单张调用，不把“一次优化请求”误用为“一次批量生图请求”。部分成功保留结果，不自动重收费补图。

局部修改保持现有选区和非选区像素保护。无蒙版能力不能伪装可用。若所选模型不支持，提示用户主动选择支持项，不能自动切换。

PSD 对象识别等必要视觉请求不属于风险预评估，不删除。背景补全改为读取所选且已确认可编辑模型，不继续暗中硬编码另一型号；不支持时说明，保留既有图层。对象级分层质量门禁保持不变。

## 6. Skill 如何参与优化

### 6.1 产品定位

现有提示词中心让人主动查案例；新能力让优化器在点击时自动查案例。共用来源和条目，不新建一套普通用户提示词库。

安装的含义是：受控技能说明/规则纳入项目、案例数据和可用快照随客户端分发、优化服务显式调用知识模块。仅在开发机安装 Codex Skill 不算产品接入。

保留上游许可证、仓库 URL、固定提交和适配说明。原始 SKILL.md 归档为上游资料；运行时使用经项目审查的提示词规则，不执行它要求的下载脚本、shell、外部消息或强制多轮选图流程。[Y1–Y4]

### 6.2 最终在线路径

用户原文/方向/模型/参考图用途 → 有预算的本地检索 → 至多 3 条相关知识 → 一次改写请求 → 增量候选 → 完整性检查 → 人工应用。

不设置在线意图分析模型、远程 rerank、独立图片描述模型、自动 JSON 修复或多 Agent 往返。优化和反推分别由用户主动发起；禁止在优化背后额外调用反推。

### 6.3 检索与知识卡

复用本地数据库，新增全文检索与中英文检索字段（确认 FTS5 构建可用）。中文需要分词/检索片段处理、常用视觉同义词和字面否定条件处理，不把普通英文分词假设为中文语义理解。

分类动态读取，不硬编码上游分类数量。按上游原始 ID 去重，合并多分类；和既有来源按内容指纹识别重复，但不同变量/约束不能粗暴合并。公开案例与个人提示词隔离，个人库默认不自动参与跨任务检索。

候选至多 20 条，按相关性、模板适用条件、否定冲突、参考图要求和重复性筛到 0–3 条；不相关就不注入。少量可验证原文摘录与设计特征组成知识卡，原始全文另存。外部知识总预算建议不超过 1,200 模型 token，以当前 tokenizer 或保守估算记录；不通过截掉用户明确要求腾位置。

示例图不作为用户上传参考图，不默认送模型；缺图或 CDN 失败不影响文本检索。

### 6.4 参考图与模型适配

当前文本模型确认支持多模态时，把压缩预览和用途放进同一次优化请求。文件仍来自 Main 受管资产，限制尺寸/字节/像素，日志不存 base64。

不支持视觉输入时明确“本次未分析图片内容”，仅利用用户文字及用途；不自动换文本模型或再发一次请求。图片缺失应报错而非静默当成无图。

少量任务文字不足以检索时可不加案例，交由这一次多模态请求处理，而非为了检索额外识图。

模型规则分别为通用、GPT Image、Nano Banana；Sunburst/Flare 可有短的版本适配提示。仅写已确认的自然语言约束，不注入另一个模型的参数。尺寸和质量优先走接口参数，未知参数不猜。Seedream 不在本轮注册。

### 6.5 文风与约束

只改善构图、光线、空间、材质、表述和冗余；保留主体、数量、人物/商品身份、画幅、指定画面文字、否定条件、商标专名及模板变量。禁止把案例品牌、竞品名字、示例文字、宣传承诺带入用户稿。

用户指定内容与案例冲突时以用户为准，但系统/提供方限制始终有效。不能为了规避服务端拒绝删词或换同义词。优化不是安全通行证明。

“简化”不能变扩写；“英文/双语”忠实转换，不自动加新创意。没有匹配时标明普通优化，不伪造案例 ID。

### 6.6 缓存、流式与取消

缓存键包含原文、方向、模型及路由配置版本、参考图顺序/哈希/用途、尺寸、技能版本、知识版本、校验规则版本、所用文本模型指纹（不含明文密钥）。匹配所有条件才复用；明确重新优化绕过结果缓存。

为本模块新增可选增量回调和定向 IPC 事件 requestId/sequence/status/delta；保持旧调用返回类型兼容。先订阅后发起请求；只发送至发起窗口；乱序去重、取消清理、超时处理、卸载无残留。

不能使用现有每次 emit 都查询全部作品/任务的重事件逐 token 广播。内存缓冲并适度节流，最终/失败/取消阶段才写 Store，遵守 AGENTS。[R5]

模型首字不是 HTTP 首包/心跳；只统计用户可见内容。结束原因 length、中断或空输出不能当完整结果。精确文字与模板变量的确定性校验失败标为需核对，不自动二次模型修复。

## 7. 知识更新与国内使用

### 7.1 频率与 UI

启用来源每 7×24 小时检查一次；计时以成功检查为准，失败单独指数退避。不要求软件关闭后常驻。手动“立即更新”不受七天限制；只检查到同版显示已最新，不重复全量下载。

提示词中心保留 `更新参考提示词/管理来源`；管理来源内增加技能知识状态、当前版本、上次成功检查、失败原因、立即更新、导入离线知识包。正常使用不要求员工填写 GitHub Token、终端命令或更新网址。

### 7.2 更新路线

客户端必须内置可用的已校验文本快照。支持项目维护的 HTTPS 知识包地址、已核实上游只读地址和本地离线包。当前没有提供可证明国内稳定的项目镜像，配置中不编造 URL；默认可使用已知上游线路，但文案仅为“上游来源”，不承诺大陆直连稳定。

面向公司国内环境要验证至少公司办公网络和一条独立网络。项目维护端可以用固定发布脚本同步上游并产出签名/哈希知识包，再上传已有受控分发地址；此处交付脚本和配置能力，不未经授权部署服务/发布知识包。镜像未部署不阻止离线快照使用，但不能声称国内在线更新已验收。

### 7.3 数据与规则更新分离

日常更新只更新数据、版本及既有 schema 支持的来源元数据；不会更新可执行代码、系统提示词或模型批准范围。模型规则与官网说明经维护者核实后随受控应用/规则发布更新，不把远端 SKILL.md 直接提到系统指令层级。

维护/构建环节生成可检索字段和短知识卡；优先确定性提取，不能让每台员工机器偷偷对一万多条语料发收费翻译请求。未译原文可保存并参与已支持的检索；更新不阻塞等全量翻译。

### 7.4 一致性与安全

清单记录 packageVersion、upstreamCommit、schemaVersion、files/size/sha256、sourceId、生成时间、归一化条目数。原始上游分类数量可能重叠，不能相加当去重总量。[Y2]

从一个固定提交/不可变包取齐所有文件，临时区校验、建索引，全部成功后事务提升 currentVersion。失败仍旧版。正在优化的请求固定旧快照；下一次用新版。禁用/删除来源后，其索引和缓存不能继续参与新优化。

更新器支持 ETag/304 与数据指纹；不直接调用存在跳过旧文件行为的 setup.js --check。[Y3]

JSON/离线包大小有来源专用上限，通用来源限制不整体放开；流式累积字节限额防伪造 Content-Length。公开上游限制 HTTPS 域名/重定向，禁止本地、内网和 URL 密钥。离线 ZIP 防路径穿越、绝对路径、软链接及解压炸弹，只接受允许文件类型。项目包签名验证使用内置公钥，不能信任包自带公钥；不接受任意下载的脚本。
