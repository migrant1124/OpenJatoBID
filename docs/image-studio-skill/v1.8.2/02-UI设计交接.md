## 2. 设计关注点

### 2.1 控件顺序（不可变更）

`图片需求 → 反推/保存/条件撤销 → 参考图片 → 模型选择说明 → 模型下拉 + 右侧优化 → 画幅/张数 → 生成图片`。

“选择模型后面”落实为阅读顺序、DOM 顺序和视觉顺序：宽屏同排右侧，窄屏下一行紧跟。只保留一个优化按钮；它不会取代反推或生成。

### 2.2 显著程度

创作区唯一强主动作是“生成图片”。“优化提示词”为次级蓝底浅色/描边按钮，仍易于找到；原“反推提示词”使用普通描边按钮。

优化弹窗的主动作是“应用到输入框”；反推弹窗相同。知识更新区域“立即更新”为主动作，离线导入为次级。不能通过层级错位暗示优化必做。

### 2.3 员工无需额外理解的配置

不显示 Skill 目录、向量、Token 预算或多 Agent 设置。模型规则自动匹配，仅一行辅助文字。来源详细日志只在展开后显示；六个请求 ID 由程序预设，接口协议配置由维护者处理，不要求员工输入技术字段。

## 3. 主界面标注

### H01 组件树

```text
ImageStudioPage（沿用）
└─ ImageStudioCreate（沿用）
   ├─ 模块标题/金龙连接状态/设置入口
   ├─ 原有二级导航：AI 生图 / 提示词中心 / 我的作品
   └─ 原有工作区结构
      ├─ 创作输入区
      │  ├─ PromptInput
      │  ├─ ExistingTools：反推、保存、条件撤销
      │  ├─ ReferenceList：主体/风格/构图/色彩
      │  ├─ ModelHelpSummary ← 新增
      │  ├─ ModelActionRow ← 新增选择，移动优化
      │  │  ├─ ApprovedModelSelect
      │  │  └─ ExistingOptimizeButton
      │  ├─ 原画幅和张数
      │  └─ ExistingGenerateButton
      ├─ 现有生成结果/缩略图/下载/局部修改/PSD
      └─ 现有图片信息
```

这棵结构的意思是：不另造一个“技能页面”，只在原创作区插入说明和型号选择，挪动已有优化按钮；其他结果与编辑能力继续使用。

### H01 交互

| 控件 | 行为 | 状态保护 |
| --- | --- | --- |
| 反推提示词 | 打开原反推流程 | 没有可用图片提示选择图片；不调用生图 |
| 保存 | 保存当前输入至现有个人库 | 不保存尚未应用的其他候选 |
| 撤销应用 | 撤销最近一次应用 | 保留现有条件，不强行常显 |
| 查看对比 | 打开 H02 | 不发 AI/模型目录请求 |
| 模型下拉 | 打开 H03 | 支持向上展开避开窗口底部；键盘可用 |
| 优化提示词 | 打开 H04 并以当前模型开始 | 原文为空、请求进行中等状态按规格处理 |
| 生成图片 | 当前请求快照进入 Main 校验/入队/生图 | 不先发本地风险评估；仍做输入保护 |
| 配置密钥 | 定位现有设置中的金龙连接区/H06 | 不在画面显示已存完整 Key |

## 4. 弹窗规范与状态

### H02 模型选择说明

主界面只显示简短摘要，详细表格包括“模型、官网定位、场景建议、局限与注意”。全部模型文案以《05》为准。说明是本地资料，不在员工每次打开时重新抓官网。

Nano 的金龙请求 ID 已按用户截图确认；官方能力、渠道协议及真实调用状态仍须区分。阅读说明或在菜单中看到型号，都不代表本机已完成鉴权或真实出图测试。`gpt-image-2-1k` 不显示无依据的速度/画质增强。

底部标核实日期和来源入口。不要用红绿分数或“最强模型”等总排名。

### H03 模型下拉

只含四个 GPT 与两个 Nano，保留完整识别名称。选择后主界面显示一个确定型号，技能自动匹配。使用正确的 combobox/listbox 语义，上下键选择、Enter 确认、Escape 收起。六项均允许选择，两个 Nano 不再显示“金龙映射待核实”。Nano 项的 ID 副标题分别为 `Nano Banana Pro`、`Nano Banana 2`，大小写及空格与截图一致。生成按钮仍以密钥、实际协议适配与当前动作支持状态校验；不能用菜单可选来伪造连通成功。

空间不足时向上展开，菜单最大高度受视窗限制，内部滚动，不裁断菜单末尾。设计稿为展开到上方的状态，不把展开后的遮挡误理解成删除上方工具。

### H04 优化状态机

| 状态 | 右侧候选 | 可用动作 |
| --- | --- | --- |
| 正在查找资料 | 显示真实状态，保留原文 | 取消 |
| 等待模型/排队 | 显示等待原因，不伪造百分比 | 取消 |
| 生成中 | 显示真实文字分片 | 停止；应用禁用 |
| 完成且校验通过 | 可编辑 | 应用、保存、重新优化、取消 |
| 引用检查未通过/截断 | 保留供核对，标记未完成 | 编辑或重新优化；不作为完整成功缓存 |
| 原输入/图片/型号改变 | 标为过期 | 重新优化；不直接应用 |
| 失败/取消 | 明确状态，主输入不变 | 关闭或人工重试 |
| 结果缓存命中 | 标明复用历史结果 | 应用或明确重新优化 |

原文只读；候选稿完成后可编辑。用户修改候选后，应基于实际编辑稿再次进行本地完整性检查，不追加 AI 请求。

案例默认折叠，显示“实际提供给 AI 的案例”，避免宣称确实全部采用。展开按实际条目展示原文/来源/可选缩略图，缩略图加载不进入模型请求路径。任何“3条案例”须来自真实计数，原型使用占位说明。

### H05 更新状态机

未检查/检查中/可更新/下载中/校验中/已最新/更新失败/离线包导入。每周检查不等于每周一定有新内容；手动立即检查可以重复，但同源在途请求去重。取消下载保留旧版；后台更新不中断当次优化。

不能使用虚构版本时间或自动显示成功。`我的提示词`在图中用于说明不覆盖，不新增一个伪来源。

### H06 设置

按原设置布局复用连接组件，图示为单独配置容器供理解，不新增一级页面。Base URL 显示默认金龙地址，敏感字段为空，保存后不回传明文。

正式应用根据配置情况显示“未填写/已配置/验证失败/状态未知”，不能用“已保存”代替“已连通”。保留完整错误码供展开查看，但确保不含 Key。

### H07 反推

保留“根据图片生成参考描述，不代表原始提示词”。图像与文字绑定，不恢复所谓原作者参数；保持原功能的选择图片逻辑和导入限制。应用结果只改输入，可撤销，不隐式再优化。

## 5. 尺寸与响应式

独立设计画布为 1680×1050；PNG 清晰输出，HTML 仅作为同尺寸布局参考。主画面 28px 外边距、18px 列间距、创作区约446px、信息区约246px、结果区弹性。此为本图展示尺度，不能硬编码进真实页面。

| 实际可用主内容宽度 | 处理 |
| --- | --- |
| ≥1280px | 沿用三栏，保证新增控件能读；模型与优化可同排 |
| 980–1279px | 输入+结果两栏，现有详情抽屉/折叠逻辑沿用 |
| <980px | 输入与结果上下排列，输入区内部滚动，生成按钮可达 |

弹窗宽不超过视窗减48px，高不超过视窗减64px；在窄屏上下对比而非缩小文字。底部操作保持可达。Main真实最小窗口与 Windows 100%/125%缩放由 Codex 验证，本图不代替运行验证。

正文建议14–16逻辑像素；辅助标签至少12。当前稿中更小字号属于设计脚注，正式员工操作关键文案不可缩到难读。沿用现有 `--yb-*` 与全局CSS/Radix；参考图色彩不决定全站主题。

## 6. 交接代码的使用方式

同名 HTML 展示组件排布、按钮层级及少量页面跳转，所有生成/更新/保存均只有“设计演示”提示；不包含业务请求、持久化、真实缓存、Key存储或数据库。

实现时提取必要布局至现有 React 组件，不能整体替换客户端外壳或把内联静态样例当真实业务数据。不要把 `1680×1050` 固定尺寸复制到产品CSS。

普通用户查看：解压后打开 `UI-设计索引.html`。浏览器可能不支持直接渲染 Markdown，完整阅读文档用 `阅读版.html` 或 Markdown 编辑器。

## 7. 可访问性和错误提示

所有图标操作带中文标题与 aria-label；可见焦点；弹窗焦点锁定并在关闭后回到发起按钮；增量输出节流，不每字播报；模型受限原因不只用颜色表达；长 ID 可换行或完整 tooltip。

错误区分：未配置Key、鉴权失败、余额/额度、限流、模型不支持参数、服务方拒绝、网络已发送结果未知、知识不可用。不得统一伪装成“敏感词问题”。
