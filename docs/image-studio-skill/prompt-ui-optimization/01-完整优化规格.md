## 0. 一句话总结

在不改变员工原有生图操作的前提下，把优化弹窗改成宽幅、可完整阅读的对比界面，并让本次案例真正能看图、读完整中文、核对 AI 实际收到的资料，减少盲目应用和反复滚动的风险；具体节省时间由实施后的对照测试确定。

## 1. 本轮最终决定

本轮保留用户最后确认的两张设计图，不改成三列工作台、不嵌入一长串图文、不改造一级导航。页面一处理「原文与优化稿的比较和编辑」；页面二处理「本次案例的图片、中文全文与真实引用内容」。两页分别呈现，共用当前优化会话，返回后不丢内容。

| 编号 | 确定要求 | 验收重点 |
| --- | --- | --- |
| R01 | 优化弹窗改为宽幅；高度受窗口约束 | 不再出现又窄又长、底部按钮在屏幕外的布局 |
| R02 | 原独立大对勾改为带图标的案例信息栏 | 图标不是复选框，不产生不明开关 |
| R03 | 优化方向使用按钮式单选 | 首次进入不预选方向；单击选择不偷偷发起付费请求，通过「开始优化」执行；已有结果换方向通过「重新优化」执行 |
| R04 | 原文与优化稿同高，右侧更宽且编辑区填满剩余高度 | 滚动发生在真实文本区，不是小输入框嵌套在大空白卡片中 |
| R05 | 案例展示为独立的第二页：上方案例卡、左图、右中文、下方实际引用 | 图片和正文都必须对应本次案例，不重新搜索凑数 |
| R06 | 完整中文提示词、原文和已发送片段相互区分 | 不能把 360/450 字符摘要标成完整提示词 |
| R07 | 案例页保留图中的复制、保存、应用、关闭、返回动作 | 保存与应用的对象明确；任何操作均不自动生图 |
| R08 | 优化与案例媒体/翻译解耦 | 点优化不等待案例下载/翻译；不开案例不加载案例图片 |
| R09 | 保留 v1.8.2 已有模型选择与连接配置 | 不修改六模型范围、Key、Base URL、其他模块默认配置 |
| R10 | 不恢复已取消的「图像生成预检风险评估」 | 此次不是重新引入审核模型/风险弹窗；保留技术校验及供应商自身限制 |

**范围解释：**本包里的两张图是已确认的视觉依据，原样附带；图中固定案例数量、示例业务文案、模型名称和 `353 / 2000` 不作为运行时常量。下文明确了动态数据、历史能力兼容和错误状态，不能把这些补全误解为允许自由重画。

## 2. 用户故事与使用路径

### 2.1 用户故事

| 角色 | 希望完成的任务 | 获得的价值 |
| --- | --- | --- |
| 普通创作员工 | 点「优化提示词」后，能一眼看到原文和完整优化稿 | 减少来回滚动，不需理解 Skill、检索或接口概念 |
| 修改提示词的员工 | 在大编辑区直接调整优化稿，再应用 | 不被窄小输入框限制，改稿有明确控制权 |
| 想理解案例的员工 | 点击本次案例，看到真实图和完整中文 | 知道参考内容是什么，而非只看到技术摘要 |
| 复用案例的员工 | 复制、保存或明确应用当前案例提示词 | 不错把优化稿、案例译文和原文混为一谈 |
| 维护人员 | 能核对本次真正发送给 AI 的案例片段 | 发现错配、陈旧缓存和过度引用，有据可查 |

### 2.2 主路径

创作页已有文字 → 选择本次生图模型 → 点击模型选择后面的「优化提示词」 → 页面一打开并等待用户选择优化方向 → 点击「开始优化」后显示真实进度 → 完成后检查/编辑优化稿 → 「应用到输入框」 → 返回原创作页 → 用户单独决定是否生成图片。

### 2.3 案例查看路径

页面一 → 点击「查看实际提供的案例」 → 打开页面二 → 默认选中本轮第一条案例 → 点击其他案例卡切换图文 → 查看原文或实际引用片段 → 「返回优化对比」或「关闭」 → 回到未被改动的页面一。

### 2.4 案例复用路径

页面二 → 选定案例与显示语言 → 复制，或保存到我的提示词，或点击「应用到输入框」 → 应用前明确告知将替换创作输入、不会添加案例图片 → 用户确认后才替换 → 保留撤销与本轮优化稿快照 → 不自动优化、不自动生成。

**既有反推路径不变：**图片 →「反推提示词」→ 预览并应用。它不是此次优化技能的替代品，也不是新增功能的必经步骤。

## 4. 页面一：提示词优化与对比

### 4.1 布局

从上至下为：标题/关闭 → 状态条 → 方向按钮组 → 案例信息栏 → 左原文/右优化稿 → 简短说明 → 底部固定操作栏。保持已确认 H01 的视觉层次，右侧占对比区域约 56%，左侧约 44%。中间箭头仅为装饰，不可点击。

宽幅适配而不是写死一个长宽比。1440×900、1280×800 环境应能看到标题、方向、充足的文本区和底部动作；小窗口允许紧凑排布和内容区滚动，但不能让按钮不可达。具体尺寸与 CSS 见 Handoff。

### 4.2 状态条

显示本轮请求提交时冻结的生图模型和优化状态，不跟随后台全局模型变化改写历史显示。状态值：查找资料、等待模型、生成中、已完成、需核对、失败、已停止、历史结果。

只有真实完成时显示绿色完成图标。点击方向后但尚未重新执行时，显示「方向已调整，点击重新优化生效」，原结果仍标记其实际执行方向，不能冒充新方向结果。

### 4.3 优化方向按钮

按钮为单选，选中用蓝色底和清楚的焦点态，不用复选框或下拉。图中四项「商业海报、产品摄影、包装设计、电商主图」列为常用项；服务层为后两项补齐模式白名单和实际规则，不能点击后仍按商业海报执行。

**已有方向兼容：**当前服务还支持「优化、扩写、简化、英文、双语、写实、插画」。用户没有明确要求删除这些能力，仍以同式按钮保留，排列在常用项之后，空间不足换行，不另造一个下拉菜单。H01 的单行四按钮是常用方向展示，不是删除其他方向的指令。首次默认沿用已有「优化」或当前选择，不因为截图高亮商业海报而把所有请求默认变成商业海报。

切换只更新待执行选项，不发起 AI 请求。生成中禁用方向切换，或要求先停止当前任务；本轮采用**禁用方向切换**，避免多种行为。重新优化前如有人工编辑，使用现有确认模式提示将替换候选，原编辑稿仍保存为当前会话草稿。

### 4.4 对勾与案例信息栏

移除原页面中孤立的大 checkbox，按 H01 换成文件/资料线性图标和信息栏。它是状态，不是勾选项。不要把图标做成能点击但没有说明的控件。

信息栏依真实值显示「本次向 AI 提供 N 条参考案例」「未找到相关案例，已按普通优化处理」「案例知识暂不可用，已按普通优化处理」或「参考案例已关闭」。继续尊重已有来源和知识启用配置；不得为去掉 checkbox 而忽略后台 `useKnowledge=false` 或停用来源。

按已确认图保留信息栏右端与页脚左侧两个同名案例入口；两者打开同一个 H02，共享数据。**本轮不擅自合并入口、改变位置或变成内联长列表。**没有实际案例时两个入口均不可操作，并有零案例说明。

图中「生成更优质」「提升表现力」只是设计示意，产品不固定宣称质量已提升。推荐真实文案：「参考相关案例中的表达方式，不改变你的明确要求。」

### 4.5 对比阅读与编辑

原文只读，保留换行与段落；右侧为可编辑的最终优化稿，标题区附「复制」。两侧卡片外高相同，右侧 textarea 从标题下方一直占满到字符计数上方。采用可伸缩布局与 `min-height:0`，不得以固定 rows 或 150px/200px 高度缩在卡片顶部。

每一侧仅一个文本滚动容器。不要在大卡片上滚动，同时又在内部小 textarea 滚动。原文和优化稿默认独立滚动，不强行按行同步，因为两段文本长度和段落未必对应。

沿用创作输入 **10,000 字符**的业务上限；图中 `353 / 2000` 不实施。长稿可完整查看、复制和编辑；超过应用上限时显示实数并禁止应用，要求缩短，不能裁掉尾部静默成功。中文输入法组合输入期间不误截断或提交。

流式输出中编辑区只读。用户向上阅读后不持续把滚动位置拉回末尾；可提供轻量「回到最新」状态操作，不抢阅读位置。部分流式结果不能直接应用为完成稿。

### 4.6 底部动作

| 动作 | 行为 |
| --- | --- |
| 取消/右上关闭 | 结束页面一；运行中取消本轮模型请求；不改创作输入。当前人工候选草稿保留，避免误关造成损失 |
| 停止 | 仅运行中显示，停止当前优化，保留已返回文字供阅读；不标为完成 |
| 重新优化 | 以当前创作输入、模型、参数与所选方向创建新请求；不自动生图；新旧结果分开 |
| 保存到我的提示词 | 保存页面一当前完整优化稿，不保存原文或案例全文；保存不改变创作输入 |
| 应用到输入框 | 通过完整性与输入版本检查后，应用页面一当前优化稿；保留原有撤销 |
| 复制 | 复制优化稿正文，不附带来源计数、状态、模板标题或隐藏标记 |

应用资格由明确的允许状态计算，不能用「排除几个失败状态」让新状态误通过。只有完整生成或已通过本地复核的人工完整修正稿能应用；网络中断/停止的半段输出不因包含几个必留文字就认定完整。

## 5. 页面二：查看实际提供的案例

### 5.1 固定结构

保持 H02：标题/关闭 → 本轮案例说明与「返回优化对比」 → 水平案例卡片组 → 左侧完整大图与右侧中文阅读区 →「本次实际提供给 AI 的内容」折叠区 → 底部说明与关闭/保存/应用。

页面二独立于页面一的排版和滚动。采用专用案例详情 Dialog，打开时页面一的会话和编辑稿保留、不可交互，视觉上不叠两张可操作卡片；关闭案例页回到页面一。不是在原对比卡下追加内容，也不替换整个生图工作区路由。

### 5.2 案例卡片

案例条数与本轮实际提供的记录一致，通常为 0–3 条；不得固定三张演示卡。顶部卡显示缩略图、案例标题和真实标签。标签缺失时隐藏，不能为填满视觉元素编造模型或效果标签。

点击后同时切换大图、标题、中文、原文、来源、已发送片段。当前案例使用描边和选中状态。案例状态以 `sourceId + itemId + contentHash` 区分，不能只用容易冲突的数字 itemId。

旧参考提示词库和 YouMind 知识包都可能被本轮引用，两种来源的详情必须都能打开。不能只修 YouMind，导致旧库案例点击后空白。

### 5.3 左侧真实样例图

使用该案例来源提供的 `sourceMedia` 或 `coverUrl`，保持比例完整显示，使用 contain，不强行铺满裁切产品、标题或边界。允许点击放大，复用现有图片查看器。

一条案例多张图时，左右箭头切换当前案例的图，不切换案例；计数为实际 `1 / N`。只有一张时隐藏或禁用箭头，不能像示意图那样 1/1 仍显示可切换状态。

| 状态 | 显示与行为 |
| --- | --- |
| 尚未加载 | 显示稳定尺寸占位，文本仍可阅读 |
| 正在加载 | 显示加载状态，不让阅读区跟着跳动 |
| 正常 | 显示真实缓存媒体；可放大 |
| 来源无图 | 「该案例未提供样例图」，不能找另一张相似图代替 |
| 网络/格式失败 | 「图片暂未加载成功」及重试；不阻止读中文或返回 |
| 仅有可用本地缓存 | 直接展示，不因离线清空 |

不重新生成图片填空，不自动将案例图片加入用户参考图，不把展示图片称为本次 AI 已分析过的图片。

### 5.4 右侧完整中文与原文

默认显示可信的**完整中文提示词**。原文就是中文时标记「原始中文」；有来源译文时标记「来源提供」；机器翻译标记「AI 译文，未人工核对」。这些是轻量状态文字，不另加复杂操作页。

「查看原文」在同一阅读区切换为原始正文，并变成「查看中文」。切换保留各语言滚动位置。右側使用宽大只读阅读区，不用小 textarea；需要修改时先明确应用到创作输入或使用已有个人库编辑流程。

复制、保存、应用均针对**当前阅读区明确显示的语言版本**。按钮提示或底部说明标清「当前操作对象：案例中文提示词/案例原文」。绝不在看中文时复制英文，或把案例摘要作为中文全文保存。

### 5.5 中文补全策略

1. 优先读取来源已有完整中文与可信译文缓存；校验必须绑定原文内容哈希。仅含少量中文品牌词的英文段落，不算完整中文。
2. 知识整理/更新环节可以增量准备中文，允许维护者统一生成并随合法知识包分发；不得让每台员工电脑首启时偷偷全库付费翻译。
3. 遇到未翻译的单条案例，保持同一布局，阅读区显示「该案例暂未提供中文全文」和「翻译为中文」。说明「将使用当前文本模型，可能产生接口费用」，用户主动点击后只翻译当前案例，不阻塞优化。
4. 翻译完成自动显示中文并缓存。缓存命中不重复请求。失败保留原文并允许用户明确重试，不自动循环计费。
5. 不把翻译作为补写、摘要、润色、优化；保持数值、段落意图、否定条件、专名和模板变量。要求原样上屏的引号文字保留原字符，必要解释放在提示词外的状态说明，不插入生成内容。
6. 超长正文无法在一次翻译预算内完整处理时，明确「正文过长，暂未生成完整译文」，保留原文；不得把半段翻译标成完成。维护侧可分段校验后发布完整译文，不能擅自提高员工端付费调用次数。

### 5.6 本次实际提供给 AI 的内容

默认按 H02 显示在图文下方，可折叠。它展示当前案例在**该次优化实际请求体中**出现的文本/片段。标签、描述、模型名只有真的发送过才可列为已提供信息。

冻结上下文不等于已发送。排队时可记录「已选案例，待提供」；请求真正提交后才能标「本次向 AI 提供」。请求已提交不等于证明模型逐条采纳。命中历史缓存时标记「历史结果及其原始参考资料」，不宣称本轮重新发送。

完整案例正文、中文译文和样例图供员工阅读，与已发送片段分开。若只发了摘要，明确「本次仅发送下方片段；完整中文和图片用于查看」。不得事后让 AI 生成一份「采用原因」冒充调用记录。

代码目前两次截短 card，最终组成 context 后还有总长限制。本次修复必须以最终请求组装后的字符串为准记录 `sentExcerpt`；不能直接把搜索返回的 450 字符 card 当成已发送全文。[S03][S05]

### 5.7 返回、关闭、保存与应用

| 操作 | 唯一语义 |
| --- | --- |
| 返回优化对比 | 关闭案例页并恢复页面一，保留人工编辑稿、方向、滚动和选中案例 |
| 案例页右上 × / 底部关闭 / Esc | 仅关闭案例页，等价返回；不连带退出整个优化会话 |
| 保存到我的提示词 | 保存当前案例的完整显示文本和来源元数据，不保存页面一优化稿；图像只保存出处/已允许的本地引用，不擅自批量下载 |
| 应用到输入框 | 应用当前案例显示文本，而不是页面一优化稿；覆盖前提示「将当前案例提示词替换创作输入，不会添加案例图片，也不会生成图片」；确认后写入主创作输入并关闭两页，保留撤销及未丢失的本轮优化稿快照 |

案例主动应用是用户明确换用另一段需求，不能套用「优化稿必须包含原需求所有必留词」的检查而错误阻止。案例应用仍须校验当前显示正文完整、长度、输入修订和明确覆盖确认；未填写的模板变量原样保留并提示，不自动虚构变量值。

浏览或切换语言本身不覆盖任何输入。案例应用与优化稿应用是两种明确动作，必须记录 `originKind`，方便撤销和收藏追溯。案例正文超过创作输入 10,000 字符时不可自动裁切应用；仍可阅读/复制，保存遵守原个人库的长度约束并说明。

### 7.3 冻结时机和更新竞态

完成本地候选筛选后，为最终选中的少量案例冻结标题、正文、媒体地址及来源版本；封装已发送片段后固定 `sentContext`。从此本轮案例展示读取该快照，不再按最新知识搜索。

工作线程可一次为最多三条结果带回完整字段供 Main 快照保存，Renderer 初次只拿轻量元数据，用户打开案例时再读正文详情。不得在 Main 中反复同步解压整库，也不能为补图文把整库发送给 Renderer 或模型。

旧参考库的详情通过稳定 ID 查询，不用标题模糊匹配。若本轮使用了翻译后的旧库正文，要记录实际发送的那份文本，不应事后换回原文再宣称已发送。

知识更新在途时，不销毁当前会话对旧详情的读取能力。签名原包不直接修改；译文保存在独立的用户数据缓存。本轮已抓取的媒体字节可固定使用；未在当时下载的远端图，只能称「来源当前可访问的样例图」，不能声称已证明生成时字节一致。

旧版本成功缓存若没有完整快照，不伪造历史详情；显示「此历史结果未保存完整案例详情」，可读原有发送摘要，用户主动重新优化后建立新快照。

## 8. 接口与组件边界

| 层级 | 建议改动 | 约束 |
| --- | --- | --- |
| Renderer | 拆分 `ImageStudioPromptOptimizeDialog`、`ImageStudioCaseDialog` 和轻量案例组件；继续由父级维护会话 | 不修改全局应用壳，不重写反推/生成/作品页 |

| Service | 增加案例会话/快照存储，复用 `aiService` 与图片缓存 | AI 翻译仍进现有全局队列，不绕开并发与计费记录 |
| Knowledge Worker | 保留搜索；增加版本一致的详情读取或一次性带回选中条目 | 不在每次切案例重建索引 |
| 数据库 | 新增局部会话、案例快照、译文索引；复用个人提示词存储 | 迁移幂等、可升级，不丢旧草稿/收藏/作品 |

读取详情和翻译属于独立操作，不让它们触发 `optimizePrompt()` 或 `generateImage()`。翻译只发送该公开案例正文，不附用户当前提示词和参考图。

## 9. 加载、缓存、取消与性能

### 9.1 请求边界

一次优化继续最多一次改写模型请求；案例图片读取为文件/网络下载，不是生图请求；单条中文翻译是用户主动的独立文本请求，单次点击最多一次，不自动修复/重试。状态、日志和用量要分别统计，不能把翻译算进「一次优化只有一次请求」来隐藏费用。

### 9.2 缓存策略

图片缓存键至少包含稳定来源身份、媒体 URL/索引及内容版本；有内容哈希时使用实际哈希。译文缓存键至少包含原文哈希、目标语言和翻译规则版本。并发点击同一案例采用在途合并，同一条待译文不能重复计费。

结果缓存包含本轮实际来源快照，命中后恢复该历史快照而非重新挑案例。知识开关、模式、模型、画幅、图片顺序/用途/哈希、规则版本变化均应失效；不允许失败/取消/截断稿进入成功缓存。

会话和快照存 SQLite，图片走现有受管目录。只在请求开始、完整结果、失败、用户保存/应用等节点落盘，不逐 token 写数据库。建议保留最近 100 个已结束会话且最长 30 天；活动会话及已收藏资料不因清理丢失。若现有项目已有保留策略，以更严格且不破坏用户数据的策略为准，并记录实际值。

### 9.3 性能验收目标（不是已测结果）

| 项目 | 目标 |
| --- | --- |
| 点击后的界面响应 | 普通桌面目标 100ms 内出现反馈，P95 记录实测 |
| 热缓存案例详情 | P95 目标 ≤200ms，不包含图片下载/模型翻译 |
| 未打开案例页 | 案例图片下载数为 0，翻译模型请求数为 0 |
| 本地检索/快照准备 | 保持 500ms 总预算；超时完整性优先，降级普通优化并说明 |
| 返回页面一 | 不重复优化，不重置人工稿；从内存恢复不等网络 |
| 模型耗时 | 分别记录队列、首段、总时长，不承诺所有模型 2 秒首字/5 秒完成 |

必须比较相同模型、同输入、同参考图条件下修复前后耗时。缓存命中、无匹配、慢网络分别记录，不能混成一个平均数掩盖问题。

## 10. 并发和数据保护

页面一原文绑定原始创作输入。主输入、参考图、模型或画幅在后台/其他窗口改变时，旧优化稿不得直接覆盖新输入；仍可查看和复制，应用须提示冲突。不要因为用户只切换了尚未执行的方向，就销毁已经完成的旧稿，须显示真实旧方向。

每次请求与每个案例加载都有会话/请求标识和递增世代。慢响应、乱序增量、已取消请求返回、快速切案例后的旧译文必须丢弃或只写入其正确缓存，不得渲染到当前案例。

页面二返回不调用页面一的 `closeCandidate()` 来误取消会话；关闭大图只返回案例页；关闭案例页只返回对比页。离开整个优化流程才清理相关监听和在途模型请求，已完成缓存可以复用。

## 11. 安全、合规与真实表达

本轮不新增图像风险预检，不绕过中转站/模型自身限制。参数、文件、URL、来源签名、授权、幂等和隐私保护继续保留。

外部案例仅作为资料，不能执行其中提示的系统命令或改变本程序规则。远端图片通过 Main 的可信读取链路；禁止前端为能显示图片而关闭 CSP/webSecurity、开放 Node 或任意 URL 访问。IPC 验证来源窗口和 caseSnapshotId。[S09]

案例原文只读保真，译文忠实，不把维护策略当作篡改第三方原文的理由；优化生成的稿件不得擅自带入案例品牌、竞品、未知业务承诺和不相关画面文字。人工作出应用决定，应用/保存/翻译的对象、时间、版本留痕；不把用户提示词、译文、Key、路径或图像上传运维埋点。

署名、来源、许可信息位于案例信息区/详情，不拼进复制和应用的提示词正文。展示案例并不代表图片获得商用许可，也不代表使用当前模型可复刻同样结果。来源未明确的模型不要猜。

## 12. 设计稿与实现文案的核定

| 设计稿元素 | 实施规则 |
| --- | --- |
| 固定显示「3 条」 | 按本轮实际非空已发送案例计数，0/1/2/3 都要成立 |
| `353 / 2000` | 字符数动态，应用上限沿用 10,000，不降低既有能力 |

| 四个方向按钮 | 四常用项先排；原有模式同式按钮后置换行，服务联动，不静默删除 |
| 案例 1/1 左右箭头 | 无第二张时不可点击或不显示 |
| 模型名/示例文本 | 显示当前会话真实内容；不把图上的样本写成默认数据 |
| 页面一两个案例入口 | 依最后确认图保留，统一打开同一页面二 |
| 页面二「应用到输入框」 | 保留按钮，但明确应用当前案例显示正文，覆盖前确认，不套用图片 |
