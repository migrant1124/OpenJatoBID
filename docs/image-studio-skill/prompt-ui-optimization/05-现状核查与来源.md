### S04｜知识构建中的完整原文

[build-image-studio-knowledge.cjs](https://github.com/migrant1124/OpenJatoBID/blob/401199121ca57ba30d622af31829e9ffccb59230/client/scripts/build-image-studio-knowledge.cjs)

每条规范化行含完整 `prompt`、`sourceMedia`、分类与变量；`card` 由标题、描述与正文前 360 字符组成。本次读取的构建脚本没有单独产生完整中文译文的步骤。构建结果带内容校验与签名，不应被客户端翻译直接修改。

**边界：**这里证明完整原文保留，不证明每条原文是中文，也不证明任一远端图片现在仍能下载。

### S05｜优化上下文与流式行为

[imageStudioService.cjs](https://github.com/migrant1124/OpenJatoBID/blob/401199121ca57ba30d622af31829e9ffccb59230/client/electron/services/imageStudioService.cjs)

重点 `optimizePrompt()`：

- 模式白名单为优化、扩写、简化、英文、双语、商业海报、产品摄影、写实、插画。
- 从旧参考库及知识包合并候选，最终最多三条；旧库候选只留 itemId/title/card/sourceId。
- 发送上下文使用 `card.slice(0, 360)` 拼接，最后再做总长度约束；所以 sources 的 card 不必等于模型最终收到的内容。
- 请求一次 `aiService.chat`，支持 onDelta、signal 与 noRetry；结果标 `referencesAnalyzed:false`。
- 返回 complete 主要由文字/变量是否包含判定；本轮要求结合流式完整性，避免把半段稿当成功。

这些是局部代码事实，不是整个应用性能、视觉能力或外部服务可用性的全面结论。
