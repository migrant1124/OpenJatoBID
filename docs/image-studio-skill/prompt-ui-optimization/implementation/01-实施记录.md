## 实际运行路径

打开「生图模式」→填写图片需求→点击「优化提示词」→在 H01 比较或编辑→点击任一「查看实际提供的案例」→在 H02 选择案例、阅读真实图片/全文/实际片段。已有中文直接读；英文案例可查看原文，翻译必须主动点击。案例「应用到输入框」需要二次确认，确认后可在创作输入处撤销。H01 误关后，创作页出现「恢复上次优化稿」。

隔离运行的优化模型回复来自本地 mock；H02 中的 YouMind 图片由现有 Main 下载链路获取公开来源媒体。截图是应用实际运行画面，不是设计图背景，也不证明真实文本模型输出质量或金龙生图成功。

## 用户实测反馈后的局部修复

- 将优化进度拆成「文本优化排队中」「等待文本模型响应」「正在生成优化稿」，避免把文本模型的等待误认作生图模型等待；原「优化」方向显示为「通用优化」，实际传给服务的方向值仍为 `优化`。
- 模型说明按客户端当时的动作白名单显示局部修改能力；未开放的模型在进入编辑器前提示。此阶段仅 `gpt-image-2` 在客户端开放局部修改；后续六模型开放决定见下节。
- 局部修改完成时从任务对应的作品记录选中新版本，在「生成结果」直接显示并提示已保存到「我的作品」。修正新作品提示与选中状态的异步顺序，避免已经显示新图却仍提示未读。

## 六模型局部修改开放（用户后续决定）

- 用户明确要求其余五款模型全部开放局部修改。六项原有请求 ID 保持不变，模型说明与入口由同一动作表自动更新；局部修改继续使用设置中的金龙生图 Key 和现有图片请求路径。
- PSD 背景拆层仍仅允许 `gpt-image-2`，避免局部修改动作开放时连带扩大 PSD 流程。
- 金龙目录目前为 `gpt-image-2-1k`、`Nano Banana Pro`、`Nano Banana 2` 标示图像编辑能力；`gpt-image-2.5-sunburst`、`gpt-image-2.5-flare` 的目录页未列出图像编辑接口。按用户决定开放后两款尝试入口，不将目录信息或本地模拟结果记作真实渠道成功。

## 优化方向与应用条件修复

- 原因一：创作页点击「优化提示词」直接调用优化服务，组件初值为 `优化`，服务在缺少方向时也默认 `优化`，因此用户尚未选择就运行了通用优化。现改为先打开对比页且方向为空；选定方向并点击「开始优化」才请求，服务拒绝空方向。完成结果换方向仍通过「重新优化」执行。
- 原因二：只读核查真实用户优化会话，22:05 的模型结果状态为 `completed`，并保留原文的指定文字与模板变量；随后保存的编辑稿少了 1 处指定文字和 1 个模板变量，故「应用到输入框」被拦截。22:07 的另一会话结果也为 `completed`，其稿件保留全部必留项。原界面把多种禁用原因合成笼统提示，现按当前稿件具体显示缺失项、长度或输入变化；完整模型稿被改坏时可一键恢复原结果并应用。
- 未降低原有完整性条件：停止/失败的部分输出仍不能直接应用，模型结果缺必留项仍需人工补齐。真实用户数据库只读，未修改既有会话、草稿或 Key；本轮未调用收费文本或生图模型。
