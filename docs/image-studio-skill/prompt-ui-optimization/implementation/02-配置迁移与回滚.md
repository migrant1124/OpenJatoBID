# 配置、迁移与回退说明

## 配置边界

- 客户端 `client/package.json` 仍为 `1.8.2`；管理端版本及发布配置没有修改。
- 生图 Key/Base URL 仍从原设置读取；没有在优化页添加 Key，也没有增加模型或更改六个请求 ID。文本优化、主动案例翻译继续使用已配置文本模型及 `aiService` 队列。案例翻译可能产生费用，本轮未调用真实文本模型。
- 知识包签名与分发配置不变。未配置受控 HTTPS 分发地址时，继续使用内置包、上游检查和签名离线导入；没有把公开仓库地址直接当作可安装包地址。

## SQLite v39 → v40

本轮将工作区 `yibiao.sqlite` 的 schemaVersion 从 39 提升到 40，只新增：

| 表 | 用途 | 数据边界 |
| --- | --- | --- |
| `image_studio_optimization_sessions` | 原输入、方向/模型、完整结果、人工稿、恢复标记、输入快照、发送状态、窗口归属与时间 | 本地工作区；不进入埋点 |
| `image_studio_optimization_cases` | 每轮最多三条完整案例快照及实际发送片段 | 来源原文与公开媒体地址，不存 API Key |
| `image_studio_case_translations` | 按原文哈希＋`zh:v1` 复用主动生成的中文译文 | 独立于签名知识包；不修改原包 |

迁移使用原有 `createSqliteDatabase` 流程：升级前自动复制数据库备份，事务内执行 `CREATE TABLE/INDEX IF NOT EXISTS` 与版本更新；重复启动的结构健康检查保留旧表。隔离 Electron 工作区多次启动后 `PRAGMA user_version = 40`，`input_snapshot` 与 `recoverable` 列也经只读查询确认；该目录不是用户真实 `userData`。旧草稿、作品和收藏在本轮代码中没有清理路径。会话及案例快照同一事务写入。完成会话的清理在新会话写入时执行，按最近 100 条、最长 30 天，排除进行中及当前标记可恢复的人工稿；个人收藏记录不在清理表内。

## 保留式回退

优先用后续修复版继续读取 v40 数据。若必须运行只认识 v39 的旧客户端，先完全退出客户端，分别保留**当前** `yibiao.sqlite` 及其 WAL/SHM 文件和升级前自动备份；不要删除整个 `userData`，也不要直接清空新表、收藏或作品。旧客户端可能拒绝高于自身支持版本的数据库，须在隔离副本上验证兼容回退后再决定正式切换。直接覆盖升级后的数据库会使升级后新增的草稿、收藏或作品暂时不可见，因此不能作为无损回退。

本轮没有在用户真实数据库上执行降级，也没有验证旧客户端读取 v40 数据；需要实际回退时，应先对数据库副本演练并核对升级前后记录，再在关闭应用的条件下操作。用于本轮 UI 的隔离工作区在 `.tmp/prompt-ui-isolated-user-data/`，仅供非付费测试。
