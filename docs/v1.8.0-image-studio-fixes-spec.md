操作语义保持：查看图片不调用模型；保存、收藏、应用提示词不自动生图；优化和反推调用文本模型；生成和局部修改调用生图模型；拆层分析如需文本视觉调用，只在用户明确启动拆层后执行。

## 4. 功能约束与状态所有权

业务权威数据仍进入 Main 侧 Store／SQLite，图片放受管目录。Renderer 只负责展示和交互，耗时任务不能绑定某个页面是否挂载。所有模型请求仍经 `aiService` 和原队列；不在页面直连，不创建第二套 SDK／凭据体系。

提交时冻结当次模型、图片、角色、尺寸、数量和文本快照。Key 仅在原配置服务和 Main 内存受控使用，不进入任务 JSON、来源请求、设计图或日志。设置变化只影响新任务，不改在途任务。

原图、参考资产、编辑版本、个人收藏和来源快照分别管理。源停用／删除／更新不能级联删个人副本；删除作品不破坏后续版本依赖。自动保存包含本轮新增画幅及风格应用状态，不因切页或重启丢失。

### 5.2 参考图预览

点击参考图主体区域打开共享大图查看器，适用于新上传 assetId 和历史作品 workId。默认适应窗口、保持原比例，支持放大、缩小、100%、拖动、多图前后切换、Esc／关闭、合理焦点返回。

预览只读本地受管图片，不重新上传、不调用模型。移除按钮、参考用途下拉与预览点击相互隔离，移除不会误打开预览，切换用途不会误删除。原参考图缩略图可裁切展示，但大图必须显示完整内容。缺失文件准确提示，不以空白弹窗成功打开代替预览。

复用相同图片查看器处理参考库示例图和可用作品，不复制三套不一致的缩放交互。此复用仅限本功能，不扩大为全站图库重构。

### 5.3 生成参数重新布局

删除创作面板“画质”标签与下拉框，删除原单独一整行的固定图片尺寸。最终同一行：

```text
生成张数                    图片画幅
[ 1 张                ▾ ]   [ 2048 × 1152 · 16:9      ▾ ]
```

上述像素仅沿用用户截图作排版例子，不是对全部模型尺寸能力的声明。生成张数保留 1／2／4 张；画幅下拉项同时显示“宽 × 高 · 宽:高”，不能只写“横版”“1K”。比例中的先后顺序始终是宽:高。

必须覆盖的比例意图：1:1、1:2、2:1、3:4、4:3、16:9、9:16。其他比例在实际接口支持时使用同一选项结构，不新增第二排尺寸按钮、画质档位或必须填写的自定义宽高。

画幅占本行较宽一列；下拉菜单不被创作卡片滚动容器裁掉。选择后即时更新草稿，不以设置页尺寸作为只读值。

### 5.4 当次画幅的规则

首次无草稿时可以将当前设置尺寸作为初值，但之后以本次选择为准。读取、保存、重启恢复、历史复用、请求构造、任务记录、作品详情均使用同一选择。尺寸与比例不能互相矛盾。

移除后台 `size !== config.image_size` 的拒绝判断，给请求传明确的当次 size／ratio；禁止为绕开限制先保存全局配置、调用后再恢复，这会干扰并发任务。

模型、Base URL、Key 继续来自系统设置；当次尺寸和张数来自生图页面。请求配置指纹记录实际提交尺寸，不能仍只记录全局尺寸。返回图片必须记录实际宽高，和请求不一致时如实显示，不伪改元数据。

按已知格式和实际接口规则校验参数。没有历史测试记录不是禁用理由；禁止新增 `contractVerified`、`testedSizes` 等人工解锁机制。只有明确的接口限制、参数无效或实际服务端拒绝时才给具体提示。不能声称任意尺寸均被支持，也不能把全部目标比例锁为不可用来通过验收。

删除画质控件不等于修改全局 quality 或模型档位。原调用需要且确实支持的质量参数沿用已确定行为，否则按接口约定省略，不能自动上调费用。`gpt-image-2-1k` 不因名字自动切换成另一模型。

## 6. 参考图与局部编辑：真实接通，不设置合同门槛（FIX-04）

### 6.1 必须一并完成的修正

移除 start 中“references 非空就报错”“非 generate 就报错”等固定拦截，以及创作页对应橙色“尚待验证”说明。不能只去掉文字或 throw：参考图内容必须被后续模型请求实际消费。

开发中的接口定义、参数格式、响应解析是 Codex 应完成的工程工作，不是普通用户需要签合同、做测试或开启开关的操作。上线界面不得使用“合同未验证”错误；测试结果属于开发报告，不得决定用户永久使用权限。

### 6.2 端到端责任

| 层级 | 输入 | 输出与约束 |
| --- | --- | --- |
| 页面 | prompt、count、size／ratio、1–4 个 assetId／workId、role、父版本、可选选区 | 提交稳定 ID 和当次参数，不提交本地路径作为图片内容 |
| Main 解析 | 稳定资产引用 | 获取真实受管图片字节，确认格式、方向、尺寸和有效角色 |
| AI 适配 | 配置快照、文字、图片字节、可选 mask | 根据当前渠道 API 构造真正编辑／参考图请求；不退回丢图的文生图 |
| 结果入库 | 服务返回图片与请求快照 | 本地保存、实际宽高、kind、参考资产关系、父子版本 |
| 界面恢复 | taskId 与事件 | 成功、部分成功、真实失败、待确认状态；保留用户输入 |

无参考图使用现有正常文生图；有参考图使用渠道支持的编辑／参考图机制；有局部选区使用原图＋mask 或明确的标注方案。参考图顺序固定，提示词中的“图 1／图 2”与文件顺序及角色一一对应。

OpenAI Images 官方文档将图片生成与编辑分为不同端点，并说明编辑可使用参考图片和 mask。[S9] 这可以作为兼容实现的技术依据，但不等于已经验证用户中转。优先核对现有成功请求与可访问说明；确认使用 OpenAI 兼容 Images API 时，将 `/images/edits` 作为明确适配目标，核对其 multipart 图片字段与 mask 语义。不要盲试多个端点、不要硬编码另一家服务地址，不把语雀页面当 Base URL。

使用 multipart 时由请求库生成 boundary，不沿用 JSON 的 Content-Type；图片通过字节、接口允许的 data URL 或可访问文件引用提交。`yibiao-asset://` 和 Windows 路径不能作为公网模型可直接读取的图片 URL。不能把角色名称当未经定义的 API 参数。

如当前渠道确实返回“不支持编辑”等错误，保留该响应及请求结构证据，继续修正适配或说明外部限制；不能把“开发者还没试过”伪装成服务端不支持。文档暂不可读也不构成新增固定门禁的理由。

### 6.3 局部修改与连续创作

复用已确认局部修改弹窗，补齐画笔、橡皮、撤销重做、清空、缩放、修改说明和提交。原图坐标保存选区，缩放显示坐标不能直接发送。

先准确记录允许变动范围和羽化带，再将编辑结果与原图对齐合成。官方文档说明 mask 是模型引导，不保证严格形状遵循，因此不能只依赖一句“其余不变”来承诺像素保护。[S9] 在标准化无损像素空间，允许范围外保持原图不变；结果尺寸／方向不可对齐时保留结果并明确失败，不强拉伸后宣称局部修改成功。

“继续创作”须带被选图片，父版本来自用户实际选择。多张同次生成结果是兄弟图，不错建父子关系。创建 kind 与记录实际是文生图、参考图生成还是局部修改相符。

### 6.4 失败与计费

正常校验只处理空描述、无效图片、数量、大小、格式、选区和必要参数。请求发出后超时不盲目重发；只下载失败时只重试下载，不能重新生成。错误保留 HTTP 状态和适当脱敏的供应商信息，区分明确失败与结果不明。

取消只作用当前任务／作用域，不取消其他投标或生图请求。已发送任务“停止等待”不伪称供应商已停止计费；成功返回的已付款结果不得无故丢弃。参考图与输入、选区在失败后保留，用户可修正后重试。

## 7. 参考提示词的图片预览（FIX-05）

### 7.1 正常流程

来源数据中的真实 coverUrl／可用参考图片 → 后台安全获取 → 生成缩略图并缓存 → 卡片显示 → 详情显示 → 点击大图。

第一层必须修正当前占位实现：有效图片条目实际渲染图片，而不是用 span 永远显示“图片预览未随包分发”。卡片有图片不要求图片先随安装包打包。

使用上游原始示例，不用本项目新生一张图冒充效果；不使用统一假封面。来源没提供图片、URL 失效与程序没实现加载是不同情况，必须区分。

### 7.2 数据与缓存

优先读有效本地缩略图；未缓存则按可见卡片懒加载。记录源、条目、原图 URL、内容版本／校验信息、缓存路径、尺寸和失败原因。受管图片使用现有资源协议返回 UI。

初次仅下载当前可见／邻近少量缩略图，不一次拉取所有来源的全部高清图。原图或高清图在用户打开大图时按需获取；若原图已经缓存则直接使用。请求合并、超时、取消、有限并发与短期失败退避沿用或最小扩展现有机制。

预览成功后重启仍可用。URL／图片内容改变时使对应缓存失效，不用“sourceId 相同”永久沿用旧图；来源文本变更但封面不变不必重复下载。收藏副本保留必要的预览引用／缓存，不因参考源清理而失效。

来源 JSON 的镜像不一定镜像其图片地址，分别检查；只按可信明确的地址映射改写，不把任意 URL 机械替换为代理。当前默认来源仍按用户确认沿用 infinite-canvas 的七个来源，不新增必须部署的服务器。

### 7.3 失败和安全

四种最小状态：加载中、已显示、来源无图、加载失败（可重试）。只对真实失败条目显示原因，不能全库统一放一个占位。详情可显示并允许打开原始出处，但不自动跳转外站。

外部图片在 Main 侧处理；校验 HTTPS、每次重定向、实际文件类型、大小与解码像素，拒绝本地路径和内网地址注入。复用现有公共资源安全策略，不把这些策略套到用户已配置的模型中转端点。来源图片请求不得带模型 Key，不关闭整个应用的 CSP 或 Electron 隔离来“修复”图片。

随包再分发必须遵守源内容使用条件；仅未随包分发不能成为永久不加载用户主动浏览的公开图片的理由。明确访问限制时按条目记录和显示，不伪造通用版权确认门槛来阻断所有图片。

## 8. 正确分页（FIX-06）

保持每页 40 条，不新增可变页大小控件。查询返回 items、total、offset／currentPage、pageSize；total 必须使用与列表完全相同的来源、启停、删除、搜索和其他筛选条件。

- totalPages = 向上取整(total ÷ 40)。
- 有结果时 currentPage = 向下取整(offset ÷ 40) + 1。
- total = 0 时显示“共 0 条 · 暂无结果”，不显示“第 1/0 页”；两侧翻页禁用。
- 正常显示：“共 N 条　上一页　第 P / Q 页　下一页”。
- P = 1 禁用上一页；P = Q 禁用下一页，不再用 items.length 是否等于 40 推断下一页。
- 搜索、来源变更回第一页；内容更新或删除使当前页越界时回最后有效页并重新查询。
- 列表与 COUNT 取同一读快照或有一致性处理；异步旧请求不能覆盖新的搜索结果。
- 固定稳定排序与 ID，不用随机顺序；同步完成不无故跳回第一页、抢焦点或关闭当前详情。

必须覆盖 0、1、39、40、41、80、81 条以及过滤后总数变化；尤其 40、80 条的最后一页不能继续进入空白页。

## 9. 参考提示词收藏到我的提示词（FIX-07）

### 9.1 产品行为

在参考卡片和详情增加统一收藏图标／按钮。第一次收藏：事务性创建个人副本、写入来源信息并标记收藏，立即在“我的提示词”可见。收藏不调用模型，不触发生图。

个人副本至少保留标题、当前可用正文（中文优先）、标签、原始出处、sourceId、上游稳定 itemId、内容版本及示例图引用。既有“另存个人提示词”可保留为有意创建独立副本的动作，不能与收藏混为一次又一次创建副本。

收藏去重键是“来源稳定 ID＋上游条目稳定 ID”，不能用内容 hash 作为唯一收藏身份：内容更新不能制造一条新的收藏。同一个原始 ID 在不同来源不应互相覆盖。已有重复前缀的内部 ID 要做兼容映射，不能改 ID 后让旧收藏失联。

### 9.2 双向一致性

参考卡片、参考详情、我的提示词的收藏状态一致。在我的提示词取消收藏，参考卡片随即变为未收藏；再次收藏优先复用仍存在的个人副本，不覆盖用户编辑。来自参考源且已有个人副本的首次“一键收藏”应复用合适的既有副本并标记，不能再复制相同记录。

取消收藏只清除收藏标记，个人副本仍保留，页面简短提示这一点。删除个人提示词是单独操作；删除后原参考条目仍存在时可以再次收藏，但不能意外复活用户删除的旧编辑内容。来源停用／删除、后台更新、镜像改址均不能删除个人副本或强改其正文。

列表不要每张卡单独查数据库：通过一次分页查询或一次批量关联返回 favorite／personalPromptId。快速双击、多窗口／并发收藏通过事务和实际唯一约束实现幂等；只靠 UI 按钮 disabled 不够。

“我的提示词”保留已有增删改、分组和标签，并提供“全部／收藏”轻量筛选；不新建一级收藏页、不重写旧对话提示词库。

## 10. 常用风格说明与轻量修正（FIX-08）

保留名称“常用风格”和现有位置。增加一句说明：**保存可反复使用的风格描述，应用后加入当前需求，不替换主体。**

完整提示词描述“画什么＋怎么画”；常用风格主要描述“怎么画”。例如当前需求写“客厅、三人沙发、猫躺在沙发前”，风格只写“自然窗光、暖色调、柔和阴影、真实摄影、材质清晰”。本例用于说明，不作为自动注入用户作品的默认内容。

新增／编辑风格保留名称、描述、备注、推荐比例。推荐比例只作提示，本轮不自动应用、不增加第二处比例配置，也不改变模型、参考图、主体或指定文字。

应用保留原主体，并将该风格描述追加一次；同一 styleId／版本已经应用时提示“已应用”，不重复堆叠。用户自行输入的类似措辞不得被全局替换或删除。跨页／重启需要保留当前应用状态，旧草稿缺字段仍能读取。

提供撤销本次应用；只在能明确恢复的修订关系内撤销。用户又改过输入时，不直接用旧整段文本覆盖新编辑。更换另一风格前区分由系统添加的风格片段与用户正文，不擅自删用户内容，也不必引入复杂模板语言。

保存、编辑、收藏和应用风格均不触发模型；生成前的人工可见输入仍是请求内容依据。

## 11. 分层 PSD：从未接通修正为可用功能（FIX-09）

### 11.1 成功定义

选中已有作品或导入图片 → 启动拆层 → 自动得到有意义的候选层 → 用户检查／必要细修 → 显隐与排序 → 预览合成 → 选择位置 → 导出真实 PSD。

复用 `imageStudioPsd.cjs`、`sharp`、`ag-psd` 的基础，但补上自动候选生成、掩码、图层管理、IPC、用户入口和实机验收。入口可在创作结果、作品详情共用同一组件。仅无选中图片／运行中等真实状态禁用，不固定 disabled。

输出边界沿用 R3：像素分层，不承诺恢复原始设计工程、可编辑字体或隐藏对象背面。至少有两个语义上有意义、含非空像素的层；具体图层数由图片决定，不硬凑五层。

### 11.2 推荐的可落地基线，不依赖第三个云模型

1. 使用已有 `gpt-6-sol` 视觉能力，基于用户当前图片提供主体名称、前景区域／点位等候选；输出必须有结构、坐标基准和可校验边界。不能把视觉模型给的粗框当作完成的像素分割。
2. 通过本地像素分割细化候选。优先评估能随应用提供的轻量分割实现，例如 OpenCV.js 的 GrabCut，使用前景／背景种子和图像像素计算轮廓；这是一条工程实现建议，不是已经在本项目验证过的效果保证。[S10]
3. 建立原分辨率的 mask 和各层 RGBA，提供保留／去除画笔细修。系统必须先产生候选；完全要求用户从零涂完整图只能作为补救，不能冒充自动拆层已实现。
4. 将真实图层及预览交给现有 PSD 写入工具，补全服务、preload、IPC 类型、保存对话框和导出记录。

Codex 必须在实施早期选择并落地一个可运行的像素分割模块，而不是再次留下“将来接入分割服务”的 TODO。算法选择、版本、体积、许可证、打包可用性及样本效果在同一 Goal 内验证，不逐项要求用户批准常规技术选型。若采用本地 WASM，应随包提供并在独立工作线程执行，不要求员工自行安装 Python／编译 OpenCV，不在每次拆层临时从国外 CDN 下载运行时。

若上述方法不满足三类实际样本，应继续在已授权技术范围内改进或采用可交付的本地替代。需要新收费服务、另填 Key、大模型下载或其他超出授权的资源时，集中说明该真实外部依赖；不得擅自增加强制第三套云模型，也不得声称未实现的算法已可用。

### 11.3 可见像素分层与合成

首个可靠基线允许“主体层＋其余可见背景层”，复杂场景可继续拆成多个候选。每个层必须沿对象轮廓保留实际内容；任意矩形裁切、网格或条带不能算语义分层。

未补全被遮挡背景时，移走主体可能露出透明孔洞，须在面板清楚说明；默认不额外调用生图模型补背景。本轮不扩展为自动恢复所有隐藏内容。

规范为同一方向和 8 位 RGB／RGBA 工作空间，明确色彩转换；记录实际尺寸，不悄悄将原始高分辨率降到分析缩略图分辨率。分析缩略图只能用于候选，最终 mask 回映原图并细化。

最小基线可采用互斥像素归属：每个原像素只交给一个可见层，其他层该处透明，保证原层序合成恢复原图。需要柔边时用经过测试的 alpha 合成方案，不能用互补半透明 mask 简单相加导致暗边、透明缝或双重覆盖。

完整未编辑层集合成在同一解码颜色空间应与规范化原图一致。用户手动隐藏层或调整层序后，以预览状态为导出依据，并明确用户操作造成的视觉变化。

### 11.4 导出验证与边界

预览与最终 PSD 使用同一组图层像素、顺序、显隐与中文名称。导出先写临时文件，完成回读校验再原子保存；磁盘不足、不合法路径或被占用时不报告成功。重导出同一拆层会话不重复调用模型。

禁止：空层凑数、重复整图、只改几个像素制造差异、任意网格切片、隐藏整图掩盖错误、单层 PSD 冒充完成。RGBA 哈希不同只是必要检查之一，不能代替语义和重组验收。

`ag-psd` 是读写库，有格式与文字层等限制，不是拆层算法；它的回读通过不等于 Photoshop 兼容验收。[S11] 首版按当前库支持的 8 位 RGB 像素图层交付，不扩展到 CMYK、PSB 或文字对象编辑。

至少使用产品照、室内／猫等多对象照片、含文字海报三类真实图样验证候选、细修和导出。文字所在层明确是像素，不承诺可改字。使用 Photoshop 打开、关闭／移动独立层并观察透明边界；无该软件时列“待实机验证”，不能将 8×6 色块测试替代。未达到功能基线就保留失败并继续修复，不能以挂灰按钮结束。

## 12. 默认提示词库每七天自动更新（FIX-10）

### 12.1 范围

默认自动更新对象为 `builtIn=true`、已启用且未删除的来源，包括用户改过地址但仍启用的内置来源；使用用户当前有效地址。自定义来源保留手动刷新，不擅自给其开启周期任务或新增自动更新开关。

默认来源仍为用户确认的七个：Banana Prompt Quicker、DavidWu GPT Image 2、Freestylefly GPT Image 2、Awesome GPT Image、Awesome GPT-4o、YouMind GPT Image 2、YouMind Nano Banana Pro。软件版本可增减内置来源配置，但“每周内容更新”不擅自新增来源或复活用户已删来源。

后台指 Electron 主进程管理的应用内服务，与提示词页面是否打开无关。软件彻底退出或系统关闭时不承诺执行，不新装 Windows 服务／任务计划，不创建 ChatGPT 提醒。

### 12.2 调度规则

| 条件 | 行为 |
| --- | --- |
| 首次安装有初始内容 | 立即显示包内有效中文内容；后台错峰做一次首次检查，成功后按七天计算下次到期；不把本地导入时间记成联网成功 |
| 已有默认源从未联网检查 | 当前本地内容立即可用；后台错峰做一次首次检查，不阻塞启动 |
| 距上次成功检查不足七天 | 不联网重复刷新 |
| 到达七天且应用运行 | 低优先级检查该源，有变化才应用 |
| 到期时应用退出／离线／休眠 | 下次运行并联网／唤醒后补做一次，不补跑多周历史批次 |
| 用户手动刷新成功 | 记作该源一次成功检查，之后七天从此计算 |
| 返回未变化／可靠 304 | 更新成功检查时间，不重写内容、不重翻译、不显示虚假新增 |
| 一个来源失败 | 只记录该源失败并退避，不阻塞其他源、不删除缓存 |
| 同时手动刷新与自动到期 | 合并同源请求，共用互斥与结果，防止重复下载和提交 |
| 用户在途改址／停用／删除源 | 旧响应不得落库，旧任务不得恢复该源 |

“七天”是成功检查后的连续 7×24 小时，不擅自固定成每周一或每日更新。持久化 UTC 时间以防重启丢失；前台按本地时区显示。时钟大幅跳变只安全重算一次，不产生循环请求。

建议失败退避采用约 1 小时、6 小时、24 小时并设上限和轻微抖动；网络未恢复不密集失败。失败重试不是把整个库改成每小时更新。普通后台失败不弹 modal、不反复 Toast，状态在来源管理中可见。

### 12.3 时间字段与并发

最少区分：最近尝试、最近成功检查、最近内容实际应用、下次到期、下次重试、连续失败数；已有字段能承载则复用。成功检查与内容应用不能混为一个字段，否则无变化会被误判为一直过期。

数据结构保留来源配置修订、启停／删除、下载地址、内容 hash、上游可用版本与更新渠道标识。持久化必要状态，启动、唤醒及轻量到期检查共用一个调度服务，禁止 Renderer mount 启动多个定时器。

### 12.4 正常变化自动更新，不再要求 confirmedReplace

正常 JSON／条目／哈希变化在校验成功后原子更新，不要求用户签字、点击确认或传 confirmedReplace。必须删除“只要 hash 不同且无顺序版本就报错”的普通路径。

主源支持可比较版本时使用它。无版本但主源格式和完整性有效时，将内容视为该源本次最新有效快照；不能仅因无递增版本号拒绝每周更新。同源在途互斥、请求世代、配置修订和成功时间用于防晚响应覆盖。

备用线路返回已知旧 hash／更低版本时不降级；备用快照无法确定新旧且与当前不同，可以保留旧内容并记录“备用版本待核对”，不得影响主线路普通更新。异常才隔离，不以一条全局强制确认规则封死全部来源。

空数据、无效 JSON、重复 ID、明显异常骤减、重定向越界或签名／校验失败保留旧快照并记录原因。不能通过 `confirmedReplace=true` 统一绕过所有保护。异常替换需要人工决策时集中处理，日常正常每周更新不弹确认。

### 12.5 增量内容、中文化与图片

按稳定 sourceId＋原始条目 ID 对比内容 hash。未变条目保留中文译文、图片缓存和关联；仅新增／改变的内容进入中文化。不能每周删除全库再写回英文，使中文丢失。

优先使用源已有中文字段，否则复用当前文本模型进行小批量、低优先级增量翻译，保护变量、专名和画面指定文字。翻译键包含原文版本、目标语言与翻译策略；不因每次启动自动重译。

翻译任务可持久化续传，前台生图／反推／优化优先；运行时遵守原有用户模型预算／限额。预算不足、无网络或无文本配置时保留旧译文与原文并标“待中文化”，只暂停翻译，不阻止有效来源快照检查；不能把英文原文直接写进中文字段宣称完成。

开发验证限额与产品的每周后台任务区分。开发不借测试名义做全库计费翻译；产品按用户已确认的自动更新意图处理正常增量，不能每周暗中全量重跑。超过既有预算、需新服务时集中说明，不默认升额度。

图片有独立更新／缓存策略，见第 7 节。图片暂时下载失败不回滚全部有效文字，已有预览仍可用。初始可用内容继续随包提供，不能回退为“只有七个网址”。

### 12.6 更新不影响个人与前台操作

任何正常同步都不改当前输入、参考图片、当次画幅、优化候选、个人收藏副本、个人风格或已有作品。已打开的提示词详情可继续显示当前快照并提示有新版本，不突然切走；分页更新保持有效当前页，只有越界时安全收敛。

来源管理显示“默认每七天自动更新”、最近成功检查／内容更新时间和失败状态。只有确有内容应用才说“更新成功”；无变化显示“已检查，无新内容”。用户自定义地址与启停／删除标记在软件升级后保持。

### 14.1 实测方式与完成门槛
