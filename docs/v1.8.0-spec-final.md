## 4. 信息架构与完整流程

一级入口“生图模式”固定。首次点击默认进入“AI 生图”，不先显示额外入口卡片页。三个二级入口在主内容区：**AI 生图／提示词中心／我的作品**，不展开成全局侧栏子树。

“提示词中心”内为**参考提示词／我的提示词／常用风格**。“管理来源”是参考库的弹窗，不另建一级或二级入口。

### 4.1 三条创作起点

- 文字起点：描述／任务预设 → 可选优化 → 查看原文和结果 → 用户应用 → 明确点击生成 → 选择结果 → 修改／保存／导出。
- 图片起点：上传参考图 → 选择角色 → 补充描述 → 生成 → 局部修改 → 新版本 → 导出。
- 灵感起点：上传图片 → 反推 → 可选优化 → 另存个人提示词或应用输入框 → 用户另行点击生成。

### 4.2 来源与交付流程

安装包预置快照 → 参考库即可使用 → 按需同步 → 成功校验后替换该源内容；失败继续用旧内容。源设置变更只影响该源，不改草稿、个人提示词、现有作品。

图片生成／导入 → 拆分图层 → 检查／修正候选边缘 → 图层合成预览 → 导出 PSD。图层写入库通过测试不等于这一完整流程已经实现。

### 4.3 动作语义

“保存提示词”只保存；“用于生成／应用到输入框”只填入创作页；“优化／反推”调用文本模型；只有“生成图片／生成修改版本”提交生图请求。“继续创作”必须带上选定图片的引用，不能仅复制其提示词。

## 5. 模型与现有配置完全一致

模型标识和视觉能力来自用户明确确认，不据名称推断供应商品牌、价格或未验证能力。

| 工作 | 使用现有配置 | 当前模型标识 |
| --- | --- | --- |
| 优化、扩写、简化、翻译、结构化描述 | “文本模型” | `gpt-6-sol` |
| 图片反推、识别图片内容／语义候选 | 同一个“文本模型”，用户确认其有视觉能力 | `gpt-6-sol` |
| 文生图、参考图生成、局部编辑 | “生图模型” | 当前选中的 `gpt-image-2` 或 `gpt-image-2-1k` |
| 遮罩、像素合成、格式编码、PSD 写入 | 本地图像处理 | 不是第三个模型 |

### 5.1 配置唯一性

生图模式只读取已有两套配置；页面只显示只读摘要与“前往设置”。不新增视觉 Key，不复制另一份 Base URL，不自动切换模型，不因参考模板来自其他模型而改用户配置。

实际支持两种图片 ID，不把 `gpt-image-2-1k` 当成标准 ID 自动改名，也不按后缀推断所有图都是 1024×1024。界面显示真实返回尺寸。不存在依据的 seed、steps、CFG、风格强度参数不发送、不伪造；风格倾向可用自然语言体现。

### 5.2 提交配置快照

新任务提交时冻结模型、请求参数、配置修订号和受管凭据引用。已入队任务不得被后续设置改动静默切换模型。队列期间的实际凭据只在 Main 内存中受控使用，不把明文凭据写入 SQLite、图片、日志或文件导出；重启后不能恢复匹配配置的未发送任务，应明确待处理，不能偷偷换新配置提交。

## 6. 文生图与参考图生成

### 6.1 创作输入

输入框中文优先，至少支持 10,000 个字符；超过产品上限明确提示，保留完整输入，不静默截断。生图接口更低限制通过预检告知，不冒充已发送完整文本。默认单图；可选择 1／2／4 张，按实际渠道支持执行受控子任务。

提供 1:1、4:3、3:4、16:9、9:16 比例意图与画质选择。不能支持的组合必须解释或禁用；只能通过裁剪获得时应明确“裁剪适配”并经用户选择，不把拉伸变形当成支持该比例。

左侧八类预设：商品图、海报图、宣传图、插画图、写实图片、图标／小元素、背景图、局部修图。预设只提供引导与可用默认值，不创建八个独立页面，不自动放入佳图品牌或招标信息。

### 6.2 参考图

支持 PNG／JPG／WEBP 文件选择、拖放，产品上限 4 张。按真实文件签名、解码大小、像素数和渠道限制做入口校验；处理方向，保留原图与受管衍生图。超过限制明确提示，不静默丢最后几张。

每张图可选择主体、风格、构图或色彩用途；顺序、用途、保留要求真正进入请求。无原生 role 参数时用明确图片编号及自然语言绑定，不发送杜撰参数。“保持主体”属于尽量保留意图，不承诺像素级一致。

### 6.3 结果

成功结果立即本地落盘、记录 SHA-256／真实尺寸／类型／任务。多图部分成功时保留成功图并准确显示失败数量；不因为一张失败清空全部结果。

本次生成完成默认选中新结果，修正旧页面停留历史图的问题。用户在任务期间明确切换查看其他作品时不抢焦点，提示“新结果已就绪”，可一键切回。结果、当前选择和版本引用都用稳定 ID。

## 7. 提示词优化、反推与个人积累

### 7.1 优化

入口：创作输入、反推结果、参考详情、个人编辑。操作包括优化、扩写、简化、英文／双语，以及商业海报、产品摄影、写实、插画方向；主界面只突出“优化提示词”，其余在同一弹窗内选择，不增加高级模式。

输出为原文、可编辑优化稿、简短变化说明。保护主体、数量、尺寸、画面指定文字、引用名称、否定条件和模板变量。不默认把短句堆成无意义关键词，不自动更换模型或增加商业承诺。

应用前不改变原草稿；点击应用后可撤销。请求绑定草稿修订号，期间输入变化时旧结果只能作为候选预览，不能覆盖新文本。保存和应用均不自动生图。

### 7.2 图片反推

输入为用户选中的上传图或已有作品，不自动读取其他素材。使用当前文本模型的视觉输入，输出主提示词、风格、构图、光影、色彩、标签与比例建议。主提示词可编辑；中文默认，原模型支持时可选择英文／双语输出。

说明固定为“根据图片生成参考描述，不代表原始提示词”。不能恢复或伪造作者真正使用的 seed、模型和拍摄参数。换图使旧任务结果与新图隔离；支持复制、优化、保存为我的提示词、用于生成。

### 7.3 我的提示词

复用原 `promptLibrary`，兼容原对话模式导入、编辑、撤销和保存。支持新增、编辑、删除、收藏、分组、标签、备注、推荐比例；保存来源包括手写、参考库另存、反推和优化结果。

使用用途元数据或兼容关联区分生图条目，不只按“生图提示词”中文组名过滤。已有条目的用途可以追加，不把对话内容自动移入生图库；重命名分组不导致生图条目消失。

参考条目另存形成个人副本，记录出处与来源版本；用户后续修改由用户所有，不被来源同步覆盖。创建／编辑表单有明确保存结果；与现有自动保存规则冲突时只在新容器适配，不回退旧库能力。

### 7.4 常用风格

字段：名称、风格描述／模板、推荐比例、可用参数、备注。支持新增、编辑、删除、应用。应用时保留主体、现有文字及参考图；有冲突先预览或提供可撤销候选，不静默清空输入，不自动换模型。保存当前设置不包含 Key 或其他秘密。

## 9. 内置内容与中文化

### 9.1 资源合同

正式资源包必须有版本清单、七源元数据、校验通过的真实条目、中文标题／标签／正文、原文与出处、条目数及权利记录；可合法分发的缩略图一并保存。不只是七个空 URL，也不能用几条自编示例冒充完整来源内容。

构建期固定上游实际 commit／内容哈希与来源版本，manifest 和数据必须来自一致版本；从临时目录验证通过后原子替换资源包。首开导入 SQLite，重复启动幂等；资源由主进程读取，不把巨大 JSON 全塞进前端 bundle。示例图和设计稿不得导入“我的作品”成为用户数据。

每源采用合法可用的真实数据快照，记录采用数量、未纳入部分及原因；不是人为只取三条凑七源。某源无数据或权利不清时，标记该源未完成，不能用假数据填充后宣称开箱可用通过。

### 9.2 翻译

原文、中文译文、个人副本分别保存。中文化必须保护画面指定文字、尺寸、变量和专有名称。源正文变更才标记相应译文过期；只改时间戳不重复翻译。

初始译文在开发／资源准备阶段集中产出和校验，可复用上游中文字段和本轮可用文本处理能力。不得在每位员工首次启动时秘密进行全量付费翻译。运行时“更新来源”下载数据与付费翻译分开；新增原文可显示“待翻译”，不挡住已有中文内容，按用户主动动作或已有明确额度处理增量译文。

### 9.3 版权和图片

上游代码许可不自动重新授权所有提示词和图片；按来源记录内容与图片使用条件，不擅去水印或署名。[S4] 无法合法随包分发的示例图用明确占位，文本仍可使用。JSON 可用不等于外链预览图可用；断网必须不阻塞文本使用。

## 10. 来源级管理、更新与升级合并

### 10.1 来源操作

| 动作 | 输入 | 必须结果 |
| --- | --- | --- |
| 新增 | 名称、HTTPS JSON URL、可选出处／备用地址、启用状态 | 新稳定 ID、独立命名空间；校验后使用 |
| 编辑 | source_id 与字段 | 记录用户覆盖、配置修订；不丢旧快照 |
| 启用／停用 | 来源 ID | 控制浏览及自动刷新，缓存保留 |
| 删除 | 目标 ID 和确认 | 参考库移除，持久删除标记，升级不复活 |
| 单源刷新 | 启用源 | 成功后原子替换该源，失败保留上版 |
| 刷新已启用来源 | 启用源集合 | 每源独立状态，一个失败不清空其他源 |
| 测试地址 | 候选 URL | 只读取、检查格式与数量，不调用模型、不写正式快照 |
| 恢复内置来源 | 用户明确选择的已删源 | 只恢复所选源，并告知将使用当前默认配置 |

来源名称限制 1–80 字符。自定义 JSON 按已核对标准归一化；外部条目 ID 置于本地 source_id 命名空间，不能覆盖其他源的记录。网页、README、HTML 登录页不当作有效 JSON。镜像只作为线路，不改变署名和内容所有权。

内置源也能编辑、停用、删除。删除来源不删除个人副本、图像快照和已有作品。同步晚返回时检查 source_id、配置修订号、删除状态，旧请求不得复活已删源或覆盖新地址。

### 10.2 四类数据所有权

随包默认来源、用户覆盖／删除标记、来源内容快照、个人提示词副本必须区分。采用现有 SQLite 即可，不搭复杂同步平台。

| 升级／更新场景 | 行为 |
| --- | --- |
| 新安装 | 七源和有效中文快照一次性初始化 |
| 升级新增默认 source_id | 添加新 ID；同名用户源不被替代 |
| 默认地址或名称变化 | 只更新没有用户覆盖的字段 |
| 用户改过地址 | 保留用户地址，标识已有自定义 |
| 用户停用或删除 | 原样保留，除非用户主动恢复 |
| 默认源退役 | 停止默认更新并说明，个人副本／作品不动 |
| 默认内容升级 | 按一致版本、稳定 ID 和哈希合并，不覆盖个人内容 |
| 用户改过下载源且已有有效快照 | 不用包内另一线路的旧数据覆盖当前内容 |
| 更新结果为零条、格式错误或异常骤减 | 保留旧版，隔离异常快照；主动确认异常替换与普通刷新分开 |
| 检测或同步失败 | 保留输入和上次成功数据，显示具体原因 |

启动时超过 24 小时才检查已启用来源；使用中默认每 24 小时检查，支持手动刷新。同源请求合并、失败退避、不每次搜索联网。最后成功同步时间与包内数据版本不同，不把本地导入时间伪装成联网成功。

有上游可比较版本时按版本判断；只有内容 hash 而无版本顺序时，不能用“下载得晚”推断“内容更新”。主线路失败转备用只作为恢复候选；无法确认是否较旧的不同快照保留当前内容并标“版本待核对”，不得静默覆盖。

## 11. 局部修改

输入：原图、画笔／橡皮选区、修改要求。支持大小调整、撤销／重做、清空、缩放／平移；遮罩保存原图坐标，显示颜色不能写入原图。

优先按真实渠道合同提交原图和 mask；不支持 mask 时可评估标注参考方式，但明确属于模型理解，并用本地合成保护允许区之外像素。生成结果尺寸／方向无法正确对齐时阻止合成，不能强行拉伸后说只改了选区。

允许变化范围包含用户选区及明确显示的羽化带。先规范方向、尺寸与色彩表示，在同一解码像素空间比较；允许区外零差异。编辑结果以无损受管图保存，JPG 导出后的有损差异不能拿来证明选区外保护失效或成功。

默认不覆盖原图，创建 parent_work_id。失败保留选区和输入；未选区或要求为空时不给无效提交。关闭弹窗不等于取消供应商正在计费的任务。

## 12. 草稿、任务、作品和导出

### 12.1 草稿与任务

草稿包含描述、参考资产、角色、可用参数与修订号。自动保存采用修订校验；切页或关闭要刷入最后修改，不能因防抖未触发丢字。冲突保留双方内容，不能只提示冲突却永久无法保存。

Main 持有长任务，至少区分：排队、请求已发出、取得结果／下载中、成功、部分成功、明确失败、结果待确认、已取消／停止等待。前端只订阅状态，不把页面卸载等同取消。

请求被接受前失败、明确 4xx、模型返回拒绝、本地下载失败和供应商结果不明分开处理。非幂等生图请求超时不能直接重发；有受支持任务 ID 时查询，没有则保留待确认。仅下载失败时重试下载而不是重生图片。遵守原队列，不扩大到修改全局其他业务重试策略。

取消仅作用目标 task／queueScope，明确已发送请求是否能取消以及可能仍计费。重启保留完整已成功作品；未完成请求按实际可恢复条件处理，不盲目再次 POST。

### 12.2 作品与版本

记录稳定作品 ID、任务 ID、原图／参考图引用、父版本、真实模型、提交提示词快照、参数、实际尺寸、文件类型、受管路径、哈希、时间和收藏。没有真实 seed 或渠道元数据就不显示。

支持搜索、收藏筛选、创建方式筛选、详情、继续创作、反推、保存提示词、下载与分层。版本使用列表／时间线，不新建无限画布。普通多图结果是同任务兄弟结果，不得伪装为顺序修改的父子版本。

软删除不等于释放磁盘。只物理清理无引用受管文件，不能删除用户原始上传路径；父作品被其他版本引用时保留需要的元数据与资产。不可用文件标记丢失，不能显示下载成功。

### 12.3 图片下载

输出实际 PNG／JPG／WEBP 编码；PNG 和支持的 WEBP 保留透明，JPG 合成白底并说明。沿用原生保存对话框；同名覆盖由对话框确认。临时文件写入成功后原子完成，磁盘不足不留下伪成功记录。导出记录只保存非敏感元数据。

## 13. 真正的像素分层 PSD

### 13.1 输出边界

本版必须提供“图像 → 有意义的独立像素图层 → 可检查和导出的 PSD”完整链路，不是 PSD 扩展名按钮。照片层、主体层、背景层等为真实 RGBA；文字像素层不承诺能改字，不要求在本版新增原生文字／矢量编辑器。

不要求配置第三个云模型。优先在现有视觉文本模型提供语义对象／区域候选、本地分割细化和图像处理、已有 PSD 写入工具之间完成。**视觉理解不等于精确分割**；必须用样本验证算法，不能只让语言模型猜一个矩形就称为自动拆层。

### 13.2 最小真实语义结果

对于可处理的样本，系统先提供语义相关的候选层，用户可检查并用复用的画笔修正。允许像素可见区域分层：主体为一层，剩余背景为一层，未补全的遮挡区域透明。移动主体可能露洞必须明确说明；这不是恢复原始设计工程。

完全从零手工涂完整遮罩只能作为补救，不能用来宣称自动拆层已完成。候选无法稳定生成时将自动拆层标为失败／受限，继续修复，不偷换成任意条带切片。需要新付费服务或下载大模型时先记录真实依赖，不擅自引入。

用户明确选择“补全被遮挡背景”且当前编辑接口确实支持时，才可用现有图片模型额外生成补全层，并标识生成内容；不得默认隐藏计费。未实现该可选增强时保留诚实的可见像素分层，不阻塞其他本版能力。

### 13.3 检查和导出

至少两个可见且有实际不同语义内容的层；图层数由内容决定。不能通过空层、重复整图、仅改几个像素、矩形网格、隐藏原始整图掩盖错误来凑验收。

显隐、排序、单层／合成预览与最终 PSD 共用同一数据。未补全背景时，完整层集在标准化像素空间重组应与原图一致；每个像素覆盖和 alpha 合成可验证，不漏像素，不重复叠加半透明边缘。保留真实尺寸、方向、透明和中文层名。

PSD 写入／回读测试之外，需在 Photoshop 实际打开、独立操作层、检查合成和透明边缘。目标软件不可用时标“待实机验证”，不能以 `ag-psd` 回读代替。当前 8×6 色块测试只能证明基础写入，不是用户场景验收。

## 14. 数据、隐私、合规与人工核对

业务权威数据进入现有 SQLite 或功能专用 Store，大图片在受管文件目录；Renderer 的 localStorage 只保存轻量 UI 偏好。备份一致的数据库及必要文件引用后迁移；验证隔离副本、失败恢复，不操作真实项目作为测试夹具。

只向当前文本／图片渠道上传用户主动选中的图片和提示词，不附带招标项目、无关本地目录或密钥。来源下载不携带模型鉴权；处理 URL 时校验协议、重定向和实际外部边界，不允许读本地文件、内网或执行远程脚本。既有模型私有端点由原配置策略管理，不把公共来源 URL 规则套到全部现有渠道。

不默认注入公司品牌、竞品或敏感示例内容；原有适用保护保留，但不得把来源作者名称误删为竞品。通用生图不新增投标审批流或全局词库模块。人工核对体现在优化主动应用、图层确认、导出前提示用户检查内容权利与用途，不增设每次都要重新审批的操作障碍。

源新增改址启停删除／同步、个人内容保存应用、任务、版本与导出在本地留痕；开发任务状态仍只放 `tasks/todo.md`。统计沿用原允许的计数和耗时，不把原始 prompt、图片、文件名或密钥上报。用户内容与测试数据、设计样图分开。

## 15. UI 与性能完成标准

以 R3 Handoff 和 11 张有效独立图稿实施；不使用此前多页概念海报、不按其改一级导航。旧图的虚构模型、时间、自动品牌与多余入口按 Handoff 勘误，不能继续实现。

响应式基于主内容可用宽度，不固定屏幕截图尺寸。至少实际检查 1440×900、1280×800、1024×768（既有最小窗允许时）及 Windows 100%／125%；不修改既有最小窗来“通过测试”。窄窗收右栏，主按钮可达，弹窗内部滚动，Tab／Esc／焦点正常。

大列表分页或虚拟化、缩略图懒加载，不把所有高清图／来源原文一次性推给 Renderer。重图解码、分割与 PSD 构造不能堵塞 Electron 主事件循环；在现有基础上采用工作线程或必要独立处理，不引入庞大新后台。

接口返回百分比不可得时显示阶段／不定进度，不伪造剩余秒数。错误提供明确原因和可执行入口，成功只在实际状态满足时显示。
